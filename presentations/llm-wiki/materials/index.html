LLM Wiki 학습 자료

원자료를 읽고 개념을 연결하며, 검토한 답을 다음 학습에 남기는 방법

AI 스터디에서 읽은 논문과 설명을 다음 질문에도 쓸 수 있는 지식으로 남겨 봅시다. 이 자료는 발표에서 빠르게 지나간 개념을 혼자 따라 읽고, 실제 Markdown 예제를 고치며 익히도록 구성했습니다. RAG·LoRA·파일 위키를 비교하는 하나의 학습 사례가 전체 자료를 이어 줍니다.

먼저 무엇을 읽을까요

원하는 일 시작할 자료 읽고 나서 할 수 있는 일
개념부터 차근차근 이해하기 학습 가이드 원자료를 개념·비교·질문 페이지로 정리하고, 새 자료가 들어왔을 때 바꿀 부분을 설명합니다.
직접 작성하며 익히기 해설 있는 실습 입력 자료로 주장과 근거를 나누고, 잘못된 답을 고치고, 검토한 답과 변경 이력을 남깁니다.
20분 스터디를 진행하기 장별 발표 대본 실제로 말할 문장, 질문, 전환과 예상 답변을 따라 진행합니다.
주장 근거와 더 읽을 원문 찾기 주제별 참고 자료 어떤 원문이 어느 주장을 지원하는지 확인하고 필요한 부분부터 읽습니다.

학습 가이드는 예제를 살펴보며 읽는 데 약 45~60분, 실습은 20~30분을 예상합니다. 이 시간은 학습 경로를 위한 추정이며 실제 독자의 속도를 측정한 값은 아닙니다. 발표 대본은 설명 18분과 청중 질문 2분으로 구성합니다.

혼자 공부하는 순서

  1. 학습 가이드에서 세 층의 역할과 자료를 반영하고 질문하고 점검하는 흐름을 읽습니다. 예제에서 “무엇을 읽었나”와 “무엇을 알게 되었나”가 어디에 각각 남는지 찾아보세요.
  2. 개념 페이지와 비교 페이지를 읽은 뒤, 질문에 대한 답이 다시 저장되는 과정을 따라갑니다. 답을 복사하는 것에서 더 나아가 근거·범위·검토 상태를 함께 남기는 이유를 설명해 보세요.
  3. 실습을 풀고 해설과 대조합니다. 표현이 다른 것은 괜찮습니다. 원문이 지원하는 범위와 자신의 해석을 구별했는지가 핵심입니다.
  4. 궁금한 부분은 참고 자료의 읽기 안내를 따라 원문에서 확인합니다. 모두 순서대로 완독할 필요는 없습니다.

발표를 먼저 보려면 발표 읽기로 돌아가기를 이용하세요. 발표 후에는 질문 하나를 골라 가이드의 예제와 실습을 연결해 읽으면 됩니다.

자료를 읽는 약속

연구 논문과 저자의 설계 문서는 실제 출처입니다. 자료 안의 스터디 폴더, 질문, 기록 카드와 학습자의 선택은 작동 원리를 설명하기 위해 만든 예제입니다. 예제의 답안을 실제 운영 결과나 측정된 도입 효과로 읽지 않습니다.

학습 목표는 링크 수나 페이지 수를 늘리는 데 있지 않습니다. 한 주장에 돌아갈 근거가 있고, 다음 사람이 그 범위와 변경 이유를 이해할 수 있다면 작은 위키에서도 시작할 수 있습니다.
