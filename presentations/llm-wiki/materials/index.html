LLM Wiki 학습 자료

정의와 작동 과정, 서로 다른 세 적용 예와 파일 교정 심화를 이어 읽는 자료

LLM Wiki는 LLM이 원자료 사이의 개념·비교·연결을 Markdown 위키로 작성하고 계속 갱신해, 다음 질문이 이전 정리에서 출발하도록 하는 지식관리 방식입니다. 답을 모으는 데서 더 나아가 여러 자료를 함께 읽은 결과를 유지합니다. 특정 완제품이나 공식 표준을 뜻하지 않습니다.

먼저 무엇을 읽을까요

원하는 일 시작할 자료 읽고 나서 할 수 있는 일
정의·동기·작동 이해 학습 가이드 원자료·위키·작업 규칙과 ingest/query/lint의 역할을 설명합니다.
다른 분야의 입력과 출력 보기 세 가지 적용 예 독서·고객 요구·강의 메모가 여러 페이지와 후속 질문으로 이어지는 과정을 읽습니다.
내 자료로 작성해 보기 실습과 해설 LLM이 쓸 페이지, 다시 읽을 파일, 새 자료의 영향과 검토할 경계를 정합니다.
발표 진행 40장 대본 핵심18분+질문2분의 계획과 별도 심화 경로를 따라갑니다.
공개 원문과 구현·논문 확인 참고 자료 저자 설계·코드 관찰·논문 실험·구성 예의 근거 수준을 구별합니다.
파일 교정의 일부를 재현 기존 교정 실행 기록 사람이 승인한 안을 Node로 적용한 diff·링크·해시 검사를 읽습니다.

발표와 깊이 읽기를 나누기

발표는40장 중1~28장을 연속으로 설명·참여1,080초(18분),40장을 Q&A120초(2분)로 쓰는 배분안입니다.29~39장 선택 심화의555초는 별도입니다.20분은 실제 리허설 결과가 아닙니다. 대본과 발표 읽기를 함께 볼 수 있습니다. 이 자료의 장 링크는 별도 읽기 화면을 여는 참고 경로입니다.

학습 가이드는 사례를 읽으며 약45~60분, 기본 실습은15~20분, 기술 스터디 심화 실습은 별도20~30분을 예상합니다. 독자의 속도를 측정한 값은 아닙니다. 처음부터 전부 완독할 필요 없이 자기 질문과 닮은 사례를 하나 고르세요.

세 사례의 실물 열기

  • 소설 독서: 장 메모에서 인물·주제·질문 답으로. 입력·전후파일 txt
  • 고객 요구: 상담과 회의에서 요구 비교·현재 응대로. 입력·전후파일 txt
  • 강의 메모: 서로 다른 단원에서 공통 개념·새 기준·종합으로. 입력·전후파일 txt

세 사례는 가상 자료로 만든 적용 예입니다. 실제 소설·고객·수업이나 모델 실행 결과가 아닙니다. 파일 읽기/쓰기 도구가 있는 에이전트가 입력과 관련 위키를 현재 문맥에 읽고, 페이지를 작성·갱신한다는 흐름을 설명합니다. 다음 질문에서는 저장한 페이지를 다시 읽어야 합니다.

자료를 읽는 약속

원저자의 적용 용도 제안, 관찰한 공개 구현, 제한된 논문 실험, 우리가 만든 예제를 구별합니다. 세 사례의 문장은 구성 예이며 공개 저장소는 설치·실행하지 않았습니다. 기존 ZIP에서 실제 재현한 것은 고정 승인안의 파일 반영과 검사입니다. LLM의 자동 검색·새 답 생성·의미 검증을 실행한 기록으로 읽지 않습니다.

도입의 판단은 파일 수보다 다음 질문에 필요한 설명과 근거를 다시 찾을 수 있는지, 새 자료가 들어왔을 때 고칠 부담을 감당할 수 있는지에 둡니다. 학습 가이드로 시작하기 · 내 질문으로 실습하기
