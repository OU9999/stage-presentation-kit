자료 하나, 주장 하나, 결정 하나부터
공개 시작 템플릿 / 실무 제안 / 2026-10-28

이 파일은 작은 범위로 시작하기 위한 발표자의 실무 제안이다. 공식 LLM Wiki·PROV·ADR 표준 양식이나 완제품의 설치 절차가 아니다. 아래 폴더·파일 이름은 예시이며 이 발표 저장소에 구현되어 있다는 뜻은 아니다. 빈칸은 실제 근거로 채우고 모르는 날짜·범위는 “미확인”으로 남긴다.
실제 설계 원문과 주장별 경계는 sources.txt, 완성된 합성 카드는 decision-example.txt, 발표 진행은 speaker-guide.txt에 있다.

작게 시작하는 파일 구조

my-wiki/
  raw/
    source-001.txt          읽은 원자료의 보존 사본 또는 원본 위치와 판 기록
  wiki/
    index.md                페이지를 찾는 목록
    log.md                  무엇을 언제 왜 바꿨는지의 이력
    topic.md                지금 필요한 개념·질문 또는 운영 페이지 한 개
    source-001.md           자료 카드 한 개
    claim-001.md            주장 카드 한 개
    decision-001.md         실제 선택이 생겼을 때의 결정 카드 한 개
  schema.md                 옆에서 작업 방법을 정하는 규칙

raw는 원자료를 보존하는 곳, wiki는 사람이 열어 읽고 고칠 수 있는 연결된 파일이다. 새 판을 받으면 raw의 이전 판을 덮어쓰기보다 별도 자료로 남기고 연결한다. schema는 raw와 wiki 다음으로 통과하는 결과물이 아니라 작업 규칙이다. S1의 구조에서 착안한 구성이고 모든 위키의 보편적 정의는 아니다.
처음부터 위 파일을 모두 채울 필요는 없다. 자료 한 개와 주장 한 개를 확인하고, 실제 선택이 생기면 결정 한 개를 남긴다. 개념·질문·운영 페이지는 필요한 것부터 만든다. 비교 페이지는 비교할 질문이 생겼을 때 추가할 수 있다.

schema.md에 적을 작은 작업 약속
- 원자료의 내용과 내 해석을 구별한다. 새 판은 이전 판과 구분해 보존한다.
- 각 주장에 자료 ID, 문장 위치, 확인일, 적용 범위를 연결한다.
- 직접 지원·해석·제안을 나눈다. 자료에 없는 반복 주기·효과·범위는 미확인으로 표시한다.
- 질문에 유용한 답이 나와도 근거와 범위를 사람이 검토한 후 선택해 wiki에 남긴다.
- 기존 주장과 충돌하거나 범위가 달라지면 변경 전에 영향 페이지·주장·결정을 검토한다.
- 승인된 변경은 log에 남기고 과거 결정은 삭제하지 않는다. 대체 관계로 연결한다.
이 규칙은 기대하는 작업 방식이다. AI의 준수, 오류 방지, 모든 연결의 발견을 보장하지 않는다.

자료 카드 최소 양식 / source-001.md

ID: [자료 ID]
제목·판: [제목 / 판 또는 버전]
작성자·발행자: [확인한 이름 / 미확인]
작성일: [확인한 날짜 / 미확인]
수정일: [확인한 날짜 / 미확인]
확인일·확인자: [자료를 실제로 확인한 날짜 / 이름]
원본 위치: [정확한 URL 또는 보존 파일 경로]
고정 버전·보존 위치: [판·revision·사본 위치 / 미확인]
관련 문장 위치: [절·쪽·문단·행 등 다시 찾을 수 있는 위치]
확인한 내용: [짧은 요약 또는 필요한 최소 문장]
한계: [확인하지 않은 범위·메타데이터]
연결된 주장·페이지: [주장 ID / 페이지]

주장 카드 최소 양식 / claim-001.md

ID: [주장 ID]
한 문장: [검토할 주장을 하나만 적기]
근거 ID·위치: [자료 ID / 관련 문장 위치]
종류: [직접 지원 / 해석 / 제안 중 선택]
적용 범위: [대상·날짜·조건·판]
지원하지 못하는 확장: [예: 한 날짜 공지에서 “매주”는 미확인]
확인 상태: [확인 / 미확인 / 충돌 / 과거 판 기준 등]
확인일·검토자: [날짜 / 이름]
연결: [관련 개념·질문·결정 / 이전·후속 주장]

자료에 링크가 있다는 것과 그 자료가 이 문장을 지원한다는 것은 다르다. 근거 문구와 주장 문구를 직접 대조한다. 미지원이라고 표시한 확장을 곧바로 거짓이라는 새 사실로 단정하지 않는다.

결정 카드 최소 양식 / decision-001.md

ID·제목: [결정 ID / 선택을 드러내는 제목]
배경: [왜 지금 선택해야 하는가]
근거: [자료·주장 ID / 적용 범위]
선택: [무엇을 하기로 했는가]
선택 이유: [왜 이 대안을 선택했는가]
대안: [다른 선택과 보류 가능성]
결과·부담: [예상 영향 / 실제 확인한 결과 / 남은 일을 구분]
상태: [proposed / accepted / rejected / superseded by 후속 ID 등]
담당·결정자: [이름 또는 역할]
결정일: [날짜]
재검토 조건: [새 판·충돌·기한 등 다시 볼 조건]
이전 결정: [이전 ID / 없음]
후속 결정: [후속 ID / 없음]

자료의 사실과 행동의 선택을 구분한다. 예를 들어 시각 공지에서 “안내를 언제 어떻게 바꿀지”가 자동으로 결정되는 것은 아니다. 후속 결정을 승인하면 이전 결정에 “superseded by [후속 ID]”를 남기고 당시 근거·이유를 보존한다. 계획·승인·실제 외부 수정 완료는 각각 구별해서 기록한다.

찾기와 변경 이력

index.md 예시
현행 페이지: [개념 / 질문 / 운영 등 필요한 페이지 링크]
현재 안내의 근거: [현행 주장·결정 링크]
아직 확인할 질문: [질문 페이지 링크]
index의 역할은 페이지를 찾는 것이다. 변경 이력을 대신하지 않는다.

log.md 한 줄 양식
[날짜] / [변경자·검토자] / [바꾼 파일·주장·결정] / [이유·새 자료] / [이전→후속 연결] / [남은 일]
log의 역할은 무엇을 언제 왜 바꾸었는지 추적하는 것이다. 현행 페이지의 내용을 대신하지 않는다. 실제로 바꾸지 않은 외부 안내물은 “점검 예정”처럼 남은 일로 적는다.

세 가지 반복 작업
ingest: 새 자료를 읽고 근거 위치를 확인해 관련 페이지에 연결한다.
query: 질문하고, 유용한 답의 근거·범위를 사람이 검토한 뒤 필요한 결과만 파일에 남긴다.
lint: 낡은 주장·충돌·빠진 연결을 살피고 미확인과 남은 일을 표시한다. 자동 점검에 누락은 가능하다.

복사해 사용할 검토 요청 프롬프트

“이 자료에서 확인되는 문장과 해석을 나누고 각 문장의 근거 위치를 붙여 주세요. 반복 주기 등 자료에 없는 내용은 미확인으로 표시하세요. 기존 페이지와 충돌하면 바꾸기 전에 영향 주장과 결정을 보여 주세요. 원자료는 덮어쓰지 말고 변경안을 제시해 주세요. 유용한 답을 wiki에 남길 후보도 근거·범위와 함께 제시하고, 사람이 검토할 항목과 남은 일을 표시해 주세요.”

이 프롬프트는 사람 검토를 돕는 작업 요청이며 오류 방지 보증이 아니다. 결과의 근거 위치, 적용 범위, 충돌, 누락을 사람이 확인한다. 자료의 날짜가 더 새롭다는 이유만으로 이전 주장을 모두 교체하지 않는다.

작은 첫 실행
1. 다시 찾고 싶은 자료 한 개를 고르고 자료 카드를 쓴다.
2. 그 자료가 지원하는 주장 한 문장을 적고 범위와 미확인을 확인한다.
3. 실제 선택이 필요하면 이유·대안·재검토 조건을 결정 카드에 남긴다.
4. index에 찾는 입구를, log에 실제 변경 이력을 남긴다.
5. 다음 질문이나 새 자료가 생기면 연결을 다시 검토하고 필요한 파일만 갱신한다.

파일을 저장하는 일은 모델 가중치를 학습시키는 일과 구분한다. 파일 wiki는 필요하면 검색(RAG)과 함께 쓸 수 있다. RAG 전반에 훈련이 없다고 일반화하지 않는다. 이 양식의 정확도·절감 시간·유지비·누락률은 측정하지 않았으며, 출처·규칙·이력이 있어도 오답과 낡은 정보는 남을 수 있다.
