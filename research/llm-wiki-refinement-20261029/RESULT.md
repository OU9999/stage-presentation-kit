# 비유·시각자료와 20분 진행안 실제 반영

공용 스터디 노트를 함께 고쳐 다음 질문에 다시 쓴다는 비유를 실제 원자료·설명·작업 규칙·변경 이유에 연결했다. 정의와 실제 위키 한 쪽, LLM/사람/오늘 실행의 역할을 초반2~4장에 두었다. 40장과 공부 자료6개는 유지하고 핵심27장·선택 심화13장으로 나눴다. 설명/참여18분+질문2분은 리허설 전 배분안이다.

## 내용에 맞춰 고른 시각자료

| 역할 | 실제 반영 |
| --- | --- |
| 친숙한 비유와 정의 | 2장 정의, 3장 실제 C1 노트의 설명·근거·이유, 4장 역할 구별, 6장 공용 노트와 파일 역할 대응 도식 |
| 도입·활동의 사진 | 1장 책상 사진, 34장 자료 고르기→질문 쓰기→대조하기의 세 사진. 준비 예와 지금의 질문 한 줄을 구분 |
| 근거와 변경 | 9장 원문 위치/메모/해석, 13장 실제 RAG 근거, 17장 큰 수정 전후 문장. 17의 실제 문장 전체를 Markdown으로 보존 |
| 재사용·결정의 관계 | 19장 한국어 역할 우선, 22장 입력→판단 방향, 24장 현행/보류, 26장 대체된 결정의 맥락 보존 |
| 수량과 확인 범위 | 31장 기존 비율 막대를 제거하고8쪽·25링크·10보존 파일의 각 검사 범위를 따로 표시. 다른 단위를 같은 축으로 비교하지 않음 |
| 원저자의 인용 | 7·30장 한국어 의미를 먼저 읽고 정확한 영문과 원문을 보조로 배치 |
| 청중 행동 | 12·23장 동일 색·폭·높이·크기의 A/B와 독립 안내, 선택 이유는 자율. 35장은 자기 노트에 질문 한 줄부터 쓰기 |

17·31·35는 시안 전체 이미지를 붙이지 않고 기존 Markdown 조판을 사용했다. 새 도식2개와 수정 도식2개는 주제 자산으로 둔다. 공통 엔진/CSS는 바꾸지 않았다. 데모25파일과 ZIP의 바이트도 그대로다. 오늘의 파일 실행과 실제 새 LLM 실행을 구분한다.

## 핵심 진행과 자료 깊이

핵심 경로는 `1→2→3→4→6→7→10→11→12→13→17→18→19→21→22→23→24→25→26→29→31→33→34→35→36→39→40`이다. 비연속8지점에 실제 장내 의미 링크를 두어 이어갈 수 있다. 상세 원문·JSON·운영 설명은 선택 심화와 기존 자료에 남겼다. 학습서·대본·원문 안내/용어집·워크숍·실행 기록을 없애 발표를 짧게 한 것이 아니다.

새 시각을 디자인 담당자와 초심자 역할이 별도로 검토하고 직접 대조했다. 비유·역할·재사용·참여 지시의 차단 문제는 찾지 못했다. 남았던 끝말 고립, 수량 카드 정렬, 준비 수량의 예시/필수 구분도 최종5장 화면에서 다시 확인했다. 이는 에이전트의 역할 기반 후검수이며 실제 사람 반응이나 실제20분 완료의 검증은 아니다. 자기 노트에 질문을 쓰는 안내와 개별 앱의 파일 읽기·수정·저장 체험도 구분한다.

원고 SHA256은 `2b09aaabe8682deacadad7571ac4b6f1f6545ac2173c3bb138f1c0533b0ec233`이다.

- 자료6개×1440/390 전문 누락0·본문18px·탐색·코드 키보드 조작 통과.
