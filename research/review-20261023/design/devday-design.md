# DevDay 디자인 검토 — 구획보다 결과물이 먼저 읽히게

작성: `/root/design_manager/devday_designer`, 2026-10-23. DevDay 디자인의 시각 문법을 검토하는 역할이며 OpenAI 근무·원본 제작 경력을 주장하지 않는다. 제품 수정 없이 원본 보존 이미지와 현재 렌더를 비교했다. 최종 시안은 [proposal.html](proposal.html), 기업 발표 디자인 관점의 취합은 [presentation-design.md](presentation-design.md)를 따른다.

## 판단과 추천

사용자가 느낀 배치·테두리의 어색함은 비교 근거가 있다. 현재 #4는 서울·도쿄의 **바깥 정렬과 서로 다른 내부 분할**을 이미 상당히 따른다. 더 크게 달라진 것은 **무엇이 어떤 매체로 보이는지, 밝고 어두운 면의 무게, 한 장의 내용이 연결되는지**다. 공통 border 색만 교체하면 이 차이의 일부만 다룬다.

현재의 12열×6행·12개 footprint는 유지해 비교할 가치가 있다. 우선 **B로 경계의 영향을 분리해 보고, C로 하나의 이야기에서 나온 결과물을 편집하는 방향**을 추천한다. B가 해결할 수 없는 작은 UI·일반 문구·소재 연결의 문제를 C에서 다룬다. 균등 타일 전환, 임의 회전·산개, 모든 border 제거를 DevDay의 정답으로 제시할 근거는 없다.

## #4: 근거 → 현재 → 구현 가능한 diff

## A/B/C의 비교 계약

파트너 `/root/design_manager/presentation_designer`와 직접 협의한 기준이다. 아래 값은 독립 시안의 제안 범위이며 OpenAI 원본 규격이 아니다.

| 구분 | 고정하는 것 | 바꾸는 것 | 판정할 질문 |
| --- | --- | --- | --- |
| A — 현재 처리 재구성 | 현재 12개 내용·파일·span·순서·수치·문장·fit/focal·가터·기본 글자 크기 | 독립 검토 페이지에 현재 처리 재현 | 실제 baseline와 같은 구조·읽기 문제를 보여 주는가. A를 원본 DevDay나 제품 전체의 재검증으로 부르지 않는다. |
| B — 경계·표면 분리 | A의 배치·자산·fit/focal·타이포·내부 padding | 외곽 border, wash, 표면 역할, 모서리 mask만 조정 | 모든 footprint가 같은 카드처럼 보이는 정도가 줄어드는가. 매체의 색과 형태가 살아나는가. |
| C — 한 이야기의 결과물 편집 | 가능하면 같은 12 footprint와 외곽 질서를 유지 | 소재·짧은 label·결과 UI·작품·crop·매체 고유 형태 | 주역 1~2개가 보이고, 나머지가 그 주장/작업을 받치는가. 작은 칸을 장식 구호로 채우지 않았는가. |

B의 출발 제안은 어두운 수치·문자만 흰색 중립선 alpha 약 0.10~0.12, wash 약 0.015~0.025로 낮추고, 사진·UI·작품의 wrapper는 투명하게 두는 것이다. 밝은 UI의 원래 면색과 사진의 색은 보존한다. 원본 사진에서 얻은 색 토큰이 아니라 검토를 위한 시작값이다. 시안 작성자가 실제 적용한 값은 `proposal.html`을 따른다.

A/B의 이미지 content box를 일정하게 유지하려면 border를 단순 삭제하는 대신 같은 1px의 투명 border를 사용하는 방법이 있다. B에서 fit·자산·crop을 바꾸거나 SVG 내부 frame을 재제작하면 선의 영향과 편집의 영향을 분리하기 어렵다. 그런 변경은 C의 역할이다. B에 Signal 검은 띠·작은 UI가 남는 것은 비교상 정직한 한계이며 B 실패만을 뜻하지 않는다.

C의 잠정 편집 주제는 **Field Notes — 관찰을 모아 정리하고 다음 행동으로 공유하기**다. 실제 제품 발표나 OpenAI 제품 복원이 아니라 독립 가상 이야기다. 기존 문서/작업 UI에 이미 있는 Field Notes 맥락을 사용하되, 모든 칸에 이름·프로젝트 번호를 되풀이하지 않는다. 오른쪽 완성 결과물을 주역으로, 기록/정리 UI 한 개를 보조 앵커로 두고 작은 칸은 서로 다른 역할을 맡긴다. `24 → 6 → 3`은 이야기상 묶음이며 퍼널 차트나 실증적 전환 비율로 연결하지 않는다.

## 범위와 다음 검토

추천 순서는 **P0: 같은 자산의 경계 비교 → 같은 이야기의 소재 편집**, **P1: UI·문서가 읽혀야 하는 크기와 나머지 장의 label/focal 정리**, **P2: 직접 검증 가능한 전환**이다. #2 사진6열, #5 아이콘월, #6 두 수치는 구조를 유지한 채 필요한 부분만 다듬는다. 제품 전체 덱 교체나 공용 런타임 수정을 이번 독립 시안 완료로 포함하지 않는다.

## 독립 시안의 실제 검토 결과

이 담당자는 `proposal.html`의 실제 HTML/CSS/템플릿을 읽고, 매니저가 생성한 [C 최종 데스크톱 캡처](proposal-desktop-c.png)를 `view_image`로 직접 검토했다. 브라우저 조작·Console·Network·모바일 검증은 매니저가 맡았으며 이 담당자의 수행 결과로 합치지 않는다.

- A/B가 같은 `current-template`와 같은 슬롯 좌표를 재사용하고, 미디어의 border 1px를 투명하게 유지하는 것을 코드에서 확인했다. 따라서 텍스트·자산·fit을 바꾸지 않고 경계/면/반경을 비교한다는 계약에 맞는다. A를 제품의 픽셀 단위 복제 화면으로 부르지 않는 한계 표기도 있다.
- C의 오른쪽 표지는 큰 제목 아래 충분한 아트 면을 확보해 이름만 적힌 문자판과 구별된다. 초기 작은 도장처럼 축소되던 아트를 파트너에게 직접 지적했고, 최종 캡처에서는 표지 전체 폭에 걸친 그래픽으로 개선된 것을 확인했다.
- 작은 세 칸은 인용 조각·음성 파형·발췌한 주제 도식으로 각각 구별된다. 여섯 주제 수치 옆에 세 주제만 그린 도식에는 ‘정리한 주제 중 일부’가 표시되어 발췌임을 명시한다.
- 중앙 UI는 한 행동+네 도구 자체 면으로 묶이고 전체 wrapper가 새 카드선으로 강조되지 않는다. 아래 왼쪽의 문제 세 가지와 아래 오른쪽의 실행 목록 세 가지가 대응해, ‘공유할 준비 완료’ 같은 일반 상태 문장을 하나 더 늘어놓던 초기안보다 결과물 역할이 분명해졌다.
- 작업 도식 안의 시안 검토용 설명을 notes로 분리하고, 표지의 불필요한 일본어·반복 번호를 정리한 것을 최종 캡처/소스에서 확인했다. 가상 수치·다른 작업 단위·별도 편집안이라는 안내는 바깥 설명에 유지한다.

최종 판단: **B는 공통 외곽선의 부담을 검토하는 최소안, C는 한 이야기의 결과물로 구성하는 권장 편집안**으로 각각 역할이 있다. C의 소재와 표면을 채택하더라도 원본 DevDay의 정확한 복원이나 현제품 반영 완료로 보고하지 않는다. 검토 후 제품 파일을 변경한 것은 없다.

변경 소유 파일은 이 문서 하나다. 공통 로그는 총괄 소유로 유지한다. 이 문서의 로컬 링크는 실제 존재를 검사했다. 제품 계약·Markdown 입력을 변경하지 않아 제품 테스트/예제 재생성을 실행하지 않았다. 제품 구현·전용 발표 모드·PDF·오프라인 전체 회귀는 이번 문서 검토의 완료 범위가 아니다.
