발표팀이 설명용으로 작성한 세 주제 메모와 예시 위키다.
주제 메모는 외부 원문의 발췌나 실제 관찰 기록이 아닌 자작 설명이다.
기술 주장의 일차 근거는 각 메모의 설계 글·논문·공식 문서에서 확인한다.
위키 문장·선택 이유·가상 조건도 발표팀의 구성 예이며 실제 모델 출력·스터디 성과가 아니다.

처음 질문: 다음 AI 스터디에서 LLM Wiki를 어떻게 시도할까?
나중의 질문: 입문자와 15분 활동은 무엇부터 할까?

읽는 법
경로별 제목을 검색해 주제 메모→자료 요약→개념·비교·계획을 따라 읽는다.
같은 경로의 ‘처음’과 ‘갱신’ 구간은 한 논리 파일의 전후 상태다.
나중에 raw/study-retro.md의 가상 조건을 읽고 기존 여러 페이지가 어떻게 달라지는지 비교한다.
요청 구간은 설계 흐름을 설명하는 예문이며 이 팩에서 모델을 실행한 기록이 아니다.
15분 활동은 준비된 문서를 읽고 관계·근거·후속 질문을 확인한다.
필요하면 각 구간을 해당 경로로 나눠 읽을 수 있다.

# 목적과 맥락

작성: 발표팀의 설명용 주제 메모. 외부 원문의 발췌나 실제 사용자의 직접 기록이 아니다.
목적: 우리 스터디에서 LLM Wiki를 왜 쓰고 어떤 질문에 다시 활용할지 정하기.

설명
- 같은 자료라도 쓸 결과와 질문이 다르면 강조할 개념·조건·차이도 달라진다.
- 자료를 보존하는 것과 그 자료를 함께 읽고 이해한 관계를 남기는 것은 다른 작업이다.
- LLM Wiki는 원자료에서 개념·비교·종합을 연결 문서로 작성하고 유지하는 층을 둔다.
- 새 자료를 반영할 때 관련 기존 페이지·목차·로그를 함께 살펴본다.
- 저장한 페이지가 다음 질문에 쓰이려면 필요한 쪽을 찾아 현재 문맥에 다시 읽어야 한다.

사람이 채울 선택 이유의 예
‘LLM Wiki와 RAG의 차이를 설명하고 다음 스터디의 진행안을 만들고 싶어서 이 메모를 골랐다.’
이 예문은 발표팀이 구성했으며 실제 사용자의 직접 관찰로 표기하지 않는다.

적용 범위
목적 한 문장과 자료 몇 개로 시작할 수 있다.
개인 기록을 계획·실행·관찰·해석·도구 작업 로그로 나누거나 기간별로 회고하는 방식은 선택적인 활용 예다.
그 구분이 LLM Wiki의 필수 다섯 계층이나 검증된 생산성 향상을 뜻하지 않는다.

일차 설계 근거
- Karpathy, LLM Wiki: https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f/ac46de1ad27f92b28ac95459c782c07f6b8c964a
  확인할 곳: The core idea, Architecture, Operations, Indexing and logging.

# 검색과 비교

작성: 발표팀의 설명용 주제 메모. 여러 기술의 역할을 같은 질문으로 비교하기 위한 자작 설명이다.
목적: 검색·지속 문서·모델 학습·에이전트 판단의 역할과 첫 시도의 선택 기준을 구분하기.

설명
- RAG는 필요한 외부 자료를 찾아 생성에 사용하는 패턴이다. 자료 준비·검색·선별·생성의 구현은 다양하다.
- Agentic RAG는 에이전트가 검색할 곳·도구·방식·반복을 판단하는 흐름이다.
- 파인튜닝은 파라미터나 학습 가능한 어댑터를 최적화한다. 파일을 고치는 작업과 구분한다.
- LLM Wiki는 사람이 읽을 연결 문서를 작성·갱신한다. 위키도 필요한 페이지를 검색해 읽을 수 있다.
- RAG도 관계·요약을 미리 만들고 결과를 저장할 수 있다. 네 방식은 서로 병행 가능한 설계 축이다.

사람이 채울 선택 이유의 예
‘검색·지속 문서·모델 학습을 같은 기준으로 설명하고 싶어서 이 메모를 골랐다.’
이 예문은 발표팀이 구성했으며 실제 사용자의 직접 관찰로 표기하지 않는다.

비교할 질문
다음 AI 스터디에서 LLM Wiki를 어떻게 시도할까?
입력·질문·비교 축을 같게 두고 남는 결과, 갱신 시점, 질문시 작업, 검토·유지 부담을 살펴본다.
이 예제는 정확도·속도·비용의 우열을 측정하지 않는다.

범위 확인
RAG의 전체 재색인이 항상 필요한 것은 아니다. 문서별 갱신을 지원하는 구현도 있다.
위키의 검색 유무나 문서 개수 하나를 보편적인 도입 기준으로 삼지 않는다.
RAG 원논문은 검색기·생성기 학습도 수행하므로 모든 RAG를 ‘학습이 전혀 없다’로 정의하지 않는다.

일차 기술 근거

- LoRA Abstract·§4.1: https://arxiv.org/html/2106.09685v2
- 검색 방식: https://docs.langchain.com/oss/python/deepagents/retrieval
- 문서별 갱신: https://learn.microsoft.com/en-us/azure/search/search-what-is-data-import
- 관계/요약을 미리 만드는 RAG 구현: https://microsoft.github.io/graphrag/index/overview/

# 지식의 활용

작성: 발표팀의 설명용 주제 메모. 지식을 다음 결과와 검토로 이어 가는 자작 설명이다.
목적: 정리한 지식을 사람이 쓸 결과물과 다음 질문으로 이어 가기.

설명
- 목적에 관련된 자료·경험·생각을 고르고 왜 필요한지 사람이 직접 적는다.
- 원문에서 확인한 내용, 사람의 직접 관찰·선택 이유, 생성된 종합을 구분한다.
- 관련 개념·비교·현재 계획을 다시 읽어 질문에 답하고 유용한 답을 검토 뒤 저장한다.
- 저장한 종합을 바탕으로 활동안·기획안·설명문처럼 쓸 결과를 만든다.
- 결과에는 사용한 근거, 선택 이유, 확인한 범위, 아직 모르는 점과 다음 질문을 연결한다.
- 공유 작업에서는 맥락·요청·논의·결과를 구분해 같은 근거와 현재 판단을 이어 읽는다.

사람이 채울 선택 이유의 예
‘정리한 지식을 진행안과 다음 질문에 연결하고 싶어서 이 메모를 골랐다.’
이 예문은 발표팀이 구성했으며 실제 사용자의 직접 관찰로 표기하지 않는다.

우리 스터디의 적용 예
현재 계획과 질문 답을 읽어 15분 읽기 진행안 한 쪽을 준비한다.
선택한 두 메모의 이름과 이유, 시간, 작성 주체, 문서 연결을 대조한다.
실제 모임 운영·입문자 이해·학습효과는 별도 확인할 항목으로 남긴다.
맥락·요청·논의·결과는 읽을 역할의 구분이며 네 파일이나 여러 에이전트가 필수라는 뜻이 아니다.

일차 설계·검토 근거
- Karpathy, LLM Wiki의 query·lint: https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f/ac46de1ad27f92b28ac95459c782c07f6b8c964a

========== rules.md ==========
# 우리 스터디 위키의 작업 규칙

목적: LLM Wiki의 특징과 RAG와의 관계를 설명하고 다음 모임의 첫 시도를 정한다.
raw/ 입력은 보존하고 wiki/의 설명을 작성·갱신한다.
원문에서 확인한 요지, 사람이 직접 쓴 선택 이유·관찰, 생성된 종합, 가상 조건과 아직 모르는 점을 구분한다.
자료별 요약과 여러 자료를 함께 읽은 개념·비교·계획을 구분하고 서로 연결한다.
주장마다 실제 읽은 메모와 원문 위치로 돌아갈 근거를 남긴다.
새 자료가 들어오면 관련 기존 개념·비교·계획·질문을 함께 검토한다.
새 개인 조건은 개념의 보편 정의를 뒤집는 대신 우리 적용 범위·선택 기준·계획에 반영한다.
index.md는 페이지를 찾는 입구, log.md는 언제 무엇을 왜 바꿨는지 기록한다.
질문할 때 필요한 페이지를 실제로 찾아 읽고 답에 사용한 파일을 알린다.
유용한 답은 검토 뒤 질문 페이지로 남기고 관련 쪽에서 연결한다.
낡은 설명·충돌 후보·끊긴 연결은 근거를 다시 읽고 수정하며 중요한 결과를 사람이 확인한다.

rules.md는 이 예제의 파일 이름이다. 첫 요청에서 읽도록 명시한다.
모든 도구가 이 이름의 파일을 자동으로 읽는다고 가정하지 않는다.

========== 첫 요청 예 ==========
rules.md와 raw/context-note.md, raw/retrieval-note.md, raw/synthesis-note.md를 읽어 주세요.
목적은 다음 AI 스터디에서 LLM Wiki의 특징·RAG와의 관계·첫 시도를 설명하는 것입니다.
사람이 채울 선택 이유를 따로 두고, 자료별 요약·LLM Wiki/검색 개념·같은 질문의 비교·현재 계획을 연결해 주세요.
기술 근거·우리 해석·가상 조건을 구분하고, 근거와 아직 확인할 질문을 남겨 주세요.
원자료는 보존하고 관련 기존 페이지·index/log를 검토한 뒤 바뀐 파일과 이유를 알려 주세요.

# LLM Wiki

LLM이 원자료의 개념·비교·종합을 연결 문서로 작성하고 갱신하는 지식관리 패턴이다.
새 입력을 기존 설명에 통합하고, 다음 질문에서는 필요한 페이지를 찾아 다시 읽는다.
유용한 답도 검토 뒤 위키에 연결할 수 있다.

핵심 작업: 자료 반영(ingest), 질문·답 구성과 검토한 결과 저장(query), 유지 점검(lint).
원자료·현재 설명·작업 규칙을 나눠 생각한다.

우리 적용 범위: 다음 스터디에서 특징·비교·첫 시도 방법을 설명할 계획. 참가자와 활동 길이는 미정.

RAG는 필요한 외부 자료를 찾아 생성에 사용한다.

위키도 목차나 검색으로 필요한 페이지를 찾아 현재 입력에 읽어야 활용할 수 있다.

# 같은 자료로 다음 질문에 답하기

공통 질문: 다음 AI 스터디에서 LLM Wiki를 어떻게 시도할까?

기본 검색-생성 예: 관련 원자료를 찾아 현재 입력에서 종합해 이번 답을 만든다.
위키를 유지하는 예: 자료 반영 때 개념·비교·종합을 문서로 남기고, 필요한 쪽을 읽어 이번 답을 만든다.

주로 남기는 것: 검색용 자료/색인과 답, 또는 지속되는 연결 문서와 그 변경 이력.
입력·변경시 부담: 정제·색인/갱신, 또는 관계 종합·여러 문서 갱신·검토.
질문시 부담: 둘 다 필요한 근거/페이지를 찾아 읽고 현재 답을 구성한다.

이 비교는 두 교육용 흐름의 예다. RAG도 요약·답 저장·관계 정리를 붙일 수 있고 위키도 검색을 쓴다.
함께 쓸 수 있다. 이번 예제는 정확도·속도·비용의 우열을 측정하지 않는다.

우리 선택 기준: 다음 질문에 쓸 연결이 남는지, 검토·유지 부담은 어떤지 먼저 확인한다.

# LLM Wiki

LLM이 원자료의 개념·비교·종합을 연결 문서로 작성하고 갱신하는 지식관리 패턴이다.
새 입력을 기존 설명에 통합하고, 다음 질문에서는 필요한 페이지를 찾아 다시 읽는다.
유용한 답도 검토 뒤 위키에 연결할 수 있다.

핵심 작업: 자료 반영(ingest), 질문·답 구성과 검토한 결과 저장(query), 유지 점검(lint).
원자료·현재 설명·작업 규칙을 나눠 생각한다.

우리 적용 범위: 입문자와 세 메모 중 두 개를 골라 읽고 별도 활동 15분은 목차·연결·후속 질문을 경험하는 데 쓴다.
보편 정의가 바뀐 것이 아니라 이번 스터디의 적용 범위가 구체화된 것이다.

# 같은 자료로 다음 질문에 답하기

공통 질문: 다음 AI 스터디에서 LLM Wiki를 어떻게 시도할까?

둘 다 현재 입력에서 답을 구성하고 필요한 원자료를 다시 확인한다.
RAG도 관계/요약을 미리 만들 수 있고 위키도 검색을 사용할 수 있다.

## 준비와 선택 이유

전체 위키는 발표팀이 작성한 세 주제 메모를 함께 읽는 구성 예다. 이 짧은 활동에서는 그중 아래 두 메모를 선택한다.

- `raw/context-note.md`: ‘목적과 맥락’에서 목적과 개념 연결을 읽고, 왜 이 자료를 남기는지 정하기 위해 선택.
- `raw/synthesis-note.md`: ‘지식의 활용’에서 사람의 입력·결과 제작·검토를 읽고, 정리에서 실제 쓸 결과로 이어 가기 위해 선택.

`raw/retrieval-note.md`의 ‘검색과 비교’는 전체 RAG 비교의 공통 근거이며, 필요한 비교 쪽에서 돌아가 읽을 수 있다.

준비물: 세 주제 메모, 관련 개념·비교·현재 계획 예시, 목적을 적을 자기 노트.
시작 전에 팩의 경로별 제목을 검색해 읽을 곳을 확인하거나, 해당 경로대로 파일을 나누어 준비합니다.
사람이 채울 선택 이유의 예: ‘차이를 설명하고 다음 스터디의 진행안을 만들고 싶어서 이 자료를 골랐다.’ 이 문장은 발표팀이 구성한 예문이며 실제 사용자의 직접 기록으로 소개하지 않는다.

## 15분 진행안

| 활동 시간 | 할 일 | 남길 것 |
| --- | --- | --- |
| 0~2분 | 왜 이 자료를 다시 쓰려는지 질문 정하기 | 목적 한 문장 |
| 2~6분 | 선택한 두 읽기 메모 확인하기 | 메모 요지와 내 선택 이유 |
| 6~11분 | 원자료→개념→비교의 연결 한 개를 따라 읽기 | 관계를 뒷받침하는 근거 위치 |
| 11~15분 | 후속 질문에 근거를 연결하고 남은 확인 적기 | 질문·검토할 답·모르는 점 |

배분은 **2+4+5+4=15분**이다. 실측 시간이 아니며 참가자의 속도에 맞춰 조정한다. 활동 기록은 자기 노트에 남긴다.

## 근거와 작성 주체

입력 메모·위키·이 활동안은 발표팀이 작성한 구성 예다. 원자료 역할의 주제 메모도 외부 원문의 발췌가 아닌 자작 설명이다. 기술 주장은 메모에 적힌 설계 글·논문·공식 문서로 돌아가 확인한다. 사람의 직접 관찰·선택 이유와 AI가 생성한 종합은 실제 작업에서 따로 표시하고 근거와 대조한다. 이 예시를 실제 학습자의 생각이나 실행한 모델 출력으로 표기하지 않는다.

- ‘목적과 맥락’: 목적·선택 이유·개념 연결.
- ‘지식의 활용’: 사람의 입력 구별, 종합 저장과 다음 결과 활용.
- ‘검색과 비교’: 검색·지속 문서·모델 학습·에이전트 판단의 구분과 병행.
