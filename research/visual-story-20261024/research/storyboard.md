# 첫 경험 개선: 12장 데이터 이야기

2026-10-24 · 이야기·시각자료 실무 `/root/research_manager/story_researcher`

제목은 **첫 경험을, 다음 행동으로.** 부제는 `12주 가상 제품 개선 프로젝트`다. 특정 실제 회사나 서비스의 성과가 아니다. W1–W4와 W9–W12의 서로 다른 신규 사용자 코호트를 비교하는 가상 전후 관찰이며 무작위 대조실험이나 인과효과를 뜻하지 않는다. 모든 주의 신규 사용자를 동일한 7일 관찰창으로 추적하고 마지막 W12 코호트도 추적을 마친 뒤 집계한다.

2–10장은 KPI, 퍼널, 시계열, 구성비, 비교 막대, 흐름도, 우선순위 매트릭스, 간트형 일정, 히트맵의 **서로 다른 아홉 표현**이다. 종류를 늘리기 위한 입체 도형·면적 장식·이중 축은 사용하지 않는다. 원형 구성비보다 정확한 라벨과 모바일 재배치가 쉬운 누적 막대를 우선한다.

## 표현이 오해를 만들지 않게 하는 조건

- **기간과 분모:** 신규는 처음 가입한 고유 사용자이며 비교 기간은 각각 1,200명이다. 12주 전체 신규 3,600명, 각 주 신규 300명, 인터뷰 응답 48명은 다른 분모다. 같은 화면이나 표에서 바꿔 쓸 때 단위를 반복한다. 활성은 가입 후 7일 내 첫 프로젝트 공유로 정의한다.
- **변화량:** 35%에서 55%는 +20%p다. 상대 변화 +57.1%와 혼용하지 않으며 주 메시지는 +20%p 하나로 둔다. 6장의 인접 단계 전환율은 3장의 유입 대비율과 구분한다.
- **시계열:** 모든 주의 7일 추적이 끝난 합성 데이터다. 주별 관찰이 높아져도 개선안이 변화의 원인이라고 단정하지 않는다. 두 비교 구간은 음영·선 등으로 표시하되 W5–8을 삭제해 연속성이 끊기지 않게 한다.
- **퍼널·막대:** 동일한 0 시작 기준과 분모를 사용한다. 퍼널은 단계별 길이를 읽는 정렬 막대로 제안하며 원근·부피·사다리꼴 면적을 수량처럼 보이게 하지 않는다. 비교 막대는 같은 0–100% 축을 사용한다.
- **마찰 구성비:** 응답자 한 명이 주된 마찰 하나를 선택한 가상 분류다. 네 항목은 48명으로 합산된다. 누적 막대의 인원·비율 라벨이 실제 구간 길이와 일치해야 한다.
- **도식·기획 자료:** 흐름도의 화살표는 이동 관계이며 인원·전환 확률이 아니다. 우선순위 점수·일정·투입량은 기획 설정이고 측정 성과와 시각적으로 구분한다.

## 모바일·대체 정보·작성 흐름

복잡한 자료는 `examples/visual-story/data.json` 한 파일에서 로컬 SVG·`data.html`·수치가 들어간 발표 본문을 함께 재생성한다. Markdown의 수치를 손으로 따로 복제하지 않는다. Markdown은 기존 19 layouts·공통 색·5종 모션을 사용한다. SVG는 `image`의 `fit: contain`을 우선하고 제목·한 줄 메시지는 가능하면 native 텍스트로 남긴다. 기존 `image`의 작은 화면 배치를 확인한 뒤 필요한 경우 프레임 비율·라벨 수를 조정한다. 새로운 범용 차트 런타임을 요구할 구체적인 이유는 현재 없다.

SVG 안의 축·수치를 읽어야 결론을 알 수 있다면 모바일에서 확대 없는 16:9 축소 화면만 대안으로 삼지 않는다. 각 그림의 `alt`는 **자료 종류·비교 기간·주요 결론**을 한두 문장으로 설명하고 원본의 모든 숫자를 길게 나열하지 않는다. 각 장의 노트와 작성 가이드에서 `data.html#해당영역`으로 연결하고 닫는 장에 클릭 가능한 `data.html`을 둔다. 실제 HTML에는 요약·표 제목·행/열 머리글·단위·기간·수치와 계산 설명을 포함한다. JSON 링크만으로 대안을 대신하지 않는다.

이는 W3C의 [복잡한 이미지 대안 지침](https://www.w3.org/WAI/tutorials/images/complex/)에 따라 짧은 대체 텍스트와 관계·추세·값을 포함한 상세 대안을 함께 준비하는 제안이다. 매니저가 원문을 확인했으며 이 문서의 실무는 새 일반 조사로 범위를 넓히지 않았다. 실제 모바일·키보드·스크린리더·인쇄 검증은 디자인·엔지니어링·총괄의 후속 범위다.

이 문서는 스토리·시각화 계약이며 제품 파일을 생성하지 않는다. 데이터 값·키 확정은 데이터 담당자와 직접 맞추고, 두 실무 결과의 연결은 별도 `synthesis.md`로 인계한다. 팀 운영 상태와 결정의 단일 기록은 루트 `WORK_LOG.md`다.
