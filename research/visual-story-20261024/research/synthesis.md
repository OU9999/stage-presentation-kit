# 숫자·그래프·도식 발표의 리서치 인계

2026-10-24 · 취합 `/root/research_manager/story_researcher`

**첫 경험을, 다음 행동으로.** 신규 사용자가 첫 프로젝트를 공유하기까지의 마찰을 관찰하고, 개선안·우선순위·일정·투입·다음 검증으로 이어지는 12장 가상 제품 발표다. 숫자를 나열하는 자료가 아니라 각 시각화가 한 질문에 답하는 이야기로 구성했다. 실제 회사의 성과나 무작위 실험의 인과효과를 주장하지 않는다.

## 실무 결과와 합의

| 담당 | 독립 초기 작성 | 함께 확정한 것 |

두 실무자는 직접 연락해 활성 행동을 **가입 후 7일 내 첫 프로젝트 공유**로 통일했다. 매주 신규 가입 고유 사용자 300명이며 방문 유입 수가 아니다. 마지막 W12의 관찰도 완료한 W13 종료에 보고한다. 원본 최종 인원은 주별 데이터에서 집계하며 퍼널에 같은 끝값을 손으로 반복하지 않는다. 인터뷰는 W2–W4 미활성 사용자 중 선정한 48명의 가상 분류이며 전체 가입자 대표 표본이 아니다.

## 발표에 사용할 숫자

- 기준 W1–W4는 420/1,200명 = 35%, 후반 W9–W12는 660/1,200명 = 55%다. 중심 메시지는 **+20%p의 관찰 차이**다. 상대 변화 +57.1%와 혼용하지 않는다.
- 12주 신규 합계 3,600명·활성 합계 1,626명이다. W1 30%·W12 58%는 주별 값이고 35%·55%는 각각 4주 집계다.
- 퍼널은 `신규 가입 → 프로젝트 시작 → 초안 완성 → 첫 프로젝트 공유`다. 기준 1,200→840→600→420명, 후반 1,200→960→780→660명이다. 유입 대비율과 직전 단계 전환율을 구분한다.
- 초안 완성→공유는 70%→84.6%, 원본 정수로 계산한 차이는 +14.6%p다. 두 표시값을 먼저 반올림해 차이를 만들지 않는다.
- 인터뷰 마찰은 18·12·10·8명 = 48명이다. 37.5·25.0·20.8·16.7%는 **응답 48명 안의 분포**다.
- 우선순위 1–5점은 기획 판단이다. 로드맵은 세 과업의 W1–4·W5–8·W9–12 계획이다. 투입은 역할×기간 3×3 행렬이며 역할 합계 6·6·6, 기간 합계 5·7·6, 전체 18인·주다. 12주 경과 기간과 인·주를 더하지 않는다.

## 디자인에 넘기는 12장

1. 표지 — 가상 전후 관찰의 목적.
2. KPI — 35%→55%와 +20%p.
3. 단계 퍼널 — 동일 가입 분모에서 인원 변화.
4. 시계열 — 12주를 생략 없이 이어 보는 활성화율.
5. 구성비 — 인터뷰 48명의 대표 마찰 분포.
6. 비교 막대 — 세 구간의 직전 단계 전환율.
7. 흐름·관계도 — 시작 템플릿·다음 행동 안내·공유 미리보기와 마찰·단계의 대응.
8. 우선순위 매트릭스 — 예상 영향과 노력의 기획 판단.
9. 간트형 일정 — 세 기간의 관찰·적용·후반 확인.
10. 히트맵 — 역할별 18인·주 투입 계획.
11. 다음 검증 — 아직 모르는 질문·사용성 점검·별도 비교 검증.
12. 닫는 행동 — 같은 기준으로 다시 확인하고 데이터 표를 연다.

KPI·퍼널·시계열·구성비·비교 막대·흐름도·매트릭스·일정·히트맵의 **아홉 가지 표현**을 사용한다. 세부 메시지·데이터 키·레이아웃·강조 대상은 [storyboard](storyboard.md)에 있다. 이전 컬러·5종 모션은 의미에 맞게 적용하며 SVG 내부 요소의 모션을 위해 새 런타임을 늘리지 않는다.

## 구현 계약과 접근 가능한 대안

출력 위치는 `examples/visual-story/`다. 후속 엔지니어링은 연구 dataset을 입력 초안으로 인수해 제품의 **data.json 하나**에서 숫자가 들어간 발표 원문·SVG·`data.html`을 함께 재생성한다. 제품이 연구 폴더의 JSON을 런타임으로 읽거나, SVG와 Markdown에 같은 숫자를 따로 손으로 관리하는 구조는 피한다. 정수와 기획 설정은 데이터 원본에, 비율·합계·차이는 생성 계산에 둔다.

기존 19 layouts·Markdown·공통 색과 모션을 유지한다. 복잡한 도표는 로컬 SVG를 기존 `image`에 `fit: contain`으로 넣고 native 제목·메시지를 함께 둔다. 이 요구만으로 React·외부 차트 라이브러리·새 범용 layout이 필요하다는 근거는 없다. 구체적인 한계가 발견되면 구현팀이 영향과 대안을 보고한다.

`data.html`은 raw JSON 대신 **실제 요약과 HTML 표**를 제공한다. 가상 여부·관찰 기간·단위·분모·계산법, 표 제목·행/열 머리글을 포함한다. 최종 anchor 계약은 `periods`, `weekly`, `funnel`, `interviews`, `step-rates`, `journey`, `priorities`, `roadmap`, `effort`, `next-validation`이다. 각 장 노트는 해당 주소를 안내하고 닫는 장은 기존 `url: data.html`로 실제 링크를 제공한다. 작성 안내에도 클릭 가능한 표 링크를 둔다. 기존 일반 source 텍스트가 자동으로 클릭 가능한 링크가 된다고 가정하지 않는다.

SVG의 짧은 `alt`는 자료 종류·기간·결론을 설명한다. 정확한 값·관계·추세는 표에서 읽을 수 있어야 한다. 390px에서 작은 SVG 축 글씨가 읽히지 않으면 단순 축소만으로 완료 처리하지 않고 native 메시지·상세 표 접근을 함께 확인한다. [W3C 복잡한 이미지 지침](https://www.w3.org/WAI/tutorials/images/complex/)은 매니저가 원문을 확인했으며 추가 일반 조사로 범위를 넓히지 않았다.

데이터 파싱·분모·합계·중첩 퍼널·비율·ID 참조·일정·투입 행렬은 [데이터 계약의 검증 기록](data-contract.md)을 따른다. 실제 SVG 가독성·브라우저 동작·모바일·오프라인·PDF는 후속 디자인·엔지니어링·총괄의 검증 범위다. 연구 단계에서는 제품 코드와 WORK_LOG를 수정하지 않았다.
