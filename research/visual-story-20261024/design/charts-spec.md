# 정량 그래픽 사양과 생성 API

2026-10-24 · `/root/design_manager/information_designer`

[charts.cjs](../../../scripts/visual-story/charts.cjs)는 후속 생성기가 그대로 호출할 순수 CommonJS 모듈이다. 확정한 [단일 데이터 계약](../research/data-contract.md)을 인수하고, 숫자를 원고나 SVG 소스에 따로 복사하지 않는다. 기존 발표의 native 제목 아래 `image`·`fit: contain`으로 배치할 그림이므로 SVG 안에 큰 장 제목을 반복하지 않는다.

## 호출과 데이터 경계

```js
const charts = require("./scripts/visual-story/charts.cjs");
const output = charts.renderFunnel(data); // 전체 SVG 문자열
```

네 함수는 모두 raw canonical dataset을 받아 전체 SVG 문자열을 반환한다. 파일 읽기·파일 쓰기·DOM·외부 요청을 수행하지 않는다. 입력 검증과 출력 경로 결정은 후속 생성기의 책임이다. 공통 팔레트·XML escape·문자 배치·사사오입·주별 기간 합계·퍼널 끝값 계산은 [theme.cjs](../../../scripts/visual-story/theme.cjs)를 재사용한다.

| 함수·출력 | 읽는 원본 | 도형과 분모 | 강조와 짧은 alt 계약 |
| --- | --- | --- | --- |
| `renderFunnel(data)` | `weeklyCohorts`, `periods`, `funnel` | 기준·후반 두 열, 단계별 정렬 막대. 각 기간 신규 가입자 합계를 분모로 하는 동일 0–100% 길이. 단계 인원과 가입 대비율을 함께 표시 | 후반 공유 단계에 blue. alt: “기준과 후반의 단계별 인원을 비교한 퍼널. 신규 가입부터 첫 공유까지의 관찰 차이를 보여줍니다.” 상세 `data.html#funnel` |
| `renderTrend(data)` | `weeklyCohorts`, `periods`, `measurement`, `meta.reportingCutoff` | W1–W12 모두 연결한 선. y축은 0–100% 고정, 비교·적용·후반 구간을 누락 없이 구분. 각 점은 해당 주 활성/신규 | 마지막 주 값에 blue, 첫·마지막 값만 크게 주석. alt: “12개 가입 코호트의 7일 내 첫 공유율 추세. 모든 주를 같은 관찰창으로 집계했습니다.” 상세 `data.html#weekly` |
| `renderComposition(data)` | `interviews` | 100% 누적 막대, 길이는 반올림 전 응답 인원/선정 응답자 수. 네 원인의 원본 문구·인원·비율을 별도 범례로 표시 | 최다 원인부터 orange·purple·blue·회색. alt: “선정한 가상 인터뷰 응답자 안의 대표 마찰 분포. 전체 가입자의 발생률은 아닙니다.” 상세 `data.html#interviews` |
| `renderStepRates(data)` | 같은 원본 퍼널의 인접 단계 인원 | 세 구간별 기준·후반 가로 막대, 같은 0–100% 축. 분모는 각 구간 직전 단계 인원이며 퍼널의 가입 대비율과 구분 | 계산한 관찰 차이가 가장 큰 구간을 blue로 강조. alt: “기준과 후반의 직전 단계 전환율 비교. 초안에서 공유 구간의 관찰 차이가 가장 큽니다.” 마지막 문장은 변경 데이터에 맞게 후속 생성기가 계산해 작성. 상세 `data.html#step-rates` |

alt는 해당 자료의 종류·기간·메시지를 짧게 설명하는 계약이다. 위 문구에 모든 수치를 덧붙여 길게 나열하지 않는다. 실제 값과 요약·관계는 같은 입력에서 생성한 HTML 표가 제공해야 한다. raw JSON 링크나 축소된 그래픽만으로 대안을 대신하지 않는다.

## 화면 사양

- 전체 SVG는 1280×640 viewBox와 불투명 Stage `#080808` 캔버스다. 기본 시스템 글꼴을 사용하며 외부 폰트·CDN·이미지·스크립트 요청은 없다.
- 가장 작은 설명·축 글씨는 26px, 범주 라벨은 30px, 주요 값은 32–38px다. native 제목·메시지가 장의 결론을 맡고 SVG는 패턴·단위·범례를 맡는다.
- 기준은 중립 회색, 후반은 blue다. 모든 메타·출처·보조 기준을 의미색으로 물들이지 않는다. 인터뷰 구성비는 서로 다른 분류의 대응에만 색을 쓴다.
- 긴 원본 라벨은 공통 `wrap()`으로 여러 줄로 나눈다. 큰 제목·긴 문단을 SVG에 채우지 않는다. 숫자는 원본 정수로 계산한 뒤 마지막 표시에서만 사사오입한다.
- 사다리꼴 면적·원근·부피·가짜 3D·이중 축·count-up을 사용하지 않는다. 생성 그래픽 내부에는 애니메이션이 없고 기존 발표의 짧은 `fade` 진입을 사용한다.
- 각 SVG에 고유 `title`·`desc`와 `aria-labelledby`를 넣는다. 설명은 원본에서 계산하며 텍스트를 XML escape한다.

## 확인한 계산과 한계

실무자가 Node에서 네 생성 함수를 직접 실행해 구문·전체 SVG 반환·title/desc·NaN/Infinity 없음·입력 불변·동일 입력의 바이트 동일성을 확인했다. 단계별 81.25%→81.3% 표시와 반올림 전 차이 +14.6%p, 퍼널의 1,200명, 구성비 37.5%를 대조했다. 주별 활성 인원 및 인터뷰 분류 인원을 바꾸면 해당 SVG가 함께 바뀌는 것도 확인했다.

이 확인은 계산·생성 경계의 검수다. 매니저가 실제 8개 SVG를 프리뷰로 렌더해 데스크톱·390px·텍스트 경계를 별도로 검수한다. 390px의 축소 SVG에서 26px 원본 라벨이 곧 읽기 좋은 화면 글씨가 되는 것은 아니다. 최종 예제는 native 메시지와 읽을 수 있는 `data.html` 표·요약을 함께 제공해야 한다. 실제 발표 화면·오프라인·PDF·보조기기 검수는 후속 구현 범위다.
