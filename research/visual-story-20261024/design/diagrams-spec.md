# 여정·기획·투입 도식 사양

2026-10-24 · 정보설계·도식 담당 `/root/design_manager/systems_designer`

[diagrams.cjs](../../../scripts/visual-story/diagrams.cjs)는 [canonical dataset](../research/dataset.json)을 받아 완성된 SVG 문자열을 반환한다. 값·원본 라벨·ID 관계를 입력에서 읽고, 일정의 위치·길이와 투입 합계는 계산한다. 파일 쓰기·네트워크·DOM·런타임 변경은 하지 않는다. 공통 색·글꼴·escape·텍스트·wrapper는 [theme.cjs](../../../scripts/visual-story/theme.cjs)를 사용한다.

| 함수 | 한 장의 표현 | 데이터와 시각 규칙 | 상세 HTML anchor |
| --- | --- | --- | --- |
| `renderJourney(data)` | 경험 네 단계와 제안 기능 대응 | `journeyMap.path`의 순서로 노드 정렬. `interventions`의 과제·단계·인터뷰 이유 ID를 원본 라벨로 연결. 연결선 두께에 이동량을 넣지 않는다. | `journey` |
| `renderPriority(data)` | 예상 영향×노력 기획 매트릭스 | `scoreScale.min/max`로 축을 만들고 점수로 점 위치를 계산. 점 안의 01–04는 식별 키이며 우측 목록과 일대일 대응한다. 같은 노력 점수의 긴 이름을 plot 안에 중복 배치하지 않는다. | `priorities` |
| `renderRoadmap(data)` | 주차별 세 과업 일정 | 주 축은 `weeklyCohorts`의 실제 주 범위. 막대 위치는 시작 주, 길이는 `종료−시작+1`이다. `followupNote`를 별도 하단 문장으로 표시해 W12 실행 구간과 W13 집계 확정을 구분한다. | `roadmap` |
| `renderEffort(data)` | 역할×기간 투입 히트맵 | `periodOrder`와 각 역할의 `personWeeksByPeriod`를 그대로 연결. 셀 숫자·행 합·열 합·전체 합을 모두 표시한다. 색은 인·주 크기의 보조이며 경과 주수와 합산하지 않는다. | `effort` |

모든 SVG는 `1280×640`이며 자체 `<title>`·`<desc>`·`role="img"`를 가진다. SVG 안에 발표의 큰 장 제목을 반복하지 않는다. native 제목과 한 줄 메시지는 후속 예제 원고에서 제공한다. Stage 바탕 `#080808`, 기본 글자 `#f6f6f4`, 보조 메타 `#a4a4a1`를 사용하고 라벨 최소 26px·일반 라벨 28–30px·핵심 셀 숫자 40–46px로 설정했다.

여정·과제는 green·blue·purple·중립을 소수의 식별색으로 사용한다. 히트맵은 blue 계열의 명도와 숫자를 함께 사용하고, 셀 색의 sRGB luminance에 따라 기본 밝은 글자와 어두운 캔버스 글자 중 대비가 높은 쪽을 선택한다. 값으로부터 생성한 범례가 실제 셀 색과 대응한다. 순서척도 점수·일정·투입은 가상 기획 자료이며 관찰된 활성화 수치와 구분한다.

## 짧은 대체 텍스트 계약

- 여정: “가입부터 첫 공유까지의 네 단계에 시작 템플릿·행동 안내·공유 미리보기를 연결한 제안 도식. 실제 이동량이나 인과 관계를 뜻하지 않습니다.”
- 우선순위: “네 개선안의 예상 영향과 노력에 대한 가상 1–5점 기획 판단. 시작 템플릿과 다음 행동 안내를 먼저 검증하는 후보로 둡니다.”
- 일정: “W1–W12의 관찰·구현·후반 관찰 일정. 마지막 코호트의 7일 추적이 끝나는 W13 종료에 집계를 확정합니다.”
- 투입: “세 역할과 세 기간의 가상 투입 계획. 셀·행·열 합계를 인·주로 비교하며 전체 계획은 데이터에서 계산합니다.”

위 문장은 현재 데이터의 의미를 설명하는 예시다. 엔지니어링 생성기는 변경된 원본에 맞춰 alt와 발표 메시지를 함께 생성하고, 정확한 값·관계는 같은 입력에서 만든 `data.html`의 실제 표와 요약으로 제공한다. 원본의 숫자를 alt와 Markdown에 따로 손으로 복제해 유지하지 않는다.

모바일에서 SVG 미세 라벨이 축소되는 한계는 남는다. 390px에서 그림이 넘치지 않는 것만으로 세부 가독성을 통과했다고 주장하지 않는다. 각 장의 native 메시지와 정확한 값·주차·참조 관계를 읽을 수 있는 HTML 표 진입을 함께 확인한다. JSON 링크만으로 이 대안을 대신하지 않는다.

## 실무 확인

구문·정적 생성 검사는 네 함수 모두 SVG·title·desc를 반환하고 `NaN/undefined`가 없으며 입력을 바꾸지 않는 것을 확인했다. 같은 입력의 결정적 출력, 투입 수정의 합계 전파, 과업 기간 수정의 라벨 전파, XML escape도 확인했다. 생성한 히트맵 9셀의 글자/배경 sRGB 대비를 별도 계산한 최솟값은 4.74:1이다. 이는 단색 셀의 계산값이며 전체 접근성·투사 환경 가독성 보증이 아니다. 정보시각화 담당도 원본 ID 연결·좌표 척도·inclusive 일정·행열 합·읽기 색 선택을 코드로 대조해 이견 없음을 직접 통지했다. 실제 SVG의 텍스트 bounds·대표 데스크톱·390px 프리뷰 검수는 디자인 매니저가 수행한다. 실제 제품의 원고·상세 표·모바일 읽기·PDF·오프라인 통합 검증은 후속 엔지니어링과 총괄의 범위다.
