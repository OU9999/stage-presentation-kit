# 외부 발표의 사진 구성과 컬러 활용

조사일: 2026-10-23 · 외부 사진·컬러 탐색 담당

## 이번 조사에서 바뀐 판단

**중립적인 슬라이드 틀은 유색 사진과 작품을 충분히 보여주기 위한 바탕이다.** 사진을 무채색으로 바꾸거나 색 면적을 일률적으로 제한하는 방식은 이번 실제 사례를 설명하지 못한다. 색이 결과물 자체일 때는 크게 보여주고, 비교 조건을 식별할 때는 작은 라벨에, 한 개의 수치를 강조할 때는 큰 타이포에, 연사를 교체할 때는 잠깐의 색면에 사용한다.

2025년 공식 발표 3개를 직접 살펴봤다. Apple 9월 이벤트에서는 **한 장씩 초점거리를 바꾸며 보여준 뒤 8장 스트립으로 요약**한다. Figma에서는 **중립 편집 화면 안에 6개 유색 작품을 비대칭으로 완성**한다. WWDC 키노트의 사진 모음→확대는 제품 UI 안의 사례이므로 원본 발표용 사진 그리드와 구분했다.

## 조사 방식과 범위

- 공식 YouTube 영상의 특정 구간을 실제 재생하고, 시간 이동 후 재생 시간이 진행되는 것을 확인해 영상 영역만 캡처했다. `view_image`로 각 프레임을 직접 보았다. 전체 영상을 처음부터 끝까지 연속 시청한 조사는 아니다.
- Apple WWDC25 세션 356의 공식 MP4도 추가 샘플링했다. 이번 사진 배열의 핵심 근거로는 채택하지 않았다. 앞선 02:40의 여섯 색 원은 사진 사례가 아니다.
- 원본 PPT/Keynote 파일이나 제작 툴은 확인하지 않았다. 무대 송출 화면, 방송 편집 틀, 제품 UI 안의 화면, 독립된 발표 이미지판을 구분한다.
- 아래의 역할 분류는 조사자의 분석 틀이다. 브랜드가 공개한 공식 규칙이라고 주장하지 않는다.
- 면적 수치는 캡처의 기하학적 이미지 영역을 대략 비교한 값이다. 채도가 있는 픽셀의 비율이나 공식 디자인 토큰이 아니다. 무대 조명·객석·의상은 제외한다.

**크롭과 캡션:** 작품의 내부 타이포·인물·오브젝트가 각 영역의 중심을 차지하며, 큰 가로 작품은 비교적 넓게 유지된다. 원본 파일이 없으므로 실제 `cover` 크롭 규칙이나 잘린 원본 영역을 확정하지 않는다. 별도 발표용 캡션은 없고 작품 내부 문자가 그대로 보인다. 제품 조작을 설명하는 장면이므로 조건 라벨을 붙인 Apple 스트립과 목적이 다르다.

**송출 구분:** 왼쪽 작은 연사 영상, 오른쪽 큰 제품 UI, 바깥 살구색은 방송용 레이아웃이다. 살구색 면적을 “발표 본문은 항상 유색 바탕”의 근거로 쓰지 않는다. 이 콜라주 역시 데모 안에서 만들어지는 결과물이지 원본 발표 슬라이드 파일 자체가 아니다.

### B. 검증한 실제 전환: 중립 → 이름 소개 색면 → 중립

1. [09:28](https://www.youtube.com/watch?v=5q8YAUTYAyk&t=568s): 기존 연사 뒤의 중앙 화면은 검정, 흰색 **Layout** 한 단어다. [프레임](evidence/color-external/figma-intro-09m28.png)
2. [09:40](https://www.youtube.com/watch?v=5q8YAUTYAyk&t=580s): 새 연사 Giorgio Caviglia가 입장할 때 중앙 화면이 연노랑 바탕, 큰 이름, 도형으로 바뀐다. 이는 양끝 장식만의 변화가 아니라 중앙 발표 화면의 변화다. [프레임](evidence/color-external/figma-intro-09m40.png)
3. 09:55: 새 연사 근접 촬영이다. 뒤의 화면 전체가 안 보이므로 중립 복귀의 증거로 사용하지 않는다.
4. [10:10](https://www.youtube.com/watch?v=5q8YAUTYAyk&t=610s): 새 연사를 넓게 보여주는 장면에서 중앙 화면이 다시 검정+흰색 **Layout**이다. [프레임](evidence/color-external/figma-intro-10m10.png)

색면은 이 구간에서 연사 소개라는 특정 이벤트에 연결된다. 진입 때 강하게 쓰고 설명을 시작할 때 비운다. 넓은 촬영 화면의 파란 조명·객석·옷은 발표 색의 면적으로 집계하지 않았다.

공식 제작 회고는 표현적인 타이포 모션과 빠른 기능적 모션을 구분하고, 도형·타이포·사진을 하나의 모션 언어로 다뤘다고 설명한다. 이는 위 전환 관찰의 보조 맥락이다. 해당 글의 웹 일정표 테마색은 슬라이드 색 규칙으로 인용하지 않는다.

- 17:10: 다음 Safari 소개의 밝은 바탕으로 이동한다. Safari 심벌 자체는 유색이므로 완전 무채색 복귀로 부르지 않는다.

여기서 사진의 유색은 제품 기능의 필수 내용이다. **중앙에 폰을 놓은 제품 UI 데모**라는 층위를 유지해야 한다. 이 사진 타일을 그대로 “Apple의 발표 슬라이드 사진 그리드 규칙”으로 일반화할 수 없다.

## 사진과 컬러를 쓸 조건 — 관찰에서 도출한 제안

다음은 우리 재사용 템플릿에 대한 권고이며 위 회사의 공식 규칙이 아니다.

| 목적 | 필요한 구성 | 컬러 사용 범위 | 근거와 실용 조건 |
|---|---|---|---|
| 결과물의 인상·질감 전달 | 사진 또는 작품 한 장을 크게 | 원본 색을 온전히 보존. 필요하면 화면 대부분까지 | 석류 사진처럼 색 자체가 증거일 때. 작은 카드 안에 축소하지 않는다 |
| 여러 촬영 조건의 비교 | 같은 비율·크기·정렬의 스트립 | 사진은 유색, 조건 라벨은 일관된 한 색 | 8장 스트립처럼 비교 축이 명확할 때. 세부 설명은 먼저 한 장씩 보여주고 요약한다 |
| 작품의 폭과 다양성 소개 | 큰 가로 이미지와 작은 세로 이미지를 섞은 비대칭 두 행 | 서로 다른 작품색을 보존하고 바깥 틀을 안정시킴 | Figma 결과물처럼 이미지 비율이 다른 경우. 짧은 일정 간격·공통 경계로 묶되 모든 이미지를 같은 정방형으로 자르지 않는다 |
| 한 개의 변화량 강조 | 큰 수치 한 개+작은 비교 조건 | 수치에만 선택한 색. 바탕·조건은 중립 | +8 hours 사례처럼 색의 역할이 한눈에 명확해야 함. 다른 지표까지 같은 강도로 칠하지 않는다 |
| 사진 속 대상과 설명 연결 | 큰 대상 이미지+부품명·연결선 | 대상색과 라벨색을 대응, 세부는 중립 | 보라 기기+보라 부품명. 사진에 이미 강한 색이 있으면 배경까지 같은 색으로 늘릴 필요가 없다 |
| 연사·챕터 전환 | 이름·짧은 제목을 큰 색면에 | 일시적으로 화면 전체까지 허용 | Figma의 연사 소개처럼 시작과 종료가 분명할 때. 다음 설명 장면의 중립 복귀도 설계 |

**비율·크롭 선택:** 같은 조건의 비교는 동일한 비율을 우선하고, 다른 성격의 작품 모음은 원본의 방향성을 살린다. 정방형 타일은 빠른 라이브러리 탐색에는 적합하지만, 작품의 가로 구도나 타이포를 전달하려는 장면에 자동 적용하지 않는다.

**권고하지 않는 일반화:** 사진은 모두 흑백이어야 한다, 컬러는 항상 10% 이하여야 한다, 녹색은 금지다, 매번 컬러 장면 뒤에는 즉시 흑백 장면이어야 한다는 결론은 이번 자료에서 나오지 않는다. 역할에 따라 유색 사진 한 장이 화면 대부분을 차지해도 되고, 8장이 작은 스트립으로 모여도 된다.
