# 발표 경험 보강 인수 기준

이전 14장은 정의와 비교의 비중이 높았다. 이번에는 청중이 질문하고, 예상하고, 실제 자료를 확인하는 흐름으로 고친다. 사용자가 **40장 정도**를 원한다고 답했다. 목표는 약 40장이며, 약 30분 진행 초안은 장수와 별도로 검토한다. 40분으로 확정한 것은 아니며 실제 리허설 측정값도 아니다.

## 청중이 얻을 것

- 저장한 원문과 연결된 공부 노트의 차이를 쉬운 비유로 설명한다.
- 한 질문에서 원문·검토한 답·수정 이유·결정으로 이동하는 실제 파일 예제를 읽는다.
- 출처 링크가 있어도 문장을 지원하지 않을 수 있음을 직접 판단한다.
- 새 근거가 들어왔을 때 현재 설명과 과거 결정 중 무엇을 고칠지 선택한다.
- 자신의 스터디 자료 하나로 시작할 수 있는 작은 실행 절차를 가져간다.

## 화면과 진행

사진은 학습 상황과 비유를 설명하고, 인용은 원저자의 설계 의도를 소개한다. 둘 다 장식 수를 채우는 용도로 넣지 않는다. 사진의 작가·출처·이용 조건과 인용 원문·맥락·번역을 추적할 수 있어야 한다.

짧은 큰 문장, 사진의 여러 비율, 정보가 담긴 도식, 원문/파일의 실제 내용, 비교, 질문과 답 공개를 교차한다. 반복되는 카드와 세 열 비교만으로 분량을 늘리지 않는다. 기존 DevDay 색과 열린 여백, 이미지 초점을 실제 화면에서 검수한다.

참여는 Zoom 채팅 또는 말로 A/B를 고른 뒤 발표자가 답 화면을 여는 방식이다. 덱의 선택·공개·돌아가기 링크를 실제로 누르고 확인한다. 자동 투표 집계 기능이나 AI 성능 측정을 한 것으로 표현하지 않는다.

## 자료·근거

기존 학습서와 실습 해설의 깊이를 유지하고, 대본의 장 순서·시간·발언·질문·전환·답 공개 시점을 새 덱과 맞춘다. 새 데모는 다운로드해 파일과 실행 결과를 재확인할 수 있어야 한다. 의도적으로 만든 오류는 교육용 오류라고 표시한다.

공개 원출처의 실제 주장, 발표자가 만든 비유·해석, 구성 예제, 실제 실행 결과를 구분한다. 원출처가 없는 효과 수치나 그래프, 유명인의 것으로 꾸민 문장, 실제 사용자의 사례처럼 보이는 재현 사진을 넣지 않는다. 개인 스터디 후기 원문은 공개 산출물에 복제하지 않는다.

## 최종 통합 검증

- 새 장 전체의 실제 화면·가독성·이미지 초점·도식과 인용 확인
- 최신 원고 revision 일치, 잘림·오류·진단·깨진 이미지 점검
- 질문 → 답 공개 → 돌아가기, 자료 링크와 데모 파일 실제 사용
- overview·발표자 화면·모바일 읽기와 자료 탐색
- 전체 사이트 build·비수정 verify·기존 회귀 검사
- commit·push, 같은 Git SHA의 GitHub Pages 배포와 공개 화면 확인

이 문서는 평가 기준이다. 통과 여부와 실제 확인 범위는 후속 검수 기록에 남긴다.
