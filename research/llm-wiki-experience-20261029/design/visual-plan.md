담당 B `/root/experience_design_manager/visual_designer`. 원고 취합 A와 직접 합의한 결과이며 별도 작업 로그가 아니다. 목표는 40장, 1~39장 설명·참여 30분 추정과 40장 별도 Q&A 2분이다. core/CSS를 변경하지 않고 기존 색·열린 여백을 유지한다. SVG 4개와 CREDITS만 새로 작성했으며 기존 SVG 3개·사진 4개는 보존했다.

## 실물에서 판단한 구성

native 화면 `photo-02-paper`, `exhibit-05`, `exhibit-07`, `case-06` PNG 4개와 로컬 사진 4개를 `view_image`로 직접 열었다. native의 넓은 여백, 좁은 사진 열, 색이 다른 bento, 아이콘이 둘러싼 큰 메시지, 낮은 가로 gallery를 참조했다. 사진을 모든 장 배경에 깔거나 밝은 카드 세 열로 반복하지 않는다. 정보가 많은 장은 도식, 실제 diff는 native 본문, 인용은 큰 문장, 자기 적용은 사진과 직접 쓰기로 번갈아 배치한다.

- 1장 P1: 책과 노트가 아래에 있다. 넓은 가로 사진, `50% 75%`로 하단 보존. 사진 위 작은 글자 겹침을 피한다.
- 3장 P3: 자료 축적 비유, 좁은 세로 split. 서가의 깊이가 의미이며 AI가 읽은 자료량이나 등장인물의 정체를 주장하지 않는다.
- 9장 P2: 원자료와 설명의 구분을 위한 세로 split, `50% 72%`. 세로 원본을 큰 가로 cover로 자르지 않는다.
- 34장 P4 중심 gallery strip: 자료와 질문을 직접 적는 흐름. P4 `44% 54%`, 얼굴과 펜 든 손이 함께 보이는 사진 높이를 확보한다. 다른 두 사진은 자료 선택의 맥락을 보완한다. 모두 스톡 장면이다.
- 7/30장: 원문 인용은 각 12단어를 한 번만 사용하고 발표팀 번역을 표시한다. 저자 사진을 추가하지 않는다. 유명인의 권위를 demo 성능 근거로 쓰지 않는다.
- 8장 기존 `wiki-layers.svg`를 유지한다. 15장 문장·근거·범위는 열린 본문, 17장 실제 삭제/추가 diff, 28장 향후 원문 판 대조, 29장 충돌 범위 확인, 31장 검사 수치는 native 구성으로 맡는다. 같은 정보를 새 SVG로 중복하지 않는다.

## 의미와 근거의 범위

B는 demo의 before/after C1, Q1, Q2, D1, D2, pending과 review.json 전문을 읽었다. 모든 도식은 이 실제 파일의 역할·내용에서 가져왔다. pending의 따옴표 문장은 원래 부족한 초안인 “파일 위키를 만들면 필요한 파일을 언제나 찾을 수 있다.”를 그대로 사용한다. 도식의 다른 문장은 길이를 줄인 요약이며 상세 원문은 demo-log와 ZIP에서 읽는다.

Q2의 다시 읽은 파일은 구성 예제의 판단 입력이다. 스크립트의 자동 검색/의미 판정/LLM 생성 성능을 뜻하지 않는다. C1의 초기 오류는 교육용으로 심었고 고정 승인안을 반영한다. 숫자 8쪽·25링크·10불변은 파일 검사 수치다. 최초 RAG 메모와 확장 메모는 같은 v4 논문 §2.3/§2.4 읽기 범위 차이이며 원문 판 교체 사건이 아니다. 28장 원문 교체는 향후 운영법으로 표시한다.

## 검수와 인계

B는 새 SVG 4개를 XML 파싱하고 text font-size 최솟값 32를 검사한다. Quick Look 임시 PNG로 도식 4개를 직접 확인했다. Quick Look이 1200 SVG를 square thumbnail로 잘라 보여주는 특성이 있어 `/tmp` 검수 사본의 바깥 width/height만 768×288로 바꿔 전체 viewBox를 확인했다. 저장소의 실제 SVG는 1200×450 그대로다. manager의 안내 후 `sips -s format png`로 실제 SVG 4개를 1200×450 PNG로 변환해 다시 직접 열었고 전체 문장·여백·잘림 없음을 확인했다. 최종 발표 브라우저 crop·본문 크기·모바일·질문 링크 클릭은 root 검수다. 최종 PNG에서 사진 얼굴/손, 책 하단, SVG 전폭을 확인한다.

A에게 4개 파일명·정확 alt·caption·fit·원본열기·사진 focus를 직접 전달했다. A의 최종 원고/대본을 B가 별도로 읽고 내용·배치·반복·범위를 교차 검토하며, A도 실제 SVG/크레딧을 읽어 회신한다. 그 결과는 후속 인수 항목에 추가한다.
