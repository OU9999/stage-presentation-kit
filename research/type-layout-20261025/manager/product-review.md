# 최종 제품 글 배치 대조

디자인 매니저 `/root/design_manager`가 제품 파일을 수정하지 않고 검수했다. 두 실무는 재개하지 않았다. 현재 `app.js`, `visual.css`, `styles.css`, 새 `examples/text-layout/content.js`를 읽고 [최종 결정](final-decision.md)과 대조했다.

TaskSpace11의 본인 p4에서 실제 제품을 열었다. desktop은1600×1000 viewport, 모바일은390×844 읽기 모드다. 총괄 p1·다른 탭·이전 Space는 조작하지 않았고 finish/업그레이드는 하지 않았다.

위 desktop6장에서는 검사한 native 제목/설명/지원 설명/hero의 장 밖 이탈이0이었다. 실제 브라우저 화면을 캡처해 직접 열어 확인했다. 총괄의 [퍼널 근거](../evidence/first-funnel.png), [큰값 교정 근거](../evidence/corrected-large.png)와도 일치한다.

390px에서는 긴 한국어와 큰값 두 장을 확인했다. 문서 폭390px, 각 장 clientWidth/scrollWidth366/366으로 본문 가로 넘침이 없었다. 제목35px, 긴 수치65px과 단위의 별도 줄을 확인했다. 긴 한국어의 제목·설명·본문 원문이 문서 흐름에서 읽힌다. 모바일 캡처는 고정 헤더와 겹치지 않도록 관찰 위치를 맞췄으며, 축소 그래픽만으로 세부 가독성을 판단하지 않았다.

코드도 수치+단위 전체 실측→공간 확장→필요한 수치 행만 국소 조정의 순서이며 rawDeck/원문 계산을 바꾸는 새 경로가 없다. 기본 명시 grid가 우선이고 음수 margin·기업명 preset·새 renderer가 없다. 중복 단위는 hero가 이미 제시할 때만 자동 조건행에서 생략하며 작성된 설명/기간/출처는 보존한다.

이번 시각 대조에서 필수 교정 이견은 없다. 원문/계산/저장/내보내기·전체보기·발표자의 전체 회귀는 총괄 검수와 구분한다. 이 기록만 작성하고 매니저의 편집/브라우저 작업을 종료한다. 제품코드/WORK_LOG/PNG/PDF/Git은 수정하지 않았다.
