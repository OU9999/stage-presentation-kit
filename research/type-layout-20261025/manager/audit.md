# 현재 제품의 글 배치 감사

담당: 디자인 매니저 `/root/design_manager`. 범위는 실제 원고 네 장·CSS·DOM이며 새로운 브랜드/색상/프레임워크/인쇄/PDF 검토는 하지 않는다.

## 직접 확인한 자료

- 현재 `examples/visual-story/content.js`와 `styles.css`, `visual.css`, `app.js`의 visual 조립 코드.
- 총괄이 보관한 `evidence/before-opening.png`, `before-funnel.png`, `before-trend.png`, `before-flow.png`를 직접 열어 비교했다.
- TaskSpace11의 매니저 전용 p4에서 동일 제품을 관찰했다. 치수 근거는 `baseline-browser.json`에 보관한다. 최초 감사는 현재 제품을 대상으로 했다. 이후 매니저도 실무가 확보한 Apple2장·Anthropic3장의 공식 장면 캡처를 직접 열어 관찰 범위와 주장이 일치하는지 확인했다. 매니저가 해당 영상을 새로 재생한 것은 아니며 원본의 직접 재생/기존 프레임 관찰 범위는 두 실무의 출처 문서로 구분한다.

## 잘 작동하는 부분

표지는 두 줄 선언과 보조 설명의 위계가 분명하다. 도표는 이전 개선으로 외곽 미디어 패널을 제거해 메시지와 같은 검은 무대에서 읽힌다. 수치·단위는 색과 크기로 구분되며 데이터와 연동한다. 따라서 새 시안은 기존 개선을 유지하면서 글의 위치·밀도를 다룬다.

## 구체적인 개선 지점

| 현재 관찰 | 실제 영향 | 비교할 가설 |
| --- | --- | --- |
| `.slide-title` 76px, visual 72px/split64px, cover118px·중앙130px 등 레이아웃별 크기가 별개로 누적된다. | 역할보다는 레이아웃 이름이 위계를 결정한다. | 선언/근거 제목/설명이라는 역할별 읽기 폭과 크기. |
| visual wide 열이 `minmax(0,1fr) auto`다. | 긴 hero값이 제목 폭을 빼앗고 줄바꿈·설명 높이를 바꾼다. | 제목과 hero 영역의 독립된 bounded grid 또는 수치를 증거 가까이 배치. |
| 제목 밑 subtitle 22px, 이어 자동 단위 context18px의 간격이 쌓인다. | 비교 조건과 단위를 찾기 위해 눈이 세 줄을 차례로 훑는다. 차트 시작점과 멀어진다. | 설명과 단위의 역할 분리, 차트 가까운 짧은 조건행. 원문 삭제 없이 재배치. |
| wide weekly 제목이 한 줄로 넓게 뻗고 58%가 오른쪽에 붙는다. | 제목과 숫자는 같은 높이지만 무엇이 58%인지 먼 subtitle을 다시 읽어야 한다. | 주장·근거 연결이 분명한 상단부와 마지막 관찰값의 가까운 라벨. |
| split funnel은 왼쪽 위 제목, 왼쪽 아래660명, 오른쪽중앙 단계 막대다. | 큰 수치와 해당 마지막 행의 거리가 길다. 설명/단위는 위쪽에 밀집하고 중간은 비어 있다. | 값과 레이블을 하나의 묶음으로 두고 비교조건을 증거 옆에 정렬. |
| flow는 큰 제목과 한 줄 설명 밑에 긴 여백 후 작은4개 단계가 놓인다. | 글의 주장과 도식의 관계를 잇는 시작점이 약하다. | 제목폭 축소·설명 위계 정리, 단계글 확대와 관계가 드러나는 근접 배치. |
| `quiet`은 eyebrow/footer와 본문의 top/bottom 공간을 함께 없앤다. | 메타 제거는 유효하지만 모든 quiet장에 같은 꽉찬 높이가 주어진다. | 메타 표시와 문장 블록 위치를 독립적으로 취급. |
| `[data-field]`는 pre-line, title 배열은 title-line block이며 `text-wrap:balance`가 공통적이다. | 명시적 의미단위는 보존되나 짧은/긴 문장에 동일한 balance가 적용된다. | 자연 줄바꿈 기본+선택적 명시적 줄바꿈, 긴문장의 읽기폭 제어. |

## 판단 범위

이 시점의 항목은 시안에서 검증할 가설이다. 폰트를 무조건 줄이거나 제목을 강제로 고치는 것을 결정한 것은 아니다. 최종 채택은 같은 원고 A/B·두 라운드 비평·390px/긴 문장/긴값의 실제 시안을 대조한 뒤 `final-decision.md`에 기록한다.
