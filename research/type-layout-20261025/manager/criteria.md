# 발표 글 배치 평가 기준

담당: 디자인 매니저 `/root/design_manager`. 제품 원고는 `../shared/corpus.js`로 고정한다. A/B는 Apple/OpenAI 무대형 관찰과 Anthropic 설명형 관찰의 서로 다른 가설이며, 회사의 내부 규칙이나 공식 스타일 지침으로 일반화하지 않는다.

## 비교 입력

- 현재 `examples/visual-story/content.js`의 opening, funnel, weekly, journey 네 장. 제목·설명·숫자·분모를 그대로 유지한다.
- 긴 한국어 질문+설명+본문, 다른 주제의 7주 지원 응답 시간, 9,876,543.2건 강조값을 별도 반례로 둔다.
- 기존 `evidence/before-*.png` 네 장은 1600×900의 실제 제품 기준이다. 독립 시안은 같은 비율에서 비교하며 390px에서는 문서 흐름으로 읽는다.

## 채택 조건

1. **첫 시선과 위계:** 문장·수치·증거 중 무엇부터 읽는지 분명해야 한다. 본문·단위·주석이 제목과 경쟁하지 않는다. 큰 수치는 원본 데이터에서 도출한다.
2. **읽기 폭:** 긴 숫자의 intrinsic 폭이 제목의 가용 폭을 바꾸지 않는다. 제목·본문의 읽기 폭을 역할별로 정하고, 한국어 단어·문맥을 보존한다. 원문의 title 배열/명시적 줄바꿈을 유지하며 CSS 때문에 문장을 축약하지 않는다.
3. **글과 증거의 연결:** 비교 조건은 해당 차트 가까이 놓고, 필요한 기간·분모·단위를 무대에서 찾을 수 있다. 같은 단위를 중복해 거대한 세로 간격으로 쌓지 않는다. 차트를 장식 패널로 감싸지 않는다.
4. **여백과 밀도:** 매 장 상단에 같은 크기의 제목을 붙이는 방식만 고집하지 않는다. 선언은 집중, 설명은 주장→근거 순서, 도식은 관계가 주역이 되게 한다. 빈 공간이 요소 관계를 흐리면 조정한다.
5. **반례:** 7주·긴값·긴한국어에서도 원문/정상값 보존. 잘라내기·말줄임·하드 문자수 반려·의미없는 0 대체를 쓰지 않는다. 긴 장은 더 넓은 배치 또는 읽기 모드가 가능해야 한다.
6. **390px:** 글은 실제 DOM에서 제목 약30–36px, 본문17–18px 수준으로 읽고 세로 재배치한다. 본문 가로 넘침은 없어야 한다. 축소된 그림만 보고 모바일 가독성 성공이라고 하지 않는다. 상세 표 대안은 유지한다.
7. **편집과 재사용:** title/subtitle/data 원본 한 곳을 고치면 반영된다. 회사 이름 preset이나 슬라이드ID 조건문 대신 중립적인 기본 규칙/작은 선택지를 권고한다. 명시적 줄바꿈은 선택이며 원문 편집에서 보존돼야 한다.
8. **등장 순서:** 첫 메시지 뒤에 증거가 이어지도록 하되 모션은 필수 전달 경로가 아니다. 읽기/편집/reduced-motion/정적 전체보기에서 내용이 완전해야 한다. 기존 200–300ms 계열을 넘어 새 모션 시스템을 만들 필요는 없다.

## 두 번의 직접 토론

첫 라운드는 동일 네 장의 상대 시안을 직접 열고 구체적인 요소·문장·위치와 바꿀 이유를 제시한다. 본인 파일을 수정하고 변경 전/후·채택/기각 근거를 남긴다. 둘째 라운드는 긴 한국어·긴값·차트·390px·다른 주제 수정 사례로 첫 합의의 실패 가능성을 검토한다. 취합자는 두 관점이 충돌한 항목과 최종 선택을 기록한다.

제품 적용은 두 라운드와 매니저 검수가 끝난 뒤 총괄에게 파일 단위로 인계한다. 이 문서는 제품 코드 수정 권한을 부여하지 않는다.
