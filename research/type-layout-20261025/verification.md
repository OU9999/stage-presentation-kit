# 발표 글 배치 적용·검증

[실제 전후 비교](index.html) · [8장 복사 실행 예제](../../examples/text-layout/index.html) · [기존 발표 적용](../../examples/visual-story/index.html#3)

이전 개선은 `1b395a5`로 먼저 커밋했다. 이후 작업은 Apple·OpenAI·Anthropic의 선별된 실제 발표 장면과 같은 원고의 두 독립 시안을 대조하고, 두 차례 직접 비평한 글 배치 개선이다. [공식 장면A](apple-openai/sources.md)·[공식 장면B](anthropic/sources.md), [토론](discussion.md), [최종 결정](manager/final-decision.md)에 관찰·권고·채택/기각의 근거를 구분한다.

## 적용한 결과

- wide는 제한된 제목 읽기 폭과300px 강조값 열 아래에 전폭 차트를 둔다. split은 왼쪽 주장과 오른쪽 수치·레이블·차트를 상단에서 묶는다. 짧은 흐름은 문장과 관계행을 가까이 배치한다.
- 긴 수치+단위는 전체 실제 폭을 재서 먼저 독립 행을 확보한다. 필요한 경우 해당 수치만 국소 조정하고, 원문/계산/편집 노드를 다시 생성하지 않는다. 긴 한국어는 기존 statement의 제목·정의·본문을 서로 다른 크기/행간으로 읽는다.
- 기존 align·명시적 title 배열·연사/날짜·motion·같은 원본 표·저장/내보내기를 재사용한다. 새 레이아웃 이름·기업별 preset·라이브러리·필수 빌드를 추가하지 않았다. 스타터는 폴더를 복사하고 content.js만 수정한다.

기존 발표12장과 새8장 PNG는 실제 제품을 열어1600×900으로 캡처했다. 기존75장 순차 검수의 일부에서는 브라우저 시계가 CSS 효과0ms에 머물러, 이후 정적 배치 검수에 reduced-motion을 사용했다. 제품의 효과 코드나 원문을 강제로 변경한 것은 아니다. 모션의 기존 계약은 자동 검사로 확인했다.

앞선 큰값 실검수에서는 오른쪽 정렬의 시작쪽 overflow가 scrollWidth에 잡히지 않는 경우를 발견했다. 수치와 단위의 요소 폭을 합산하도록 고쳤고 모바일 수치 영역의 실제 가용 폭도 확보했다. 최종 모바일 큰값은 전체 문자를65px로 보존하며 단위를 다음 줄에 배치한다.

## 비교와 원본 보존

기존4장 기준은 `1b395a5`의 검증 PNG다. 긴 설명/큰값 비교는 같은 새 예제 입력을 `1b395a5`의 런타임과 현재 런타임으로 각각 열어 캡처했다. 원본 회사 슬라이드는 연구 근거로만 보관하고 제품 자산에 넣지 않았다.

기존 루트 원고·5개 Markdown·제품 개선 원고의 내용/수치를 바꾸지 않았다. 새8장은 복사 가능한 가상 자료다. [최종 소스 SHA](evidence/final-source.json), [정적 참조·사본 검수](evidence/final-static.json)에 현재 파일을 기록한다. 이전 날짜의 검수/해시는 그 작업 당시 이력으로 보존한다.

디자인 매니저와 두 실무 모두 종료했다. 운영 지침·소유권·결정은 단일 [WORK_LOG](../../WORK_LOG.md)에 있다. 최초 검수 시에는 로컬 검토 상태로 인계했고, 2026-10-26에 글 배치 개선을 [bfd9bad](https://github.com/OU9999/stage-presentation-kit/commit/bfd9badae811b6a086a1eb9a13b090276781fbdc)로 커밋해 origin/main에 푸시했다. 이전 두 커밋도 함께 전달됐다. 제품 소스·검수 SHA는 그대로이며 새 PDF 생성이나 별도 외부 배포 설정은 하지 않았다.
