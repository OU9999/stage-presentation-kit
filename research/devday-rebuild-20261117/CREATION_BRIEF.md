## 초기 산출물과 소유

4슬롯(root+manager+실무2). `$manager`로 두 명을 실제 실행하고 각자 실질 초기 산출물·서로 직접 협업·실무 취합 담당을 지정한다. MODEL.json의 새 확인을 공유하고 정확 gpt-6.1-sol/xhigh/none을 사용한다.

- B는 원고 편집·타이포·native 조판/최소 공용 확장·취합을 맡는다. 인용·메시지는 편집 가능한 native 글자로 만든다. 기존 Markdown 계약을 쓰고 필요한 최소 확장은 명시 variant에 한정한다. 실제 보편적 레이아웃 동작은 재사용 가능하게 구현하되 LLM Wiki id를 공용 CSS에 하드코딩하지 않는다.
- manager는 두 산출물 인터페이스·시각 판단·소유 조정·실제 확인 범위를 책임진다. root가 final 미감 판단을 별도로 한다.

초기는 **큰 타이포·비교 그림·자료와 인용·결과물**을 드러내는 4개 내외의 실제 시안이다. 숫자는 양식 할당량이 아니라 먼저 풀 위험 범위다. `research/devday-rebuild-20261117/prototypes/`에 소스/자산을 만들고 원본 본편은 아직 바꾸지 않는다. root가 브라우저로 양 발표폭 캡처를 수집한다. prototype 자체를 빌드하는 경로/명령을 인계한다. 공용 runtime 수정이 필요하면 소유를 B로 고정하고 관련 변경/영향을 보고한다. product 공용 변경 뒤 root 캡처까지 입력 동결을 지킨다.

## 인계 조건

시안을 실제 실행 가능한 상태로 만든다. manager가 파일·원본과 달라진 보이는 성질·아직 어색한 부분·실행 명령·변경 범위·실제 테스트를 인계한다. 단순 제안/자체승인/체크리스트로 완료하지 않는다. 원본의 구체 비례·정렬·작업 형태와 아직 다른 부분을 숨기지 말고 root에게 직접 알린다. freeze 시 모든 제품 writer의 종료/hold를 직접 확인한다. root와 독립 검증팀이 실제 화면을 반려하면 같은 팀을 재개해 재수정한다.
