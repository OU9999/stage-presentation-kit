# 본편 이행 계약

root가 **실제 시안 재검수의 채택 범위와 라운드**를 지정해 제작 재개할 때 적용한다. 이 문서의 존재는 시안 승인이나 지금 본편 쓰기 허가의 대용이 아니다.

최신 목표: 원본 내용보다 미감 우선. OpenAI DevDay 발표와 거의 차이 없는 시각 완성도, 사소한 어색함까지 수정. WORK_LOG 최신 지시/권한과 DESIGN 관련 기준, 이번 review의 실제 최종 명세를 읽는다. 단순 상대 개선·역할 존재·문구 정확성·검사 통과로 미감 합격을 내리지 않는다. root는 WORK_LOG/Git/브라우저/build/실캡처/최종 통합을 소유한다.

## 본편의 실제 편집

- 현재20장·긴 원문·예전 한 행/필드/세 영역/표 배치를 고정하지 않는다. 타이포/비교/관계/자료/결과물/행동을 실제 이야기로 재편집한다. 문구 재작성·요약·선택·생략, 장수/순서/매체 변경 가능. 모든 장을 같은 중앙 한 문장으로 바꾸는 것도 해법이 아니다.
- 채택한 시안의 실제 형태·폭·행·획·여백·자료 표면을 본편에서 보존하되, 옛 레이아웃/QA에 맞추려고 못생긴 판으로 되돌리지 않는다. 문구를 바꾼 장도 새로운 실물로 다시 검수한다. 원본과 현재 반려본을 직접 대조한다.
- LLM Wiki의 발표 정체성과 핵심은 남긴다. 원자료를 읽고 연결해 다음 질문에 다시 쓰는 경험, 사람의 판단과 AI 해석 구별, 실제 시작 행동을 명료하게 편집한다. 여러 설명은 대본/읽기에서 이어갈 수 있다. 원자료·원래 문서/데모/자산·기존 역사 증거 파일은 보존한다. 가상 활동안/자료를 실제 모델 실행·효과 측정이라고 바꾸지 않는다.
- 새 public source는 `talks/llm-wiki/slides.md`. 필요한 대본/해설·공개자료 링크/소속도 실제 새 장 흐름에 맞춘다. 원래26주제의 상세는 기존 공개 해설/대본에 남길 수 있고, 모든 주제를 같은 발표면에 보존시키지 않는다. 현재 장 번호를 강제로20에 맞추지 않는다.
- A는 필요한 새 자산/자료의 미감과 원본 대조, B는 원고/공용native 조판·자료/QA 계약·취합을 맡는다. manager가 소유와 인터페이스를 직접 인계하고 전원 렌더입력 hold/종료를 확인한다. root는 새 전체 본편을 실제 캡처해 다시 검증팀을 실행한다.

## 실제 관측 계약과 재사용성

기존 QA의20장/63 native·6SVG·일부 정확 문구/옛 sourceLine을 새 디자인의 입력 제약으로 되살리지 않는다. 새 원고의 실제 AST·자료/필드·DOM과 기술 계약을 정직하게 대응시킨다. 기존관측/회귀 이력은 그대로 보존하며 문서의 현재 개수/역할/명령도 갱신한다.

`talks/llm-wiki/qa/keynote-current.json`, `keynote-coverage.json`, 필요한 `scripts/llm-wiki-keynote-qa.cjs` 및 관련 테스트/관측 안내·작성 안내를 B 단독 소유로 갱신할 수 있다. code/관측 누락을 통과시키거나 임의 font floor를 전역 완화하지 않는다. 실제 옮긴 내용의 읽기 위치·앵커·정확한 역할은 계속 검증한다. 바뀐 선언이나 자료 표면의 합리적 크기와 예전 문구/행 고정을 구별한다.

레거시 native 양식을 쓰는 장도 모든 native 필드를 측정한다. 예를 들어 results의 실제 `H1.slide-title[data-field="title"]`는 원고의 실제 `slide.title` 필드와 연결한다. sourceLine을 가짜로 합성하지 않는다. block AST는 실제 sourceLine/tag/text/소속·br·emphasis로 계속 대조하고, legacy는 실제 data-field/필드값/tag/실glyph와 대응시켜 빠짐·중복·변조를 차단한다.

root가 새 capture helper에 실제 `dataField` 관측을 추가했고 prototype results H1에서 `title`, 두 실제 glyph행,72논리px를 실제 수집했다(`legacy-field-observation.json`). helper 정본은 이번 연구의 `line-metrics-current.mjs`, `reading-line-metrics-current.mjs`; root가 소유한다. B는 QA 소비 인터페이스 변경을 root에게 직접 알려 협의한다. root가 쓰는 cap helper를 동시에 수정하지 않는다. SVG가 새 shape/곡선/기하로 바뀌면 실제 관측 포맷도 root와 직접 협의한다.

새 조판은 명시 재사용 옵션으로 구현하며 주제 id/한국어 문구를 공용 CSS나 runtime의 예외키로 삼지 않는다. 이전 prototype/원본/실캡처/리뷰를 덮지 않는다. 전체 build/대량test는 root가 한 번씩 실행하며 실무는 관련 작은 단위검사를 수행한다.

## 완료 인계

실제 새 본편·대본/읽기·자료·계약을 함께 동결해 인계한다. 변경/보존 파일, 실제 실행한 단위검사, 아직 어색하거나 확인하지 못한 곳을 짧고 구체적으로 알린다. manager/A/B가 직접 source/인터페이스를 확인한 뒤 writer 종료를 명시한다. 제안서/예고로 이행을 완료했다고 하지 않는다.

root가 전체 build/verify·필요 테스트와 현재입력 실제4범위(발표1920/1280,읽기1440/390) 관측 회귀를 실행한다. 검증팀은 새 전체 실물에서 시각지적을 다시 내고, 필요하면 같은 제작팀을 재개한다. 명시 범위 `--require-approved`와 root 최종 원본 대조를 거친 뒤만 내부 시각 승인으로 보고한다. 커밋/푸시/배포는 이번 이행에 없다.
