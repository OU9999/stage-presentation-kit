# LLM Wiki 확장 발표의 디자인 보드

## 관찰과 재설계 기준

현행 24장 중 3·14·20장의 실제 PNG와 첫 영상 32:30 프레임을 직접 확인했다. 기존 화면은 글자를 읽을 수 있지만 큰 검정 타이포/얇은 2열/밝은 문서가 반복된다. 35분 발표에서는 개념을 외우는 구도와 실제로 쓰는 구도의 차이가 필요하다.

첫 영상의 원자료 수집·목적 질문·개념 생성·기록/회고, 둘째 영상의 짧은 문답·RAG 시연이 설명 역할별로 달라지는 점을 참고한다. 아래는 독자 제작하는 발표 구성이다. 첫 영상 07:45·09:15의 실제 개념 슬라이드를 추가로 직접 확인했다. 09:15는 크림 바탕, 큰 검정 제목의 핵심어 강조, 작은 원자료 면에서 큰 네이비 위키·그래프 면으로 흐르는 비대칭 구도를 사용한다. 이 추가 관찰은 직전 판이 선택한 앱 화면·대화 장면만으로 원본의 외양을 판단했던 한계를 바로잡는다. 원본의 이미지·브랜드·인물·화면을 복제하지 않고 정보 위계와 논리를 새 내용으로 다시 설계한다. 추가로 첫 영상 19:45·24:15·28:45·36:35·39:15·43:16, 둘째 16:14 프레임을 직접 열어 확인했다. 첫 영상은 큰 플래너 질문, 날짜별 노트/로그, 앱 연결 창, 개념 생성 요약과 삶의 목적 문서를 실제로 확대한다. 둘째 16:14에는 같은 자료와 질문을 두 화면에서 비교하는 시연이 보인다. 시연의 법률 내용 자체는 이번 발표의 사례로 복제하지 않는다.

## 시각의 중심

**자료가 들어오고, 관계가 남고, 다음 질문이 달라지는 장면.**

파일 경로를 읽는 시간을 줄이고 저장 결과·동일 질문·변경된 문장이 보이는 시간을 늘린다. 장마다 새 박스와 아이콘을 배치하기보다, 내용에 맞는 여섯 개의 구도를 번갈아 사용한다.

## 공통 언어

| 요소 | 설계 |
| --- | --- |
| 무대 | 이번 주제는 `theme: paper`로 전환. 크림 캔버스와 큰 차콜 글자, 내용의 네이비 관계 면 중심 |
| 핵심 색 | 크림 `#F2F0E8`, 네이비 `#172238`, 틸 `#63D7C5`, 코랄 `#BD4B45`, 녹색 `#286A5B` |
| 문서 면 | 아주 밝은 아이보리는 읽을 문장 1개가 주역일 때만 사용. 모든 시연에 같은 문서 상자 반복 금지 |
| 제목 | 기존 native 제목 60~76px, 한두 줄. SVG 내부 주역 64~92px, 본문 34~42px |
| 보조 | 파일명·근거 경로 26~30px. 중요한 결론을 보조 크기로 쓰지 않음 |
| 변화 | 입력·기존 관계·새 연결을 위치/라벨/색으로 함께 구별. 색에만 의존하지 않음 |
| 여백 | 장식용 빈 공간보다 문장·도식·실제 비교가 차지할 면적 확보. 안전 여백 약60~90px |
| 실행 범위 | 구성 예와 관찰한 원영상의 구분은 캡션/대본에 표시. 모든 화면에 긴 경고문 반복 금지 |

## 여덟 가지 화면 역할

### 1. 장의 질문과 예고

큰 `01 / 02 / 03 / 04` 장 번호와, 이번에 풀 질문 두 줄. 얇은 전체 목차 네 단어와 현재 강조를 함께 둔다. 챕터 전환은 단순 검정 제목만 반복하지 않고 큰 의미색 타이포와 작은 대표 관계를 배치한다.

### 2. 목적과 맥락

왼쪽은 같은 원자료 한 묶음, 오른쪽은 두 가지 사용 목적. 예: ‘스터디에서 설명하기’와 ‘내일 일정을 정하기’. 결과를 나란히 보여 목적이 무엇을 남길지 바꾼다는 이유를 시각화한다. 실제 사람의 기록을 복제하지 않고 구성 예의 문장을 쓴다.

### 3. 연결·축적·갱신

고정 위치의 세 자료가 하나의 개념과 비교로 모이고, 다음 자료가 들어오면 같은 비교 문장의 일부만 바뀐다. 접힌 문서/텍스트 단위가 중심이고 선은 실제 관계에만 사용한다. 동일한 시각물을 세 장 연속 복제해 변화를 단계적으로 보여줄 수 있다.

### 4. 인제스트 시연

원자료와 목적 질문, 생성 결과를 모두 한꺼번에 작게 넣지 않는다. `수집`→`왜 남겼나요?`→`무엇이 생겼나요?`의 세 장에서 같은 위치를 확대한다. 입력은 분량과 URL, 목적은 사람의 짧은 답, 결과는 생긴 개념·관계·갱신 문장으로 보여준다.

### 5. 동일 질문의 RAG·위키 비교

두 화면은 같은 질문과 같은 원자료로 시작한다. RAG 장은 ‘찾아온 근거를 이번 답에 종합’의 시간 흐름, 위키 장은 ‘이미 남은 개념·비교를 다시 읽고 필요하면 갱신’의 축적 모습을 보여준다. 다음 장은 양쪽을 동일한 3행 비교표로 정리한다. 우열표·RAG 기억불가·위키 검색금지로 표시하지 않는다.

### 6. 하루의 다섯 겹

의도·실행·현실·해석·AI 로그를 같은 크기 카드5개로 나열하지 않는다. 서로 다른 기록 유형을 큰 타이포와 같은 길이의 얇은 연결·작은 문서 행으로 구별하고, 공통 괄호로 회고와 다음 계획에 모은다. 실제 시간축·기간·고정 순서로 오독될 막대는 사용하지 않는다. ‘계획과 실제’, ‘관찰과 해석’이 구별되도록 한다. 영상 발표자의 개인 사례이며 필수 LLM Wiki 구조로 일반화하지 않는다.

### 7. 규칙과 지식 그래프

왼쪽에는 글로 적힌 정리 기준 3줄, 오른쪽에는 한정된 실제 개념/출처/사례 노드7개를 놓는다. 그래프는 아름다운 점무늬가 아니라 연결을 따라 읽는 방법을 보여준다. 노드 이름과 연결 의미가 필요하며 그래프가 자동으로 진실을 증명한다는 인상 금지.

### 8. 회고와 다음 행동

일별 기록→주간에 반복된 패턴→월간 질문의 세 시간 범위를 계단처럼 쌓는다. 타임라인 대신 매 주기에서 남는 문장 하나가 주역이다. 마지막에는 내 자료 두 개·목적 한 줄·다음 질문을 큰 빈칸으로 표시해 청중의 첫 행동을 만든다.

## 인수 기준

- 이전판과 비교해 표지·목적·동작·비교·활용·마무리에 서로 다른 구도가 보임
- 처음 듣는 청중도 제목과 주역 내용을 읽어 이 장의 질문을 알 수 있음
- RAG와 LLM Wiki 비교에 동일한 질문·자료·검토 조건 유지
- SVG 본문 최소34px, 메타26px; 내용이 많아지면 글자 축소 대신 다음 장으로 분리
- 모든 텍스트 실제 bbox 경계·겹침 검사, 1440/960 화면과 390 읽기에서 의미 확인
- 근거 영상 시간/기술 문헌/구성 예의 역할이 대본과 학습 자료에서 이어짐
