## 가독성과 조판

- 밝은 문서에서 제목·본문·메타정보의 밝기 차이 확인
- SVG 본문 32~44px, 경로/보조 26~30px의 원본 크기를 실제 PNG에서 확인
- 원자료와 파일 경로는 보조 정보, 읽어야 할 개념 문장이 주역으로 보임
- 사진·카드·색 테두리 박스·복잡한 네트워크 그래프의 장식 반복 없음
- 3/6~13장의 하단 핵심 문장과 문서 사이 안전 여백 확보
- 표 17장과 코드 요청 22장의 네 항목 모두 화면 안에 완전히 표시
- 14/16/18/20장은 상단을 중심으로 정보가 배치되어 하단 여백이 큼. 발언 중심 구도이며 이를 채우기 위한 장식 추가 불필요
- 6~13장의 연속 작업면은 같은 파일이 어떻게 쓰이는지 기억하게 하는 목적. 다만 실제 청중의 읽기 속도·20분 낭독 시간은 측정하지 않음

## 직접 교차 문답과 좁은 개선

### 6장 작업 규칙의 위치

엔지니어링팀과 시각 담당 모두 `rules.md`가 wiki의 밝은 작업면 안쪽에 배치되어 물리 경로를 오독할 가능성을 관찰했다. 의도는 전체 작업의 규칙을 안내하는 보조 문구이며, 8/11장의 루트 표시와 6장 대본도 전체 규칙임을 설명한다. root 판단으로 작은 개선을 실행했다.

- 두 작업면 높이를 500→430으로 조정
- `rules.md`의 동일 문장을 두 면 바깥 아래 공통 행으로 이동
- 생성 스크립트 동기화, `raw-wiki.svg`만 변경
- 다른 7개 SVG 전체 바이트 보존; 근거 `rules-delta.json`
- 추가 인수: 갱신된 6장 PNG를 `view_image`로 직접 다시 확인. `rules.md`가 raw/wiki 두 면 바깥의 공통 행으로 읽히며 본문·캡션·하단 사이 여백 정상
- root의 8종 SVG 경계 재검수 이상 0개 결과 인수
- 제품 자산 writer 종료, 추가 시각 수정 요구 없음

### 7~9장 설명 시점

발표팀이 7/8장에 비교·모델 적응 링크가 이미 보이는데 9장 대본은 LoRA를 이제 추가하는 듯한 표현이라는 점을 질문했다. 시각 담당의 의도는 3장 완성 결과 선공개 이후 두 자료를 반영한 위키를 부분별로 확대하는 설명이다. 빈 위키에서 파일이 하나씩 실제 생성되는 시간순 시연이 아니다.

root가 같은 혼동 가능성을 독립 확인했고, 발표팀이 7~9장 대본을 `두 메모를 함께 반영한 결과를 부분별로 보기 → RAG 개념의 반영 확인 → LoRA 비교의 반영 확인`으로 좁게 교정했다. 화면과 대본의 의도가 일치하며 추가 SVG 수정은 불필요하다.
