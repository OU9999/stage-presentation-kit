# LLM Wiki 발표 시각 계약 초안

- 담당: 발표 전문가팀 시각 담당 `visual_specialist`
- 단계: root의 24장 이야기 계약 승인 후 SVG 8개 제품 반영
- 직접 확인: 현행 원고·`DESIGN.md`·`MARKDOWN-FIRST.md`, 이전 실제 화면 7장과 14장 PNG
- 자막 확인: 첫 영상 29:44~36:31의 원자료 수집·raw/wiki·개념 연결·수집 목적·작업 매뉴얼 설명, 둘째 영상 13:34~16:02의 위키 설명과 규모/문맥 부담 설명
- 대표 프레임 직접 확인: 첫 영상 31:40·32:30·33:30, 둘째 영상 14:30
- 관찰: 첫 영상은 밝은 Obsidian의 raw/wiki 탐색기와 원자료 문서, 에이전트의 목적 질문·생성 파일 요약을 나란히 보여 주는 시연; 둘째 위키 구간은 인물 대화
- 미확인: 전편의 프레임·전환·정확한 글꼴/색상·슬라이드 덱 전체
- 근거 경계: 아래 구성은 현행 발표 진단과 새 발표 목적에 따른 독자 설계. 원본 영상의 외양을 복제하거나 관찰 결과로 주장하지 않음

## 핵심 판단

현재 화면은 검정 바탕과 충분한 여백을 갖췄으나, 문서 아이콘·화살표·추상 범주를 거듭 읽게 만드는 구조다. `새 자료 → 개념·비교·종합 → 다음 질문`을 이해하려면 매번 발표자의 번역이 필요하다. 새 발표에서는 이번 AI 스터디를 하나의 위키로 만들고, 청중이 읽을 수 있는 파일 내용이 변화하는 장면을 중심에 둔다.

## 시각 원칙

| 항목 | 계약 |
| --- | --- |
| 무대 | 기존 검정 Stage·큰 제목·조작 UI 유지 |
| 작업면 | 검정 위에 놓인 큰 밝은 문서. 파일과 링크를 읽는 동안은 한 작업면에 집중 |
| 컬러 | 본문은 흑백, 링크는 파랑, 새로 바뀐 문장은 옅은 노랑. 범주마다 서로 다른 색 금지 |
| 표현 단위 | 원자료·목차·한 개의 개념 페이지·한 개의 비교 페이지·한 개의 질문 페이지 |
| 위계 | 질문/주장 > 실제 문서 내용 > 파일명 > 근거 링크 |
| 반복 | 같은 파일 트리와 문서 위치를 여러 장 유지하고 내용만 단계적으로 변경 |
| 기술 비교 | 네 기술을 동일 크기의 네 카드로 나누기보다, 같은 질문에 각 기술이 바꾸는 대상을 비교 |
| 원본과 예시 | 영상의 주장·Karpathy 설계·발표용 구성 예를 대본/출처와 짧은 캡션으로 구별 |
| 구현 | 기존 `compose: message/media/document/quote` 사용. 주제로컬 SVG, 공통 runtime 변경 최소화 |

## 화면 규격

- 발표 캔버스: 기존 1600×900 유지
- 문서형 SVG: 1500×540, `fit: contain`, 본문 상하 안전 여백 확보
- 본문 최소 32px, 파일명 26px, 보조 24px, 주역 문구 44~54px
- 한 문서에 큰 제목 1개, 읽을 본문 3~5줄
- 서브창 2개 이하, 복잡한 네트워크 그래프·전체 터미널·작은 실제 앱 캡처 금지
- 모바일 의미 확인용 원고 alt와 이미지 아래 핵심 문장 유지. 파일 내부 글자는 별도 학습 자료에도 텍스트로 제공
- SVG 자체에는 조작 가능한 버튼처럼 보이는 컨트롤과 가짜 다운로드 링크 미사용

## 대표 네 장

### 1. 내 자료가 있어도, AI는 다시 처음부터 읽는다

- 장 역할: 문제를 본인 경험으로 인식
- 구성: 화면 왼쪽에 `영상 A / 영상 B / 내 메모` 세 출처를 얇은 세 줄로 배치, 오른쪽은 질문 하나 `내 스터디에는 무엇을 써야 할까?`
- 시각 중심: 커다란 질문과 그 아래 비어 있는 `아직 남기지 않은 비교`
- 다음 장 변화: 같은 위치에 비교 파일이 생김
- 피할 것: 정리 전 어수선한 종이 더미와 정리 후 빛나는 뇌의 장식 비유

### 2. LLM이 만든 것은 요약 세 개가 아니라, 연결된 설명이다

- 장 역할: LLM Wiki의 저장 결과를 눈으로 정의
- 구성: 24% 폭의 파일 트리 `raw/`, `wiki/`, `rules.md`; 76% 폭의 큰 밝은 문서 `wiki/비교/지식-활용.md`
- 주역 문서: `RAG는 필요한 근거를 가져온다`, `LLM Wiki는 다시 쓸 설명을 써서 남긴다`, `둘은 함께 사용할 수 있다`
- 관련 링크: 문서 하단에 `[[RAG]]  [[LLM Wiki]]  원자료 A·B`
- 기술 검토: 문장 최종 확정은 엔지니어링팀의 검토 결과 적용

### 3. 새 질문의 답도 위키의 일부가 된다

- 장 역할: 질문→답→저장의 귀환을 실제 내용으로 설명
- 구성: 직전 파일 트리 유지, 열린 파일만 `wiki/질문/스터디에서-시작하기.md`로 교체
- 주역 문서: 질문 한 줄, 근거가 있는 답 두 줄, 연결 한 줄
- 한 번의 변화: 질문 파일 아래 `현재 답 · 근거 · 다음 확인` 세 항목 등장
- 피할 것: 큰 원형 루프·세 개의 서로 다른 처리 박스. 화면에서 파일이 새로 남는 변화 자체로 설명

### 4. 새 자료가 오면, 같은 설명이 더 구체적이 된다

- 장 역할: 지속적으로 갱신하는 위키와 단발 요약의 차이
- 구성: 같은 비교 파일 확대. 기존 비교 축 `검색으로 근거 가져오기 / 설명을 문서로 남기기`를 보존하고, 새 축 `검색 전략을 누가 결정하는가` 한 줄만 옅은 노랑 띠로 추가
- 설명 예: `agentic RAG: 필요한 도구·검색 순서를 모델이 선택할 수 있다`
- 근거: 원자료 참조와 `아직 확인할 조건` 한 줄
- 경계: 새 정보로 비교가 정교해지는 발표용 구성 예. 일부러 오답을 만든 뒤 교정하는 사례로 전개하지 않음

## 직접 검수 기준

- 1440×810·960×540에서 파일명보다 본문이 먼저 읽히는지 확인
- 밝은 작업면에서 흰색 본문·검정 강조 같은 테마 반전 충돌 없음

- 그림 안 링크는 의미만 표시하고 실제 경로는 원고·학습 자료에서 연결
