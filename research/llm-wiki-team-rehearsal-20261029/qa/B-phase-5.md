- 상태: 독립 초안 동결. 기본 구간(1~28장, 40장) 이후에 별도로 본 선택 심화다. 이 검토로 기본 구간의 초기 반응을 고치지 않는다.
- 추가 노출: `input/phase-5.md`와 29→39 PNG를 각각 `view_image`로 직접 확인하고 정확 발화·전환과 대조했다. 코드·논문·실습 원파일·학습서·상대 기록은 열지 않았다. 아래 사실은 발표가 제공한 내용의 이해이며 외부 원문 검증 결과가 아니다. 실제 음성·실시간 대기·실행 시간은 평가하지 않았다.

## 자기 말 회상

“공개 구현도 이름만 보고 설계 전체를 실행한다고 생각하면 안 된다. 등록과 LLM 작성이 나뉘며, 질문이 읽는 문맥에는 검색과 길이 제한이 있고 저장 안내가 실제 자동 저장은 아닐 수 있다. 연구 결과도 목표 자료를 이미 주는 쪽과 검색하는 쪽을 비교했다면 위키 전체의 우위로 말하기 어렵다. 파일 교정 예제는 사람이 정한 문장을 Node로 반영하고 링크와 보존 바이트를 확인한 범위다. 의미가 맞는지와 검색을 잘하는지는 다른 확인이다.”

## 앞선 미해결 질문의 변화

- 해결된 범위: 30장은 공개 코드 한 판의 문맥 선택·수동 저장 동작을 설명한다. 35장은 사람이 검토한 수정 전후를, 37장은 모든 답/검토한 답 사이의 운영 선택과 이전 선택 보존을 보여 준다. 38장은 링크·보존 검사가 무엇을 보장하지 않는지 답한다.
- 부분 해결: 검토할 때 문장·근거 위치·범위를 대조한다는 행동이 37장에서 구체화됐다. 어떤 답을 현행에 넣을지 결정의 예는 얻었지만 중복 탐지나 Lint 후보 확정 절차 전체는 아니다.
- 여전히 미해결: 내가 고를 실행 환경, 최소 시작 폴더/작업 규칙, 자료 몇 개로 첫 LLM 실행을 완주하는 명령·예상 결과, 읽은 페이지 확인 출력, 누락/중복 처리 및 점검 주기. 심화가 이 질문을 모두 해결하는 실습은 아니라고 받아들였다.

## 유지·변경과 선호

- 유지: 기본 구간과 분리된 선택 심화, 29~30의 등록/작성/저장 구별, 34~35의 파일 교정 범위와 실제 문장 전후, 37~38의 의미 검토/파일 검사 구별.
