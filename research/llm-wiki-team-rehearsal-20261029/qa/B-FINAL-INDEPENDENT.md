# QA 실무 B 개별 최종 회상·반응

- 상태: 동료 반응·교차회의 전 독립 최종 초안 동결. 이전 구간 초안 불변.
- 본 자료: phase-1~5의 정확 말할 문장/전환과 PNG. 실제 순서는 1~9→10~18→19~28→40→선택 심화29~39다. 모든 PNG를 각각 `view_image`로 직접 열었다. 코드·논문·학습서·실습 파일·타인 반응·과거 보고·WORK_LOG·Git은 열지 않았다.
- 검토자 역할: 실무 활용을 알고 싶은 AI 스터디 참석자 관점. 실제 관객 대표, 음성 청취, 실시간 20분 체험, 완전 블라인드가 아니다. 기본 구간의 20분은 발표 계획이며 여기서 측정한 시간이 아니다. 기억 회상에는 구간별 메모와 40장 화면 단서의 영향이 있다.

## 현재 자기 말 설명

LLM Wiki는 LLM 에이전트가 원자료 사이의 개념·비교·잠정 종합을 Markdown 위키로 작성하고 갱신해 다음 질문에 다시 읽게 하는 관리 방식이다. 사람이 자료와 질문·범위 및 검토를 이끌고, 에이전트가 파일을 읽고 쓴다. 새 자료가 기존 설명 여러 곳을 바꾸고, 질문이 저장한 설명을 실제로 찾아 읽고, 유용한 답을 다시 연결한다. 점검은 의심 후보를 찾는 일이며 확정 오류나 자동 수정과 같지 않다.

저장 파일은 모델 가중치 학습이나 자동 영구 기억이 아니다. 검색 누락과 설명 오류는 남는다. 반복 질문의 재사용 가치와 반영·검토 부담을 같이 보고 작게 시도해야 한다. 공개 구현·연구·가상 사례·파일 교정 실습은 서로 다른 근거다. 심화에서 본 파일 검사 숫자만으로 정확도나 시간 절감이 확인되지는 않는다.

## 무엇이 가장 유용했나

- 고객 CSV 사례가 가장 강하게 남았다. 같은 형식이어도 월말 수동 전달과 매일 자동 수신을 합치지 않고, 고객 요구와 현재 개발 상태·출시 약속을 구별한다. 이것이 저장할 비교의 실무 가치를 보여 준다.
- 소설의 인물 설명 전후와 강의 비교 행은 ‘갱신’이 실제로 무엇을 뜻하는지 보여 준다. 새 정보가 늘 이전 오류를 고치는 것은 아니라는 점도 배웠다.
- 24장에서 직접 쓴 질문: “지난 AI 스터디의 발표 준비 메모와 새 피드백을 함께 보면, 다음 발표에서 유지할 설명과 바꿀 설명은 무엇인가?” 실제 자료를 읽은 결과가 아니라 역할 관점으로 만든 적용 질문이다.
- 25장의 요청은 가져가서 쓸 수 있다. 새 자료와 함께 기존 개념·비교·종합을 고치고, 근거·조건·충돌·미확인을 나누며 주요 변경 이유를 보여 달라고 한다. 26장의 작은 시도와 재읽기 검증이 다음 행동으로 이어진다.

## 주의 변화와 현재 남은 것

첫 정의와 폴더/규칙 설명에서 추상성이 잠깐 높아졌고, 연결 위키의 순환과 실제 전후에서 회복됐다. 고객 비교 질문은 내 판단을 요구해 관심이 높았다. 기본 구간 후반의 연속 복습에서는 새 행동을 기다리게 됐으며 질문 작성·요청 예문에서 다시 집중했다. 심화 연구 비교는 첫 실행 관심과 거리가 있었지만, 실제 문장 diff와 검토한 답의 현행 연결에서 유용함을 느꼈다. 이는 화면·대본 비교의 반응이며 실제 전달 속도 측정은 아니다.

기본 개념과 작은 시도의 판단 기준은 설명할 수 있다. 바로 구축할 자신까지 생긴 것은 아니다. 최소 실행 환경·폴더·작업 규칙 예문과 실제 LLM 실행 한 번, 읽은 페이지 확인 출력, 누락·중복·Lint 후보 처리 절차가 여전히 궁금하다. 공개 코드·논문·고정 파일 교정 심화는 이 시작 안내와 목적이 다르다고 이해한다.

## 유지할 점과 우선 변경

1. **우선 유지:** 원자료 보존/위키 갱신, 사람/에이전트/읽는 도구 구분, 파일과 학습 구별, 고객 요구/상태/약속 구분, 24~26장의 자기 질문과 작은 시작. 기본 구간의 중심 메시지가 일관된다.
2. **기본 구간 우선 변경:** 10장 화면에는 이미 3장 정보가, 16장에는 이미 새8주차가 보이는데 발화는 다음 단계로 예고한다. 화면과 말의 시점을 맞추면 갱신 전후가 더 선명해지겠다.
3. **심화 우선 변경:** 39장의 좁은 2·4번째 카드와 작은 글씨, 우측 제목 여백. 근거 종류를 동등하게 비교할 수 있게 크기와 폭을 정리했으면 한다.
4. **그다음 검토:** 26장에서 재사용 확인 기준 두 가지(근거를 다시 찾았나/수정 부담을 감당하나)를 화면에서도 더 잘 읽히게 하기. 최소 시작 템플릿은 기본 구간을 늘리기보다 후속 자료로 바로 연결하는 편을 선호한다.

기본 구간을 먼저 마치고 심화를 질문에 맞춰 선택하는 구성을 선호한다. 실무 적용 관점에서는 고객 사례와 요청 예문을 중심으로, 연구 조건 비교는 관심자가 선택해 읽고 실제 첫 실행은 별도 안내로 잇고 싶다. 이는 개인 역할의 선호이며 실제 다수 청중 선호로 일반화하지 않는다.
