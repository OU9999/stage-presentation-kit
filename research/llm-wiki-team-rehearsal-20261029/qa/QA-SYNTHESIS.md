# QA 발표 구간 모의 검토 취합

## 결론

A/B 모두 “개념·비교·잠정 종합을 파일로 갱신하고 다음 질문에서 실제로 다시 읽는다”는 원리를 자기 말로 회상했다. 고객 CSV 사례와 24~26장의 자기 질문·시작 요청·작은 검증이 이해와 시도 의향을 연결했다. 공통 우선 수정은 10·16장의 화면/발화 공개 순서와 선택 심화 39장의 가독성이다. 첫 실행 환경과 검토 출력은 발표에서 일부 미해결이지만, 연결된 학습서·실습 목적지는 미검증이다.

## 검토 범위와 한계

- 대상: 전달받은 target HEAD `bd6aae6`의 고정 발표 입력. QA가 Git으로 소스를 재확인하거나 제품을 수정하지는 않았다.
- A 관점: LLM 채팅 경험이 있는 가벼운 AI 스터디 학습자. B 관점: 실무 활용을 알고 싶은 AI 스터디 참석자. 둘 다 역할 기반 모델 검토자이며 실제 사람/초보자 집단/실제 관객 대표가 아니다.
- 각자 정확 대본·전환을 읽고 PNG를 1~9→10~18→19~28→40→선택 심화29~39 순으로 각 장 `view_image`로 직접 확인했다. 기본 구간 회상은 선택 심화 전에 동결했다. 구간별 초기 반응은 후반에서 해결돼도 소급 수정하지 않았다.
- 실제 음성 청취·녹음·실시간20분·실제20초/5초 대기·입력 수집·완전 블라인드 시험이 아니다. 20분은 발표 계획이며 여기서 시간 적합성을 측정하지 않았다. 구간 대본 선노출과 모델 문맥·메모, 40장 화면 자체의 회상 단서가 있었다.
- 코드·논문·학습서·링크 목적지·실습 원파일·전체 원문은 직접 검증하지 않았다. 구현/연구 사실은 발표가 전달한 범위에서 이해를 검토했다. 새 외부 근거나 실제 LLM 실행 성공을 확인한 보고가 아니다.

## 유지할 점

- 3~8장의 문제·관계 저장·실제 재읽기와 역할/규칙 구분. 파일 생성이 자동 기억이라는 오해 없이 핵심을 회상했다.
- 11장의 실제 문장 전후, 13~15장의 고객 요구/현재 상태/출시 약속 구분, 17~18장의 조건 추가와 종합. 특히 고객 사례가 두 검토자에게 가장 빨리 구체화됐다.
- 20~26장의 실제 읽음·유지 부담·자기 질문·시작 요청·작은 검증. 원리에서 다음 행동으로 이어졌다.
- 기본 구간과 선택 심화의 분리 및 29~39장의 근거 범위 구별. 파일 검사 숫자를 의미 정확도나 도입 성과로 넓히지 않았다.

## 24장 직접 작성 행동

- A: “다음 AI 스터디에서 같은 주제를 다시 질문할 때, 저장해 둔 비교 페이지가 실제 답변에 쓰였는지 어떻게 확인할까?”
- B: “지난 AI 스터디의 발표 준비 메모와 새 피드백을 함께 보면, 다음 발표에서 유지할 설명과 바꿀 설명은 무엇인가?”

각자 24장 PNG 후 25장 PNG 전에 역할 관점의 질문을 직접 적었다. 구간 대본은 먼저 읽었고 타이머·실제 개인 자료 확인·채팅 입력 수집은 없었다. 따라서 질문 작성 가능성의 제한된 관찰이며 20초 행동 성공률은 아니다.

## 우선순위와 구체 변경안 — A↔B 직접 회의 합의

| 구분 | 근거와 변경안 | 차단 판단·이유 |
| --- | --- | --- |
| 기본 구간 우선 | **10장:** 발화는1장 소개 후3장을 예고하지만 화면에는 추적 장치/보호 설명이 이미 보인다. 화면을1장 상태로 제한하고3장 정보는11장에서 공개한다. **16장:** 발화는2·7주차 뒤 다음 강의를 예고하지만 화면에8주차/Gini가 보인다.8주차는17장에서 공개한다. | 핵심 의미의 이해 자체를 막지는 않았지만 변화 전후 체험을 약하게 하므로 발표본 정리 전에 우선 맞춘다. 화면분리가 어렵다면 말할 문장과 전환을 이미 전체 전후를 보는 소개로 고치는 대안이 있다. |
| 선택 심화 우선 | **39장:** 두 검토자의 실제 PNG에서 제목 마지막 ‘다’가 보이지 않고2·4번째 카드가 좁으며 본문이 작게 읽힌다. 제목 온전 표시와 네 카드 폭·본문 크기를 확인한다. | 해당 심화 화면의 읽기 품질에 직접 영향. 기본 구간 전체를 막을 사유는 아니나 이 화면 배포 전 확인이 필요하다. PNG 시각 관찰이며 원본 레이아웃/스타일/렌더링 원인은 미확인이다. |
| 후속 경로 우선 확인 | **25~27장 이후:** 최소 파일·규칙·권한 확인과 첫 실행/읽음 확인의 안내로 연결되는지 확인한다. 본문을 크게 늘리기보다 초보 실습의 첫 단계로 잇는 편을 두 검토자가 선호한다. | 소개 원리 이해의 차단은 아니며 혼자 첫 실행을 재현할 수 있다고도 확인하지 않았다. **발표에서 미해결/목적지 미검증** 상태다. ‘자료에 안내 없음’이라는 결론이 아니다. |
| 후순위 | **26장:** 사진 캡션 근처에 “필요한 근거를 다시 찾았나? / 잘못된 정리를 고칠 부담을 감당하나?”가 읽히게 한다. | 대본에는 이미 있는 기준이라 내용 누락 차단은 아니다. 적용 후 판단 기준의 회상을 돕는 개선이다. |

QA 모의 검토만으로 전체 발표 중단을 권할 근거는 없었다. 이는 행사 진행 가능성·시간 적합성·실제 청중 이해도에 대한 승인이 아니다. 현재 확인된 화면/발화 문제를 먼저 정리하고, 실행 안내의 실제 목적지는 별도 확인하는 결론이다.

초반 추상 설명과19~23장 복습에서 주의가 낮아졌다가 사례/행동에서 회복됐다. 실제 낭독 시간·관객 반응이 없어 특정 장 삭제나20분 적합/부적합 판정으로 넓히지 않는다.

## 실제 남은 차이와 회의에서 바뀐 강조

- A는 강의 개념의 조건 비교에 적용하고 싶어 하며 첫 환경·잘못된 수정의 복구·실제 읽은 구간 확인을 더 궁금해했다.
- B는 회의/피드백의 요구·상태·판단 보존에 적용하고 싶어 하며 중복 저장·Lint 후보 처리에 더 관심을 보였다.
- B의26장 두 확인 질문을 A가 받아 후순위 합의안이 됐다. B는 A의 복구·실제 읽은 구간 질문을 받아 ENG 인계에 포함했다. 두 사람 모두 첫 실행 안내를 본문 증량보다 후속 경로로 잇는 쪽에 동의했다.
- 이 차이는 활용 선호와 관심의 차이다. 서로 충돌하는 수정 요구는 확인되지 않았고 억지 이견을 만들지 않았다. 실제 다수 청중의 선호로 일반화하지 않는다.

## ENG 인계 질문

아래는 후속 팀간 회의의 검증 질문이며 지금 제품 수정을 위임하는 지시가 아니다.

1. 10·16장의 PNG와 정확 발화 시점을 확인하고, 후속 정보를11·17장으로 늦추는 최소 수정이 가능한가? 화면 변경이 어렵다면 어떤 말할 문장·전환을 현재 화면에 맞춰야 하는가?
2. 39장 제목 마지막 글자와2·4카드의 작아진 폭/글씨는 어떤 원인인가? 제목 온전 표시·네 카드 가독성을 고친 렌더를 확인할 수 있는가? 현재 QA는 원인 코드를 확인하지 않았다.
3. 27·40장 후속 링크의 실제 목적지에 파일 권한 확인, 최소 폴더/규칙 예문, 첫 LLM 실행과 예상 파일 변경, 잘못된 수정의 복구 단계가 있는가? QA는 목적지를 열지 않았으므로 실제 범위를 확인해 달라.
4. 작은 재사용 시도에서 에이전트가 실제 읽은 페이지·구간·근거와 변경 이유를 확인할 구체 출력은 무엇인가? 발표가 보장하는 범위와 실습에서 확인할 범위를 나눌 수 있는가?
5. 중복 답·관련 페이지 누락·Lint 후보를 사람이 검토/확정하는 최소 행동은 무엇인가? 현행/검토 대기 정책은 예시라는 한계를 유지하면서26장 두 확인 질문과 연결할 수 있는가?
