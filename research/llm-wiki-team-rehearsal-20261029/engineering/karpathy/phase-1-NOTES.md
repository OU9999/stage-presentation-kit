# Phase 1 즉시 관찰 — 1~9장

공개 설계 검토자 역할의 화면 PNG·정확 대본 순차 모의 경험이다. 실제 Karpathy 참여/승인, 실제 음성 청취, 실시간 낭독 측정이 아니다. 1→9 PNG를 한 장씩 view_image로 직접 열고 해당 발언·전환과 대조했다. 미래 구간·원문·학습서는 아직 보지 않았다. 이 기록은 다음 구간 전에 동결한다.

- 1~3장: 문제는 자료의 소유나 단순 검색 실패가 아니라 여러 자료 사이에서 했던 비교·종합의 재수행으로 읽혔다. 2장의 긴 정의는 한 화면에 크고 읽히지만 개념·비교·연결이라는 추상어가 연속된다. 특정 완제품/표준이 아니라는 발언이 출처의 범위를 명확히 한다.
- 4장: 원자료→연결된 위키→다음 질문, 유용한 답의 역류를 한 화면에서 이해했다. '작업 규칙은 전체에 적용'은 다음 6장의 예고로 기능한다. 시각물과 '여러 자료…잠정 종합' 발언은 일치한다.
- 5~6장: 파일 에이전트가 문맥에 읽고 쓰며, 사람은 자료·질문·결과 확인을 맡는다. 읽기 도구가 지식 생성 주체로 섞이지 않았다. raw 보존/wiki 갱신/schema 적용의 구분은 분명하다. '규칙이 세 번째로 변환되어 나오는 결과물은 아닙니다'는 도식의 아래 선과 맞는다.
- 7~9장: Ingest는 여러 관련 페이지의 조건/비교/잠정 종합을 수정한다. Query는 저장 위키를 현재 문맥으로 읽고 답을 재저장할 수 있다. Lint는 의심 목록이며 참거짓 판정기가 아니다. 7장에 고정 순서가 없다고 명시한 점, 8장에 가중치 학습과 구별한 점이 기술적 오해를 줄인다.

현재 이해: 파일 기반 지속 상태를 읽기/쓰기 도구로 재사용하는 운영 방식이다. 자동 영구 기억이나 가중치 갱신으로 이해하지 않았다.
남은 질문: 관련 페이지를 어떻게 놓치지 않고 고르는가? 갱신된 종합에 대한 출처와 사람이 검토할 변경 단위는 무엇인가? schema는 누가 얼마나 구체화하는가? 이 질문은 아직 결함으로 확정하지 않는다.
주의 변화: 1~3장의 추상 정의 뒤 4장의 피드백 화살표로 집중이 높아졌다. 5~6장은 역할을 정리하는 구간, 7~8장은 실제 동작을 예측하게 하는 구간이었다. 9장의 세 카드 구조는 직전 두 흐름 그림보다 정보가 덜 연결되어 보여 사례가 필요해졌다.
