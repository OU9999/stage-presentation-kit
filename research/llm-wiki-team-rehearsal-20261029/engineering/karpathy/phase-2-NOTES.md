# Phase 2 즉시 관찰 — 10~18장

동결: 2026-10-29 08:02:26 UTC. 읽은 범위: phase-1~2(1~18장)만. 직접 PNG 실독: 이번 10,11,12,13,14,15,16,17,18을 한 장씩 순서대로 view_image. 원문·학습서·미래 구간·동료 결과 미열람. 실제 청취/효과 실험이 아니다.

- 10장: 발언은 1장 상황과 동기 미확인을 소개하지만 화면에는 3장 추적 장치, '동료를 피신시키려 했다', 갱신할 서하 페이지가 이미 나온다. 전환은 '3장을 읽으면…달라질까요?'라서 화면이 답을 먼저 준다. 화면의 '서하…설명한다'와 미확인 항목은 사실과 자기 설명 구분 자체를 보존한다.
- 11~12장: 전후 파일 구절이 모호한 동기를 발화 주체가 있는 설명으로 바꾸며, 확정 진실로 굳히지 않는다. 다음 질문을 질문 페이지로 저장하고 인물·주제에 연결한다는 Query 동작을 이해했다.
- 13~15장: 같은 CSV 형식과 다른 목적/주기/자동화 범위를 분리한다. 요구를 보존하며 회의 후 상태/FAQ를 갱신한다. '보류…출시일은 미확정'은 고객 요구를 로드맵 약속으로 승격하지 않는 명료한 예다. 13장 질문에는 '상위 개념은 같고 요구 조건은 구분'이라고 속으로 답했다. 5초 실제 대기나 응답 공유는 수행하지 않았다.
- 16장: 발언은 2주차와 7주차만 다루지만 화면 오른쪽에 새 8주차 분류트리/Gini가 있다. 10장과 같은 선공개가 반복된다. 17장의 표는 위키가 기존 오류를 발명해 정정하는 대신 비교 기준을 확장함을 이해시키며, '이 예의 기준'으로 일반화 범위를 제한한다.
- 18장: 자료 3개가 공유 개념·비교를 거쳐 종합 문장과 다음 질문으로 이어진다. 구체적인 저장 파일 경로가 지속 산출물이라는 느낌을 강화한다.

남은 질문: 사례는 구성 파일이므로 실제 에이전트가 필요한 관련 페이지를 찾아 갱신하는 성공률/방법은 여전히 입증하지 않는다. 출처 문단과 변경분을 한 번 실제 형태로 보면 mechanism과 작성 예를 더 쉽게 분리할 수 있겠다.
주의 변화: 소설의 인식 상태 보존은 흥미롭고 고객 사례는 업무적으로 즉시 이해된다. 세 사례가 모두 새 정보→연관 갱신→질문 저장 패턴이라 세 번째에는 반복을 인식했다. 10/16장 선공개 때문에 전후 변화의 놀라움과 주의 초점이 약해질 가능성을 기록한다(사람 반응 검증은 아니다).
