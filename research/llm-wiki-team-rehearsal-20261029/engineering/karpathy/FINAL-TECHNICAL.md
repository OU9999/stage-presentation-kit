## 저자 설계·우리 적용·입증 범위

저자 설계는 위 표의 원문 범위다. 우리 적용은 가상 소설/상담/강의, 근거 위치·범위의 기록, 검토 답의 현행 연결, ADR 응용이다. 이 선택들이 유일한 LLM Wiki 형식이라는 주장은 없다. 확인한 실물은 발표 PNG·정확 발언·현재 사례 파일 문장이다. 구성 예가 실제 LLM 실행의 성공, 인간 학습 향상, 검색 정확도/비용 개선을 입증하지 않는다. 공개 코드/논문 세부 사실은 이 검토에서 새로 독립 검증하지 않았으므로 구현 검토자와 실제 회의로 확인할 항목이다.

## 후속 자료/실습에서 해결할 질문

- 관련 페이지 누락은 어떻게 발견할까? →읽은 페이지 목록/변경 목록과 실제 질문의 필요한 근거를 대조하는 작은 예를 만든다. 효과는 별도 관찰한다.
- 새 원문과 잠정 종합이 충돌하면 어떤 기록을 남길까? →판·범위·근거 위치, 충돌 후보와 사람의 판단, 변경 이유를 실제 파일 한 쌍에 표시한다. 이는 검토자의 운영 제안이다.
- 첫 규칙 파일은 어디에 어떻게 둘까? →현재 자료의 시작 경로에 최소 예와 실제 파일 읽기/쓰기 조건을 연결한다. 모든 발표 청중에게 설치나 환경 실습을 요구하지 않는다.

독립 최종 동결 이후 상대 검토를 읽고 하는 회의는 별도 기록에 남긴다. 이 파일과 초기 인상은 수정하지 않는다.
