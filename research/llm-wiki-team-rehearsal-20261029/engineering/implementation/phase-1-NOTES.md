# Phase 1 즉시 기록 — 구현·근거 관점

1~9장 PNG를 view_image로 한 장씩 1→9 순서로 직접 열고 phase-1 정확 발언·전환과 대조했다. 실제 음성·시간 측정은 없다. 미래 구간과 자료는 열지 않았다.

- 1~2: 관계 재사용이라는 문제와 Markdown 지식관리 방식이라는 정의가 붙는다. 완제품이나 표준이 아니라는 발언이 구현 패키지를 기대하지 않게 한다. 큰 정의 문장에서는 '계속 갱신'의 실행 주체/시점이 아직 궁금하다.
- 3~4: 질문별 재종합을 저장된 개념·비교·잠정 종합으로 바꾸려는 목표가 명확하다. 4장의 답→위키 환류선은 유용한 답의 저장이 선택 가능하다는 대본과 맞는다. 어떤 답을 유용하다고 판단하고 잘못된 종합의 전파를 막는지는 남는다.
- 5: 파일 도구가 있는 에이전트가 현재 문맥으로 읽고 쓰며 사람은 범위·확인을 맡는다는 역할 구분이 중요하다. 파일=모델 기억 오해를 말로 차단한다. 화면의 읽는 도구/Obsidian은 실행 엔진이 아님을 이해했다.
- 6: raw 보존/wiki 갱신/schema 전체 적용 도식과 '세 번째 변환 결과물 아님' 발언이 일치한다. 구체 파일명·규칙 실행법은 아직 없다.
- 7: 고정 파이프라인이 아니라 필요한 기존 페이지를 고치는 흐름으로 보인다. 새 자료가 영향을 미치는 페이지를 어떻게 찾는지, 누락을 어떻게 알아내는지 질문이 생긴다.
- 8: index·검색→본문의 현재 문맥→답→선택적 저장으로 이해했다. 가중치 학습과 구별한다. 페이지 전체/부분 읽기·문맥 한계·원자료 회귀 조건은 남는다.
- 9: lint는 오래됨·조건 차이·빠진 연결을 찾는 의심 목록이며 확정 오류 자동 판정이 아니다. 세 카드가 발언과 일치한다. 링크 점검과 의미적 점검을 어떤 도구가 나누는지 아직 모른다.

현재 이해: 파일 접근 에이전트+보존 원자료+갱신 가능한 Markdown+사람의 방향 설정이라는 구현 최소요소. 자동화·검색 방식은 유연한 설계로 보인다.
주의 변화: 초반 추상 정의에서 4·6·8 흐름선으로 작동방식이 붙었고 7~9에서는 재사용 이득보다 갱신 누락/오류 누적의 운영 비용에 주의가 간다. 이는 관찰자 자신의 모의 반응이며 사람 학습효과가 아니다.
