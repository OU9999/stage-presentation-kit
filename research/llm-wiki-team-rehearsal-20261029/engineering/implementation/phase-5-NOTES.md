# Phase 5 즉시 기록 — 선택 심화

읽은 범위: core/40 독립 회상 동결 뒤 phase-5 발언·전환/PNG 29→39를 view_image로 한 장씩 직접 실독했다. 원문·후속자료는 아직 열지 않았고 아래 판정은 발표 이해다.

- 29~30: 구현은 ingestSource 등록과 llmIngest 내용 작성, handleQuery 키워드 상위8×앞3000자, handleSave 수동 안내를 분리한다. 실제 본문을 읽지 않고 index만 준다면 기존 본문 조건을 전부 검토하는 동작은 아니다. 구현의 한계를 정확히 코드에서 확인할 필요가 있다. 이 심화가 core의 일반 설계가 곧 공개 코드 완제품의 동작이라는 오해를 막는다.
- 31: 살아 있는 코드의 판/해시 추적은 변경 신호이며 의미 오류나 자동 수정이 아니다. 확장 구현의 대상이 원형 raw 보존과 다름을 이해했다.
- 32~33: 고정 section/대상 자료 제공 대 top5 검색이라는 선택 조건 차이를 별도로 드러낸다. 59문항·21벡터가 효과 크기라는 뜻은 아니며 단일 corpus/1회 답/한 judge 범위라는 제한이 맞물린다. 원논문 실제 방법을 대조해야 한다.
- 34~35: 학습용 오류를 고정 승인안으로 바꾸는 Node 파일 교정이다. '실제 diff'는 파일 수정의 실행이고 LLM 생성 성공이 아니다. RAG/LoRA의 학습 유무를 demo 파일 쓰기의 학습 유무로 넓히지 않는 교정 내용이 이해된다.
- 36~37: Q2의 재독 목록은 구성한 판단 입력이며 retrieval trace는 아니다. D1 대체/D2 신규는 ADR의 응용이고 필수 LLM Wiki 규칙이 아니다.
- 38: 8쪽/25링크/보존10파일은 서로 다른 검사 단위이며 정확도·검색·시간 절감 점수로 쓰지 않는다. 이 수치는 ZIP/로그/코드를 대조해 확인할 대상이다.
- 39: 설계/코드관찰/논문실험/가상 구성의 증거 종류를 분리한다. 그러나 화면에서 공개코드와 구성예 카드 폭이 다른 두 카드보다 작고 글씨도 매우 작다. 읽고 있는 PNG에서는 식별되지만 발표 중 한 번 훑을 때 두 카드가 부차적 범주처럼 보일 우려가 있다. 실제 투사/사람 가독성 실험은 아니다.
