# 미감을 되찾는 Markdown 발표 — 팀 회의와 결정

2026-10-28. 총괄은 통합·브라우저·전달을, 디자인 매니저와 두 실무자는 공통 CSS·서로 다른 두 원고를, 엔지니어링 매니저와 두 실무자는 파서/모델·렌더러/작성 안내를 맡았다. 동시 실행 한도 때문에 디자인 구현 후 엔지니어링 구현으로 인계했다. 공통 상태는 [WORK_LOG](../../WORK_LOG.md)를 참조한다.

사용자의 요청은 기존 큰 문장·사진 배치·다양한 그리드·컬러를 살리면서, 간단한 Markdown을 여러 발표에 재사용하는 실제 결과였다. 이전 두 감사의 보고만 반복하지 않고 제품과 두 예제를 구현했다.

| 안건 | 직접 협의한 결정 | 실제 결과 |
| --- | --- | --- |
| 기본 Markdown의 미감 | 내용의 형태로 안전한 기본 조판을 선택한다. 성과·인과·수치 계산은 추론하지 않는다. | message/split/media/gallery/quote/document 기본 분류. 두 원고16장 중11장은 배치 이름 미지정. |
| 복잡한 자료와 재사용 | 기존 heading/blocks AST를 참조한다. 본문을 다른 schema에 다시 쓰지 않는다. | stage-slide의 작은 장 설정과 stage-group의 H2 범위 설정. mosaic/editorial/closing 선택. |
| 사진과 색 | 사진 고유색·alt·title caption을 유지한다. 그룹 이름과 위치에도 의미를 남긴다. | 주역/보조 사진, 파랑 관찰·주황 행동, 초록 단서·보라 질문, 강조 밖 중립 단위. |
| 팔레트 원본 | 기존 styles.css의 tone-color를 재사용한다. | 새 CSS의 중복10HEX 제거, Paper 대응색과 blocks 전용 neutral. |
| 원고와 읽기 | DOM은 원고 순서, 발표의 공간 관계는 CSS가 담당한다. | 읽기에서 전체 문장·표·링크·원래 비율의 사진 복구. |
| 부적합한 선택 | 원문을 삭제하지 않고 document로 돌아가며 원고 위치를 알린다. | 발표와 읽기 직접 진입 모두 작성자 점검에 경고 표시. |

초기 실제 화면 검수에서 두 번째 회의를 열었다. 하나의 공통 초점으로 세로 인물을 가로 타일에 넣자 얼굴 전체가 사라졌고, 비어 있는 eyebrow의80px 예약이 자료 면적을 줄였다. 디자인 매니저가6개 PNG를 직접 보고 엔지니어링 매니저와 필수 교정을 합의했다.

기존 focus 문자열을 유지하면서 gallery/mosaic에는 사진 순서별 짧은 좌표 배열을 선택할 수 있게 했다. 배열은1~6개 안전 좌표만 받으며 개수·구도가 맞지 않으면 전체 사진을 contain으로 보존한 document와 경고를 제공한다. H2 그룹의 focus는 문자열을 유지했다. 디자인 매니저는 워크숍4장의 초점 한 부분만 수정했고, 종료된 파서/모델 영역은 렌더러 담당에게 명시적으로 이양해 단독 교정했다. 비quiet blocks의 빈 상단 예약도 회수했다.

마지막에 디자인 매니저는 최종16장·Paper2장·모자이크 변형2장, 총20개 PNG를 독립 검수했다. 공개 예제16장에 추가 필수 미감 결함은 없다고 판정했다. 모든 사진의 얼굴 자동 보존이나 작은 문서 메타까지의 세부 독해를 보장한 판정은 아니다.
