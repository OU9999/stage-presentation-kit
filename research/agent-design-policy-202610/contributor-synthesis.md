## 독립 산출과 공동 결론

실무 A는 [OpenAI·AGENTS 조사](agent-instructions.md), 실무 B는 [디자인 문맥 조사](design-context.md)를 먼저 실질 초안으로 작성했다. 이후 양측이 상대 문서 전문을 직접 읽고 경로·관찰·근거·제안·다음 작업을 일대일 메시지로 교환했다. 이 파일은 매니저의 [리서치 확정안](RESEARCH.md)을 위한 취합이며 제품 문서나 추가 운영 로그가 아니다.

현재 AGENTS 로그4항과 디자인3항은 모두 유지할 가치가 있다. 새 내용 출처의 paper 스타일 승계와 기술 검사 중심 완료라는 기존 실패에 대해, 남은 좁은 보완은 **현 발표 디자인 절의 첫 항목에 핵심 방향을 직접 요약하고 발표 위임·복구 때 기준과 현재 검수 상태를 연결하는 것**이다. 기존 WORK_LOG 절과 사용자 제공 로그4항을 파일 맨 앞의 원문 prefix 그대로 보존하며 절 전체를 재배치하지 않는다. 최초 DevDay 조사·현재26장 감사·DESIGN 정본·기존 CLI·원고/runtime/자산을 다시 만들지 않는다.

공식 문헌은 파일 자동 탐색, 짧고 구체적인 문맥, 결정·미해결 사항의 인계, 디자인 의도와 현재 자료의 연결을 뒷받침한다. 이 저장소의 Stage 기본값·예외·핵심 문구·검수 시나리오는 프로젝트 판단이다. 자동 주입이나 문구 존재만으로 실제 독해·준수·실수0을 보장하지 않는다.

## 엔지니어링에 넘길 최소 계약

기존 WORK_LOG 절과4항을 파일 맨 앞의 원문 prefix 그대로 유지하고 현 디자인3항의 의미도 보존한다. 절 전체를 재배치하지 않는다. 기존 선독 범위를 원고·자산·공통 스타일/runtime으로 명료화하고, 현 발표 디자인 절 첫 항목의 직접 핵심은 다음 의미를 짧게 담는다.

> 별도 디자인 변경 지시가 없으면 Stage의 검정 바탕·큰 타이포·넓은 여백·한 시각 중심을 유지한다. 장의 역할에 맞는 밀도·구도 변화와 실제 자료의 고유색·표면을 보존하며, 내용 참고자료의 색·레이아웃을 기본값 변경 권한으로 삼지 않는다.

조건부 위임·복구는 디자인 절에 둔다. 새 파일 양식이나 필드를 만들지 않고 기존 직접 메시지·WORK_LOG·관련 DESIGN·검수 기록을 사용한다.

- 위임: 최신 지시·목표, 변경/보존 범위, 적용할 디자인 핵심과 예외, 현재 검수 상태, 완료 조건, 미완료 담당과 다음 행동을 직접 전달한다.
- 복구: 압축·인수인계 후 **진행 중인 발표 작업을 재개할 때** WORK_LOG와 DESIGN 관련 절, 해당 범위의 현재 검수 상태를 확인한다. 매 작업마다 DESIGN 전체를 재독하게 하지 않는다.

현재 일반 check의21승인/5개선필요와 `--require-approved`의 예상 실패는 유효한 기존 상태다. 엔지니어링은 기존 CLI를 실제 실행해 이 구분이 유지되는지 확인할 수 있다. 통과를 만들기 위해 판정을 바꾸거나 기존 화면 hash만 교체하지 않는다.

## 완료와 인계 상태
