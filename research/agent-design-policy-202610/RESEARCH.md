**현재 7규칙의 핵심은 유지하고, AGENTS에 디자인 핵심 요약과 디자인 작업의 조건부 위임·복구만 더한다.** 기존 DESIGN이 없어서 실패한 것은 아니다. 최초 AGENTS에 디자인 연결이 없었던 공백과, 내용 출처의 paper 언어를 기본값으로 승계한 작업 판단, 기술 검사로 현재 판의 시각 인수를 대신한 완료 판단을 구별한다. 현재 추가된 세 디자인 규칙은 뒤의 두 판단을 교정하는 유효한 계약이다.

## 엔지니어링 최소 변경 계약

소유권은 root가 재개하는 기존 엔지니어링 매니저가 확정한다. 리서치팀은 제품 문서를 편집하지 않았다. 권고하는 필수 변경은 AGENTS의 작은 문구 보강이며, 필요한 운영 예시는 기존 DESIGN-REVIEW의 짧은 안내 또는 이번 검증 산출물에 둔다. DESIGN의 상세 토큰·역할표·원본 조사·예외 전문·검수 schema를 복제하지 않는다.

1. 파일 맨앞의 기존 `# 작업 로그 관리` 절과 네 항을 원문 prefix 그대로 유지한다. 현재 위치의 `# 발표 디자인 작업` 절에서 기존 선독 규칙 앞에 핵심 한 항을 직접 둔다. 파일 전체 절 순서는 바꾸지 않는다.

   > 최신 사용자 지시가 우선이다. 별도 디자인 변경 지시가 없으면 Stage의 검정 바탕·큰 타이포·넓은 여백·한 시각 중심을 유지한다. 장의 역할에 맞는 밀도·구도 변화와 실제 자료의 고유색·표면을 보존하고, 내용 참고자료의 색·레이아웃을 기본값 변경 권한으로 삼지 않는다.

2. 기존 선독 규칙의 적용 범위를 `발표 원고·자산·공통 스타일/runtime을 작성·수정하기 전에`로 구체화할 수 있다. 기존 선독·범위·보존·사용자 우선·입력 계약의 의미는 유지한다. 관련 없는 조사·로그·단순 운영 문구 수정에 제품 재캡처나 전체 문서 선독을 강제하지 않는다.
3. 다음 조건부 위임·복구를 디자인 절의 1~2항으로 추가한다. 가독성을 위해 두 항을 권고한다. 새 인계 파일·폼·필드가 아니라 기존 직접 메시지와 WORK_LOG를 사용한다.

   > 발표 디자인 작업을 위임할 때는 최신 지시·목표와 변경·보존 범위, 적용할 디자인 핵심·예외와 정본 경로, 현재 검수 범위·판정, 미완료 담당·다음 행동과 완료 조건을 직접 전달한다.

   > 진행 중인 발표 디자인 작업을 압축·인수인계 후 재개할 때는 DESIGN의 관련 기준과 현재 검수 상태도 확인한다.

4. 기존 현재 화면 규칙과 승인 보고 규칙을 그대로 유지한다. WORK_LOG 절의 파일 맨앞 위치·제목·네 항 원문·내부 순서를 보존한다. 모든 일상적 디자인 판단에 새 사용자 승인을 물으라는 지침을 추가하지 않는다. 사용자가 이미 요청·승인한 테마 변경이나 예외는 적용 범위와 영향 검수를 기록하며 진행한다.

직접 요약은 핵심을 놓친 실패에 대응하는 의도적 소규모 중복이다. 반례·토큰·이유 전체는 DESIGN 한곳에 남기며, 기준이 바뀌면 이 짧은 요약도 대조한다. 검정·색상 수·같은 양식 수만으로 합격시키는 규칙은 만들지 않는다. AGENTS를 연결하면 실수0이 된다는 보장은 없다.
