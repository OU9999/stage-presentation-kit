엔지니어링 매니저는 디자인팀의 ‘최소 경로를 좌표·색 수정만으로 축소하지 말 것’과 ‘5의 공통 prelude가 자료 주역을 앞지르면 보류할 것’이라는 두 반론을 각각 직접 수용했다. 디자인팀도 현재 rules의 존재, 무방향 관계와 native flow의 비동등성,15의 의미 그룹과 primary의 차이를 수용했다. 현재 중요한 기술·디자인 불일치는 없다.

### 중립색과 자료 표면에 대한 범위 교정

LLM 원고26장의 명시 `tone: neutral`은 엔진이 강제한 기본값이 아니다. 엔지니어링의 직접 코드·입력 대조에 따르면 native 강조/H2 대비에 실제 영향을 주며 생략한 blocks의 blue 기본값과 다르다. 그러므로 ‘사진·색 개수는 합격 기준이 아니다’를 ‘중립 선택은 영향이 없다’ 또는 ‘색 추가 금지’로 확대하지 않는다.

검정 Stage 안에서 대상·관계·조건·첫 행동과 대응하는 의미색, 읽을 자료의 표면·구절을 시안으로 비교할 수 있다. 외부 SVG의 녹색 관계점·주황 조건과 실제 원본 자료의 고유색은 native neutral과 구별한다. 다만26장의 neutral 일괄 제거, blue 자동 복원, 색 비율·빈도 할당, 전역 팔레트 교체에는 합의하지 않았다. 원래 없던 사진·성과·실제 UI를 꾸미지 않고, 설명용 재구성은 그 지위를 유지한다. 색만 바뀌고 주역·읽는 관계·자료의 구체성에 이해 차이가 없다면 채택 근거가 충분하지 않다.

### 다음 제작 순서와 구체 최소 보완안

1. **변경 brief:** 역할·주장·주역·정확한 구절/관계·필수 본문·보존 자료/원본·현재 판정/scope·모음 준거와 금지 이식·지원 경로/한계·실제 시각 검토자를 한 행 또는 짧은 묶음으로 인수한다. 교정 장수·시안 수·채택 수 하한을 두지 않는다.
2. **capability 선택:** 원고·자산으로 가능한 최소 경로를 먼저 선택한다. 지원이 있어도 좋은 구도가 자동 생성되는 것은 아니다. 자유 배치/무방향선/rich link/공통 postlude의 좁은 native 미지원을 본편 교정 전체의 선행 엔진 리메이크로 확대하지 않는다.
3. **실제 크기 대안 선택:** 현재안과 대표 시안을 직접 비교하며 ‘달라진 표면·스케일·거리 → 먼저 읽힌 대상 → 다음 근거와 관계 → 줄어든/남은 오독 → 채택·보류 이유’를 적는다. 보존안이 더 역할에 맞으면 바꾸지 않는다. 11 선택/13 사용 순서 보존과 다른 허용 반례는 그대로 인수한다.
4. **회귀 계약 독립 검토:** 시안의 역할·표현을 채택한 뒤 기존 baseline은 보존하고 새 원문/DOM/기하에 대한 계약을 독립 검토한다. exact fixture에 맞추기 위해 정당한 표현을 포기하거나, 통과시키기 위해 의미·관측을 삭제하지 않는다.
5. **현재 관측·기술과 수동 판정:** 변경 장·앞뒤 흐름·보드·영향 읽기/링크와 필요한 glyph·소속·표시 크기·contain/기하를 현재 입력으로 확인한다. 이후 직접 시각 판정과 명시 scope의 `--require-approved` 결과를 구별해 보고한다. 현재13구조/51계약/83회귀 통과를 새 시안 승인으로 승격하지 않는다.

정본/작업방법 보완도 작은 범위로 합의했다. 후속 문서 작업을 배정할 때 DESIGN의 현재 판 검수 절 한곳에 변경 brief와 대안 인수 문장 예시를 둔다. MARKDOWN-FIRST는 그 절의 참조와 현재 지원하는2H2/2H3·공통 prelude의 작은 입력 예시로 연결한다. DESIGN-REVIEW는 reason 예시에서 실제 본 주역·관계와 대안 선택 이유를 안내하되, 기계가 미감을 증명하는 것처럼 새 schema 필수 필드를 늘리지 않는다. 이미 있는 AGENTS·coordinate·manager 규칙을 다시 신설하기보다 위 인수물을 실제 packet에 넣는다. 이번에는 문서·제품을 실제 수정하지 않았다.

작성 진입점은 추가로 직접 대조했다. `templates/talk/slides.md`의 메시지/근거/행동3장과 `lib/scaffold.cjs`의 init/new 공통 템플릿, 생성 README의 간접 디자인 안내, 저장소 README의 정본/예제 안내, package의 문서 포함·예제/자산/연구 제외를 확인했다. 최소 스타터는 유효하며 기능 버그가 아니다. 간접 안내를 LLM26장 선택의 입증된 직접 원인으로 단정하지 않고 **재발예방의 진입 공백**으로 분류한다.

후속 최소안은 생성 README에서 역할 선택→자료 주역/보존→지원되는 최소 레시피→실제 크기 비교로 가는 정본 절을 직접 찾게 하는 것이다. brief/작은 native 예시는 설치 패키지에 실제 포함된 DESIGN/MARKDOWN-FIRST 안에서 읽고 시작할 수 있어야 하며, 패키지에 없는 research 예시 링크에만 의존하지 않는다. 새 CLI, 사진 자산 복사,3장 템플릿 확대의 의무는 추가하지 않는다. 엔지니어링 매니저가 이 분류와 패키지 내 접근 조건을 직접 수용·수신 확인했다.

### 실제 합의·소유권·남은 결정

양 매니저는 위 기술 경계, 실제 시안 인수 조건, 의미색의 선택 여지, 최소 문서/진입 보완, 후속 순서에 실제 회신으로 합의했고 중요 불일치가 없음을 서로 확인했다. 엔지니어링 매니저는 자기 인계만 편집하고 디자인 매니저는 이 교차회의 절만 편집한다. 원 실무 감사·통합·프로브 결과와 기존 승인 기록은 수정하지 않았다. root가 최종 통합·기계 검사·단일 WORK_LOG·브라우저 마감을 맡는다.

이번 완료 범위는 독립 감사 뒤의 직접 교차 검토와 실행/예방 명세 합의다. **본편 시안 제작·채택, 교정 구현, 변경 후 관측·회귀 계약 검토와 실제 시각 승인**은 아직 남아 있고 실제 담당/실행 범위는 root가 후속 배정한다. 프로젝터·다른OS·발표 거리·전체 읽기/모션·실제 청중 효과 등 기존 미확인 범위도 유지한다. 새로운 승인이나 정본 변경을 완료했다고 보고하지 않는다.
