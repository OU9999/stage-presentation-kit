## 결론과 원인 분리

현재 근거는 ‘Markdown이 모음의 좋은 표현을 만들 수 없다’거나 ‘자동 조판이 잘못 선택했다’는 설명을 지지하지 않는다. 이번 실제 비교9종은 모두 LLM Wiki와 같은 `parseDocument → layout:blocks → StageBlocks` 경로다. LLM Wiki26장은 모두 원고가 compose를 명시했고 현재 AST·planner·저장 브라우저 DOM composition이26/26 일치하며 경고0이다. 더 오래된 legacy 예제가 공통 app 아래 별도 layout을 쓰는 사실을 이번 비교의 원인으로 혼동하지 않는다.

핵심 원인은 역할별 자료를 읽게 만드는 authoring 선택과 시안/검수의 인수 방식이다. 도식을 넣은 장도 실제 자료의 주역·거리를 다시 선택해야 하며, 설명 문장의 문법·크기 통과만으로 관계가 드러나는 것은 아니다. 현재 재현된 native 지원 경계는 좁게 명시하되, 이를 현 덱 전체의 renderer 결함으로 확대하지 않는다.

색도 선택의 일부다. LLM Wiki는 26장 모두 `tone: neutral`을 명시했으며, 공통 blocks에서 생략할 때의 기본은 `app.js:395–396`의 blue다. `blocks.css:5,27`에서 neutral은 강조를 본문색으로 바꾸므로 native 강조·그룹명의 색 대비를 줄인다. 반면 현재 비교 bento·icon-wall·editorial-photo는 그룹/항목에 의미색을 명시하고 자료의 고유색도 보존한다. 따라서 사진/색의 개수만으로 원인을 설명하지 않는다는 말이 현재 중립 선택의 영향까지 없다는 뜻은 아니다. 검정 Stage 안에서 대상·의미에 맞는 색과 자료 표면을 시안으로 비교할 여지는 남기며, 색 비율·빈도 할당이나 전역 팔레트 교체를 권하지 않는다. 외부 SVG 안의 기존 녹색 관계점·주황 조건은 native neutral 선언으로 제거되지 않는다.

## 제작·위임·검수의 실행 packet

1. **작성자/위임 매니저: 역할과 보존 brief.** 현재 입력/PNG·명시 판정/scope, 바꿀 장과 구획, 한 장의 주장·주역·읽을 구절/관계, 필수 본문·원자료/자산 지위·링크, 보존 반례와 미확인 범위, 실제 다음 검토자를 직접 전달한다. 비교의 사진/색/수량을 과제로 바꾸지 않는다.
2. **엔지니어/작성자: capability 결정.** Markdown 블록/legacy/native/SVG 중 실제 입력 경로와 지원되는 필드·한계, 필요한 파일만 적는다. validator 성공과 렌더 출력, DOM 구조와 실제 배치를 구별한다. 5의 공통 소속, 10의 무방향선, 15의 두 판단 그룹을 구조 인수 조건으로 삼는다.
3. **작성자/지정 시각 검토자: 실제 크기 비교.** 기존안과 최소 시안에서 먼저 보인 대상→다음 근거→관계→남은 오독을 적어 채택/보류한다. 먼저 대표적인 관계/문서/메시지 문제를 비교하되 시안 개수/채택 수 하한은 두지 않는다. 13처럼 보존안이 목적에 맞으면 바꾸지 않는다.
4. **엔지니어/독립 검토자: 회귀 계약의 변경 검토.** 정당한 SVG→native 교체나 원고 소속 변경은 현재 exact 문구/자산 경로 fixture를 실패시킬 수 있다. 단순히 테스트를 최신값으로 맞추지 않는다. 동결 baseline의 이전 실패 재현을 보존하고, 필수 내용·관계·원본·glyph/contain/DOM 관측을 새 표현에 대응시킨 계약을 독립 검토한 뒤 갱신한다. 실패를 없애기 위한 내용 삭제·관측 누락·체커 완화는 인수하지 않는다.
5. **root/관측 담당: 현재 입력 관측.** 변경 장 개별·앞뒤 흐름·전체 보드·영향 읽기/링크와 Range 행·크기·소속/기준선·필요 SVG 기하를 갱신한다. 변경된 제품에 옛 캡처 해시를 덮어쓰지 않는다. viewport/stage/논리값을 분리하고 실제 회귀 명령은 현재 입력으로 실행한다.
