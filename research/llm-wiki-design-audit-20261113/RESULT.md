## 디자인 지침과 작업 방법의 최소 보완안

DESIGN에는 이미 역할·리듬·관계·자료 고유면·실제 화면 검수 원칙이 있다. 실행되지 않은 원칙과 실제 안내 공백을 나눠 보완한다. 아래는 양 매니저의 합의된 후속 명세이며 아직 정본에 적용하지 않았다.

| 위치·단계 | 구체 보완 |
| --- | --- |
| DESIGN 현재 판 검수 절 한곳 | 변경 장의 역할·주역·정확 구절/관계·원본/예시 지위·보존·모음 준거·지원 경로·다음 검토자를 한 행으로 인수하는 예시를 둔다. |
| 시안 선택 | 현안과 달라진 표면·스케일·거리, 먼저 읽힌 대상, 줄어든 오독, 채택/보류 이유를 실제 크기 화면과 함께 적는다. 실패 장수·시안수 하한은 두지 않는다. |
| MARKDOWN-FIRST 착수·지원 예시 | 위 한곳의 brief로 연결하고 H2/H3 의미 그룹·공통 prelude와 SVG 내부 고정 배치의 경계를 안내한다. native와 일반 Markdown 문법을 혼동하지 않는다. |
| DESIGN-REVIEW의 reason 예시 | 같은 시각 인수 문장을 예시로 안내한다. 새 미감 필드를 강제로 추가하거나 자동 승인 기능으로 확대하지 않는다. |
| init/new의 생성 README | 패키지에 포함되는 DESIGN/MARKDOWN-FIRST 안에서 완결되는 brief·최소 재사용 레시피를 직접 찾게 한다. 제외된 research/사진 경로에만 의존하지 않으며 새 CLI·스타터 확대가 선행조건은 아니다. |
| 위임·팀 운영 | 기존 AGENTS/coordinate/manager의 소유·직접 전달·독립 초안·반론·writer 종료 규칙을 실제 작업 packet으로 집행한다. 동일 규칙의 중복 문서를 늘리지 않는다. |

이번 감사 자체에서도 초안의13·11장을 필수 실패로 보던 판단을 직접 반론으로 회수했다. root의 초기 명세 분량 요청이 실패 장 할당량으로 읽힐 위험도 철회했다. 엔지니어링 프로브의 방향 edge와 공통 정의 소속도 실제 코드 반론으로 바로잡았다. 이 기록은 팀 구성만으로 좋은 판단을 보증할 수 없음을 보여준다.

후속 실행 순서는 **brief와 지원 경로 확인 → 역할에 맞는 대표 시안 → 실제 크기에서 채택 판단 → 필요한 회귀 계약의 독립 검토 → 현재 입력 관측·기술 검사 → 수동 판정과 명시 범위 require-approved**다. 실제 실행 담당은 root가 후속 작업에서 지정한다.
