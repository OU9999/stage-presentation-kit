# 시스템 4종의 열린 구도

`systems.js`는 `window.VisualSystems.render(visual)`에서 `{plot, hero, table}`를 반환한다. 공통 `VisualDesign` helper로 native DOM·SVG를 만들며 파일·네트워크·입력 변경이 없다. 제품 코드를 바꾸지 않은 이식용 시안이다.

| kind | 입력 | 구도·읽기 대안 |
| --- | --- | --- |
| flow | `items` 문자열/label 객체, 선택 `links` | 2개·5개 등 실제 단계 수에 맞춘 텍스트·화살표. 분기 입력에는 실제 연결 목록. 모바일에서는 native 세로 순서. |
| matrix | `items[{label,x,y}]`, `xLabel/yLabel`, 선택 focus | 열린 좌표면·직접 이름을 우선한다. 충돌/긴 라벨은 목록으로 보존하며 같은 좌표의 숫자는 겹친 항목 수를 나타낸다. 원래 점 위치를 지터로 바꾸지 않는다. 모바일에는 모든 이름·좌표를 native 목록으로 표시. |
| timeline | `items[{label,start,end}]`, 선택 unit | 임의 범위의 native 과업 레인. 원점·끝은 입력에서 계산하며 단일 시점은 점으로 표시. 시작/끝을 그대로 표에 남기고 주수나 성과를 추정하지 않는다. |
| heatmap | `rows/columns/values[][]`, 선택 unit | 가변 행·열의 의미 셀·숫자. 값별 배경 대비가 높은 글자색을 고르고 누락은 관측값 없음으로 보존. 작은 화면은 영역 스크롤과 동일 값의 표. |

시스템 4종은 의미가 모호한 합계·기간을 큰 숫자로 자동 추정하지 않아 `hero:null`을 반환한다. matrix의 복수 focus는 이름 강조만 한다. 좌표축은 자동 범위를 쓰며 필요한 경우 `xDomain/yDomain`을 선택할 수 있다. 외곽 패널·SVG 배경 사각형·상시 노드 카드는 없고 PDF·인쇄 조건을 사용하지 않는다.

표 모델은 모든 원본 행·연결·셀을 보존한다. 유한 숫자·참조·자료형 진단은 후속 제품 모델의 책임이며 이 시안의 레이아웃을 이유로 정상 수량을 반려하지 않는다. 실제 8종 데스크톱/390px 검수는 매니저가 수행하고, 제품 편집·내보내기·정확한 입력 진단은 엔지니어링에 인계한다.
