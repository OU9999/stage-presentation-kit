# 세 매니저 직접 토론 결과

2026-10-24 · 디자인 매니저 `/root/design_manager`

- **디자인 → 엔지니어링:** image/contain에 SVG 파일을 넣는 계약은 border를 없애도 제목·핵심 값·plot을 분리한다. inline/native visual을 같은 grid로 조립하고 wide/split·focus 자동 값과 간단한 배열 입력을 요구했다.
- **엔지니어링의 응답:** `layout: visual`의 직접 데이터 계약과 native 제목 편집, 숫자·라벨 수정 시 그림/읽기 표 동시 갱신에 동의했다. 복수 focus의 합계 의미는 모호하므로 line은 단일 값, 좌표면의 복수 focus는 라벨 강조만 하자는 반론을 디자인이 수용했다.
- **라벨 충돌:** 같은 좌표·긴 이름을 입력 반려 사유로 삼지 않는다. 직접 라벨을 먼저 쓰고 필요하면 리더선/외곽 목록으로 연결하며 읽기 영역은 모든 값을 보존한다.
- **디자인 ↔ 리서치:** 무대에는 현재 결론의 단위·기간·분모 종류를 남기고 반복된 자세한 설명은 표/노트로 내린다. 가상 여부는 공통 footer에서 일관 표시한다. 0–100 축은 현재 비율 그래프의 설계 선택이며 모든 데이터에 강제하지 않는다.
- **8종 방향:** 선·퍼널·비교 막대·구성비·흐름·좌표면·일정·히트맵을 같은 카드에 넣지 않고 각 역할에 맞는 wide/split 구도로 조립한다. 데이터 도형과 장식 패널을 구분한다.
- **범위:** 웹 발표 완성도와 쉽게 복사해 다른 수량/주제로 바꾸는 흐름을 기준으로 한다. PDF·인쇄 제약은 사용하지 않는다. 초기 단계는 세 매니저가 직접 작성했고 실무자를 생성하지 않았다.

실제 계약은 [엔지니어링 제안](../engineering/contract-proposal.md), 최소 문맥·재사용 사례는 [리서치 토론](../research/discussion.md)과 [사례](../research/reuse-cases.md)를 따른다. 디자인의 [세 대표 프로토타입과 사양](brief.md)을 제품의 8종 구현으로 확장할 때 소유권을 다시 배정한다. 운영 상태와 결정의 단일 기록은 루트 `WORK_LOG.md`다.
