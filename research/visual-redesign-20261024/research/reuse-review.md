## 작성 안내의 정확성

`examples/visual-starter/README.md`의 **폴더 전체 복사 → content.js 수정 → index.html 열기/새로고침** 흐름은 실제로 성립했다. `labels`와 값 배열을 같은 순서·개수로 맞추고, 직접 값과 분자/분모 중 한 방식을 고르며, `focus`가 큰 강조값을 계산한다는 설명도 검수 입력과 일치한다. raw `examples/visual-starter.js` 하나만으로 실행 파일 전체가 제공되는 것은 아니며, portable 폴더에 HTML과 runtime이 함께 들어 있다는 구분이 필요하다. 현재 안내는 이를 구분한다.

발표 안의 표는 현재 편집 상태이고 별도 `data.html`은 디스크 `content.js`를 읽는다는 안내도 정확하다. 본 검수는 **파일을 수정한 뒤 새 문서로 열기**만 수행했다. 화면 편집·저장·내보내기·모바일은 총괄의 검수 영역으로 중복 실행하지 않았다.

## 발견 사항과 한계

1. 실제 예제 2장 `observed-change`는 처음에는 35/55%의 기간과 가입자 분모만 적고 **가입 후 7일 내 첫 프로젝트 공유율**이라는 측정명을 해당 장에서 빠뜨렸다. 데이터 담당자와 같은 문제를 확인해 매니저에게 직접 보고했다. 총괄이 subtitle을 `가입 후 7일 내 첫 공유율 · 기준 W1–W4 / 후반 W9–W12`로 교정한 것을 현재 파일에서 직접 확인해 해결 상태로 기록한다. 숫자 계산은 바뀌지 않았다.
2. 다른 주제로 바꾼 portable의 별도 표는 본문 h1·표 제목·값을 새 원고에서 읽었지만 브라우저 탭의 `document.title`만 원래 스타터 제목을 유지했다. 표와 실행에는 영향이 없다. 총괄이 생성 템플릿에서 탭제목도 같은 원고로 동기화했고, 매니저와 본 실무자가 `scripts/direct-deck.cjs`·최종 portable `data.html`의 해당 구문을 정적으로 확인했다. 기존 `/tmp` 복사본은 교정 전이며 이 후속 폴리시의 브라우저 재검증은 수행하지 않았다.

짧은 native 메시지·단위·기간·분모는 무대에 남기고 전체 행·방법론은 표/노트에서 읽게 하는 구분이 적절하다. 표의 구조와 수치는 확인했지만 스크린리더 전체 검수·물리 발표 거리의 가독성·모든 브라우저 준수까지 입증한 결과는 아니다. 최종 두 발견의 교정 상태와 데이터 실무의 결론은 취합 문서에 연결한다.
