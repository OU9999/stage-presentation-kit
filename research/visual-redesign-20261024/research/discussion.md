# 세 팀 직접 토론의 리서치 합의

2026-10-24 · 초기 토론에서 확정한 핵심만 기록한다. 목표·담당자·현재 작업 상태의 단일 기록은 루트 `WORK_LOG.md`다.

- **무대 통합:** 외곽 테두리만 제거하는 데서 끝내지 않고 큰 메시지·강조 수치·plot을 같은 캔버스에서 배치한다. 여덟 장 연속으로 이미지 문서를 삽입하는 리듬도 바꾼다. 디자인 매니저와 직접 합의했다.
- **문맥의 위계:** 단위·비교 기간·분모 성격·기획 여부는 결론을 읽을 자리에 짧게 남긴다. 가상 안내는 이 예제의 공통 footer·표지로 일관되게 표현한다. 모든 원본 값·W13·표본 선정·계산·반올림 설명은 표·노트로 옮긴다. 다른 사용자의 실제 자료에 허구 메타를 강제하지 않는다.
- **작은 작성 계약:** 엔지니어링이 제안한 `layout: visual`과 작은 도표별 선언을 사용한다. 한 도표의 라벨·값 또는 순서만으로 장을 만들고 필요한 장을 복사·삭제한다. 7점 추세·5범주·2/5단계 흐름을 관련 없는 프로젝트 데이터 없이 만들 수 있어야 한다.
- **값과 계산:** 이미 계산한 `values`와 선택형 분자/분모 입력을 구분한다. 직접 값의 `%` 단위만 보고 발생률 범위를 추정하지 않는다. 계산 불가·누락은 0으로 대체하지 않는다. 배열 길이·유한 값·명시한 연결 참조·의미상 잘못된 구성비 등 필요한 진단을 유지한다.
- **형태별 의미:** 선·막대·매트릭스의 음수는 실제 의미가 있으면 허용하고 구성비의 음수와 구분한다. 선형 흐름은 문자 순서 배열로 충분하며, 명시적 분기 연결을 쓸 때만 참조를 검사한다. 여러 항목을 선택한 매트릭스 점수를 임의 합산해 성과 수치로 만들지 않는다.
- **웹으로 검증:** 새 단독 스타터를 `file://`로 열어 다른 주제·수량·390px·상세 표·편집/내보내기를 검증한다. PDF 작업·페이지 수·인쇄를 이번 완료 조건으로 두지 않는다. 새 레이아웃의 실제 필드와 실행 검증은 후속 구현에서 확정한다.

직접 토론 상대는 `/root/design_manager`, `/root/engineering_manager`다. 근거는 [감사](audit.md), 구체 입력은 [재사용 사례](reuse-cases.md)에 있다. 제품 코드는 이 초기 토론에서 수정하지 않았다.
