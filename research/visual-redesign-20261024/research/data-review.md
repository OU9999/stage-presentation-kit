# 직접 원본의 숫자·의미 검수

2026-10-24 · `/root/research_manager/data_analyst`

제품의 `content.js`·`deck-model.js`·`visual.js`를 읽고, 원본 정수의 독립 계산과 실제 `StageVisual` 렌더러의 반환값·표를 경량 DOM에서 확인했다. [계산 근거](data-checks.json)의 **13개 검사 그룹이 통과**했다. 제품·WORK_LOG·새 테스트 파일을 수정하지 않았고 브라우저·PDF 검증을 실행하지 않았다.

## 발표 예제

현재 직접 원본은 [content.js](../../../examples/visual-story/content.js)의 12장이다. `visual` 9장이 `line/bars/composition/funnel/flow/matrix/timeline/heatmap` 8종을 사용하며 같은 렌더러가 표 9개를 만든다. 이전 연구의 JSON·SVG 생성물이 현재 작성 원본인 것으로 해석하지 않았다.

| 확인 대상 | 독립 계산과 현재 표시 |
| --- | --- |
| 기준·후반 | 주별 정수를 합산하면 420/1,200=35%, 660/1,200=55%. `activation`에서 이 값을 만들고 2장 hero는 후반 55%, 표는 35·55를 반환한다. 차이는 +20%p이며 상대 변화 +57.1%와 구분한다. |
| 12주 추세 | W1 90/300=30%, W12 174/300=58%. 마지막 hero와 표의 표시가 58이며, 표에 같은 행의 분자 174·분모 300도 남는다. |
| 퍼널 | 기준 1,200→840→600→420, 후반 1,200→960→780→660. 양쪽 시작·끝 인원은 같은 주별 원본에서 도출한다. |
| 인접 단계 | 기준 70.0·71.4·70.0%, 후반 80.0·81.3·84.6%. 최대 관찰 차이는 마지막 구간의 +14.6%p다. 현재 hero **84.6%는 후반 전환율의 수준**이며 +14.6%p 차이를 표시하는 기능은 아니다. focus가 이 구간을 고르는 계산과 표 값이 일치한다. |
| 인터뷰 | 18+12+10+8=48명. 표 구성비 37.5·25.0·20.8·16.7%, 합 100.0%. hero는 원값 18명과 해당 비중을 구분한다. |
| 투입 계획 | 3×3 행렬의 합이 18인·주. 이는 가상 역할·기간 계획이며 신규 가입자·인터뷰·실제 성과의 분모와 합치지 않는다. |

숫자 계산은 부동소수점의 극소 오차를 1e−9 허용치로 비교하고 사용자에게 보이는 소수 첫째 자리 표시는 별도로 확인했다. 예를 들어 JS 내부 57.99999999999999가 58로 표시되는 것은 수치 계약 위반이 아니다.

가상 프로젝트·7일 이내 첫 프로젝트 공유·W13 종료 추적·서로 다른 기간 관찰이라는 문맥을 확인했다. 실제 회사 성과나 변경의 인과 효과를 입증한 것으로 표현하지 않는다. 기획 점수·여정·일정은 관찰 통계와 구분된다.

## 다른 수량과 누락 값

- [portable 원본](../../../examples/visual-starter/content.js)과 [복사 가능한 raw 스타터](../../../examples/visual-starter.js)는 동일하다. 7점의 다른 분모를 가진 비율 자료에서 마지막 136/170=80%, 표 원값 136·170을 확인했다.
- 5분류 `[8,12,10,6,4]`는 합계 40건이며 비중은 20·30·25·15·10%다. 가장 큰 12건은 30%다. 4분류 고정 조건은 없다.
- 2단계와 5단계 문자열 흐름을 각각 검증·렌더링해 같은 수의 표 행을 확인했다. 특정 프로젝트 ID나 단계 수를 요구하지 않는다.
- line의 `null`은 선을 끊고 표에 `—`를 표시한다. 누락 지점에 0을 찍지 않으며 그 지점을 focus로 삼아도 숫자 hero를 만들지 않는다. heatmap의 원값 0과 `null`도 표에서 `0`·`관측값 없음`으로 구분한다.
- 분모 0은 `validateVisual()`의 해당 분모 경로 오류가 되고, `StageVisual.render()`가 그 진단으로 멈춘다. 비율 0으로 대체하지 않는다. 구성비 합계 0도 `계산 불가`로 표현하며 0%라는 거짓 비중을 만들지 않는다.

동료 `/root/research_manager/story_researcher`의 별도 지원업무 재사용 결과와 직접 대조했다. `/tmp/stage-reuse-story-20261024-R7xH3G/support-reuse/content.js`를 별도로 읽어 마지막 64/80=80%, 5분류 `[6,8,12,10,4]`의 합 40·비중 15/20/30/25/10%, 5단계 흐름을 독립 확인했다. 원래 스타터와 다른 입력이며 같은 의미·계산 계약을 만족한다. 해당 실제 브라우저 `file://` 복사·배열 변경 검증은 동료 보고에 귀속한다.

## 발견한 의미 문맥과 교정

초기 검수에서 2장의 35·55%는 계산이 맞았지만, 해당 장의 제목·subtitle·표 계열명·노트에 분자 행동인 ‘가입 후 7일 내 첫 프로젝트 공유’가 없었다. 4장의 정의를 읽지 않으면 2장만으로 무슨 비율인지 알기 어려웠다. 데이터·스토리 담당이 서로 확인해 매니저에게 직접 보고했고, 매니저가 총괄의 최소 문구 교정을 요청했다. 총괄의 교정 뒤 원본을 다시 읽어 subtitle이 **‘가입 후 7일 내 첫 공유율 · 기준 W1–W4 / 후반 W9–W12’**이고 값은 35·55로 그대로임을 직접 확인했다. 전체 숫자 검사를 불필요하게 반복하지 않고 바뀐 문맥과 해당 값만 확인했다.

## 검수 범위

이번 검수는 데이터 계산·같은 입력에서 만드는 hero/표·누락 진단의 코드 경로에 한정한다. 실제 브라우저 배치·모바일 가독성·애니메이션·편집 저장·다운로드는 다시 검증하지 않았다. matrix의 리더 라벨 배치는 총괄의 최종 시각 교정이며 본 수치 검수의 변경 대상이 아니다. 최종 코드 식별값은 계산 근거의 SHA 기록 시점에 해당한다.
