# 웹 발표의 사용성·서사 감사

2026-10-24 · 리서치 매니저 `/root/research_manager` 직접 작성

아래 초기 감사의 코드 경로·350줄 입력·고정 제한은 로컬 기준 커밋 `ab96f16`의 개선 전 상태다. 일부 전용 생성기·원본 JSON은 후속 구현에서 정리됐으며 현재 사용 경로를 뜻하지 않는다.

현재 도표는 정확한 숫자와 상세 표를 제공하지만, **발표 무대보다 도표 문서를 넣은 액자처럼 보이고 다른 주제로 옮기기 어렵다.** 이번 완료 기준은 웹에서 보이는 결과와 간단한 작성 흐름이다. PDF 출력·페이지 수·인쇄를 기준으로 삼지 않는다.

## 실제 재사용 시도의 결과

현재 제품 입력의 복사본으로 기존 `validateData`를 호출했다. 파일은 바꾸지 않았다. 이는 검사기의 개수 제한을 확인하는 최소 변경이며, 기존 프로젝트 전체를 새 이야기로 완성한 덱이 아니다. 특히 단독 선형 흐름을 위해 원래 프로젝트의 기능 제안 참조까지 유지해야 한다는 전제를 제거하려는 시도다. 새 범용 입력의 실제 성공 검증은 후속 구현에서 수행한다.

| 시도 | 결과 | 해석 |
| --- | --- | --- |
| 기존 입력 | 진단 0 | 기준 예제는 정상이다. |
| 주차를 7개로 변경 | `weeklyCohorts`의 정확히 12개 제한 1건 | 7점 추세 자체의 계산 문제가 아니다. |
| 인터뷰 분류를 5개로 늘리고 표본 합계도 맞춤 | 정확히 4개 제한 1건 | 양의 정수·합계가 맞아도 수량 때문에 거절한다. |
| 여정 순서를 2단계로 변경 | nodes/path의 정확히 4개 제한 2건 | 두 단계 흐름에 네 단계가 필요한 이유는 없다. |
| 여정 순서를 5단계로 변경 | 개수 제한과 `undefined` 고정값 진단 4건 | 도메인 ID·고정 순서가 범용 흐름을 막고 오류도 사용자가 이해하기 어렵다. |

구체적인 다른 주제와 짧은 설정은 [재사용 사례](reuse-cases.md)에 있다. 이 시도는 숫자 정확성 제한을 없애자는 뜻이 아니다. 유한 숫자·선언된 배열의 길이 대응·계산 분모·명시한 참조·구성비의 음수 등 **해당 시각자료의 의미에 필요한 진단**은 유지한다. 누락이나 계산 불가를 0으로 채우지 않는다.

## 작성 편의의 수용 기준

1. 빌드 없이 `content.js`의 한 슬라이드 설정을 붙여 넣어 도표를 만든다. 패키지 설치·외부 CDN·SVG 문법 편집이 선행 조건이 아니다.
2. 수치·라벨은 한 블록에서 한 번만 바꾼다. 제목 문장에 숫자를 손으로 중복 적도록 강요하지 않는다. 계산형 강조를 고르면 값·도형·상세 표가 같은 데이터에서 나온다.
3. 7점 추세·5범주·2/5단계 흐름을 다른 도메인의 메타·ID 없이 만든다. 장 하나 추가는 설정 블록 하나 추가, 삭제는 해당 배열 항목 하나 삭제로 끝난다.
4. 원시 측정값 `values`와 비율을 계산하는 분자/분모 입력을 구분한다. 단위 문자열 `%`만으로 0–100 범위나 분자≤분모를 추정하지 않는다. 의미상 음수가 가능한 선·막대와 구성비를 같은 규칙으로 묶지 않는다.
5. 필요한 값이 없으면 해당 자료에 진단·누락 상태를 보여주고 다른 정상 장은 계속 볼 수 있다. 상세 표도 0으로 잘못 대체된 값을 표시하지 않는다.

실제 390px·키보드·편집/내보내기·다른 주제 설정의 동작은 후속 구현에서 검증한다. 이 초기 감사는 제품 코드나 공통 런타임을 수정한 결과가 아니다.
