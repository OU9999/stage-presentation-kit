# 한 파일로 쓰는 visual 입력 제안

2026-10-24 · `/root/engineering_manager` · 제품 구현 전 계약 제안

## 작성 흐름

발표 폴더를 복사하고 content.js의 장과 자료를 바꾼 뒤 index.html을 연다. 설치·빌드·SVG 생성·수정 원고/생성 원고 구분은 이 흐름의 필수가 아니다. 기존 제목 편집·저장·내용 내보내기·발표자·읽기 흐름에 새 visual 자료를 연결한다.

```js
window.PRESENTATION = {
  title: "지원 경험을 개선하는 작은 실험",
  slides: [
    {
      layout: "visual", title: "7번의 관찰, 다음 질문.",
      visual: {
        kind: "line", labels: ["1주", "2주", "3주", "4주", "5주", "6주", "7주"],
        values: [65, 65, 70, 70, 74, 75, 80], unit: "%", focus: 6,
        emphasis: "focus", composition: "wide"
      }
    }
  ]
};
```

위 데이터의 마지막 값 80%는 focus에서 자동으로 꺼낸다. 별도 heroValue:80 같은 숫자 사본을 쓰지 않는다. 여러 장에서 같은 자료가 필요하면 content.js의 상수·배열을 함께 참조할 수 있다. 렌더러는 원본 객체를 변경하지 않는다. 예제의 가상 표시는 예제 설명이며 모든 발표의 필수 meta가 아니다.

## 최소 자료형

| kind | 사용자에게 보이는 최소 입력 | 수량·배치 |
| --- | --- | --- |
| line | labels + values, 또는 labels + series | 7개·12개 등 실제 길이를 사용. null은 없는 관측값으로 표시하고 0으로 메우지 않음. |
| bars | labels + values, 또는 labels + series | 5범주·복수 계열. 긴 라벨은 가로 막대/줄바꿈/읽기 표로 배치. |
| composition | labels + values | 비음수 원값으로 비중을 계산. 별도 percentages 사본 불필요. 합계 0은 ‘구성비 계산 불가’. |
| funnel | labels + series[{label, values}] | 단계 수는 배열에서 결정. 계열별 동일 단계 대응과 실제 수치 유지. |
| flow | items:[문자열 또는 label 객체] | 2·5단계 순서를 바로 연결. 분기일 때만 선택형 id/links. |
| matrix | items:[{label,x,y}], xLabel, yLabel | 같은 좌표도 허용. 점의 원래 위치와 번호/외곽 목록·리더선을 구분. |
| timeline | items:[{label,start,end}], unit | 고정 12주가 없는 상대 범위. 종료가 시작보다 앞선 경우만 진단. |
| heatmap | rows + columns + values[][] | 2×2·3×5 등 입력 크기. 숫자와 읽기 표를 함께 제공. |

이 표는 kind별 역할이며 현재 제품의 enum 확정이나 모든 renderer의 구현 완료를 뜻하지 않는다. 최종 API는 우선 사용 사례를 만족하도록 작게 확정한다. labels/values는 짧은 단일 계열의 편의 입력이고 내부에서는 같은 series 표현으로 정규화할 수 있다. 둘을 동시에 주면 어떤 데이터를 쓸지 조용히 추정하지 않고 해당 장에 안내한다.

## 다른 주제의 짧은 사례

5범주 지원 문의는 기존 인터뷰·코호트·기획 데이터 없이 다음 자료만 쓴다.

```js
{
  layout: "visual", title: "지원 문의는 어디에 모일까?",
  visual: { kind: "composition", labels: ["계정", "결제", "사용법", "오류", "기타"],
    values: [8, 12, 10, 6, 4], unit: "건", focus: 1 }
}
```

단순 승인과 제작 흐름은 IDs나 다른 도메인 자료를 요구하지 않는다.

```js
{ layout: "visual", title: "작은 승인 흐름",
  visual: { kind: "flow", items: ["요청", "승인"] } }

{ layout: "visual", title: "제작에서 공개까지",
  visual: { kind: "flow", items: ["기획", "초안", "검토", "수정", "공개"] } }
```

직접 관측값 대신 비율을 계산할 때만 분자·분모를 받는다. 같은 사례의 7점 완료율을 다음처럼 만들 수 있다.

```js
visual: {
  kind: "line", labels: ["1주", "2주", "3주", "4주", "5주", "6주", "7주"],
  numerators: [78, 91, 91, 112, 111, 135, 136],
  denominators: [120, 140, 130, 160, 150, 180, 170], unit: "%", focus: 6
}
```

두 방식은 별개다. unit이 %라는 이유만으로 모든 값에 0–100 범위를 강제하지 않는다. 증가율은 100%를 넘을 수 있다. 분자≤분모 같은 조건도 선택한 의미가 실제 전체 중 비중인 경우에만 설정한다. 전체 비율이 필요하면 원본 합계 754/1,050으로 계산하며 반올림된 일곱 비율을 평균하지 않는다.

## 화면·편집 계약

- layout:visual은 image/media-frame을 통하지 않는다. 제목·자동 핵심값·plot·범례가 같은 그리드를 쓰고 불투명 배경 사각형을 기본으로 만들지 않는다.
- composition:wide/split은 자료 배치만 정한다. emphasis:focus는 단일 focus에서 값을 도출한다. matrix의 복수 focus는 라벨 강조이며 합계를 추정하지 않는다.
- 발표는 넓은 영역을 사용하고 읽기 화면에서는 native 메시지·퍼널 행·표를 재배치한다. SVG 전체를 줄인 것만으로 모바일 읽기를 통과했다고 하지 않는다.
- 제목·설명은 기존 native 편집 대상이다. 배열·단위·focus의 기본 수정 위치는 content.js다. 거대한 수치도 데이터에서 계산되므로 별도 장식 텍스트를 고치지 않는다. 전체 visual 입력은 저장·내보내기·발표자 복제에 보존한다.
- 표·요약은 현재 visual 입력에서 자동으로 만든다. 기존 data.html URL을 유지한다면 같은 content.js와 같은 표 함수를 읽는 작은 페이지로 바꿀 수 있다. JSON fetch나 표 전용 생성기·사본 데이터는 필요 없다.

## 남길 진단과 없앨 제약

필요한 진단은 유한 숫자·계열과 라벨 대응·명시한 링크 참조·비율 분모·선택한 표현의 의미다. 누락을 0으로 채우지 않으며 분모 0은 계산 불가로 표시한다. 음수는 line/bar/matrix에서 정상 자료이고 composition의 음수는 의미 오류다. 오류는 해당 장/항목의 경로와 수정 방법을 알려 다른 장과 원본을 보존한다.

정확한 12/4/3개, 7일 창, fictional=true, 좌표가 같다는 이유의 반려, 모든 차트에 필요한 전체 도메인 구조, 임의 글자 수 상한과 자체 XML 부분집합 파서는 새 경로에서 제거한다. 공간이 부족한 긴 자료는 배치·읽기 화면·표로 풀고 값 자체를 반려하지 않는다.

## 구현·정리 순서

1. 공통 visual renderer와 모델의 작은 계약을 만든다. 필요하면 visual-renderer.js 하나를 키트에 포함하고 기존 app.js가 직접 호출한다. DOM SVG 요소와 textContent를 사용해 XML 파일의 재파싱을 없앤다.
2. 먼저 7점 추세·5범주·2/5단계와 디자인의 wide line/split funnel/matrix를 실제로 연다. 다른 주제를 쓰기 위해 기존 예제의 전체 JSON을 복사하거나 Node 명령을 실행해서는 안 된다.
3. 현재 예제를 content.js의 직접 visual 장으로 옮긴다. 기존 생성기를 필수 안내에서 제거하고 그 도구·고정 스키마·파서를 삭제 또는 비활성 이력으로 정리한다. 옛 결과는 기준 커밋과 연구 자료에 남길 수 있다.
4. 기존 다섯 Markdown 예제는 선택형 작성 흐름을 보존한다. 공통 스크립트가 바뀌면 해당 HTML 참조는 유지·검증하되 새 visual 발표를 Markdown 재생성해야 하는 것으로 안내하지 않는다.
5. 새 계약의 수치/참조·다른 수량·저장/내보내기·모바일 표·빈 자료/누락·원본 불변을 검증한다. PDF 페이지 수·인쇄와 이전 데모 고정 수량의 회귀는 새 기능의 완료 조건으로 고집하지 않는다.
