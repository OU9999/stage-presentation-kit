최신 사용자 지시·WORK_LOG 최상단·DESIGN·ENGINEERING_BRIEF의 소유/보존/종료 조건을 유지합니다. 본 문서는 첫9의 실제 반려를 다음 구현에 직접 전달합니다. main-01과 동결 prototype은 덮어쓰지 않습니다.

## 실제 반려와 필요한 구조 변경

독립 critic와 manager는 원본을 먼저 본 뒤1920/1280의 첫9개별 화면을 읽었습니다. 기술 결과나 과거 승인을 보기 전 반려입니다. 자세한 정본은 review/main-01/, root의 별도 실독은 root-main-01-review.md입니다.

1. **8장의 익명 두 일반 설명 열을 재구성합니다.** 정확 구절이라도 같은 구체 자료에서 요약과 개념의 차이가 보이지 않습니다. 한 실제 개념 문서의 읽을 부분/관련 근거나 다른 명확한 자료를 선택하고, 불필요하면 다른 장과 통합합니다. 제목·강조·행간 교정으로 재통과시키지 않습니다.
2. **초반1–6의 문장 연속을 편집합니다.** 표지→정의→목적→긴 선택 이유→추상 비교→질문이 이어져 자료를 보기 전에 선언을 계속 읽습니다. 선택 이유가 남은 실제 메모 같은 읽을 대상을 더 일찍 배치하고,4/6의 반복 설명을 해설/대본으로 옮깁니다. 실제 자료1개를 끼운 것만으로 자동 해결됐다고 보지 않습니다.
3. **주변 설명층을 실제로 덜어냅니다.**4의 머리말/큰 예문/지위/링크,6의 위·아래 반복,7의 제목/관계설명/예시지위/링크/footer가 다시 쌓입니다. 각 장에서 읽을 부분을 선택합니다. 필수 관계 설명을 작게 둔 채 출처메타로 면제하는 것은 허용하지 않습니다. 필요 역할은 크게 보여 주거나 공개 해설로 명확히 옮깁니다.
4. **유지 후보의 범위:**7의 작은 입구/큰 기존 문서·경계에 붙은3무방향 선,9의 조건보다 첫 행동이 즉시 보이는 구조는 두 크기에서 유지후보입니다. 주변 읽기층은 재검토합니다. 모든 장을 이 패턴으로 복제하지 않습니다.

이미 프로젝트의 실제 global `.stage-document-links`에는 학습 자료 링크가 있습니다(lib/project.cjs). 매 장에 별도 탐색 문단을 중복하지 않아도 실제 공개 접근을 제공할 수 있습니다. 마지막 자료 장/읽기 경로도 함께 설계합니다. 필수 설명을 CSS로 숨기거나 가상의 notes 문법으로 보내지 않습니다. 반복 footer를 정리하는 공용 제어가 실제로 필요하면 기존 작성/렌더 구조의 최소 지원을 A가 단독으로 구현하고 B와 계약합니다. 특정 발표 전용 CSS나 거대한 새 입력체계는 만들지 않습니다.

독립 초기 미감 판정 뒤 root가 첫1280의 실제 SVG도 수집했습니다(main-01/present-1280/svg-metrics.json).7의 필수 관계 설명 ‘원자료의 입구’·‘함께 읽고 고칠 기존 문서’는 contain 후 각각23.098논리px로 관측됩니다. 필요하면 크게 조판하거나 실제 해설로 편집하며 출처메타로 면제하지 않습니다. 세 직선/rect 포트의 실제 경계 관측은 제안 계약대로 수집됐습니다. 새 SVG 둘의 DOM `data-material-kind`는 현재 null이므로 실제 설명용 재구성이라는 지위를 명시적으로 연결해야 합니다. 이 관측은 시각 반려를 대체하는 합격 판정이 아닙니다.
