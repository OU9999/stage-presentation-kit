# LLM Wiki 키노트 해설

발표는 지금 기억할 주장과 한 자료에 집중합니다. 이 해설은 발표면에서 옮긴 설명을 생략 없이 이어 읽는 공개 자료입니다. [발표 읽기](../slides.md) · [학습 자료 목록](./index.md) · [설명용 예제 팩 전문](../assets/expanded-study.txt) · [현재 발표 대본](./speaker-script.md)

이 예제의 메모·위키·선택 이유·답은 발표팀의 설명용 구성입니다. 외부 원문의 정확 발췌, 실제 사용자의 직접 기록, 이번 세션의 모델 출력이나 실제 스터디 성과로 소개하지 않습니다. 기술 주장의 일차 근거는 [원문과 근거](./reference-library.md)에서 확인합니다.

## 정의와 개인 맥락

**LLM Wiki는 내 자료를 AI와 함께 정리하고 연결하는, 나만의 마크다운 지식 베이스입니다.** 사람이 읽고 고칠 수 있는 문서에 자료의 개념·비교·종합과 근거를 연결하고, 새 자료나 질문에 맞춰 현재 이해를 고칩니다. 마크다운은 글·제목·목록·링크를 적는 텍스트 파일 형식입니다. 폴더에 자료를 모으는 일과, 그 자료 사이의 관계를 설명하고 유지하는 일은 구별합니다.

개인비서도 내 상황·선호·이전에 선택한 이유를 다시 읽을 수 있어야 맥락을 참고할 수 있습니다. [OpenClaw의 메모리](https://docs.openclaw.ai/concepts/memory)와 [Hermes](https://github.com/NousResearch/hermes-agent)는 개인비서형 에이전트의 탐색 예이며 이 발표의 필수 도구나 검증된 효과를 뜻하지 않습니다. LLM Wiki라는 설계 아이디어의 출발은 [Karpathy의 글](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)입니다.

같은 문서를 함께 편집한다는 말에는 서로 다른 책임이 있습니다. 사람은 누구를 위해 무엇을 만들지 목적을 정하고, 생각과 판단·선택 이유를 직접 씁니다. AI는 허용한 자료를 읽고 문서와 연결·목차를 쓰거나 고칩니다. 사람은 바뀐 문서의 중요한 내용을 확인하고 AI의 해석을 바로잡을 수 있습니다. 문서를 남기기만 하면 AI가 항상 읽거나 자동으로 모든 관련 문서를 고친다고 보장하지 않습니다.

다시 쓸 목적의 예는 “LLM Wiki와 RAG의 차이를 설명하고 다음 스터디의 진행안을 만들고 싶다”입니다. 이 목적과 “AI가 내 자료를 좀 더 잘 이해해 줬으면”이라는 요구는 발표팀이 구성한 예문입니다. 실제 사용자의 감정이나 경험을 대신 쓴 기록이 아닙니다. [현재 본편의 선택 이유 메모](../slides.md#3)과 [선택·기록의 책임](#사람의-선택과-기록)을 함께 읽습니다.

### 선택 이유 메모

**목적과 맥락 — 사람이 채울 선택 이유의 예**

> ‘LLM Wiki와 RAG의 차이를 설명하고 다음 스터디의 진행안을 만들고 싶어서 이 메모를 골랐다.’

현재 선택 이유 자료면은 `raw/context-note.md`의 위 구절을 정확 발췌한 재구성입니다. 발표팀 구성 예이며 **실제 사용자의 직접 기록이나 모델 출력이 아닙니다.** 짧은 지위 표지는 원문 작성 주체를 없애는 뜻이 아닙니다. 정확 발췌의 전체 맥락은 [예제 팩](../assets/expanded-study.txt)에서 같은 경로 제목으로 바로 찾을 수 있습니다.

## 원자료와 작업 약속

같은 예제 팩에는 ‘목적과 맥락’·‘검색과 비교’·‘지식의 활용’이라는 세 자작 주제 메모가 있습니다. `raw/`는 원자료와 사람이 남긴 선택 이유를 보존하는 자리, `wiki/`는 정리하고 갱신할 이해, `rules.md`는 두 영역을 다룰 작업 약속입니다. 이 이름은 설명용 구성 예이며 모든 도구가 따라야 하는 필수 규격은 아닙니다.

| 파일·문서 | 읽을 내용과 역할 |
| --- | --- |
| `raw/context-note.md` | ‘목적과 맥락’: 목적·선택 이유·개념 연결·남은 질문 |
| `raw/retrieval-note.md` | ‘검색과 비교’: 검색·지속 문서·모델 학습·에이전트 판단의 구분과 병행 |
| `raw/synthesis-note.md` | ‘지식의 활용’: 사람의 입력·종합·결과 제작·검토·다음 질문 |
| `raw/study-retro.md` | 나중에 추가하는 입문자·준비된 팩·15분 활동이라는 가상 조건 |
| `wiki/sources/*.md` | 각 자료의 요지를 다시 찾는 자료 요약과 원자료 근거 |
| `wiki/concepts/llm-wiki.md`·`retrieval.md` | 여러 자료의 공통 개념과 적용 범위 |
| `wiki/comparisons/rag-vs-wiki.md` | 같은 기준의 차이와 우리 선택 기준 |
| `wiki/syntheses/study-plan.md` | 여러 자료·조건을 엮은 현재 계획 |
| `wiki/questions/first-study.md` | 질문에 읽은 근거와 검토할 답 |
| `wiki/outputs/study-session-plan.md`·`wiki/reviews/study-session-plan.md` | 사용할 활동안과 확인할 항목 |
| `wiki/index.md`·`wiki/log.md` | 문서를 찾는 목차·링크와 바뀐 이유 |

실제 전문은 한 텍스트 팩의 경로별 구간입니다. 위 이름이 각각 별도 공개 `.md` 파일로 등록되어 있다는 뜻은 아닙니다. [팩 전문](../assets/expanded-study.txt)을 열어 경로 제목으로 찾을 수 있습니다. 같은 경로의 ‘처음’과 ‘갱신’은 한 논리 파일의 전후 상태입니다.

작업할 때 지킬 네 약속은 **원자료 보존 / 근거 연결 / 관련 문서 갱신 / 중요한 결과 확인**입니다. raw를 없애고 wiki로 대체하지 않습니다. 실제 읽은 자료의 위치를 남기고, 새 자료와 관련된 기존 설명·비교·계획·질문·목차·로그를 살펴봅니다. 변경 파일과 모르는 점을 받아 중요한 결론을 사람이 원자료와 대조합니다. 약속은 자동 갱신 기능이나 오류 없음의 보증이 아닙니다.

## 검색과 지속 문서

중심 작업의 비교축은 **이번 질문에 필요한 근거를 검색해 답하기**와 **사람이 다시 읽을 연결 문서를 작성하고 유지하기**입니다. RAG는 외부 자료를 찾아 생성의 입력 문맥에 사용하는 패턴입니다. LLM Wiki는 사람이 읽는 지속 문서 층을 둡니다. 두 방식은 함께 쓸 수 있고, 규모가 커지면 위키에서도 검색이 필요합니다. RAG도 관계·요약을 미리 만들거나 답을 저장할 수 있습니다.

| 살펴볼 점 | RAG 구성 | 작은 LLM Wiki |
| --- | --- | --- |
| 중심 작업 | 자료를 검색해 답하기 | 문서를 정리하고 연결하기 |
| 준비할 것 | 검색 방법·색인 등 설계 | 파일·목차·링크부터 시작 |
| 질문할 때 | 찾은 근거를 참고 | 정리한 문서와 원자료를 참고 |
| 유지할 것 | 검색 품질·자료 변경 | 문서 내용·연결·자료 변경 |

같은 질문은 “다음 AI 스터디에서 LLM Wiki를 어떻게 시도할까?”입니다. RAG 경로는 같은 세 메모에서 지금 필요한 부분을 찾아 이번 답의 입력 문맥으로 사용합니다. 위키 경로는 같은 메모를 근거로 미리 정리한 ‘LLM Wiki 개념’·‘RAG와 위키 비교’·‘우리 스터디 계획’과 필요한 원자료를 다시 읽습니다. 답을 우리 목적과 조건에 맞추고 쓸 만한 답을 확인한 뒤 문서로 남길 수 있습니다. 이는 설명용 흐름이며 실제 검색이나 모델 실행의 기록이 아닙니다.

검색 유무·문서 개수 하나로 도입을 결정하지 않습니다. Agentic RAG의 검색 판단, 파인튜닝의 파라미터·어댑터 최적화와 파일 편집도 구별합니다. 정확도·속도·비용의 우열을 이 예제에서 측정하지 않았습니다. [기술 근거와 범위](./reference-library.md) · [현재 계획의 변경과 근거](#계획이-바뀐-근거)

## 요약과 기존 문서의 관계

**자료 요약은 한 자료를 다시 찾는 입구이고, 개념 문서는 여러 자료의 공통 주제를 설명합니다.** ‘목적과 맥락’ 한 메모의 요약은 자료를 넣는 목적과 선택 이유를 되짚습니다. ‘LLM Wiki 개념’ 문서는 세 메모를 함께 읽어 자료 사이 관계와 현재 이해를 연결 문서로 작성·갱신한다는 설명을 남깁니다. 개념은 ‘RAG와 위키 비교’·‘현재 계획’과 함께 읽습니다.

개념 문서의 세 근거 메모 이름은 **목적과 맥락 · 검색과 비교 · 지식의 활용**입니다. 현재 관계 장면에서 작은 **자료 요약은 원자료의 입구**, 큰 두 영역은 함께 읽고 고칠 기존 문서입니다.

한 자료 요약의 전문은 팩의 `wiki/sources/context-note.md`, 여러 자료의 개념은 `wiki/concepts/llm-wiki.md` 구간입니다. 요약의 근거는 `raw/context-note.md`이며 개념의 근거는 `raw/context-note.md`·`raw/retrieval-note.md`·`raw/synthesis-note.md`입니다. 개념 문서 전문의 첫 문장은 “LLM이 원자료의 개념·비교·종합을 연결 문서로 작성하고 갱신하는 지식관리 패턴이다.”입니다. 이 역시 발표팀의 예제 문서이며 실제 모델 출력이 아닙니다. 현재 본편은 정의를 반복하는 개념 문서 대신 [같은 계획이 바뀐 두 구절](#계획이-바뀐-근거)을 자료로 선택했습니다. 두 문서의 차이와 전문·근거는 [같은 팩 전문](../assets/expanded-study.txt)에서 경로 제목으로 읽습니다.

같은 세 메모를 읽고 내용을 나누며, 자료 요약을 입구로 관련된 **기존 개념·비교와 현재 계획의 관계를 보완**합니다. 새 자료와 사람이 남긴 선택 이유를 보존하고, 관련 문서·목차·링크도 확인해 고칩니다. Ingest는 이 읽기·나누기·연결 보완의 작업을 가리킵니다.

### 세 무방향 관계

현재 본편의 작은 **자료 요약은 원자료의 입구**이고 큰 **기존 개념·비교와 현재 계획은 함께 읽고 고칠 기존 문서**입니다. 현재 관계 장면의 세 관계는 다음과 같습니다.

1. 자료 요약 ↔ 개념·비교
2. 자료 요약 ↔ 현재 계획
3. 개념·비교 ↔ 현재 계획

작은 자료 요약이 입구이고 두 큰 문서가 갱신 대상이어도 이 선은 무방향 관계입니다. 요약→개념→계획 파일을 순서대로 새로 만드는 필수 생성 절차나, 양방향 자동 갱신 보장이 아닙니다. [현재 관계 장면](../slides.md#7) · [역사 10장 도식의 설명과 원본](./diagram-reading.md#10장-읽고-나누고-연결-갱신하기)

| 문서 | 함께 읽는 관계 |
| --- | --- |
| LLM Wiki 개념 | RAG와 위키 비교 · 우리 스터디 계획 |
| RAG와 위키 비교 | 개념의 차이 · 계획의 선택 기준 |
| 우리 스터디 계획 | 개념과 비교를 우리 조건에 적용 |

이 표는 원래 12장에 있던 관계 설명 전문입니다. 목차와 링크는 관련 개념과 원자료를 다시 찾는 길입니다. 새 자료가 오면 문서와 관계를 보완합니다.

### 다섯 관계

역사 3장의 ‘자료에서 연결된 지식으로’에는 별도의 다섯 관계가 있습니다. **개념 ↔ 현재 이해 / 비교 ↔ 현재 이해 / 현재 이해 ↔ 계획 / 현재 이해 ↔ 다음 질문 / 계획 ↔ 다음 질문**입니다. 출발인 세 메모를 보존하고, 자료의 개념·비교를 현재 이해와 다음 질문에 다시 쓰는 뜻입니다. 앞의 세 관계와 합쳐 수를 바꾸거나 자동 갱신 방향으로 읽지 않습니다. ## 원자료와 정리한 이해

새 조건은 **입문자와 함께, 준비된 읽기 팩으로, 15분 활동을 한다**는 가상 조건입니다. 이 조건에서 “설치보다 문서 읽기부터”를 첫 행동으로 고른 예입니다. **15분이라는 시간만으로 자동 도출한 답이 아닙니다.** 원래 목적은 설치보다 자료 사이 연결의 근거를 찾고 싶다는 것이고, 준비된 팩이 있으며 입문자가 함께한다는 조건도 판단에 들어갑니다.

`raw/study-retro.md`는 조건을 보존합니다. 그 조건을 읽어 개념의 ‘우리 적용 범위’는 입문 설명부터, 비교의 ‘선택 기준’은 작은 자료 묶음부터, 계획의 ‘작업과 시간’은 15분 읽기 활동에 맞춰 고치는 구성 예입니다. 새 개인 조건이 보편 개념의 정의를 뒤집는 것은 아닙니다. 조건 메모만 추가하고 예전 계획을 방치하지 않도록 관련 내용을 함께 확인합니다. 자동으로 모든 문서가 수정되거나 정해진 순서로 생성된다고 가정하지 않습니다.

이후 “입문자와 15분 활동은 무엇부터 할까?”를 묻고 개념·비교·현재 계획을 다시 읽어 답합니다. 준비된 문서를 읽고 관계의 근거 한 개를 찾는 선택을 확인한 뒤 유용한 답을 문서로 남길 수 있습니다. 구절의 전체 맥락과 전후 상태는 [예제 팩](../assets/expanded-study.txt), 발표의 선택은 [현재 첫 선택 장면](../slides.md#8)에서 읽습니다. 이번에 실제 활동·모델 실행·생성 시간·학습효과를 측정한 결과가 아닙니다.

### 계획이 바뀐 근거

현재 본편의 계획 자료면은 [예제 팩](../assets/expanded-study.txt)의 같은 논리 파일 `wiki/syntheses/study-plan.md`에서 다음 두 구절을 정확 발췌한 재구성입니다.

| 같은 계획의 상태 | 정확 발췌 |
| --- | --- |
| 처음 계획 | 참여자 배경과 활동 길이는 아직 미정이다. |
| 갱신한 계획 | 가상 조건: 입문자 포함, 준비된 세 메모 중 두 개 선택, 별도 활동 15분. |

두 문장은 별도 사람의 실행 결과를 비교한 것이 아니라 하나의 설명용 계획 문서의 전후 상태입니다. 근거는 `raw/study-retro.md`의 가상 모임 조건입니다. 입문자·준비된 팩·15분이라는 조건을 읽어 현재 계획에 반영한 예이며, 보편 개념의 정의나 필수 생성 순서를 바꾼 것이 아닙니다. 관련 개념의 적용 범위·비교의 선택 기준도 함께 살펴봅니다. **실제 사용자 기록·모델 출력·참가자 활동·시간·학습효과를 측정한 결과가 아닙니다.** [현재 계획 장면](../slides.md#6)

## 사람의 선택과 기록

자료를 모두 넣기 전에 두 가지를 묻습니다. “앞으로 만들 결과와 관련된 자료인가?”, “가치 있다고 느낀 이유를 직접 적을 수 있는가?” 판단했다면 같은 주제의 자료 두 개부터 연결해 다음 질문에 도움이 되는지 봅니다. 자기 맥락을 완벽한 온톨로지로 분류하는 일보다 지금 만들 결과와 다시 묻고 싶은 질문을 먼저 적습니다.

예제의 선택 이유는 “LLM Wiki와 RAG의 차이를 설명하고 다음 스터디의 진행안을 만들고 싶어서 이 메모를 골랐다”입니다. 맥락은 다음 AI 스터디 준비, 중요한 점은 원문·내 이유·연결된 종합의 구분, 앞으로의 쓰임은 한 쪽 진행안과 다음 읽기 활동입니다. 이 문장 자체도 발표팀의 구성 예이며 실제 사용자의 직접 기록으로 소개하지 않습니다.

**누구를 위해 무엇을 만들지 목적은 사람이 정합니다. 감정·생각·판단·선택 이유는 사람이 직접 남깁니다.** AI가 추정한 내 생각을 내가 쓴 기록으로 바꾸지 않습니다.

| 기록의 지위 | 남기는 방식 |
| --- | --- |
| 원문 | 실제 읽은 자료의 구절·위치와 작성 주체를 남깁니다. 본편의 “본편 뒤 별도 활동은 15분만 배정한다.”는 `raw/study-retro.md` 구절입니다. 이 예제의 raw 메모는 발표팀의 자작 설명입니다. |
| 사람의 직접 기록 | 내 경험·감정·생각·판단·선택 이유임을 표시하고 내가 씁니다. |
| AI의 요약·해석 | 생성한 종합과 추정임을 표시하고 원문·사람 기록과 구분하며 근거를 확인합니다. |

활용은 공부의 개념·남은 질문, 프로젝트의 배경·결정 이유, 글과 발표의 근거 재사용입니다. 사람이 같은 마크다운 문서를 **읽고·고치고·다시 쓰기** 쉽다는 것이 장점입니다. 벡터 검색을 쓰면 사람이 원문을 읽을 수 없다는 뜻이 아니며, 실제 성과나 생산성 향상을 이 사례가 보장하지 않습니다.

## 활동안과 미확인 범위

목표는 **한 관계의 근거를 찾아 읽고, 다음 질문과 확인할 점을 남기기**입니다. 선택한 두 메모는 목적·선택 이유·개념 연결을 읽을 `raw/context-note.md`와, 사람의 입력·결과 제작·검토를 읽을 `raw/synthesis-note.md`입니다. `raw/retrieval-note.md`는 전체 비교의 공통 근거로 돌아가 읽습니다. 준비물은 세 메모·관련 개념·비교·현재 계획 예시와 자기 노트입니다.

| 활동 시간 | 할 일 | 남길 것 |
| --- | --- | --- |
| 0~2분 | 왜 이 자료를 다시 쓰려는지 질문 정하기 | 목적 한 문장 |
| 2~6분 | 선택한 두 읽기 메모 확인하기 | 메모 요지와 내 선택 이유 |
| 6~11분 | 원자료→개념→비교의 연결 한 개를 따라 읽기 | 관계를 뒷받침하는 근거 위치 |
| 11~15분 | 후속 질문에 근거를 연결하고 남은 확인 적기 | 질문·검토할 답·모르는 점 |

2+4+5+4=15분은 계획 배분이며 실측 시간이 아닙니다. 표의 ‘원자료→개념→비교’는 이번 읽기 활동에서 따라 읽을 순서로, 본편 그림의 세 무방향 관계와 다릅니다. 설치·계정 연결·위키 제작은 이 짧은 활동 범위에 포함하지 않습니다.

본편 자료면은 실제 제공 활동안에서 한 행을 고른 **설명용 재구성**이며 실제 도구 UI 캡처가 아닙니다. 확인할 수 있는 것은 시간 배분·선택 이유·근거 위치·작성 주체·문서 연결입니다. 실제 모임에서 필요한 쪽을 찾았는지, 15분 안에 이해했는지, 학습에 도움이 됐는지는 미확인입니다. 실제 모임 운영·입문자 이해도·학습효과·설치나 모델 생성 시간의 실측 자료로 소개하지 않습니다. [활동안 전체와 다음 확인](./session-plan.md) · [현재 활동안 발췌](../slides.md#13)

## 확인과 유지

AI가 만든 연결은 원자료가 뒷받침하는지 확인합니다. 읽기 좋은 문장이라도 조건이 다른 자료를 하나로 묶었거나 원자료가 말하지 않은 관계일 수 있습니다. “15분이므로 설치보다 읽기”처럼 시간 하나만 이유로 삼으면 입문자·준비된 팩·원래 목적이 빠집니다. 원자료의 조건으로 돌아가 관계와 선택 이유를 확인합니다.

위험은 내용 오류뿐 아니라 **새 자료와 예전 설명의 충돌**, **문서·링크를 유지하는 시간**에도 있습니다. 중요한 결론은 원자료와 대조하고, 오래된 설명·서로 다른 조건·끊긴 링크를 찾아 바뀐 이유를 남깁니다. 작업 결과에는 바꾼 파일·근거·아직 모르는 점을 요청합니다. 확인할 사람이 없는 자동 정리와 검증된 현재 이해를 같게 보지 않습니다.

### 선택의 근거 확인

현재 확인 장면의 **“15분이니까 ‘읽기부터’?”**는 발표용 확인 질문입니다. 자동 결론의 근거를 실제 원자료가 충분히 뒷받침하는지 묻는 장치이며 실제 참가자나 모델이 말한 기록이 아닙니다. 판정은 **목적도 확인합니다**입니다.

바로 대조할 원자료는 [예제 팩](../assets/expanded-study.txt)의 `raw/study-retro.md`입니다. 문서 ‘다음 모임의 조건 메모’의 정확한 구절은 다음과 같습니다.

> 도구 설치보다 목차와 연결을 따라 다음 질문의 근거를 찾는 경험을 먼저 하고 싶다.

구절은 **전체 가상 조건**인 입문자·준비된 팩·15분과 함께 읽습니다. 시간만으로 첫 행동이 자동 결정된다고 결론내릴 수 없고, 자료 연결의 근거를 찾고 싶다는 목적도 선택에 들어갑니다. 원문 인용인 원자료 발췌와 발표용 질문·해석을 구별합니다. 실제 사용자 기록·모델 출력·실행 성과·학습효과의 실측이 아닙니다. [현재 확인 장면](../slides.md#15)

## 시작 요청과 선택 기준

| 지금 상황 | 먼저 해 볼 일 |
| --- | --- |
| 같은 주제를 반복해서 묻는다 | 작은 연결 문서를 만들고 다음 질문에서 다시 쓰는지 확인 |
| 일회성 질문이다 | 간단한 노트와 검색으로 충분한지 먼저 판단 |
| 자료가 많고 찾기가 어렵다 | 검색과 목차를 함께 설계하고 필요한 근거를 찾는지 확인 |
| 자료가 자주 바뀐다 | 관련 문서·링크를 누가 확인할지와 유지 비용을 먼저 정하기 |

규모만으로 위키가 필요하다고 결론내리지 않습니다. 아래 전문을 복사해 자기 목적·파일 경로·직접 쓴 기록으로 바꿉니다. 이는 요청 예문이며 실행 기록이 아닙니다.

```text
목적: [누구를 위해 무엇을 만들고, 다음에 어떤 질문에 다시 쓸지]
자료: [같은 주제의 자료 두 개와 실제 파일 경로]
내 기록: [내가 직접 쓴 생각·판단·선택 이유]
작업 위치: [허용한 폴더] / 작업 규칙: [rules.md 경로]

원자료는 보존하고, 원문·내 직접 기록·AI의 요약과 해석을 구분해 주세요.
자료의 요지와 공통 개념·차이·현재 계획을 연결해 주세요.
필요한 기존 문서·목차·링크를 찾아 갱신하고 근거 위치를 남겨 주세요.
바꾼 파일, 중요한 결론의 근거, 충돌과 모르는 점을 알려 주세요.
내 목적·감정·생각·판단·선택 이유를 대신 지어내지 마세요.
중요한 내용은 내가 확인한 뒤 다음 질문에 다시 쓰겠습니다.
```

처음에는 목적을 적고, 자료 두 개를 골라 연결하고, 중요한 내용을 확인하고, 다음 질문에서 다시 읽습니다. 설치나 특정 도구 선택이 선행 의무는 아닙니다. [예제 읽기와 해설](./workshop.md)에서 준비된 팩으로 이어갈 수 있습니다.
