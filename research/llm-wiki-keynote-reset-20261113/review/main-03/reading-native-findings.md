# main-03 지원 문서 실물 반려

초기 양폭 본편40PNG에서는 추가 시각 반려를 발견하지 않았다. 이 초기 판단 뒤 root가 수집한 모바일 native 지원6화면을 직접 열어 아래 문제를 새로 발견했다. 링크 표시·정확 절의 본문 존재·18px 독서 크기와, 실제 한국어 호흡·문법 노출은 별도 판단이다. 발표 A의 6/15 역할 개선 판정은 바꾸지 않는다.

| 현재 근거 | 실제 보이는 행/글자 | 판정·다음 행동 |
| --- | --- | --- |
| `main-03/technical/direct-support-03-390.png` | 선택 이유 인용의 첫 행 끝 `다음 스터` / 다음 행 시작 `디의 진행안을` | 390 읽기3 needs-changes. 정확 인용은 보존하고 `스터디` 어절의 음절 중간 분리를 교정한다. |
| `main-03/technical/direct-support-08-390.png` | 핵심 한계의 행 끝 `답이 아닙니` / 다음 행 시작 `다. 원래 목적은` | 390 읽기8 needs-changes. 시간만의 인과가 아니라는 의미와 전체 조건을 보존하고 부정 서술어의 실제 행을 교정한다. |
| `main-03/technical/direct-support-15-390.png` | 첫 문단에 `**“15분이니까 ‘읽기부터’?”**는`의 별표가 문자로 출력됨 | 읽기15의 연결된 공통 public 본문 needs-changes. 정확 질문/원문/판정을 지키고 native 강조 구문의 노출을 교정한다. 생성 `keynote-notes.html:274`도 같은 literal을 담으며 viewport 의존 현상이 아니다. |

반례를 본 즉시 root와 manager에게 직접 전했고 A에게는 발표15의 역할 개선과 구별되는 지원 읽기 문제임을 직접 알렸다. 이후 source만 보고 추정한 것이 아니라 실제390 PNG에서 본 글자와 생성 DOM을 대조했다.

나머지 이미 본 native3/6/7/8/13/15에서 추가 literal 강조 구문은 발견하지 않았다. 선택 이유/동일 계획 전후/세 무방향 관계/입문자·준비팩·15분·원래 목적/활동안/질문과 목적 원문의 내용은 읽을 크기로 이어진다. 6과13의 표 오른쪽 끝, 양폭12클릭 전체 및20의 요청문 선택·자료 전문 접근은 B의 완결 관측 인수 전이다. 그 범위를 승인으로 채우지 않는다.

다음 소유자는 root가 재개하는 기존 지원 문서/읽기 엔지니어다. 원문 지위·자료·조건·책임을 보존하고 이 세 native 구절의 현재 입력을 교정한 뒤 실제 지원 화면과 영향을 받는 읽기 범위를 새 근거로 재검토한다. B는 제품·공통 스타일·원고·지원 문서를 수정하지 않았다.
