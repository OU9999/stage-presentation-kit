# R02 — 세 역할의 실제 구도 유지 후보

검증관 A가 `evidence/r02/present-1920/slide-01.png`~`slide-03.png` 세 원본을 직접 열고 원본 DevDay20:30·20:00·36:00의 역할과 비교했다. 첫 미감 판단을 B·manager·root에게 즉시 전달한 뒤 manifest·입력 해시·지원자료/대본을 읽었다. 기술 통과·이전 승인 이유로 판정을 만들지 않았다. R01 제품·근거·반려 기록은 동결 보존한다.

| 실제 장 | 빠른 미감 판정 | 유지할 실제 변화 |
| --- | --- | --- |
| 01 | 메시지 패턴 유지 후보 | ‘다음 질문에 다시 씁니다’가 곧바로 읽힌다. 부연·제목·관계가 같은 장에서 메시지와 경쟁하지 않는다. R01과 PNG SHA가 같지만 현재 실제 PNG도 다시 열었다. |
| 02 | 자료 대조 패턴 유지 후보 | 왼쪽의15분 조건과 오른쪽의 ‘새 도구 설치보다 기존 목차와 문서 연결부터’라는 선택이 같은 축으로 읽힌다. 오른쪽의 큰 문서 영역이 주역이며 왼쪽은 보존할 조건으로 구별된다. R01의 목적문장↔일반동작이라는 다른 정의 두 열에서 읽을 대상 자체를 다시 선택했다. 파일 정보·문서 제목·하단 예시지위는 지금 주역과 경쟁하는 크기/분량은 아니다. |
| 03 | 관계 패턴 유지 후보 | 작은 ‘자료 요약’ 입구와 큰 두 기존 문서가 구별되고, 세 선의 끝이 문서 경계에 직접 귀속된다. R01의 V와 떠 있는 세로선 대신 세 무방향 관계가 한 체계로 보인다. 주역이 도식이고 메모 분류·갱신 약속 목록이 다시 붙지 않았다. |

02의 오른쪽 문서 제목에는 ‘입문자와15분 활동’이 있다. 이 선택을15분 하나만으로 자동 도출된 인과로 소개하지 않는다. 현재 지원자료/대본은 구성예·실행한 모델 출력 아님을 분명히 밝히지만15분 조건만 설명하고 있으므로, **제품 이행본의 대본/지원자료에 ‘입문자와15분 활동이라는 가상 조건에서 고른 선택’으로 귀속할 것**을 B에게 직접 전달했다. R02 동결본을 고치라는 요청은 아니다. 원본 팩과 자료 전문·원래 관계·네 작업 약속은 보존한다. 가짜 실행성과·실제 사용자 기록·원본 UI로 지위를 올리지 않는다.

이 패턴은 메시지/자료/관계의 세 다른 구도를 본편 이행의 출발점으로 사용할 수 있다는 판단이다. `--require-approved`를 통한 발표 승인, 전체26장 승인,1280·읽기·모션·다른OS·실프로젝터 또는 사용자 승인으로 표현하지 않는다. 최종 제품의 새 입력·실제 화면을 다시 본다.

검토 범위: presentation-stage-only, viewport1920×1080/DPR1, 실제stage1557.3335×876. 원고 SHA `b2f9de95d60b8026b937f760c4c54387584df257f2d47599cce0486d7b3510c7`, DESIGN SHA `c28cb774ff7544506f2c02913d4588578a045ea98509ac3ea7475cc164f3a062`. 캡처 manifest SHA `d6b0e96f67320b35017660521044707c16e912f8bb9559f21d109df5f5d7577b`가 자산·공통 CSS/runtime을 포함한 전체 입력을 묶는다. 각PNG SHA는 R02.verdict.json에 남긴다.

이행 뒤에도 역할을 한눈에 말할 수 없거나, 같은 비교축이 없거나, 파일명/정의/약속이 자료와 동급 본문으로 재누적되거나, 관계 끝이 대상에서 분리되거나, 설명용 예제가 실제 증거처럼 소개되면 needs-changes다. 큰 글자·검정·여백 또는 기술 pass는 이를 대신하지 않는다.
