# main04 승인 실패의 원인과 책임

현재 결과를 OpenAI DevDay 무대 수준이라고 승인한 판단은 잘못됐다. 사용자 최신 반려가 현재 판정이며 **main04는 미감 needs-changes**다. 이번 완료 대상은 실패 원인 감사다. 발표 디자인을 개선하거나 재승인한 것이 아니다.

root는 팀의 이번 결론을 읽기 전에 [독립 자기 감사](ROOT_ACCOUNTABILITY.initial.md)를 작성했다. 기존 검증 manager와 A/B도 각자 실물을 다시 보고 자기 초기 소명을 저장한 뒤 서로의 반론을 대조했다. 다음 결론은 합의 인원수가 아니라 원본·현재 화면·당시 문장·지시의 대응에 근거한다.

## 1. 원본의 미감을 역할 이름으로 바꿔 평가했다

원본에서 ‘비교’, ‘관계’, ‘자료와 인용’이라는 역할을 추출한 뒤 현재에도 그 역할이 있으면 비슷한 수준으로 구현됐다고 판단했다. 무엇이 먼저 보이는지, 문장 해독 전에 그림이 차이를 전달하는지, 대상의 표면·비례·타이포가 정돈됐는지에 대한 판정이 빠졌다.

- **5장:** [원본 Codex90](../evidence/official-XkKdbPhIvbY-90.png)은 같은 창 모형 안의 작업 형태와 밀도로 차이를 먼저 보여준다. [현재5](../main-04/present-1920/slide-05.png)는 추상 작업명과 긴 계획 발췌를 서로 다른 수준으로 놓고, 상자·분기·라벨·문장을 차례로 읽게 한다. A의 당시 승인문 **“1920/1280 모두 이번답보다 실제 문서가 주역이다.”**는 대상의 존재와 면적을 설명할 뿐, 좋은 비교 그림이라는 증거가 아니다.
- **7장:** [원본 Codex210](../evidence/official-XkKdbPhIvbY-210.png)의 작은 표식·이름·열린 연결과 달리 [현재7](../main-04/present-1920/slide-07.png)은 넓은 채움 판과 굵은 긴 문서명이 관계보다 무겁다. 위의 두 문서와 아래의 긴 한 제목도 비슷한 글자 덩어리로 보인다. 세 선과 제목을 정확히 보존한 것을 좋은 관계면으로 승격했다.
- **15장:** [원본1440](../evidence/official-Fls_onRviPM-1440.png)의 식별 가능한 기사 표면과 확대 인용을, [현재15](../main-04/present-1920/slide-15.png)의 작은 합성 발췌면과 긴 네 줄 인용이라는 두 역할로 환원했다. 중복 시작구절·다른 읽기 출발점·거친 비례가 남아 있는데도 두 영역의 존재와 크기 차이를 완성도라고 인수했다.

[원본·이전·현재 비교](../index.html)에는 이제 당시 제작 의도와 현재 반려 이유를 구별해 표시한다. 사각형·긴 문장·표 자체를 금지하거나 원본 UI를 복제하라는 결론은 아니다.

## 2. 자료의 정확성과 가독성을 좋은 디자인의 증거로 사용했다

[현재13](../main-04/present-1920/slide-13.png)은 긴 문서명·부제·필드·굵은 행 조각을 확대한 워크시트다. 검수는 완전한 정체성, 세 필드, 한 행이 모였는지를 자세히 확인했다. 하지만 이 조건은 현재처럼 정돈되지 않은 면도 만족한다. [원본1500](../evidence/official-Fls_onRviPM-1500.png)의 서로 다른 고유 작업면이 만드는 설득력은 ‘한 자료가 있다’는 설명으로 생기지 않는다.

11장의 placeholder가 드러나는 학습 표와 14장의 멀리 떨어진 세 열도 의미가 유효하다는 이유로 다시 승인됐다. [09–16 실제 보드](../main-04/present-1920/contact-09-16.jpg)의 표·동등 열·큰 설명문 반복을 역할 이름의 변화로 방어했다. ‘같은 양식을 억지로 바꿀 필요는 없다’는 원칙을 현재 양식의 완성도를 면제하는 근거로 썼다.

정당한 자작 자료라는 사실과 잘 편집된 자료면이라는 판단은 별개다. 허위 출처 금지, 본문 크기, 정확한 관계는 지킬 조건이며 지금 외양을 필연적으로 만든 원인으로 입증되지 않았다.

## 3. 작은 결함을 고치는 동안 원래 목표가 실제 작업 목록에서 빠졌다

main02 이후 [root의 MAIN03 지시](../MAIN03_PRODUCTION.md)는 현재 제목, 모바일 고립행, 강조 문법의 교정과 14의 recap 유지로 좁혀졌다. 검수도 이 목록의 해소 여부에 집중했다.

실제 혼합 결과가 **3장**이다. 모바일의 ‘싶어서’ 고립을 고친 것은 타당하다. 그러나 같은 의도개행이 발표에도 적용돼 [main02의 세 행](../main-02/present-1920/slide-03.png)이 [현재 네 행](../main-04/present-1920/slide-03.png)으로 늘었고, 긴 행→중간 행→짧은 동사행→강조의 계단형과 아래 두 보조 문단이 남았다. 검수는 충돌이 없고 의미가 붙어 읽힌다는 이유로 발표의 조형 비용을 면제했다.

5장은 구체 계획을 넣으면서 설명 층과 복잡성이 늘었고, 13장은 정체성을 강화하면서 소개층이 늘었다. 6/7의 의미 교정은 유효했지만 미감 개선까지 입증하지 못했다. 11/14는 새 악화보다 남은 미달을 재승인한 사례다. **main03→04의 발표40 PNG는 같으므로 해설 한 구절 삭제가 발표 외양 악화의 원인은 아니다.** 이미 실패한 미감 판단을 정확히 재사용했다.

## 4. 우리가 고른 형식이 보존 지시가 되며 잘못된 선택을 굳혔다

확인된 결정 순서는 다음과 같다.

1. A/B가 준비 단계에서 큰 문서명·정확 구절·세 관계·한 행이라는 시안 형식을 공동 선택하고 B가 수용기준으로 문서화했다.
2. A가 미감으로 채택하고 B가 수용·취합했다. manager가 인수하고 root가 본편 이행 지시로 확정했다.
3. main02에서 14의 recap 의미를 방어한 판단이 manager 인수→root의 MAIN03 유지 지시→제작의 추가 구도 재설계 제외로 이어졌다. **main03 최종 판정은 그 뒤의 재승인**이다.
4. main03 전체 검수에서 기존 veto가 해소되고 새 오류가 없다는 이유로 전부 승인했다. main04에서는 동일 화면 확인을 통해 그 판단을 이어받았다.

DESIGN과 MAIN_BRIEF에는 이미 내용을 지원자료로 옮기고, 장수·구도를 재편집할 권한이 있었다. 이를 쓰지 않고 선택한 형식의 정확성을 방어한 것이 문제다. 뒤에 내려진 명시 지시를 제작자가 어겼어야 한다는 결론도 아니다. 최초 채택과 이후 범위 재협의를 막은 사람들의 결정 책임이다.

| 담당 | 실제 책임 |
| --- | --- |
| A · 미감 검증 | 자료명·면적·역할 존재를 조형의 완성도로 승인했다. 첫 시안 채택과 main03 전체 검수에서 막을 수 있었다. |
| B · 의미/읽기·취합 | 정확 구절·관계·읽기 조건을 현 형식에 고정하고, 남은 제품 교정 요구가 없다는 전체 결론으로 넓혔다. |
| 검증 manager | 두 담당자가 같은 약한 추론을 할 때 반증하지 않고 출시 가능한 수준으로 인수했다. |
| root · 최종 책임 | 부족한 시안을 본편 지시로 굳히고, 교정을 국소 목록으로 좁혔으며, 직접 본 화면을 최종 승인·완료로 보고했다. 팀 배정과 독립 초안 절차로 이 판단 책임이 없어지지 않는다. |

독립 초안과 직접 반론은 실제 수행됐다. 하지만 같은 좁은 수용 질문을 공유했으므로 운영의 독립성이 판단의 질을 보장하지 못했다. 테스트·해시·기록의 정밀함은 잘못된 미감 전제를 안정적으로 운반했다.

## 5. 별도 결함: 일반 미리보기와 검수 캡처의 런타임이 달랐다

root가 실제 일반 주소를 열어 **15장 전체 오류 화면**을 재현했다. 같은 현재 원고에서 일반 탭은 옛 HTML의 deck-model/blocks 참조를 사용해 새 `evidence` variant를 거부했다. 같은 주소를 캐시 우회와 새 문서로 열면 현재 런타임으로 정상 렌더됐다. [전후 상태](delivery-before-after.json), [오류 화면](normal-cached-15.png), [캐시 우회 화면](cache-bypassed-15.png)을 보존했다.

당시 로컬 서버에는 Cache-Control이 없었다. 캡처에서 캐시를 비활성화한 것과 일반 탭의 낡은 문서/리소스 재사용이 달랐으며, 세부 캐시 계층을 HTTP 또는 BFCache 하나로 확정하지 않는다. 사용자가 실제로 그 오류 화면을 봤다고 단정하지도 않는다.

root 소유 로컬 preview helper에 `Cache-Control: no-store`를 추가하고 해당 서버만 재시작했다. 캐시 비활성을 해제한 일반 주소에서 새 문서 탐색 15→5→15를 확인해 현재 런타임·이미지 로딩·작성자 오류0과 응답 헤더를 기록했다([수정 검증](delivery-fixed.json), [현재 일반 화면](delivery-fixed-normal-15.png)). 사용자 전역 캐시·저장소는 지우지 않았다. 이미 열린 다른 낡은 문서까지 자동 갱신됐다는 주장은 아니다.

이것은 검수와 인계의 별도 실패다. **신선한 main04 캡처 자체가 미감에 못 미친다는 1–4절의 원인을 면제하지 않는다.** 이 수정으로 디자인을 개선했다고 보고하지 않는다.

## 실제 조치와 다음 채택의 조건

기존 승인 JSON·캡처·초기 소명은 이력으로 보존했다. 현재 보고서와 비교 페이지의 승인 표시는 철회했고, 사용자 반려가 유효한 동안 옛 결과를 승인 보고서로 다시 출력하는 경로도 차단했다.

다음 제작에서 현재5/13/15는 **통과하면 안 되는 반례**다. 새 승인 이유가 이 화면도 그대로 통과시킨다면 기준이 달라진 것이 아니다. 작은 실제 후보를 원본·현재 반려본과 같은 크기로 놓고, 해독 전 비교·자료의 표면/비례·문장 실루엣·읽기 출발점이 무엇이 달라졌는지 먼저 보여야 한다. 그 뒤 채택한 표현의 의미·기술·읽기 검사를 맞춘다. 지금 박스·표·줄수·같은 화면 배치는 보존 의무가 아니다.

새 체크리스트, 사진·색·장수 할당량, 정해진 반려 횟수, 팀 인원 증가로 해결됐다고 하지 않는다. 이번 감사에서 발표 원고·자산·공통 runtime은 수정하지 않았다. 현재 미감 실패와 새 시안 제작·검증은 미완료다.

팀의 실제 소명: [A 최종](art-direction.final.md) · [B 최종](process.final.md) · [manager 책임](MANAGER_ACCOUNTABILITY.md) · [인과·반론 대조](cause-comparison.md). root가 직접 인용과 시간순서·책임 범위를 대조해 이 보고서로 통합했다.
