# 첫 실제 반려 뒤 구조 수정

전제: root가 round01 검증관팀의 최종 원문/직접 반론과 전원 writer 종료를 인수한 뒤 실행한다. 정본은 `review/round-01/`의 A/B 초기·최종/원문 JSON 및 manager-summary다. root/제작팀이 승인을 추정하거나 처음 반려를 미세간격 교정으로 덮지 않는다. 원본·실패시안·과거판정은 보존한다.

같은 제작 manager/A/B를 재개한다. 모델/공통 로그/소유 원칙은 PRODUCTION_BRIEF와 동일하다. manager는 새 `production/round-02-handoff.md`, A는 새 `prototypes/talks/round-02/assets/**`와 `production/round-02-visual-intent.md`, B는 새 `round-02/slides.md`·materials와 `production/source-proof-round02.cjs/json` 및 취합을 단독 소유한다. **기존round01 원고/자산/증거/proof/원문을 수정하지 않고 복제해 별도 round02를 만든다.** 기존 config는 두 덱을 찾을 수 있어 변경 필요가 없으면 유지한다.

## 실제 반려와 고칠 구조

- **pilot1 / 본편05**: 두 완전한 절차를 반복해 공통 원자료/이번답과 입력의 동의 설명이 차이보다 크게 보인다. 공통 대상을 공유하거나 묶어 절차 반복을 줄이고, **지속되어 다시 읽을 문서**를 가장 분명한 차이로 편집한다. 이름만 있는 좁은3카드를 늘리지 말고 이 사례의 실제 선택 구절/변경 대상 단서 한 가지를 선택한다. `다음/스터디의/첫 시도` 같은3행 조각을 피한다. 공통질문·두 방식 모두 이번답을 만듦·위키도 검색/RAG도 저장·관계 확장 가능·병행 가능은 보존한다. 없는 성능/속도/비용 차트와 가짜 UI를 만들지 않는다. 단순색/폰트축소로 교정하지 않는다.
- **pilot4 / 본편15**: 자료정체성+native 목적구절의 구조적 진전은 보존한다. 그러나 왼쪽3조건/선택stub와 오른쪽 질문/인용/재진술/예시가 두 문서 병행 독서가 됐다. **질문↔정확 목적구절↔선택 위치가 한 읽는 경로**가 되게 편집한다. 필수 입문자·별도15분 조건은 읽을 크기로 남기되 긴 원문3덩어리를 모두 같은 크기로 반복하지 않는다. 준비된 팩 조건/세메모 전체 맥락은 필요한 가시 단서와 실제 공개절로 정확 보존할 수 있다. 질문은 재구성, 목적은 팩의 정확 구절, 원문raw도 자작 가상 예라는 구별을 유지한다. 필수 조건/목적을 작은 캡션·alt·대본에만 숨기지 않는다. 같은판의 배경색/간격만 바꾸거나 단지 질문만 키우지 않는다.
- **pilot2/3 / 본편07/13**: 양 검증관과 root가 구체 문서명/세 무방향 관계, 한 문서 정체성/한 행의 국소 장점을 수용했다. 통일성 수량 때문에 다시 그리지 않는다. 복제한2/3의 SVG bytes와 본문은 유지하고 sourceLine/경로 갱신 영향만 검증한다. 승인 범위를 미래본편/읽기로 승계하지 않는다.

## 의미와 탐색을 구분하는 기존 입력

이미지 Markdown title은 기존 figureFor에서 **실제 figcaption**으로 렌더되고 원고/읽기/sourceLine이 보존된다. 순수 출처·구성예 지위만 그 경로로 정돈할 수 있다. 현재32px 본문에 반복된 `발표팀의 구성 예`와 성과/비측정 설명 전체를 모두 같은 무게로 둘 필요는 없다. 이 장에 수치/실행 성과 주장이 없다면 비측정 전체 설명은 정확 공개절에 유지하고 발표면의 범위/지위는 짧고 분명하게 편집한다. 조건·질문·사람의 판단을 캡션으로 분류해 숫자 검사를 회피하지 않는다. B가 역할/원문/요약·정확 발췌를 구별하고 A와 실제 표시를 직접 합의한다.

## 구현/검증 경계

`split/evidence` 공통 구현은 첫판에서 정상 작동했고 root의 전체360테스트/기존본편 네 현재회귀가 통과했다. **이번 재개는 새로운 격리 원고·자산·읽을 문서만 변경**한다. 공통 코드/CSS/parser·기존 docs·본편·과거 자산·과거 증거·WORK_LOG는 읽기전용으로 돌아간다. 새로운 공통 결함이 입증되면 범위/근거를 먼저 root에게 전달하고 다른 작업을 계속한다.

B는 첫16개 정합 계약에서 의미/보존/지원·현재hash를 새 경로로 검증하고, 바뀐 요약/정확 발췌/metadata 역할을 정당한 구조 변경으로 이행한다. 과거 결과나 하한을 고쳐 통과시키지 않고 원래 팩·기존2/3·원자료/역사 보존을 대조한다. old source-proof.cjs/json은 그대로 둔다. 짧은 정적 검사 뒤 렌더 입력 hold를 먼저 인계하여 root의 실제 시각 검토를 늦추지 않는다.

root가 build/verify·새1920/1280 네 실제 PNG/원본-이전-새 대조/명시문맥·실제 SVG/native glyph/필요 읽기·지원 클릭을 수집한다. 제작팀 전원 종료 뒤 같은 검증관팀을 실제 재호출한다. 반려 횟수 할당량은 없고 unresolved veto가 남으면 다시 구조를 고친다. 이번 마감은 새 네 실물과 검수의 현재성 범위이며 본편 전체 이행/승인과 구별한다.
