## 독립 반려와 다음 실제 호출

다음 중 하나가 남으면 A/B 각자의 핵심 veto를 평균·다수결·테스트 수로 해제하지 않는다: 비교 대상 없이 두 정의만 남음, 자료가 일반 예문판으로 평탄화됨, 구체 문서/세 관계가 의미 변조됨, 필수 내용이 작아져 미니문서가 됨, 전후 흐름에서 보는 대상이 같은 문장열로만 이어짐, 사진/아이콘/색의 수로 복원을 주장함. 반려는 **관찰→같은 역할 원본→이해 영향→구조 수정→다시 볼 범위**를 포함한다. 고정 반려횟수·장수·매체 비율은 없다.

root는 다음 순서로 실제 루프를 실행한다.

1. 검증팀 writer 종료를 확인하고 별도 제작 manager+실무2를 순차 배정한다. 제작자는 [TEAM](TEAM.md)·현재 DESIGN·두 최종 판정·확정05/07/13/15 범위를 직접 인수한다. 검증관은 제품 제작 파일을 쓰지 않는다.
2. 격리된 작은 시안을 현재 공용 엔진으로 만들고 원고/자산·공통구조의 writer를 구분한다. 문법 제약은 구체 막힌 시안과 최소 재사용 확장으로 보고한다. 엔진 교체/새 설치를 선행하지 않는다.
3. 제작 writer hold/종료 뒤 root만 빌드·캡처한다. **1920×1080·1280×720/DPR1의 실제 stage PNG, 네 장 보드, 기존 앞뒤 흐름/02 대조, 원자료와 같은 역할 원본, 현재 source/asset/CSS/runtime fingerprint**를 함께 전달한다. viewport와 실제 stage 크기를 구별한다. 빠른 시각 반려를 전체 마감 QA 뒤로 미루지 않는다.
4. root가 `collaboration.followup_task`로 `/root/devday_verification_manager`를 실제 재호출하며 회차·입력/manifest 경로·장 대응·변경/보존·writer 종료를 전달한다. manager는 기존 A/B를 순차 가능한4슬롯 안에서 follow-up하여 독립 실물 판정과 직접 반론을 다시 받는다. 서면 기준을 남긴 사실만으로 검수 호출을 대체하지 않는다. 원본·새 실물을 먼저 보고 기술 결과와 과거 reason을 후속 확인한다.
5. 핵심 veto가 남으면 제작자에게 구조 수정으로 돌려보낸다. 선택한 시안만 본편·공개 해설·대본·역할/coverage 계약에 이행하고 현재 입력으로 필요한 관측과 검사를 갱신한다.

본편 마감에는 [현재 관측 회귀](../../../MARKDOWN-FIRST.md#실제-관측의-프로젝트-회귀)의 발표1920/1280·읽기1440/390 네 범위를 각각 일치하는 manifest/metrics로 실행한다. 현재 입력 hash 불일치·필수 관측 누락을 통과시키지 않으며 역사 baseline 실패 재현과 구별한다. 수동 판정과 새 현재 근거를 연결한 **명시 범위의 `--require-approved` 성공만** 시각 승인으로 표현한다. 기술 회귀의 `visualApproval:false`, 연구 준비 완료, 본편 승인, 사용자 미감 승인은 서로 구별한다.
