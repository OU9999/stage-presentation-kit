# 현재 저장소 자체를 공개할 때의 범위

확인일 2026-10-23 · HEAD `f9553170e56bcca24909d22e7ebd0f8d7df01f0d` · 읽기 전용 조사. 기존 미커밋·미추적 문서를 보존했으며 저장소 공개 전환·Pages 설정·배포를 실행하지 않았다.

## 초기 판단

**현재 저장소를 PUBLIC으로 바꾸고 같은 저장소에서 Pages를 사용하는 것은 가능하다. 도구·예제·연구까지 모두 공개하려는 의도라면 운영도 가장 단순해진다.** 이전에 권한 별도 배포 저장소는 원본을 비공개로 유지하면서 발표 결과만 공개하는 선택이었지, 현재 저장소를 공개하면 안 된다는 기술적 제약은 아니다.

판단할 차이는 발표 URL만 공개하는지, **현재 Git 저장소의 파일·이력 전체를 공개하는지**다. Pages에서 웹에 올릴 파일만 골라도 PUBLIC 저장소의 다른 파일·과거 커밋은 GitHub에서 볼 수 있다. 공개 전환과 Pages 활성화도 별도 작업이다. [GitHub의 공개 전환 범위](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/managing-repository-settings/setting-repository-visibility).

## 실제 파일과 이력

## 연구 자료의 권리 확인 범위

[예제 credit](../../assets/CREDITS.md)는 Pexels 사진·자체 SVG를 재사용 예제 자산으로 나누고, 연구 사진/영상 프레임은 별도 원권리자 비교 증거로 구분한다. [전반 조사](../review-20261023/research/general.md), [아시아 조사](../review-20261023/research/asia.md), [서구 조사](../review-20261023/research/west.md)도 출처·촬영자/제공사·부분 확인 범위를 기록하고 연구 원본을 자유 사용 예제 자산으로 옮기지 않는다고 적었다.

확인한 기록은 **출처·credit·연구용 수집과 비교 범위**다. 보도사진·외부 영상 캡처·행사 페이지/참석기 HTML 원문 보관물 전체를 PUBLIC 저장소에 재배포할 포괄 허락을 확인한 기록까지는 찾지 못했다. 그렇다고 권한이 없거나 공개가 위법하다고 확정하지 않는다. 연구 전체도 공개하려면 각 자료를 그대로 포함할지, 원문 링크·자체 분석 중심으로 정리할지 결정하고 해당 범위의 조건을 확인하면 된다.

최신 트리에서 연구 파일을 지워도 기존10커밋에 있는 연구 원본까지 사라지지는 않는다. 과거 자료를 공개하고 싶지 않다면 현재 이력까지 공개하는 방식과 맞지 않으므로, 정리한 새 공개 이력/별도 저장소 또는 승인받은 이력 정리를 검토한다. 이 조사에서는 삭제나 이력 변경을 하지 않았다.

## PUBLIC과 오픈소스 라이선스는 별개

현재 추적 파일에서 `LICENSE`/`COPYING`/`NOTICE`류 파일은 없었다. **라이선스 파일이 없어도 저장소를 PUBLIC으로 바꾸거나 Pages를 켤 수 있다.** 다만 누구나 보는 것과 다른 사람에게 수정·재배포를 허용하는 오픈소스 라이선스를 정하는 일은 다르다. GitHub는 공개 저장소를 볼 수 있고 fork할 수 있다고 설명하지만, 일반적인 사용·수정·재배포 조건을 주려면 라이선스를 명시하도록 안내한다. [GitHub 라이선스 공식 설명](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository).

도구를 재사용 가능한 오픈소스로 배포하려면 자기 코드의 라이선스를 선택하고, 외부 사진·연구 원문은 별도 조건을 따른다고 구분하는 편이 분명하다. 자기 코드에 라이선스를 붙이는 것으로 외부 사진·기사/웹 원문의 권리 조건까지 일괄 바뀐다고 안내하지 않는다. 이 문서는 법적 권리 판정이 아니다.

## 다른 담당에게 제기할 반론

기술 담당의 “기존 repo PUBLIC+Pages가 가장 단순하다”는 판단은 **전체 공개 의도**라면 맞다. 그러나 “발표 링크만 필요”라는 범위에 현재383파일·연구310파일·작업로그·과거10커밋 공개까지 자동 포함되는지는 다른 결정이다. Pages 배포 폴더를 줄여도 PUBLIC Git 원본은 숨겨지지 않으므로 이 경계를 먼저 분명히 하자는 반론이다.

도구·연구 전체를 공개하려는 조건이라면, 현재 가상 노트 제거·별도 배포 저장소·공개 viewer를 필수 보안 절차로 요구하지 않겠다.

## 직접 협의 결과

[기술 담당 초안](current-repo-pages-draft.md)을 실제로 읽었다. 기술 담당은 기존 전체 구조에서 참조129개가 유지되므로 패키저·노트 제거를 공개의 필수 조건으로 삼을 이유가 있는지 반론했다. 본인이 현재 노트와 전체 공개 의도에서는 필요하지 않다고 수용했다. 반대로 기술 담당은 본인의 “발표 링크 공개가 Git 전체 이력 공개 의도는 아니다”라는 반론을 수용했다. PUBLIC 저장소에서 Pages artifact만 선별해 원본을 숨길 수 없다는 사실과, 라이선스/외부 자료 확인을 기술 불가와 구분하는 데 합의했다.
