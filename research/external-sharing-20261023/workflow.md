# 외부 공유를 위한 실제 발표 흐름 조사

확인일: 2026-10-23. 코드 기준: `f2991dcd5454d570b97d436f018f7aaf44fdf740`(직접 HEAD 확인). 범위: 현재 저장소의 코드·입력·가이드 직접 확인과 발행 기능 제안. 이 문서는 제품 구현·배포 완료 보고가 아니다. 저장소 비공개를 유지하고, 발행한 발표는 링크를 가진 누구나 인증 없이 읽는 조건을 따른다.

## 결론

현재 STAGE는 로컬 작성·재생 도구로 쓸 수 있다. 외부 링크를 제공하려면 **선택한 발표를 독립적인 공개용 폴더로 내보내 정적 호스팅**하는 단계를 추가하는 것이 가장 작다. 원격 실시간 서버나 청중 로그인은 이 첫 단계에 필요하지 않다. 발행자는 호스팅 계정을 최초 연결해야 한다. 청중은 각자 장을 넘기고, 발표자는 기존 로컬 발표자 창과 화면 공유로 진행한다.

현재 폴더를 그대로 올리면 작성용 UI·원문·발표자 노트·연구 파일도 공개될 수 있다. 공개용 산출물은 작성 원본과 별도로 만들어야 한다. 특히 노트는 화면만 숨겨서는 제외되지 않는다.

## 현재 가능·부족

| 단계 | 현재 코드에서 확인한 동작 | 외부 사용에 필요한 차이 |
| --- | --- | --- |
| 작성 | params `content.js` 또는 Markdown 원고로 작성한다. 새 C안 문장도 화면에서 직접 편집한다. | 현재 양식을 그대로 유지한다. 발표별 입력/자산을 선택하는 발행 단계를 붙인다. |
| 미리보기 | 설치 없이 로컬 `index.html`을 열 수 있다. 로컬 HTTP로도 재생한다. | 배포될 파일만 모은 임시 결과를 미리보기해야 원문 상대 경로 실수를 잡는다. |
| 저장 | id+HTML 경로를 키로 브라우저 `localStorage`에 편집본을 저장한다. 원본 서명이 같을 때만 복원한다. 실제 저장소는 브라우저의 origin에도 구분된다. | 이 저장은 서버 발행이 아니다. 공개 viewer는 작성용 편집본을 복원하지 않고 배포한 내용을 보여줘야 한다. |
| 내용 내보내기 | 현재 `rawDeck` 전체를 `content.js`로 다운로드한다. 서버에 쓰거나 원본 파일을 바꾸지 않는다. | 원본 내보내기를 유지하고, 별도의 공개용 발행 산출물을 만든다. |
| Markdown 반영 | `slides.md` → `content.js`와 `index.html` 단방향이다. 화면 편집의 Markdown 역변환은 없다. | 단기에는 Markdown을 원본으로 정하고 화면 수정은 원문에도 반영한다. params 사용자는 내보낸 `content.js`를 원본으로 삼는다. 이 차이를 발행 안내에 적는다. |
| 자산 | 생성 HTML은 저장소 공통 JS/CSS와 사진을 상대 경로로 참조한다. 생성기가 미디어 파일 누락은 확인한다. | 선택한 발표와 사용 자산·런타임·필요 크레딧을 한 폴더에 복사하고 경로를 다시 쓴다. 현재 생성 폴더 하나만 업로드하면 완결된 발표가 아니다. |
| 발표자 | 같은 브라우저의 원래 창과 팝업이 `opener`/`postMessage`로 장·테마·타이머·내용을 동기화한다. 노트와 다음 장을 보여준다. | 로컬 발표자 기능은 유지한다. 다른 기기의 청중에게 장을 동시에 넘기는 서버 기능은 현재 없다. |
| 청중 링크 | `#4` 등으로 시작 장을 지정할 수 있고 각자 넘겨 볼 수 있다. | 공개 정적 URL을 발급한다. viewer에서 작성·내보내기·초기화·발표자 버튼을 제외하고 읽기/탐색·전체 화면을 남긴다. |
| 노트 | `notes`가 원본 `content.js`에 포함된다. `?presenter=1`만으로 노트 화면을 렌더링한다. 토큰은 창 간 메시지 확인용이다. | 공개 데이터에서 노트를 제거한다. 작성본의 전체 데이터·숨은 확장 필드도 복사하지 않고, 렌더러가 표시하는 필드만 명시적으로 투영한다. |
| 업데이트 | 원본이 달라지면 `sourceSignature`가 달라져 오래된 브라우저 편집본의 자동 복원을 건너뛴다. 원본은 자동 교체하지 않는다. | 같은 공개 URL의 파일을 새 발행본으로 교체하고, 버전/해시로 확인한다. 이미 열린 청중 탭의 자동 갱신은 별도 기능이며 첫 단계에는 새로고침으로 명시한다. |
| 오프라인/PDF | 런타임은 제3자 라이브러리 없이 작동한다. 로컬 자산을 함께 두면 파일 재생이 가능하다. PDF 인쇄는 발표자 영역을 제외한다. | 온라인 링크를 한 번 열었다고 오프라인이 보장되지는 않는다. 현재 service worker는 없다. 로컬 패키지와 PDF를 백업으로 보관한다. PDF는 동영상 재생을 대신하지 않는다. |

## 사용자에게 보일 첫 번째 흐름

1. 기존 방식으로 내용을 작성하고 로컬에서 미리 본다. 화면에서 바꿨다면 params는 내용을 내보내 원본으로 교체하고, Markdown은 원문에도 반영한다.
2. 공개 폴더를 만드는 명령으로 선택한 발표를 패키징한다. 예시 UX는 `node scripts/package-deck.cjs <원본> <출력폴더>`이며, 이 명령은 아직 구현되지 않았다. 성공 시 배포 폴더·제외한 노트·발행 버전을 보여준다.
3. 그 폴더만 정적 호스팅에 올린다. 최초 계정 연결 뒤에는 패키징·검증·업로드·같은 공유 링크 출력을 별도의 통합 발행 명령으로 묶는 것을 목표로 한다. 특정 호스팅에 종속되는 입력 형식은 추가하지 않는다.
4. 발급받은 HTTPS URL을 청중에게 공유한다. `#4` 같은 시작 장 링크도 쓸 수 있다. 청중은 자기 속도로 넘겨 본다.
5. 발표자는 노트가 남은 로컬 원본과 발표자 창을 사용한다. 행사장 화면 또는 화상회의에는 원래 슬라이드 창만 공유한다. 청중에게 공개한 파일에는 노트가 없다.
6. 수정 후 같은 명령으로 새 버전을 만들고 같은 사이트에 재발행한다. 기존 URL은 유지하고, 열린 탭은 새로고침하면 새 버전을 읽는다. 이전 발행 산출물은 되돌리기에 사용한다.

발행을 버튼으로 더 줄이는 일은 후속 편의 작업이다. 현재 브라우저가 내보내는 파일은 `content.js` 하나이며 사진·동영상을 ZIP에 모으지 않는다. 로컬 폴더를 선택받아 미디어를 읽고 공개용 ZIP을 만드는 별도 기능이 필요하므로, 이미 되는 기능처럼 안내하지 않는다.

Console·Network 오류가 없고 모바일 읽기·PDF를 확인한다. |

필드 투영은 모델의 오류 복구/알 수 없는 필드 보존 동작과 분리한다. [현재 모델](../../deck-model.js)은 편집·내보내기를 위해 원문을 보존한다. 이를 전역 변경하면 사용자 원본을 잃을 수 있으므로 공개 데이터 생성에만 새 투영을 적용한다.

## 범위와 확인하지 않은 것

- 이번 작업은 코드 조사와 실행 계획이다. 새 packager·viewer·발행 버튼·호스팅 프로젝트는 만들지 않았다.
- 비공개 Git 저장소와 공개 정적 사이트는 다른 공개 범위다. Git push 성공만으로 외부 발표 URL이 생기지는 않는다.
- 공개 링크는 인증 없는 정적 열람이며, 검색 노출 제한·다운로드 제한·원격 동시 진행을 제공한다는 뜻은 아니다.
- 서비스 선택·공식 한도·계정 가용성은 [배포 조사](deployment.md)에서 확인하고 [취합안](synthesis.md)에 통합한다.
