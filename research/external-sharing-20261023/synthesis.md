# STAGE 외부 발표 도구화 — 엔지니어팀 취합안

2026-10-23 · 코드 기준 `f2991dcd5454d570b97d436f018f7aaf44fdf740` · 상태: 조사·구현 계획. 공개 배포를 실행하지 않았다.

## 추천

**기존 로컬 작성 도구를 유지하고, 선택한 발표만 공개용으로 패키징해 Cloudflare Workers Static Assets에 올린다.** GitHub 원본 저장소는 비공개로 유지하고, 청중은 발급받은 HTTPS 링크를 로그인 없이 연다. 첫 단계는 각자 장을 넘겨 보는 정적 발표다.

Workers를 기본으로 권하는 이유는 현재 제품이 HTML·JS·CSS·사진으로 재생되며, Cloudflare도 신규 프로젝트를 Workers에서 시작하도록 안내하기 때문이다. 서버 코드를 추가하지 않는 정적 전용 구성을 사용한다. 정적 자산 요청은 무료·무제한이고 자산 저장 추가 요금이 없다. 이는 함수·DB·동기화 서버를 추가할 때의 비용까지 포함하는 표현이 아니다. [공식 신규 프로젝트 권고](https://developers.cloudflare.com/pages/), [정적 파일 동작](https://developers.cloudflare.com/workers/static-assets/), [정적 자산 과금](https://developers.cloudflare.com/workers/static-assets/billing-and-limitations/).

브라우저에서 폴더/ZIP을 끌어다 올리는 절차가 더 중요하면 **Pages Direct Upload**가 차선안이다. 원본 저장소 공개 전환이나 GitHub 요금제 변경은 기본안에 필요하지 않다. 세부 비교·파일 크기 제한·공식 근거·계정 현황은 [배포 보고](deployment.md)에 뒀다.

## 현재 제품에서 확인한 핵심 차이

| 현재 | 외부 발표 도구의 첫 결과 |
| --- | --- |
| 화면 편집은 자기 브라우저에 저장되고, 내보내기는 `content.js` 다운로드다. 서버 원고는 바뀌지 않는다. | 확정한 원고와 자산을 발행하면 같은 공유 URL의 배포본이 바뀐다. 청중은 새로고침으로 새 버전을 읽는다. |
| 예제 폴더는 공통 JS/CSS와 사진을 상대 경로로 참조한다. Markdown 생성은 HTML·내용 파일만 만든다. | 발표 하나의 런타임·표시 데이터·사용 사진/영상·크레딧을 독립 폴더로 모은다. 저장소 구조 없이 재생한다. |
| 노트가 `content.js`에 함께 실리고 `?presenter=1`에서 보인다. 예제 7장 모두 노트가 있다. | 공개 데이터는 렌더러의 표시 필드만 투영해 생성한다. 노트·원문·알 수 없는 확장 메모·연구 자료를 포함하지 않는다. |
| 발표자 창은 같은 브라우저의 원래 창과 `postMessage`로 연결된다. | 발표자는 노트 있는 로컬 원본/팝업으로 진행한다. 청중 링크는 독립 열람이며 다른 기기의 장을 동시에 넘기지는 않는다. |
| 공개 서버에 그대로 올리면 청중에게도 작성 UI와 각자 로컬 편집이 남는다. | 기존 렌더러에 작은 공개 모드를 추가해 읽기·탐색·전체 화면만 제공하고 작성용 저장본을 복원하지 않는다. |

코드와 실제 입력을 직접 확인한 결과다. 7개 미디어 참조는 고유 사진 6개이고 모두 로컬에 있다. 데이터·런타임·사진의 현재 크기는 약2MB 범위의 발행본을 만들 수 있는 수준이다(최종 패키지 생성 전 추정). [코드·입력 조사와 상세 수용 기준](workflow.md), [사진·파일 실측](evidence/deployment-local.json), [원본 조사 영수증](evidence/workflow/source-audit.json).

## 실제 사용 순서

**첫 외부 링크(P0):** 로컬 작성 → 미리보기 → 공개 패키지 생성 → 결과만 업로드 → 고정 HTTPS 링크 공유 → 수정 후 같은 사이트 재발행.

1. params 또는 Markdown으로 작성한다. 화면 편집을 썼다면 params는 내보낸 파일을 원본에 반영하고, Markdown은 수정 내용을 원문에도 옮긴다. 현재 화면 편집은 Markdown으로 역변환되지 않는다.
2. 새 공통 패키저가 발표 하나를 검증하고 공개용 결과만 만든다. 이 패키저는 **구현할 작업**이며 현재 명령이 아니다.
3. 발행자가 Cloudflare 계정을 최초 연결한 뒤 결과 폴더를 배포한다. 청중에게는 계정이 필요 없다. 발표를 보기 위해 로컬 서버나 발표 컴퓨터를 켜둘 필요가 없어진다.
4. 고정 주소를 공유한다. `/talks/<slug>/index.html#4`처럼 장 직접 링크를 유지한다. 첫 주소는 제공되는 호스팅 도메인을 사용하며 실제 계정·사이트 이름은 아직 정하지 않았다.
5. 발표자는 노트 있는 로컬 원본에서 발표자 창을 열고 원래 슬라이드 창을 행사장/화상회의에 공유한다. 청중에게 준 정적 링크는 각자 열람용이다.
6. 수정 후 재패키징·재배포한다. 같은 URL을 유지하고 열린 청중 탭은 새로고침한다. 발행 버전/파일 해시로 확인하며 이전 버전으로 내용과 자산을 함께 되돌릴 수 있게 검증한다.

첫 단계는 **발표 1개당 Worker 프로젝트 1개**로 분리한다. 새 발표는 별도 대상 이름을 쓰고, 재발행은 해당 프로젝트만 갱신해 다른 발표 링크를 보존한다. 이후 한 사이트에 여러 발표를 모을 때는 전체 발행 목록을 유지하며 선택한 발표만 바꾸는 패키징이 필요하다. 발표 A·B를 발행한 뒤 A만 수정해도 B의 URL·내용·자산이 그대로 남는 것을 수용 기준으로 둔다.

**반복 발행 편의(P1):** 계정 연결을 한 번 마친 뒤 `검증 → 패키지 → 업로드 → 같은 링크 출력`을 한 명령으로 묶는다. 다음 편의 작업은 현재 편집 내용을 입력으로 받는 `공유용 ZIP 만들기`와 공개 미리보기다. 이때 브라우저에 로컬 사진 폴더를 선택받는 절차도 구현해야 한다. 두 기능 모두 현재 제공하는 것으로 안내하지 않는다.

## 구현 책임과 완료 조건

현재 팀은 실제 매니저1명과 실무자2명으로 구성했고, 작성·사용 흐름 담당이 초기 분석과 최종 취합을 수행했다. 다음 구현에서는 역할을 아래처럼 나누면 된다. 이는 작업 명세이며 구현 착수·완료를 뜻하지 않는다.

| 책임 | P0 작업 | 완료 판정 |
| --- | --- | --- |
| 패키징·배포 엔지니어 | 공통 검증/선언된 미디어 순회를 재사용한 공개 packager, 자산 수집·경로 재작성·사진 credit·manifest, 발표별 정적 전용 배포 대상과 발행 절차 | 저장소 바깥 결과 폴더만으로 재생된다. C예제7장·고유사진6개가 외부 HTTPS에서 열린다. 누락 파일/공개에 쓸 수 없는 `file:` URI는 정확한 경로로 실패하며 이전 발행본을 유지한다. 발표 A만 재발행해도 별도 발표 B의 링크·내용·자산이 보존된다. |
| 작성·viewer 엔지니어 | 기존 런타임에 명시적인 공개 모드 추가, 표시 필드만 투영하는 데이터 경계, 작성/공유 UI·저장 흐름 분리 | notes/확장 필드의 표식 문장이 공개 결과 전체에 0개다. 원본은 그대로 보존한다. 공개 URL에서 편집 저장·발표자 진입·원문 링크가 없고, 기존 로컬 저장본으로 공개 내용이 바뀌지 않는다. |
| 매니저/통합 검증 | 기존 작성·C안 회귀 확인, 공개 파일 목록·실제 외부 URL·재발행·복구 독립 확인 | 청중 로그인 없이 서로 독립된 브라우저에서 탐색·읽기·사진·장 직접 링크가 동작한다. localhost를 꺼도 열린다. 문장과 사진 변경 후 같은 URL 새로고침으로 최신본을 확인하고, 복구 시 이전 내용/사진을 확인한다. Console·Network 실패0, 모바일 읽기·PDF를 확인한다. |

설명서·입력 계약·기존 원본 내보내기를 호스팅 업체에 묶지 않는다. 공통 패키지 산출물을 배포 어댑터가 소비하게 해 서비스 변경이나 로컬 오프라인 보관에도 재사용한다. 서버 코드·로그인·DB·공동 편집을 P0에 추가하지 않는다.

## 지금 필요한 결정과 남은 한계

공개 범위는 사용자가 정한 **“링크가 있으면 누구나 열람”**으로 확정했다. 청중 로그인·별도 도메인 구입·저장소 공개 전환의 추가 결정은 필요하지 않다. 실제 첫 배포에 필요한 외부 단계는 발행자의 Cloudflare 계정 연결과 대상 사이트 식별이다. 현재 계정 자체의 존재·로그인·권한·subdomain은 미확인이다. 로컬에 Wrangler/배포 설정이 없다는 관찰을 계정 부재로 단정하지 않는다.

현재 구현한 기능은 로컬 작성·발표이며 **공개 packager/viewer·외부 링크·반복 발행 명령은 아직 없다.** 이 보고서에서는 코드 조사·공식 문서 확인·구현 명세까지만 완료했다. 서비스 설정·CLI 설치·배포는 실행하지 않았다. Git commit/push와 공개 사이트 발행은 별도 작업이다.

원격 청중의 자동 장 따라오기·공동 편집·온라인 편집의 즉시 서버 반영은 후속 요구다. 현재 발표자 팝업을 그 기능으로 설명하지 않는다. 온라인 링크의 자동 오프라인 저장도 현재 없으므로 중요한 발표는 로컬 폴더와 PDF 사본을 함께 보관한다. PDF는 동영상·상호작용을 재현하지 않는다.
