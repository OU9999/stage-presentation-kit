# LLM Wiki 26장 시각 재점검과 교정 명세

2026-11-02 · 디자인 실무 B `/root/design_manager/audit_designer` · 단독 작성/양 실무 취합 담당

## 판정과 범위

**26장 재점검은 수행했으며 본편 전체 시각 승인은 아니다.** 현재 정지 화면에서 10·17·18·20·24장은 `needs-changes`(개선 필요)다. 나머지 21장은 아래에 명시한 정지 화면·역할·위계 범위에서 `approved`(승인)다. 실제 본편 교정은 이번 파일에 구현하지 않았으므로 5장의 상태를 승인으로 바꾸지 않는다. 발표 현장·사람 대상 이해 실험·모션·작은 viewport·읽기 모드는 `unreviewed`(미확인)이며 이번 승인 범위에 포함되지 않는다.

승인은 검정 배경, 도식 수, 빌드 성공, 레이아웃 개수의 결과가 아니다. `stale`(오래된 근거)는 검수 뒤 관련 입력이 바뀌어 그 판정을 현재 승인에 쓸 수 없다는 뜻이다. 개선 필요는 유효한 재점검의 결과이며 미확인이나 오래된 근거와 다르다.

기준은 확정 [RESEARCH.md](../research/RESEARCH.md), SHA256 `783a30e20c7ac2ae640a862768c13aab77b9fde07134cfb4c793d5f78ec7294e`이며, 최신 사용자 지시가 우선한다. 독립 초기 감사에서는 원고 전체와 연구/실무 취합을 읽고 현재 전장4시트·26장 원본PNG·DevDay4보관프레임을 `view_image`로 직접 확인했다. 독립 초기 산출을 먼저 작성한 뒤 상대의 DESIGN 재구성안 전체를 읽고 직접 반론·대조했다.

## 입력과 실제 확인 근거

- 대상 원고 [slides.md](../../../talks/llm-wiki/slides.md) SHA256 `6df65ff95f74d48df3845d212d4bd36b111980e077d9ff332299c9bba7728b09`, 시작 HEAD `2a95f37`.
- 캡처·측정 정본 [manifest.json](../evidence/before/manifest.json), 제품 입력 [input-hashes.json](../evidence/before/input-hashes.json). 초기 감사 시 111개 입력이 모두 실재하고 해시가 일치했다. 이 가운데 `talks/`98개를 포함한다. 저장소 루트 `test.md`는 없지만 `talks/llm-wiki/test.md`는 실재한다. 두 경로를 혼동하지 않는다.
- 전체 흐름: [1–8장](../evidence/before/contact-01-08.jpg), [9–16장](../evidence/before/contact-09-16.jpg), [17–24장](../evidence/before/contact-17-24.jpg), [25–26장](../evidence/before/contact-25-26.jpg). 장별 원본 근거는 아래 26행에 연결한다.
- 원본 DevDay 보관프레임: [Keynote23:00](../../evidence/color-devday/keynote-23m00.png)의 의미별 색과 병렬 범주, [24:15](../../evidence/color-devday/keynote-24m15.png)의 단일 이름 전환, [48:30](../../evidence/color-devday/keynote-48m30.png)의 큰 실제 인물 이미지와 짧은 설명, [Codex20:00](../../evidence/color-devday/codex-20m00.png)의 큰 핵심 문장과 의미색을 직접 보았다. 이번에 영상을 재생하거나 전편 빈도·공식 HEX·제작기술을 측정하지 않았다.
- 캡처 당시 DESIGN SHA는 기존 기준의 이력이며, 재구성한 DESIGN을 읽은 검토 SHA는 최종 대조 절에 별도로 기록한다. 기준 파일의 변경을 묵시적으로 승계하지 않는다. 최종 manifest는 `presentation-stage-only`, viewport1440×1000·DPR1, stage1344×756이며 각 측정과 PNG가 같은 invocation에 대응한다. 갱신된4시트와26장 원본PNG 전체를 다시 직접 읽었다(필수 위험6장 포함). 최종 입력 재계산은111개 중 DESIGN만 달라졌고 나머지110개는 일치·누락0이다. 기존 DESIGN 해시는 덮어쓰지 않았다.

기술상 이미지 누락·DOM 경계 초과0이라는 root의 측정은 화면 판정과 별개다. 아래 이유는 실제 보인 메시지·기하·타이포·읽는 순서에 근거한다. 내용의 외부 사실성 전체를 새로 검증한 문서는 아니다.

## 장별 교정 계약

다음은 **미구현 교정 명세**다. C04는 승인된 장의 선택 제안이고, C10·C17·C18·C20·C24만 제품 전체 시각 승인을 위해 해결할 필수 교정 대상이다. 본편 교정은 이번 작업 범위 밖이며, 이 목록은 이번 예방·기록 작업의 완료 조건으로 구현을 요구하지 않는다. 공통 CSS 변경이나 전면 재작성 없이 해당 장/해당 SVG의 위계를 먼저 조정한다. 선택한 구현이 의미를 유지하면서 아래 이해 문제를 푸는지 후속 화면으로 판정한다. 여기서 예시 문구는 제안이며 내용 삭제나 의미 축소의 허가가 아니다.

### C04 · 승인 유지, 선택적인 주장-지원 명료화

- 재판정: 초기에는 두 동위계 열이 비교 대상으로 보인다고 판단했으나, A와 매니저의 반론 뒤 새 원본을 다시 읽었다. 두 표제가 이미 필요한 맥락/위키의 지원을 구분하므로 현재 정지화면 범위는 승인한다. 아래는 추후 문구나 대상이 바뀔 때 쓸 수 있는 선택 제안이며 필수 교정·자동 실패 조건이 아니다.
- 주역/순서: `내 상황·선호·이전에 선택한 이유` → 문서로 정리 → 필요할 때 다시 읽기. 한 방향 관계를 중심에 둔다. 제목은 주장을 맡고 도구 예시는 마지막 보조 출처로 낮춘다.
- 구현 후보: 두 열을 유지한다면 가운데 명시적 관계와 크기 차이를 주고, 기능 설명을 더 큰 도착점으로 한다. 단순히 화살표만 붙여 위계가 그대로인 상태는 충분하지 않다.
- 보존: 모든 맥락 항목, 필요할 때 재읽기, OpenClaw/Hermes 예시와 링크. 다른 도구보다 위키가 우월하다는 비교를 새로 만들지 않는다.
- 검수: 발표 전체 화면1440×1000,960×900에서 3–5 연속 및 원본 도식 실배치 크기. 읽기 모드에서 링크와 문장 의미 보존을 확인한다. 두 크기의 후속 캡처는 아직 미확인이다.

### C10 · 관계도와 세 설명층의 경쟁

- 이해 문제: Ingest의 소화/연결이 새로운 동작인지9장의 연결망을 반복한 것인지 첫 시선에 분명하지 않다. 바깥 제목·내부 제목·하단 굵은 설명이 주역을 나눈다.
- 주역/순서: 제목의 한 주장 → 같은 세 메모를 읽고 나눔 → 요약 입구와 기존 개념/비교의 연결 → 현재 계획 및 목차/링크 갱신. 세 설명층은 이 순서를 지원하는 위계로 통합한다.
- 구현 후보: SVG 내부 제목을 보조 설명으로 낮추고 바깥 제목과 중복되는 말을 줄이되, 읽기→나누기→갱신하기 문구는 그림 가까운 순서 안내로 유지한다. 연결망과 노드 의미를 크게 유지한다.
- 보존: 세 원자료, 자료 요약/개념·비교/현재 계획 노드, 연결선, `자료 읽기→내용 나누기→문서·목차·링크 갱신하기`. 본편9도식 중 해당 도식을 빼지 않는다.
- 검수: 8–11 전체 흐름과10장1440×1000/960×900, SVG 원본과 실제 contain 배치 크기. SVG만 확대해서 통과시키지 않는다.

### C17 · 어려움·대응·결과를 구별

- 이해 문제: 개인별 기준 차이(현상), 질문부터 적기(대응), 재사용 방향(목적)이 같은 세 범주로 제시된다.
- 주역/순서: `목적과 경험에 따라 묶는 기준이 다름` → `왜 골랐고 어떤 질문을 풀려는가?` → 다시 쓸 방향. 가운데 질문을 중심으로 원인/결과가 지원하도록 한다.
- 구현 후보: 큰 질문 한 문장과 그 앞뒤의 짧은 근거를 비대칭으로 배치하거나, 세 문구의 역할을 원인/판단/쓰임으로 명시한다. 장을 나누거나 문장을 버릴 필요는 없다.
- 보존: 동일 자료라도 목적/경험에 따라 다름, 선택 이유, 풀 질문, 목적 없는 수집의 어려움. 16의 선택 이유와18의 직접 기록으로 이어지는 의미를 보존한다.
- 검수:16–19 연속과17장1440×1000/960×900. 가운데 질문이 먼저 읽히며 현상과 대응이 구분되는지 정지화면으로 판단한다. 청중 이해 효과를 실험했다고 쓰지 않는다.

### C18 · 사람이 직접 쓰는 목적과 판단

- 이해 문제: 사람의 직접 목적/판단이 핵심인데 AI정리 구분과 동위계로 나뉘어 책임의 주역이 약하다.
- 주역/순서: `목적과 내 판단은 내가 적습니다`를 중심에 두고 `누구를 위해 무엇을 만들지`와 `감정·생각·판단·선택 이유`를 직접 기록의 구체 항목으로 읽는다. 이어서 원문/내 기록/AI정리의 구분을 읽는다.
- 구현 후보: 사람이 쓰는 두 내용은 같은 주역군으로 묶고, AI정리 구분은 낮은 위치의 경계/보조 설명으로 둔다. AI를 주역으로 그리는 큰 장식이나 사유를 생성해 준다는 표현은 넣지 않는다.
- 보존: 사람 목적, 감정/생각/판단/선택 이유, 원문/내 기록/AI요약과 해석 구분. 핵심 사용자 맥락을 대본으로만 숨기지 않는다.
- 검수:17–19·6장 역할 분담과의 차이,18장1440×1000/960×900. 한 시선에서 사람이 직접 쓰는 무엇/왜가 보이고 구분 문구도 읽혀야 한다.

### C20 · 실제 활동안 문서의 정체성과 읽을 부분

- 이해 문제: 실제 만든 것은15분 활동안인데 `실제 결과`가 실행/효과로 넓게 읽힐 수 있다. 하단 작은 주의와 caption 반복 때문에 문서 성격과 읽어야 할 관계가 약해진다.
- 주역/순서: `정리한 지식으로 만든15분 활동안 발췌` 같은 정확한 대상 표기 → 활동안 목표 → 두 메모 확인/원자료→개념→비교를 따라 읽기 → 후속 질문/남은 확인. `실행·모델 생성시간 실측 아님`은 대상과 가까운 읽을 수 있는 보조 표기.
- 구현 후보: 밝은 문서를 그대로 크게 두고 바깥 제목/문서 제목의 중복을 줄인다. 목표와 관계를 따라 읽는 행에 위계를 주되 네 시간 구간과 내용을 모두 유지한다. 작은 주의/자료 설명의 중복은 통합해 읽을 수 있는 한 보조층으로 둔다.
- 보존: 밝은 면,15분 활동안 제목·목표·메모팩 출처,0–2/2–6/6–11/11–15분 네 구간과 활동, 비실측 주의, 실제 진행안 링크. 활동안 예시를 실제 참가·실행 성과로 주장하지 않는다.
- 검수:19–21 흐름,20장1440×1000/960×900, SVG 원본/실배치와 읽기 모드 링크. 목표·관계 행·비실측 표기가 실제 배치에서 읽히는지 확인한다. 밝은 면 제거는 해결 기준이 아니다.

### C24 · 첫 행동과 보조자료의 위계

- 이해 문제: 요청4행은 큰 면 안에 있어 이미 주역이다. 그 아래 비슷한 글자 크기의 자료링크 두 행에는 지원 경로라는 층위 표지가 없다. 여러 링크/행동이 있다는 사실 자체를 실패로 삼지 않고, 첫 요청의 예와 보조자료의 성격을 좁게 구별한다.
- 주역/순서: 첫 요청의 목적 → 내 두 자료와 직접 쓴 기록 → 원문/내 기록/AI요약 구분과 연결 → 원자료/변경파일/모르는 점 확인. 이후 예제/읽기/원본보관 링크는 지원 경로로 읽는다.
- 구현 후보: 요청문 중심 면을 유지하고 링크 두 행을 `함께 볼 자료` 같은 보조 성격 아래 묶거나 크기/간격으로 한 보조층을 만든다. 현재 제목이 이미 첫 요청을 안내하므로 별도 행동 표지나 새 버튼은 필수로 추가하지 않는다. 링크를 숨기거나 의미를 읽지 못할 정도로 줄이지 않는다.
- 보존: 요청4행의 모든 요구, 직접 쓴 생각/선택 이유, 예제 팩·자료 읽는 방법·원본 그림/48장 원고 링크. 자료 접근을26장으로만 밀어내지 않는다.
- 검수:23–26 흐름,24장1440×1000/960×900과 읽기 모드. 요청문이 먼저 읽히며 보조자료 라벨/링크도 찾을 수 있어야 한다. 긴 한국어/코드줄 잘림을 기술 검사와 별도로 본다.

## 유지할 반례와 흐름

4장의 승인 유지 역시 동위계2열 자체가 오류가 아님을 보여 준다.17–19·21–22가 모두3열이라는 관찰은 수정 후보를 찾는 단서일 뿐이다. 이번 독립 감사는 **17·18은 교정,19·21·22는 현재 역할 내 승인**으로 구분했다. 19의 세 활용처,21의 세 이점,22의 세 위험은 병렬 범주가 성립한다. 각 장의 표제와 행위가 다르고20장의 밝은 활동안이 사이에서 실제 대상을 제시한다. 17·18을 바꾼 뒤 이 흐름이 달라지면 인접19도 다시 보며, 그때의 화면 없이 미래 구성을 승인하지 않는다.

8–11은 검색 상자→열린 문서관계→소화/갱신 관계→두 문서 비교로 기하와 설명 역할이 달라진다.10장 위계 교정은 필요하지만 `media가4장 연속`이 그 이유는 아니다.1·25·26의 낮은 정보량은 시작·결론·질문의 역할에 맞으므로 모든 장에 주장+도식 또는3열을 강제하지 않는다.

현재26장·본편9도식·그림19개 부록·48장 원문·대본·학습자료와98개talks 입력을 보존한다. 이 문서 작성은 해당 파일들을 편집하지 않는다. 후속 구현은 선택한 교정의 영향 범위와 실제 읽을 의미를 다시 확인하고, 콘텐츠 삭제나 링크 이동을 임의로 묶어 처리하지 않는다.

### 독립 초기 산출과 직접 반론·합의

- A `/root/design_manager/guide_designer`는 기존 DESIGN 정본 재구성의 실질 초안을 먼저 작성했다. B는 연구·원고·화면을 독립 검토해26행과6개 초기 교정안을 먼저 작성했다. B가 A초안145행 전체를 읽었고, A도 B초안 전체를 읽은 뒤 서로 직접 연락했다.
- B→A 반론: 위험17–24보드만 제시하면3열 전체가 실패처럼 읽힐 수 있다.19의 동등 활용처,21의 병렬 동사 이점,22의 대등 위험차원이 실제 승인·보존 반례임을 정본에 한 문장으로 명시하자고 제안했다. A는 이를 수용해 정본 예시에 반영했다.
- A→B 반론1:4장의 두 표제가 이미 필요 맥락→위키 지원을 구별하고, 도구 링크는 마지막 문단이므로2열만으로 실패를 확정할 근거가 약하다. 매니저의 독립 반론도 같았다. B는 갱신된4장 원본을 다시 읽고 수용했다.4장은 승인, C04는 선택 제안으로 낮췄다.
- A→B 반론2:24장의 요청문은 큰 면으로 이미 시각 주역이다. B는 이를 명시하고 C24를 보조자료 두 행의 성격·위계 보완으로 한정했다. 제목이 첫 요청을 안내하므로 새 행동 표지나 버튼 추가는 필수가 아니라는 반론도 수용했다. 링크가 여럿이라는 사실 자체를 실패 규칙으로 삼지 않는다.
- A와 B는17의 현상/대응/쓰임 위계,18의 사람 직접 기록 주역,20의 밝은 활동안과 비실측 정체성 보존에 합의했다.19·21·22 승인/보존,8–11의 기하 차이,1·25·26의 저밀도 대비를 함께 유지한다.
- B는 매니저 [DESIGN_HANDOFF.md](DESIGN_HANDOFF.md) 전체를 읽고 기록 최신성 검사와 제품 시각 승인의 구별, 캡처 당시 기준/재검토 기준 분리, 제품 입력이 달라질 때 재캡처하는 계약에 동의했다. 미확인 상태 코드는 handoff와 `unreviewed`로 맞췄다. 실제 저장 형식/명령 이름은 후속 엔지니어링팀이 결정한다.
