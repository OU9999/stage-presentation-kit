# 리서치 실무 취합: 기준 복구와 재발 방지

2026-11-02 · 취합 담당 `docs_research` · 상대 `visual_research` · 독립 실무 조사·상호 반론·합의 완료, 편집 종료

## 전달할 결론

최초 DevDay 기준과 현재 210행 DESIGN.md 사이에 **기준 부재는 없다**. 기준이 후속 작업의 시작·변경·완료 계약에 연결되지 않으면서, 새 내용 참고자료의 스타일이나 임시 현재값이 다음 작업의 기본으로 승계되는 경로가 확인됐다. 지금 필요한 것은 현재 26장의 내용·핵심 그림·원문 보관을 유지하면서 역할별 위계와 흐름을 재검토하고, 해당 판의 시각 근거가 다음 변경에도 유효한지 확인하는 운영이다.

이 결론은 두 실무자의 독립 조사 뒤 직접 대조한 결과다. 최종 디자인 선택과 제품 수정 승인은 디자인팀·엔지니어링팀의 후속 인수 대상이다. 현재26장 전체의 청중 이해도나 미학을 자동/실험으로 검증했다고 주장하지 않는다.

## 디자인팀 인수 조건

1. 정본의 권한과 역할을 밝힌다. 최신 사용자 지시를 우선하고, 현재 Stage 기본값·역할 리듬·매체 고유면·가독성·허용 변형을 짧게 정리한다. 과거 관찰·현재 의무·새 제안은 구별한다.
2. 현재26장 역할 맵을 이번 감사 기준선으로 만든다. 각 장의 핵심 메시지·역할·증거/대상·시각 중심과 앞뒤 연결을 남기며 본편9도식/전체19도식/48장 원문 보관과 연결을 확인한다. 후속 작은 문구 수정에서는 이 맵을 재사용하고 변경 영향 장·인접 흐름만 갱신한다.
3. 구체 교정 후보를 판정한다. 17–19와21–22의 평준화, 20장의 발췌 정체성·가독성, 24장의 첫 행동·예시 요청·보관 링크의 위계를 실제 화면에서 확인한다. 수정이 필요 없다는 결론도 화면 근거로 설명할 수 있어야 한다.
4. 수정 전후 같은 장에서 무엇을 먼저 읽고 어떤 관계/행동을 이해하게 되는지 설명한다. 카드를 없애거나 색을 추가했다는 사실만으로 승인하지 않는다.
5. 바뀐 장과 영향받는 연속 구간을 현재 revision으로 인수한다. 기능 결과·시각 관찰·미확인 사항을 나누고 명시적인 승인/수정/미확인 판정을 남긴다.

## 엔지니어링팀 인수 조건

1. 시작/완료 진입점에서 기준과 검수 절차를 연결한다. 문서 존재 검사와 파일명 교정만으로 끝내지 않는다. DESIGN 읽은 버전, 변경 범위, 역할/자료 보존, 시각 검토 결과의 위치를 확인 가능하게 한다.
2. 검토 근거의 신선도만 자동 검사한다. 원고·기준·관련 자산·공통 CSS/runtime fingerprint가 캡처/검수 대상과 맞는지, 대상 장·모드·검토 상태가 채워졌는지 검사한다. source가 같아도 SVG/CSS가 바뀌면 근거 재확인 대상으로 삼는다. ‘DevDay 점수’ 같은 미학 수치를 만들지 않는다.
3. build/verify/test의 기능을 분리해 보고한다. 생성물 일치가 시각 승인으로 표시되지 않게 하고, 기존 자동 검사와 변경에 맞는 실제 브라우저/읽기·가독성 확인을 수행한다.
4. 공통 스타일을 바꾸면 해당 레이아웃·테마·긴 한국어·실제 UI·읽기·모션 줄이기 등 영향 범위를 골라 회귀한다. 원고만 바뀌면 변경 장과 앞뒤 흐름을 중심으로 재검토한다.
5. 기존9도식/19자산·48장 보관·대본·학습자료를 임의 삭제하지 않는다. 실제 내용·링크·접근성 의미를 유지하고 현재 파일 부재를 과거 해시로 통과시키지 않는다.

## 우선순위와 제외할 오해

P0는 문서의 권한·작업 진입점·현재판 시각 검토 연결, 26장 역할/보존 대조, 구체 실패 후보 판정이다. P1은 결과를 구현하고 원고/공통자산 변경이 무효화하는 근거를 다시 확인하는 장치다. P2는 재사용 예제·선택적 토큰 도구이며 필요가 입증된 뒤 다룬다.

검정=DevDay 통과, 컬러 개수 할당량, 카드 전면 금지, 같은 layout N장 오류, 장수를 줄이면 개선, 이전 revision 승인 승계, 자동 테스트 수=시각 승인, 최신 DESIGN.md 유행이 기존 정본을 대체한다는 해석은 채택하지 않는다.

## 직접 반론·합의 기록

- A→B: 기존 기준이 이미 살아 있고 후속 변경 계약의 효력 문제라는 독립 관찰 공유. 8–11 media 연속은 유효 반례, 17–19/21–22는 평준화 우려, 20 밝은 문서는 보존한다는 판정 전달.
- B→A: 공식 운영 사례와 현재210행/진입점 대조를 공유. 같은 layout/색 개수의 자동 오류화에 반대하고, 시작·변경·현재판 승인 연결에 동의.
- B는 A 초안 전체를 직접 읽고 최신4 보드를 직접 확인한 뒤 세 가지 반론을 전달했다. 화면 관찰 후 ‘예정’ 문구를 갱신할 것, Stage 기본값의 비협상 표현을 최신 사용자 지시·예외와 연결할 것, 과거 보고서가 revision을 구분한 사실을 보존하고 현재 전체 불합격으로 확장하지 말 것.
- A는 B의 문서 운영 초안 전체를 읽고 P0~P2와 외부 규격 미도입·자동gate 경계에 동의했다. 외부8자료 원문은 B가 확인했으며 A가 독립 재검증한 것으로 쓰지 않기로 했다.
- A→B 반론 두 가지를 채택했다. 사소한 수정마다 전체26장 역할맵을 새로 쓰지 않고 기존맵+변경 영향/인접장만 갱신한다. 원고 revision만 같은 것을 충분한 검수 근거로 삼지 않고 관련 SVG·공통CSS/runtime fingerprint를 결합한다.
- A는 B의 세 반론을 모두 반영해 상태와 직접 관찰 범위를 갱신하고, Stage를 최신 사용자 지시 우선·명시적 변경 전 기본값으로 한정했다. B가 두 반론의 수용과 최종 합의를 직접 회신했다. 양측 실무 산출물 편집 종료 후 매니저에게 인계한다.

제품·원고·DESIGN.md·AGENTS.md·WORK_LOG는 두 실무자의 편집 대상이 아니다. 결정과 결과는 매니저에게 직접 전달하고 root가 공통 로그를 갱신한다. 두 조사 파일과 이 취합 파일의 작성·상호 검토가 완료되었으며 편집을 종료한다. 후속 디자인·엔지니어링 수용은 이후 실제 변경과 현재판 검증을 통해 이행한다.
