# LLM Wiki의 본질·등장 동기·사례 재구성

2026-10-29. 원고 SHA-256: `bec9b35fc7b711651ef55d354ede5b760a2d710650bb2fd7128c83f8657cab7f`.

LLM이 원자료와 기존 위키를 읽어 개념·개체·비교·종합을 작성하고 계속 유지한다는 설명을 발표의 중심으로 복원했다. 사람의 claim 검토·승인과 Node 파일 교정 예제가 패턴 전체를 대신하던 구성을 바꿨다. 비유를 먼저 배워야 본체를 이해하는 구조에서, 정의·문제·기전·활용 사례를 직접 따라가는 구조로 전환했다.

40장 중 기본 경로는 1~28→40이다. 설명·참여 18분과 질문 2분은 배분안이며 실제 낭독 실측이 아니다. 선택 심화 11장의 555초는 별도다. 기본 경로는 28장의 실제 이동 링크로 닫히고 40장에서 심화로 들어갈 수 있다.

## 근거와 사례의 구분

[Karpathy의 고정 원문](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f/ac46de1ad27f92b28ac95459c782c07f6b8c964a)의 본문을 마지막 Note까지 대조했다. 원문은 특정 완제품·표준이 아닌 설계 패턴이다. 등장 동기는 저자가 해결하려는 문제와 설계 선택으로 설명하며 역사적 최초성·자동 정확성·유지비 제로를 주장하지 않는다. 새 엔지니어링 역할은 이 공개 원문에 근거한 검토 역할이며 실제 저자 참여·고용·승인을 뜻하지 않는다.

독서·고객 요구·강의 사례의 파일 문장은 발표팀이 만든 적용 예다. 각각 인물과 주제의 해석, 요청의 차이와 현재 응대, 여러 단원의 공통 개념과 기준 비교를 남긴다. 인물의 자기 설명을 사실로 확정하거나, 고객 요구를 출시 약속으로 바꾸거나, 이전에 없던 오류를 만들어 교정했다고 말하지 않는다. [독서 입력·전후 파일](./engineering/examples/reading.md)·[고객 요구](./engineering/examples/team.md)·[강의 메모](./engineering/examples/course.md)과 제품의 TXT 첨부3개, 학습서·실습의 코드블록을 함께 제공한다.

공개 구현은 고정 판의 코드를 읽은 관찰이다. [Microsoft의 질문·저장 handler](https://github.com/microsoft/llmwiki/blob/e09126f257c1fcf8e63234382748a51cf6a5df7f/packages/vscode/src/chatParticipant.ts#L237)는 저장된 페이지를 읽는 답변 경로와, `/save`가 실제 파일 저장 대신 수동 방법을 안내하는 한계를 구별해 설명한다. 설치 성공·조직 도입 성과로 소개하지 않는다.

[Wright 논문 v1](https://arxiv.org/html/2609.25303v1)은 한 강의 코퍼스의 제한된 QA 실험으로 소개한다. 실제 wiki arm에는 고정된 목표 문맥을 제공하고 RAG arm은 검색하므로 표현 자체의 공정 비교·보편 우위로 읽지 않는다. 학생 학습성과·비용 측정으로 확대하지 않고 본편에 수치 경쟁 그래프를 넣지 않았다.

## 제작·검토

엔지니어링 manager와 두 실무가 독립 원문/현행 원고 감사와 사례/코드/논문 조사를 작성한 뒤 직접 교차했다. 소설의 자기 설명, 팀 질문의 시점, 강의 사례의 없던 오류 서술을 바로잡고 40장 계약을 확정한 다음 같은 담당자들이 실제 원고와 자료를 반영했다. [연구 취합](./engineering/SYNTHESIS.md) · [회의](./engineering/MEETING.md) · [구현 검수](./engineering/REVIEW.md).

작성팀 종료 뒤 별도 manager와 시각/초심자 실무가 전장 보드와 개별 PNG, 원고·대본을 독립 검토하고 직접 교차했다. 본질 설명과 사례의 전달을 막는 차단은 발견하지 않았다. 30장 링크만 단어 분리를 고쳐 새 화면을 재인수했다. 11장 발췌 크기와 39장 카드 위계는 향후 작은 시청창 리허설의 선택 후보로 남겼다. 실제 사람 반응이나 Zoom 송출 실험으로 보고하지 않는다. [후검수와 결정](./post-review/SYNTHESIS.md) · [직접 회의](./post-review/MEETING.md).

- 기본29장 실제 진행, 13장 상담 카드의 동등한 시각 처리, 장내 링크5개·개요40장·발표자 양방향 이동을 확인했다.
- 390px 읽기40장 전문/순서, 자료6개×1440/390px 전문·18px 본문·키보드 메뉴와 코드 스크롤, 읽기 anchor18개의 헤더 가림 없음, 사례TXT3 실제 클릭·다운로드와 바이트를 확인했다.
- 자동 줄 후보 중 38장의 완전한 종결어와 39장의 독립된 복귀 행동 문구는 실물 판단으로 유지했다. 30장의 `고정 코드`는 한 줄로 고쳤다.
- 기존 고정 demo25파일과 ZIP SHA `9c0a83b5bf0a2b22e9c9102ed0d26c81ce683d4fc0589ce96a741f998f6a44f2`는 그대로다. 이 실행을 새 LLM 호출로 바꾸지 않았다.

자료 코드 키보드 검수는 메뉴 닫힘 후 레이아웃이 안정된 다음 검사하도록 대기를 보완했다. 긴 학습서의 첨부는 해당 사례 anchor에서 실제 열었다. 이 검수 절차 보완을 제품 수정으로 집계하지 않는다. 공개 배포 인수는 커밋·푸시 후 DEPLOYMENT 기록으로 연결한다.
