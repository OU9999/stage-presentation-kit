# 독립 3장 storyboard 제안

현재 40장 제품에는 반영하지 않은 평가용 안이다. [독립 판정](senior-review.md)의 17·31·35장 문제를 각각 한 장으로 다룬다. 원래 발표의 한정된 실행 범위를 유지한다. 렌더링된 그림은 구도 제안이며 기존 덱의 최종 픽셀 사양이나 새 공통 템플릿이 아니다.

## 안 1 — 현재 17장: 바뀐 범위를 먼저 읽는다

시각안: [PNG 미리보기](storyboard-17.png) · [SVG 원본](storyboard-17.svg)

- 큰 제목: **‘모든 시스템’에서 ‘이 데모’로 좁힌다**
- 중심 좌우: ‘삭제 / 모든 외부 파일 시스템’, ‘추가 / 이 데모의 파일 수정’. 가운데 작은 ‘범위 교정 →’.
- 실제 문장: 왼쪽 ‘외부 파일을 쓰는 시스템은 모델을 학습하지 않는다.’ 오른쪽 ‘이 데모의 파일 수정은 모델 매개변수 학습을 실행하지 않는다. 외부 파일을 쓰는 시스템에도 별도의 학습 과정이 있을 수 있다.’
- 하단: ‘원문과 주장의 범위를 맞춘 실제 changes.diff 문장 발췌’ 한 줄. 전체 파일 링크는 짧은 보조 텍스트 한 개만 사용한다.
- 정보 선택: 원래 문장을 새 일반화로 뒤집는 것이 아니라 범위를 좁혔다는 변화가 먼저 보이게 한다. 실제 문장은 생략 없이 아래 두 열에 유지한다. 사진은 추가하지 않는다. 사진은 이 차이를 설명하지 못한다.
- 발언: ‘없다를 있다로 바꾼 것이 아닙니다. 어떤 시스템을 말하는지 좁혔습니다.’ 이후 실제 문장을 읽는다.
- 구현 범위: 이번 덱의 제목·문장 순서·강조와 기존 두 열 layout으로 핵심 의도를 구현할 수 있다. 이 그림의 세부 크기까지 동일하게 구현하려면 독립 로컬 SVG를 발표 이미지로 사용하는 별도 선택이 가능하다. 현행 layout API에 임의의 스타일 지정이 이미 제공된다고 전제하지 않는다. 어느 경우에도 공통 엔진 변경이 필수라는 근거는 없다. diff 전체를 별도 앱처럼 상호작용하게 만들 이유가 없다.

## 안 2 — 현재 31장: 숫자마다 무엇을 확인했는지 읽는다

시각안: [PNG 미리보기](storyboard-31.png) · [SVG 원본](storyboard-31.svg)

- 큰 제목: **이번 실행에서 확인한 것**
- 같은 높이의 세 구획: ‘8쪽 / 승인한 교정안 반영 / 기존 5쪽 갱신 + 신규 3쪽’, ‘25개 / 로컬 링크 확인 / 파일을 가리키는지 검사’, ‘10개 / 보존 파일 해시 확인 / 읽기 메모 5 + 초기 페이지 5’.
- 하단: ‘답의 의미 · 검색 누락 · 시간 절약은 이 검사의 결과가 아닙니다.’
- 정보 선택: 단위가 다른 값을 비율·순위·동일 막대 높이로 비교하지 않는다. 각 값은 작업 기록이다. 기존5/신규3은 첫 구획의 내역으로 충분하다. 이 장의 시각적 보상은 높은 점수가 아니라 구체적인 확인 범위를 알게 되는 것이다.
- 발언: 세 구획을 왼쪽부터 읽고 ‘파일 작업을 확인한 것이며 의미 검토는 앞의 원문 대조와 review에 남겼습니다’로 연결한다.
- 구현 범위: 이번 덱의 차트 콘텐츠를 기존 세 열로 교체하면 가능하다. 공통 차트 컴포넌트나 엔진 수정은 필요하지 않다. 같은 축·그래프·애니메이션은 사용하지 않는다.

## 안 3 — 현재 35장: 제목보다 쓸 양식을 크게 둔다

시각안: [PNG 미리보기](storyboard-35.png) · [SVG 원본](storyboard-35.svg)

- 큰 제목: **다음 모임에 다시 쓸 질문 한 줄**
- 가운데 실제 쓰기 양식: ‘자료 A [제목] + 자료 B [제목] → 내 질문 [한 줄]’.
- 그 아래 다음 단계: ‘근거 위치는 다음 모임에 확인: [자료의 어느 부분?]’.
- 예시는 한 줄: ‘RAG 메모 + 지난 Q1 → 다음 답이 고친 파일을 읽었는지 어떻게 확인할까?’
- 하단: ‘질문 한 줄 먼저 · 20초 · 채팅 공유는 선택’. 세 자리를 완성해야 참여한 것으로 보지 않는다. 20초는 원 대본의 계획이며 충분성이 검증된 시간이 아니다.
- 정보 선택: 자료 두 개·질문·근거 위치라는 세 가지를 설명문으로 기억시키기보다 직접 채울 자리로 보여준다. 참가자에게 자료 두 개가 즉시 없으면 최근 읽은 자료 하나에서 질문 한 줄부터 쓸 수 있다고 말로 안내한다.
- 발언: ‘질문 한 줄을 먼저 적고, 자료 제목은 기억나는 만큼 써 보세요. 근거 위치는 다음 모임에 찾아도 됩니다’ 후 실제로 기다린다. 화면에서 답을 대신 써주거나 참여 수치를 표시하지 않는다.
- 구현 범위: 이번 덱의 제목 축소, 예시 축약, 본문 순서 변경으로 가능하다. 빈 칸은 정지된 시각 양식이다. 공통 엔진·입력 저장·참가자 추적·실시간 타이머 기능은 필요하지 않다.

## 우선 조치의 범위 구분

| 조치 | 이번 덱 내용/원고/기존 layout에서 가능한 것 | 공통 엔진 변경 |
| --- | --- | --- |
| 17의 범위 대비 | 제목, 핵심 단어 강조, 실제 문장 좌우 배치 | 불필요 |
| 19의 관계 정리 | 한국어 역할을 먼저, ID를 보조로, 지원 기록 별도 묶음. 기존 관계도 수정 | 불필요. 단계별 공개를 엔진으로 새로 만들 필요는 없으며, 필요하면 정지 장의 내용 선택부터 해결 |
| 31의 검사 결과 | 차트 대신 단위가 명시된 세 열로 표현 | 불필요 |
| 35의 개인 작성 | 큰 양식·구체 예시·한 줄 행동 지시 | 불필요 |
| 12·23의 정답 단서 | A/B 같은 색, 답 링크는 발표 중 시선 경로에서 낮추기, 안내 줄 정리 | 불필요. 키보드/링크 동작을 고칠 요구가 생긴 경우에만 별도 엔진 조사 |
| 7·30의 한국어 위계 | 한국어 의미 우선, 영문/출처는 보조 | 불필요 |
| 34의 사진 의미 | 자료 A/B/C 실제 제목 카드 또는 활동 제목으로 내용 일치 | 불필요 |
| Zoom 크기 검증 | 실제 공유 환경에서 화면과 발언을 점검 | 제품·공통 엔진 변경과 별개의 검증 작업 |

위 안은 구현 허가나 제품 개선 완료 선언이 아니다. 이번 평가에서 확인한 전달 문제에 대한 검토 가능한 대안이다.
