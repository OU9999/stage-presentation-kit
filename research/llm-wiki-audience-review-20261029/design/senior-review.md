### 글자·색·사진·리듬의 통합 판단

큰 제목과 흰 본문은 검은 바탕에서 분명하다. 그러나 Zoom에서는 전체 1344×756 캡처가 참가자의 작은 창으로 줄 수 있다. 원해상도에서 읽힌다는 사실로 모든 하단 경로·영문 출처·보조 회색 문장이 Zoom에서 읽힌다고 보장할 수 없다. 핵심은 제목 크기보다 본문 중 무엇을 실제로 읽혀야 하는지 결정하는 것이다. 17·19·31·35장에서 그 선택이 우선이다.

한국어의 의미 단위로 줄을 끊은 6·21·29장은 좋다. 23장의 오른쪽 안내는 긴 링크 문장이 되어 ‘이’가 줄말에 고립된다. 27장의 출처 링크도 결과 설명과 같은 크기여서 문장 흐름을 늘린다. 파일 ID는 22장처럼 한국어 내용을 동반할 때 추적에 도움이 되지만, 19장의 여덟 ID는 별도의 기억 항목이 된다. 번호를 없애기보다 한국어 역할을 먼저 읽게 한다.

파랑·초록·보라·주황·노랑은 검은 바탕에서 구분되며 화면의 통일감을 만든다. 다만 Q1은 4장에서 보라, 19/22장에서 파랑이고, 초록은 다음 질문·고친 범위·현행 선택·다음 행동을 두루 맡는다. 모든 색에 고정 의미를 요구할 필요는 없지만 선택 화면의 정답 암시는 줄여야 한다. 12·23의 A/B를 동일 색으로 두는 변경은 색을 빼는 미감 취향이 아니라 과제의 공정성에 관한 제안이다.

사진은 1장에서 정서를 열고 34장에서 시각 밀도를 바꾸는 데 쓰인다. 3의 서가 비유는 이해 가능하지만 9는 실제 정보 구별을 보여주지 않는다. 사진 수가 많거나 적어서 좋다고 판단하지 않는다. 현재 덱의 중반에는 사진보다 실제 문장의 전후, 범위 표시, 파일 관계를 시각적으로 보여주는 편이 내용에 더 기여한다.

참여는 A/B 두 번과 자기 노트 한 번이 실제 행동 전환이 될 수 있다. 다만 A/B는 정답의 단서가 많고 같은 B 선택을 반복하여 깊은 판단을 반드시 끌어내지는 않는다. 35장의 자기 자료 연결은 전이 가능성이 가장 크나 실제 반응이나 학습 효과는 아직 알 수 없다. ‘몇 명 참여했다’는 숫자를 만들지 않는다.

### 개선 순서와 검증 조건

1. 17장의 변화 핵심, 19장의 한국어 주 흐름, 31장의 확인 단위, 35장의 쓰기 양식을 먼저 설계한다. 이 네 장은 사례 이해와 적용 행동을 직접 바꾼다.
2. 12·23의 답 단서와 긴 안내 줄을 정리하고, 7·30의 한국어/영문 위계를 조정한다. 34장은 제목과 사진의 정보 단위를 맞춘다.
3. 13–20, 24–28의 연속 구간에서 말로만 풀어도 되는 반복 설명을 찾아 리허설한다. 원래 20분 목표가 유지되는지 manager/root가 확인해야 하며, 시간을 맞추려고 임의로 장수를 먼저 줄이지 않는다.
4. 대표 약한 장을 실제 Zoom 공유 크기와 채팅 패널이 열린 상태에서 확인한다. 참석자가 17장의 무엇이 바뀌었는지, 19장의 어떤 내용이 다음 질문에 쓰였는지, 31장의 검사가 무엇을 확인했는지, 35장에서 무엇을 적는지 설명할 수 있는지 묻는다. 이는 향후 검증 제안이며 완료된 사용자 테스트가 아니다.

### 판단 한계

이 문서는 정지 화면과 대본 기반의 전문가 평가다. 실제 음성 속도·머무는 시간·전환·발표자 표정·네트워크 압축·채팅 반응을 관측하지 않았다. 현재 미감의 방향을 나쁘다고 단정하지 않지만, 공식 발표 네 프레임과 검은 배경/큰 글자/색상만 닮았다는 이유로 같은 완성도라고 보지도 않는다. 시각 증거로 확인한 결론은 ‘기초 정돈은 강함, 핵심 장의 정보 선택과 Zoom 행동 화면은 추가 설계가 필요함’이다.

### 청중 모의 결과를 읽고 바꾼 우선순위

**8~10장에서 LLM·사람·오늘의 파일 실행 관계를 구체화하는 일을 초기 판정보다 높은 우선순위로 올린다.** 초기에는 10장의 범위 구분을 명료한 장으로 평가하고 Node라는 실행 용어의 위계만 지적했다. 모의청중 A/B는 8장의 설계 설명, 10장의 고정 승인 Node 적용, 32장의 실제 운영 역할이 떨어져 있어 ‘LLM은 어디서 어떤 일을 하나’가 늦게 결합된다고 남겼다. B의 초기 판정도 같은 우려였다. 실제 화면/대본을 다시 대조하면 이 관측은 지원된다. 따라서 32장 분담의 짧은 예고와 최종 파일 한 페이지를 8~10장 근처에서 함께 읽는 안을 우선 권한다.

구체적으로 ‘자료 두 개 읽기 → LLM이 설명·연결·수정 후보 제안 → 사람이 문장/근거 범위 대조 → 승인한 파일 갱신 → 다음 질문에서 다시 읽기’를 한국어 동사로 보여준다. ‘오늘 화면은 사람이 준비한 승인 결과를 Node가 적용한 예’라는 상태를 붙인다. 실제 LLM 실행을 새로 했다고 꾸미지 않는다. 이 변경은 이번 덱의 내용 선택·기존 도식·발언 순서로 가능하며 공통 엔진 변경이 필요하지 않다.

19장의 식별자 부담, 12/23의 쉽게 드러나는 답, 31장의 성과 지표 오인 가능성은 초기 시각 판단을 유지한다. 35장은 청중 A와 B의 시작 준비가 다르다는 결과를 반영해 ‘질문 한 줄 먼저, 자료 제목은 기억나는 만큼’으로 성공 기준을 낮춘다. 자료 두 제목·질문·근거 위치를 20초에 모두 완성해야 한다고 보이게 하지 않는다. 근거 위치는 다음 모임에 확인해도 된다는 분기를 둔다.

청중 결과는 두 동일 모델 역할의 모의 워크스루이고 일부 초기 선노출이 명시돼 있다. 실제 참석자의 재미·학습·만족·참여나 대표 집단의 반응으로 바꾸지 않는다. A는 도구에서 시작하는 실행 안내가 부족하다고, B는 한 질문을 동료와 검토하는 시작은 가능하다고 보았다. 이 차이는 유지한다. 실제 도구 조작 체험을 목표로 한다면 별도 실행 장면이 필요하고, 가벼운 개념/운영 토론이 목표라면 현재 기록 재사용 장면을 중심으로 편집할 수 있다.

### 독립 대안과 구현 범위

[senior-storyboard.md](senior-storyboard.md)에 17·31·35의 세 씬과 실제 문장·시선 순서·발언·실행 범위를 적었다. 각 씬의 SVG와 PNG를 만들고 세 PNG를 직접 열어 문장 누락/잘림 없이 전체 구도가 보이는지 확인했다. 이 산출물은 design 하위 독립 제안이며 40장 제품·CSS·생성물에는 반영하지 않았다.

- [17장 PNG](storyboard-17.png): ‘모든 시스템’→‘이 데모’가 먼저 보이고 실제 변경 문장은 아래에 남는다.
- [31장 PNG](storyboard-31.png): 비율 그래프를 없애고 8쪽·25링크·10보존 파일의 다른 단위와 확인 내용을 구분한다. 부록으로 옮기는 B의 짧은 경로 제안도 유효하다.
- [35장 PNG](storyboard-35.png): 자료A/B와 질문의 빈 양식을 크게 두되, 질문 한 줄이 우선이며 근거 확인은 다음 모임으로 이어진다.

제안된 우선 수정은 내용·원고·기존 두열/세열/도식의 조정으로 가능하다. 이번 관찰에서 공통 엔진 변경이 필요하다는 근거는 없다. 실시간 입력·타이머·참여 추적·새 상호작용을 공통 기능으로 추가하는 것은 이번 문제의 필수 해법이 아니다. 최종 제품 변경과 실제 Zoom 낭독 검증은 root가 별도 범위로 판단할 작업이다.

### 최종 상태

독립 초기 판정 동결, B와 직접 근거 회의, 청중 종합 실독 후 우선순위 변경 기록, 3씬 독립안, 이미지 최종 검수를 완료했다. 미감 판정은 ‘기초 정돈은 강함, 핵심 정보 선택·초반 역할 구체화·행동 화면 보완이 필요함’으로 유지한다. 사람 리허설이 남아 있으므로 전달 성공/실제 소요 시간은 완료 판정하지 않는다.

B는 수정된 §2·storyboard 문서와 최종 PNG 세 개를 모두 직접 다시 열고, 31장의 단위/우측 여백, 17장의 실제 문장 전체, 35장의 작성 부담 조정, 구현 범위의 정합성을 확인했다고 직접 회신했다. 추가 수정 요청이 없음을 받은 뒤 이 역할의 파일 편집을 종료한다.
