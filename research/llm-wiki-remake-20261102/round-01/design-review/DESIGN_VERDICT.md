## 제작 중 지원 가정 오류의 구분

초기 A/매니저 명세는17장의 `현상p → blockquote → 지원p`가 기존 quote로 구현된다고 기술했다. 실제 planner는 첫 본문이 blockquote여야 하므로 document fallback이 발생했다. CSS의 위계 지원만 읽고 planner의 적합성 조건까지 대조하지 못한 **구체 명세의 지원 가정 오류**다. AGENTS/DESIGN이 이 순서를 무조건 지원한다고 지시한 것은 아니다.

구현팀이 이 차이를 발견해 코드·영향을 확인하고 root와 디자인팀에 직접 전달했다. root는 명시 `compose: quote`에서만 기존 단일 인용220자/지원200자 한도와 원순서를 유지하며 앞뒤 짧은 문단을 허용하는 최소 수정을 수용했다. auto 선택과 다중 인용·이미지·목록·길이 초과 fallback을 보존하고 의미 있는 회귀를 추가했으며 MARKDOWN-FIRST의 실제 지원 설명도 맞췄다. 이는 기준 완화나 조판 이름만 바꿔 합격시키는 조치가 아니다. 공통 변경의 대표 화면과 읽기·모션 줄이기 근거를 확인한 뒤 지침 적합성을 판정한다.

실제 사건이 없는 압축/모든 클라이언트 준수·미래 실수0을 검증한 것으로 보고하지 않는다. 정책 승인 여부는 이번 작업에서 지침의 권한·보존·역할·인계·현재판검수 계약이 충분히 작동했는지와 미해결 모호성의 존재로 판단한다.

## 최종 지원 화면 인수

매니저는 [공통 영향 기록](../../round-03/common/verification.json)의13관측과 해당15PNG를 전부 직접 읽었다. 두 기존 타주제 quote, 밝은 문서, 실제 스톡 사진, 긴 한국어 메시지, 타주제390읽기, LLM17과타주제quote의 모션 줄이기, 본편7/23표,24코드의 좌/중/우, 새2SVG 원본이 실제 화면으로 대응한다. 처음 밝은 문서를 ‘사진’ 근거로 부른 metadata와 실제 보이는 대상을 구별했고 별도 실제 사진 화면을 확인했다. 자료의 역할을 파일 라벨만으로 판정하지 않았다.

24코드는 실제 wheel 입력으로0/69/138까지 이동했고 최대138에서 ‘읽어 줘’·‘개념과 근거를 연결해 줘’·‘모르는 점을 알려줘’까지 네 요구의 끝이 화면 안에 있다.7/23표는 자체 clientWidth와scrollWidth가316으로 같고 전행을 읽는다. 원본SVG는1500×650 viewport 안에서SVG1500×600으로 열렸으며 발표 contain과 의미/표면이 같다. 모션 줄이기는 시스템 reduce=true·활성 animation0/이름 없음의 DOM 관측과 완성 화면을 대조했다. 이 근거를 일반 모션 재생의 미감·타이밍 승인이나 다른 모든 발표의 무오류 보장으로 확대하지 않는다.

선택적 미세 표기 흠은 native8절 공통질문 앞뒤에 literal `**`가 보이는 것이다. 질문과 RAG/위키 구분·자료관계·복귀 동작은 온전히 읽히며 필수 정보의 삭제·오해·접근 차단이 없어서 필수 수용 조건의 실패로 분류하지 않는다. A/B도 독립 화면에서 확인해 같은 범위로 반론을 정리했다. 알려진 현상은 숨기지 않고 이번 판의 한계로 남긴다.

## 별도 판정

**AGENTS/DESIGN의 제작 적합성: 이번 실제 리메이크 범위에서 승인한다.** Stage의 공통 언어를 지키면서 역할별 위계·연속·매체 고유면을 선택했고,26주제와9도식의 의미·원본19도식·48장 원문·데모·사용자 기록을 보존했다. 독립 문맥에 최신 목표·소유·보존·정본·현재 입력/검수와 미완료를 직접 전달했다. 지원 조건의 오가정은 실제 planner와 대조해 명세/입력 문법/구현값의 책임을 나눠 교정했고, 공통 변경을 다른 주제·읽기·모션 줄이기에서 확인했다. 현재판 실화면 검수 규칙은 기술검사로 놓친 이미지 누락·가림·빈 타일·불완전 행동 근거를 실제로 반려하고 정정하게 했다. 이 작업의 결과에 영향을 주는 미해결 정본 모호성이나 지침 추가 수정 요구는 없다.

이 승인은 지침에 문구가 있다는 이유나 팀 합의만으로 부여하지 않았다. 실제 제작의 선택·실패·교정·독립 반례와 최신 화면을 근거로 한 제한된 승인이다. 새로운 전역 규칙·색/구도 할당량을 추가할 이유가 없었으며, MARKDOWN-FIRST의 실제 quote 지원 설명만 구현과 동기화됐다. 앞으로 모든 발표·모델/클라이언트·압축 상황에서 실수0, 현장 프로젝터·청중 이해·음성 리허설·일반 모션 미감을 보장하지 않는다.

root는 네 기록 각각에 `node scripts/design-review.cjs check --source talks/llm-wiki/slides.md --record <해당기록> --require-approved`를 실제 실행해 모두 exit0을 직접 전달했다. 매니저는 네 정본을 직접 읽고 현재 원고/DESIGN hash·각1–26 scope/viewport·원문 reviewSource hash와104개 검토자/이유/상태 행이 동결된 실무자 JSON 원문과 완전히 같음을 별도로 대조해 인수했다. 상태/사유를 기계 생성해 승인을 만든 것이 아니다. 이 명시 범위를 다른 화면 크기·현장·일반 모션·청중 효과로 확대하지 않는다.

A/B는 독립 실질초안 뒤 서로의 전문과 매니저 판정 전문을 읽고 직접 반론을 해소했다. 초기 오기와 좌표 원인 추정의 한계를 정정했고, 실제 영상/동작을 보지 않은 범위를 승인에서 제외했다. 각 소유3파일(리뷰1+장별JSON2)을 동결하고 writer 종료를 보고했다. 매니저는 최종 전문과4JSON을 직접 대조해104개 장/모드/크기·근거·개별 이유·판정의 대응과 추가 필수 수정 요구0을 확인했다. root는 원문 판정을 바꾸지 않고4정본 기록으로 기계 취합해 승인 전용 검사를 수행했다.

root의 [보존 대조](../../final/preservation.json)와 [탐색 검증](../../final/navigation.json)도 인수했다. 이 추가 인수는 제품 원본과 자료 접근 경로의 확인이며 위 네 시각 범위를 무제한 확장하는 정책 변경이 아니다.

마감 추가 탐색 기록을 매니저가 읽는 중 예제 팩 `textStart`의 한글 깨짐을 발견해 root에 직접 알렸다. 링크 도착/원본 바이트 보존과 브라우저 디코딩의 정상 여부를 구별했다. 원본 TXT의 UTF-8 한글과 정식 서버 `scripts/stage.cjs:337`의 `text/plain; charset=utf-8`은 정상이며, QA용 Python 서버가 charset을 누락한 응답이었다. root는 원본/제품을 바꾸지 않고 QA 서버의 TXT MIME만 정식 서버와 맞춰 재검증했다. 매니저는 [정정1440 화면](../../final/pack-utf8-1440.png)과 [정정390 화면](../../final/pack-utf8-390.png)을 직접 읽고 한글 제목·설명·읽는 법이 정상 표시됨을 확인했고, [인코딩 기록](../../final/pack-encoding.json)의 UTF-8 characterSet/응답 타입·원본 불변을 대조했다. 기존 탐색 기록은 실패 이력으로 보존하며 그 예제 팩 디코딩 주장은 이 정정 근거로 대체한다. 이 추가 확인은 매니저/root 수행 범위이며 종료한 A/B의 직접 관찰로 확대하지 않는다.

디자인팀은 이 검수 문서와 직접 작성한4판정JSON만 편집했으며 제품·기존 원본·정본 지침·WORK_LOG를 변경하지 않았다. 최종 필수 수정 요구0, 양 실무자와 매니저 writer 종료다.
