# LLM Wiki 26장 실제 리메이크 구현 명세

작성: `/root/remake_design_manager/art_director` · 2026-11-02. 상태: 독립 실질초안·직접 반론·최종 전문 대조를 거쳐 초기 계약 합의 완료. 제품 구현·시각 승인 전이다.

## 이번 판의 목적과 경계

최신 사용자 요청은 현재 지침에 맞는 LLM Wiki의 실제 리메이크와 독립 디자인 검증이다. 이전 감사의 ‘본편 교정은 범위 밖’을 이번 작업에 적용하지 않는다. 26장 전체 흐름을 다시 검토하고, 역할에 맞는 화면은 유지하며, 이해 문제를 만드는 위계와 관계를 실제로 바꾼다. 화면을 바꾸는 장의 수나 새 레이아웃 개수는 완료 조건이 아니다.

기준은 루트 [DESIGN.md](../../../DESIGN.md) 145행, SHA256 `75e405eb4d1695fc5b4d5301d9393a2b3a0f938a3288dd3c9807e2845ca90817`이다. 최신 사용자 지시가 우선한다. Stage의 검정 무대·큰 타이포·넓은 여백·한 시각 중심을 유지하고, 장의 역할에 따른 밀도와 기하 변화를 만든다. 밝은 문서와 의미색은 콘텐츠로 보존한다. 내용 참고자료의 paper 색/배치를 덱 기본값으로 승계하지 않는다.

입력 정본은 [slides.md](../../../talks/llm-wiki/slides.md), 시작 SHA256 `6df65ff95f74d48df3845d212d4bd36b111980e077d9ff332299c9bba7728b09`이다. Markdown 입력은 [MARKDOWN-FIRST.md](../../../MARKDOWN-FIRST.md), 공통 계약은 [CONFIG.md](../../../CONFIG.md)를 따른다. 현재 HEAD `2a95f376d60c65b79f9151937e4a2b36e5173f38`와 기존 dirty 변경을 보존한다.

구현 담당자는 원고·필요한 새 자산·관련 대본/참조만 우선 변경한다. 기존 `compose`와 그룹 `primary`의 실제 동작을 먼저 사용한다. 공통 runtime/CSS 추가는 기존 조판으로 해결할 수 없는 실제 화면 증거가 생긴 경우에 한해 영향 범위를 매니저에게 직접 전달하고 결정한다. 새 입력 키·주제 전용 runtime·좌표 프레임워크는 이 명세에 필요하지 않다.

## 직접 관찰한 화면과 판단의 근거

이번 실무자는 기존 [1–8장 보드](../../design-governance-20261102/evidence/before/contact-01-08.jpg), [9–16장 보드](../../design-governance-20261102/evidence/before/contact-09-16.jpg), [17–24장 보드](../../design-governance-20261102/evidence/before/contact-17-24.jpg), [25–26장 보드](../../design-governance-20261102/evidence/before/contact-25-26.jpg)를 `view_image`로 직접 보았다. 필수 10·17·18·20·24와 보존 반례 4·19·21·22의 원본 PNG도 직접 열었다. 이 관찰은 현재 명세를 위한 교정 전 화면 관찰이며 새 제품의 승인 기록이 아니다.

보관 [DevDay20:30](../../evidence/devday/keynote-20m30.png)의 큰 단일 문장, [20:00](../../evidence/devday/keynote-20m00.png)의 큰 이름/하나의 도표, [36:00](../../evidence/devday/keynote-36m00.png)의 실제 작업 화면 중심 기하를 직접 재관찰했다. 메시지→근거→실제 대상의 정보량 변화를 재사용한다. 별 배경·인물 합성·행사 로고·원본 글꼴/HEX는 채택하지 않는다. 새 영상/문헌 조사는 수행하지 않았다.

기존 [LLM_WIKI_AUDIT.md](../../design-governance-20261102/design/LLM_WIKI_AUDIT.md)와 [지침 운영 연구](../../agent-design-policy-202610/RESEARCH.md)를 실독했다. 기존 21장 승인/5장 개선 필요는 시작 이력이다. 새 원고·자산이 생성되면 옛 승인 21개를 새 판에 자동 복사하지 않는다.

root가 추가 제공한 [390폭 읽기10장](../before/reading-390-slide10.png)과 [20장](../before/reading-390-slide20.png)도 직접 열었다. 10장은 큰 본문 문장과 달리 도식 전체가 본문폭으로 축소되어 노드 보조 설명을 읽기 어렵고, 20장은 세부 활동이 작지만 전체 활동안으로 가는 문장 링크가 있다. 링크의 존재는 직접 보았으나 목적지 접근 행동은 이번 실무자가 아직 수행하지 않았다. 이 관찰에 따라 작은 읽기에서 관계/문구의 동등 설명 또는 원본 접근을 실제 확인하는 조건을 추가한다.

## 전 26장 역할과 구현 방향

## 필수 5장 상세 구현

### 10장 — 상태 그림에서 갱신의 일로

현재 바깥 제목/내부 `요약을 넘어, 기존 설명과 연결`/하단 굵은 과정이 서로 별개 강조층이다. 내부 큰 문장만 작게 만들고 나머지 기하를 그대로 두는 것으로 종료하지 않는다. 9장이 미리 유지한 문서의 상태를 보여 준다면 10장은 그 문서가 어떻게 갱신되는지 보여야 한다.

- `compose: media`, `fit: contain`, `tone: neutral` 유지. 제목은 `Ingest는 자료를 소화하고 연결하는 일` 유지한다.
- 원본 `assets/expanded/ingest-map.svg`를 수정하지 않고 `assets/remake/ingest-map.svg`를 만든다. 설명용 SVG의 title/desc에도 자료 읽기·분해·갱신과 원자료/판단/종합 보존을 적는다.
- 1500×600 기준 후보: 왼쪽 약 1/4은 세 메모의 이름과 보조 설명, 가운데는 `자료 요약 / 원자료의 입구`, 오른쪽은 위 `개념·비교 / 기존 설명과 연결`, 아래 `현재 계획 / 여러 자료의 종합`으로 배치한다. 메모→요약 입구, 요약과 개념·비교, 요약과 계획, 개념·비교와 계획 사이의 의미 연결을 남긴다. 원본 관계선은 방향을 지정하지 않았으므로 새 양방향 갱신 화살표를 의무로 만들지 않는다. 연결선을 과장된 성과 화살표나 수치로 바꾸지 않는다.
- `읽고 나누기`는 메모→입구의 가까운 작은 동작 안내, `문서·목차·링크 갱신`은 오른쪽 관계군 가까운 안내로 둔다. 읽기/나누기/갱신은 한 흐름 안에 보이되 자료요약·개념/비교·현재계획을 강제적인 파일 생성 순서로 설명하지 않는다.
- SVG 내부의 별도 큰 주장 제목은 제거한다. 원고 하단의 `자료 읽기 → 내용 나누기 → 문서·목차·링크 갱신하기`는 보조 문장으로 유지하되 굵은 강조를 풀어 그림과 경쟁을 낮춘다. 문서·목차·링크 갱신을 SVG에서 찾을 수 있어야 한다.
- 수용: 제목 한 주장→입력→요약 입구→기존 관계 갱신을 따라갈 수 있다. 작은 글자만 줄인 결과, 노드/연결을 뺀 단순 세 단계, 9장과 구별 없는 삼각형으로 판정되면 재작업한다.

### 17장 — 현상과 대응과 쓰임

기존 quote 조판은 작은 H1, 큰 인용문, 보조 문단을 원고 순서대로 표시하므로 신규 runtime 없이 비대칭 위계를 만든다. 아래는 구현 가능한 원고 후보이며 내용 의미를 유지한다.

```md
<!-- stage-slide
compose: quote
tone: neutral
-->
# 내 맥락을 정리하는 일은 어렵습니다

같은 자료라도 내 목적과 경험에 따라 **묶는 기준이 달라집니다.**

> 왜 골랐고,
> **어떤 질문을 풀려는가?**

기준부터 적어 다시 쓸 방향을 잡습니다.
목적 없이 모으기만 하면 다시 쓰기 어렵습니다.
```

quote의 줄바꿈이 실제 HTML에서 의도한 두 줄을 보장하지 않으면 어절/폭을 실제 화면에서 조정한다. 두 개의 `>` 줄은 원고상의 호흡 후보이지 자동 hard break 보장이 아니다. 읽기 모드도 현상→질문→대응/쓰임 순서로 남는다. 불필요한 카드/화살표/번호로 인과를 장식하지 않는다.

### 18장 — 직접 기록의 책임 한 축

먼저 일반 editorial의 `primary`를 검토했다. 현재 두 그룹의 primary는 폭 확대가 자동 적용되지 않고, centered의 폰트 규칙도 별도로 작동한다. 첫 두 내용을 한 인간 주역군으로 합치면 두 그룹이 되므로 `primary:true` 한 줄만으로 문제를 해결했다고 볼 수 없다. 이번 구현의 우선 후보는 지원되는 quote 조판이다.

```md
<!-- stage-slide
compose: quote
tone: neutral
-->
# 사람이 직접 남기는 맥락

> 목적과 내 판단은
> **내가 적습니다.**

누구를 위해 무엇을 만들지 목적은 직접 정하고,
감정 · 생각 · 판단 · 선택 이유를 직접 남깁니다.

기록은 구분합니다: 원문 · 내 기록 · AI가 쓴 요약과 해석.
```

17의 큰 질문 다음에 18의 큰 책임 선언이 이어지는 연속 구도는 의도한 전개다. 서로 다르게 보이는 것 자체를 위해 레이아웃을 바꾸지 않는다. 위 후보의 구체 항목이 실배치에서 너무 낮은 위계로 밀리면 일반 editorial primary를 사용하되 사람의 목적/판단을 하나의 큰 주역군으로 하고 AI구분을 작은 지원군으로 구현해 다시 캡처한다. 구체 항목을 대본으로만 옮기는 해결은 허용하지 않는다.

제목을 바꾸면 대본 시간표·18장 절 제목·README 등 제목에 의존하는 참조를 함께 맞춘다. 대본의 원문 목적과 직접 기록 의미는 보존한다. 6장은 사람·AI 협업 역할, 18장은 사람에게 남는 책임이라는 차이를 말할 수 있어야 한다.

### 20장 — 실제 제공하는 활동안, 미실측 결과

- 바깥 H1은 `정리한 지식으로 만든 15분 활동안`으로 정확히 바꾼다. 대본 시간표·20장 절·자료의 `발표 20장 실제 결과` 링크 라벨·README의 관련 결과물 표현도 정체성이 일치하도록 조정한다.
- 원본 `assets/expanded/session-plan.svg`는 보존하고 새 `assets/remake/session-plan.svg`를 만든다. 밝은 문서면을 크게 유지하며 contain으로 전체를 표시한다.
- 문서 첫머리에 `입문자와 함께 읽는 15분 LLM Wiki 활동`과 `활동안 발췌 · 시간 배분 예시`의 정체성을 두고, `실제 운영·학습효과·설치/모델 생성 시간의 실측이 아님`을 목표 가까운 읽을 수 있는 보조행으로 둔다. 문서 아래 작은 바깥 각주만으로 범위를 설명하지 않는다.
- 목표, `자작 주제 메모 팩 · 목적과 맥락 + 지식의 활용`, 0~2/2~6/6~11/11~15분과 각 활동을 그대로 남긴다. 네 시간구간을 차트의 성과/생성시간으로 바꾸지 않는다. 관계를 따라 읽는 6~11분 활동과 목표가 문서 내용의 핵심으로 보이도록 간격/굵기를 조정한다.
- 원고 링크는 `15분 활동안 전체 읽기`처럼 전체 제공 문서임을 밝힌다. 기존 caption과 링크 뒤에 같은 활동 설명을 중복하지 않는다. 빠진 범위 설명이 없도록 한 보조층으로 통합한다.
- 수용: ‘실제’는 제공된 문서가 존재한다는 뜻이며 실행/효과 증명으로 읽히지 않는다. 제목·목표·근거메모·네 활동·비실측 범위를 모두 실제 contain 크기에서 읽을 수 있어야 한다. 자료가 길면 글자를 계속 줄이지 않고 SVG의 여백/행 간격/제목 중복부터 조정한다.

### 24장 — 요청문 뒤의 지원 자료

기존 코드면과 네 행 요청문을 유지한다. 별도 큰 CTA·새 버튼·장식 카드를 만들 필요가 없다. 원고의 코드 fence 뒤를 다음처럼 묶는다.

```md
### 함께 볼 자료

[예제 팩](./assets/expanded-study.txt) · [자료 읽는 방법](./materials/workshop.md)

[원본 그림·48장 원고 보기](./materials/visual-appendix.md)
```

`compose: document`에서는 H3가 코드의 26px보다 약간 큰 글자일 수 있어, 라벨 추가만으로 위계가 해결된다고 가정하지 않는다. 실제 화면에서 요청문 면/행간/상단 위치가 첫 시선을 맡고 H3+두 링크가 하나의 뒤따르는 군으로 읽히는지 본다. 라벨이 과도하게 커지면 문단 `함께 볼 자료`로 낮추는 기존 문법을 사용한다. 링크를 읽을 수 없게 축소하지 않는다.

## 보존과 실제 구현 인계

본편은 26장, 1–25장 35분+26장 Q&A5분 배분안을 유지한다. 이 시간은 음성 리허설 실측이 아니다. 본편 핵심 9도식은 의미를 전부 유지하며 10·20만 새 경로의 개선판으로 교체한다. 전체 19도식, 48장 원문/대본, 고정 데모 ZIP/로그, 모든 학습자료와 사용자 [test.md](../../../talks/llm-wiki/test.md)는 원본을 보존한다. 원고 교정에 따른 새 SVG를 원본 위에 덮어쓰지 않는다.

구현 인계 때 다음을 직접 전달한다: 최신 사용자 목표, 이 명세와 공용 DESIGN_CONTRACT/ACCEPTANCE 경로, 제품 소유 범위, 기존 원본/dirty 보존, 새 자산 경로, 현재는 교정 전 21/5 이력이고 새 판은 미검수라는 상태, 구현→실제 캡처→독립 검수의 다음 행동. 이 파일의 작성자는 원고·코드·자산·WORK_LOG를 편집하지 않는다.

완료 판단은 후속 [ACCEPTANCE.md](ACCEPTANCE.md)의 독립 기준과 [DESIGN-REVIEW.md](../../../DESIGN-REVIEW.md)를 따른다. 새 근거는 발표1440×1000/960×900 각각 전26장 PNG·전체 보드·manifest, 필수5장과 전후 흐름, 변경 SVG의 원본/실배치, 읽기1440/390폭의 전26장 문장·표·코드·이미지·자료 링크다. root의 실제 캡처 범위에 맞춰 미확인 환경은 명시한다. 기술 검사·이미지 경계 검사 성공은 시각 승인과 별도다.

### 작은 읽기에서 9도식의 의미 접근

390폭에서 SVG를 본문폭100%로 줄이고 generic alt만 두는 것으로 읽기 합격을 주지 않는다. 기존9도식과 새10/20 도식마다 필요한 노드·관계·본문을 실제 읽을 수 있거나, 동등한 native 설명/상세 자료 또는 확대 가능한 원본으로 접근할 수 있어야 한다. 이미지가 작다는 이유만으로 모두 새 기능을 추가하지는 않는다. 기존 자료에 같은 의미가 있다면 그 목적지와 해당 내용을 실제 열어 확인하는 최소 해결을 사용한다.

10장의 권장 최소 해결은 본편 이미지 인접 설명에서 ‘같은 세 메모를 읽어 자료 요약을 입구로 만들고, 기존 개념·비교 및 현재 계획과 연결하며, 관련 문서·목차·링크를 갱신한다’는 관계를 읽을 수 있게 하거나, 해당 전문이 있는 상세 읽기 경로를 제공하는 것이다. 발표 하단 설명이 길어져 도식과 경쟁하면 상세 읽기 문서/원본 접근으로 역할을 나눈다. 단순한 세 동작만 반복하고 요약/기존 문서/현재 계획의 관계를 생략하지 않는다.

20장은 기존 native [session-plan.md](../../../talks/llm-wiki/materials/session-plan.md)에 제목·목표·메모 선택·시간표·미실측 범위가 있으므로 전체 활동안 링크가 우선 경로다. 390폭에서 실제 링크를 열고 전체 네 행·범위·근거를 읽을 수 있음을 확인한다. 나머지7도식도 같은 접근 점검을 하며 작은 관계의 읽기 경로가 막히면 그 장의 이해 문제와 최소 해결을 명시한다. generic alt, 파일이 있다는 사실, 링크 hash 통과만으로 이 확인을 대체하지 않는다.

## 직접 상호검토와 마감

독립 실질초안 뒤 B `/root/remake_design_manager/independent_critic`의 ACCEPTANCE 전문과 매니저 DESIGN_CONTRACT 전문을 읽고 직접 반론을 교환했다.

- A→B: 12장 수용표의 화살표 순서가 대등한 세 측면을 강제 과정으로 바꿀 여지가 있다. B가 수용해 ‘개념별 분리·목차/원자료 재읽기·새 자료로 관계 보완’의 대등한 세 측면으로 정정했다.
