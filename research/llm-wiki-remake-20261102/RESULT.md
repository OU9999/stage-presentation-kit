# LLM Wiki 실제 리메이크 결과

2026-11-02 · **LLM Wiki 리메이크를 완료했다. 디자인팀이 발표·읽기의 총104개 범위를 승인했고, 현재 입력의 승인 전용 검사4개가 모두 통과했다. AGENTS.md와 DESIGN.md도 이번 실제 제작 범위에서 별도 적합성 승인을 받았다.**

## 바뀐 발표

검정 Stage, 큰 타이포, 여백과 장별 시각 중심을 유지하며 기존 감사에서 개선이 필요했던 10·17·18·20·24장을 실제 교정했다. 나머지 21장도 새 판으로 검토했다. 유효한 병렬 비교와 자료의 밝은 문서면을 보존했고, 모든 장을 같은 구도로 바꾸지 않았다.

작은 화면에서는 축소된 SVG만으로 의미 접근을 승인하지 않았다. [관계 읽기](../../talks/llm-wiki/materials/diagram-reading.md)를 새로 만들고 8개 도식에 연결했다. 20장은 기존 native 활동안 전문을 연결한다. 발표 본편 26장·35분+Q&A5분 배분, 핵심9도식의 의미, 원본19SVG·원문48장·고정 데모·사용자 메모를 보존했다. 제목·대본·진행표·관련 안내도 맞췄다.

## 구현 중 발견한 계약 차이

17장의 ‘현상 문단→인용→지원 문단’은 기존 quote planner의 선두 인용 제약에 맞지 않았다. 이를 실제 구현 전에 발견해 명시 `compose: quote`에만 단일 인용 앞뒤의 짧은 문단을 원순서로 허용했다. auto 선택·길이 제한·다중 인용/이미지 등의 fallback은 유지했다. 관련 회귀를 추가하고 MARKDOWN-FIRST의 실제 지원 설명을 보완했다. 새 전역 레이아웃이나 CSS는 추가하지 않았다.

[구현 인계](engineering/IMPLEMENTATION.md)와 [실제 보존 대조](final/preservation.json)에 변경·동기화·196개 로컬 참조·다른4덱33개 조판 동일성의 범위가 있다. root도 시작 hash와 현재 파일을 독립 대조해 기존 talk98파일 중 의도한7개 변경 외91개가 동일함을 확인했다.

## 독립 검수와 반복

디자인팀이 원고·자산·대본과 실제 PNG를 함께 읽고 장별 이유를 직접 작성했다. root는 상태나 승인 이유를 자동 생성하지 않고 그 판정을 검수 기록으로 결합한다. 제품 시각 승인과 AGENTS/DESIGN의 이번 제작 적합성 승인은 별도다.

검수 중 반려한 근거도 보존했다. round-01 읽기는 실패한 이미지도 `complete=true`가 되는 조건과 전체 페이지 캡처의 sticky 도구막대 끼임을 놓쳤다. round-02는 screenshot clip의 좌표 기준을 잘못 가정한 캡처에서 빈면이 생겼다. 정확한 브라우저 내부 원인은 확정하지 않았으며, 일반 viewport 원본과 로컬 crop으로 교정했다. root와 디자인팀이 각각 실제 이미지를 보고 두 근거를 반려했다. 승인 기준이나 제품을 그 근거에 맞춰 바꾸지 않았다.

최종 읽기 근거는 [round-03](round-03/read-390/manifest.json)이다. 이미지 자연폭을 확인하고 실제로 스크롤하며 일반 viewport PNG를 저장한 다음, 도구막대 사이의 실제 픽셀만 로컬에서 잘라 원순서로 접합했다. 원본 viewport·조각 좌표·입력 hash를 모두 남겼으며 DOM이나 CSS를 숨기지 않았다. 제품 구현 이후의 3개 라운드는 근거 교정의 반복이며, 세 번의 서로 다른 제품 재설계로 집계하지 않는다.

추가 자료 인수에서 예제 팩의 한글이 깨진 현상도 디자인 매니저가 발견했다. 제품 원본 UTF-8 바이트는 정상이었고 root의 임시 Python 서버가 `.txt`에 charset을 빠뜨렸다. 프로젝트 정식 서버는 이미 UTF-8을 명시한다(`scripts/stage.cjs:337`). 임시 서버의 `.txt` 응답만 같은 MIME으로 맞춘 뒤 실제 링크를 다시 클릭해 UTF-8·한글 전문을 확인했다. 원본·BOM·제품 코드는 변경하지 않았다. [정정 인코딩 관측](final/pack-encoding.json)과 [실제 화면](final/pack-utf8-1440.png)이 원래 navigation의 잘못 디코딩된 textStart를 대체하며, 원래 기록은 이력으로 보존한다.

## 승인 기록

디자인 실무자가 실제 장별 상태·검토자·시점·이유를 직접 작성했고 매니저가 화면과 문서의 교차 검토를 인수했다. root는 이 원문을 기계 취합한 뒤 아래 명령을 각 기록에 실제 실행해 모두 종료0을 확인했다.

이번 제작에서 추가 정본 수정 요구는 없다. Stage 기본값/예외 권한, 역할·밀도·매체 표면, 의미·원본 보존, 직접 인계와 현재 판의 독립 화면 검수가 실제로 작동했다. 명세의 입력 지원 오가정은 구현·문법 안내에서 교정했고, 캡처 결함은 기준을 완화하지 않고 재수집했다. [2026년10월 기준 지침 연구·보강](../agent-design-policy-202610/RESULT.md)에서 연결한 지침을 실제 제작으로 검증한 결과이며, 문서가 존재한다는 사실만으로 부여한 승인이 아니다.

## 범위와 남는 한계

브라우저의 명시한 두 발표 크기·두 읽기 크기와 기록된 기능을 검수했다. 실기기/프로젝터, 실제35분 낭독, 청중 이해·학습효과와 모든 모션의 재생 품질은 검증하지 않았다. 시스템 모션 줄이기의 정적 완성 상태는 별도 실제 확인했다.

관계 읽기8절의 공통 질문에 강조 기호 `**`가 문자로 남는 미세 표기 흠은 디자인팀이 내용·관계·이동을 막지 않는 비차단 항목으로 판단했다. 최종 승인 범위와 구별해 남긴다. 향후 모든 발표의 실수0을 보장하거나 이번 검수를 다른 입력에 자동 승계하지 않는다.

커밋·푸시·공개 배포는 수행하지 않았다. 실제 팀 구조는 디자인 매니저+실무2 → 엔지니어링 매니저+실무2 → 같은 디자인 매니저+실무2 순차 운영이며, root가 브라우저·빌드·로그·최종 통합을 맡았다. 구체 계약은 [디자인 계약](design/DESIGN_CONTRACT.md), [독립 수용 기준](design/ACCEPTANCE.md)에 있다.
