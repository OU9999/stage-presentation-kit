# A FIRST — 발표만 전달된 독립 기록

동결 UTC: 2026-10-29 09:27:17. 담당 A는 이번에 신규 배정된 공개 Karpathy 설계 대조 검토 역할이며 이전 개인 청취 기억은 없다. 실제 Karpathy 참여·승인·말투 재현이 아니다.

읽은 범위: input/phase-1~4 발언·전환, 화면 PNG 1→28→40 총29장을 순차·개별 tools.view_image 직접 실독, WORK_LOG 중립1~6줄. 현재 QA/상대 결과·이전 평가·새 원고·코드·연결 자료·변경 설명은 미열람. 화면/대본 반복 검토이며 블라인드 실험, 실제 음성·실시간20분 낭독, 사람 이해도 측정이 아니다. 이 기록을 이후 비교 결과로 소급 교체하지 않는다.

## 원리

- LLM 에이전트가 여러 원자료의 개념·비교·연결·잠정 종합을 Markdown 위키로 작성하고 계속 갱신한다(2,4~7).
- 사람은 자료·질문·범위와 결과 확인을 맡고 읽는 도구는 탐색 창이다. 파일은 현재 답변의 문맥에 실제 읽혀야 한다(5,8,20).
- Ingest는 기존 여러 페이지를 함께 바꾸며 고정 통과 단계가 아니다. Query의 유용한 답도 저장해 연결한다. Lint는 낡은 설명·조건 차이·빠진 연결을 다음 읽기와 수정 후보로 찾는다(7~9,23).
- raw와 wiki는 보존 입력/갱신 설명, schema는 전체 작업의 규칙이다(6). 파일 갱신은 모델 가중치 학습과 구별된다(8).

## 주장으로 전달된 것

관계 재구성의 일부를 지속 페이지로 옮겨 다음 질문의 출발점으로 삼자는 설계다(1~4,28). 가상 소설·고객 상담·강의는 성능 증명이 아니라 남길 지식과 갱신 방식을 보여 주는 적용 예다(10~19). 인물 자기 설명과 확정 동기, 접수 요구와 출시 약속, 예의 기준과 모든 모델 일반화가 각각 다르다는 경계를 유지한다(11~12,14~18,21). 재사용 가치는 유지 부담과 자기 질문에서 확인해야 하므로 일률적 비용 절감·정확도 향상 주장은 받지 않았다(22,26).

## 남은 질문

2. 2장의 발표팀 정의와 세 응용, 공개 구현의 근거 범위가 연결 자료에서 어떻게 구별되는가?
3. 파일 교정 ZIP(27)은 실제 LLM 실행과 다르다는 설명이 있는데, 구체적으로 무엇까지 재현하는가?
4. Lint 의미적 점검과 기계적 파일 검사는 어느 범위까지 연결되는가?

## 주의·미감

2장 정의→역할/구조→세 가지 증분 사례→한계/부담→자기 질문→시작 요청의 흐름이 자연스럽다. 3장 CSV 조건이 13장에서 구체화되고 24장 예로 회수되어 무관한 예고처럼 보이지 않았다. 10장 전에 3장 새 근거가 노출되지 않고, 11장의 자기 설명을 확정 사실로 읽을 압박도 없었다.

목록/카드가 반복되지만 원리와 오판 범주를 기억시키는 리듬이 있다. 원자료·위키·규칙은 시각적 구조가 다르며(6), 27장의 동일 크기 카드는 이어 읽는 경로의 병렬로 읽었다. 효과나 증거 효력이 동등하다는 주장은 받지 않았다. 2장 본문은 길고 사례 간 골격 반복은 있으나 현재로서는 제품 수정이 필요한 장애로 판단하지 않는다.
