## 구간 1: 1–9장

- 읽은 범위: input/phase-1.md 및 slide-01.png부터 slide-09.png까지 순차 직접 열람. 아직 다른 phase·제품 소스·기존 보고·상대 결과는 열지 않음.
- 1장: 책상 사진과 자료 관계를 다음 질문에 쓰자는 질문이 일치. 구체 산출물이 아직 없지만 2장 정의로 가는 전환이 그 공백을 즉시 메움. 사진은 논문/문서와 정리의 경험을 떠올리게 하며 기술 성능을 약속하지 않음.
- 2장: 큰 문장으로 개념·비교·연결의 Markdown 작성/계속 갱신/다음 질문의 출발점을 한 번에 고정. 화면의 "발표팀이 풀어 쓴 정의"와 대본의 비표준·비완제품 설명이 권위 범위를 제한함. 정의는 길지만 핵심 대상과 동작을 명시함.
- 3장: 가상 CSV 요구라는 한 사례로 재종합 비용을 잡음. 화면이 "이전 비교가 정리되어 있지 않으면"이라고 조건을 적고 대본이 모든 검색 시스템에 대한 일반화를 막아 비교 허수아비 위험이 적음. 기술적 우월성 증명은 아직 없음.
- 4장: 원자료 → 연결된 위키 → 다음 질문, 답의 저장 루프가 한 화면에서 읽힘. LLM이 가운데 위키를 작성/갱신한다는 녹색 레이블과 대본이 일치. 작업 규칙은 전체에 적용이라는 별도 메모여서 산출물과 혼동되지 않음.
- 5장: 에이전트/사람/읽는 도구의 세 역할을 분리. 모델이 파일을 현재 문맥에 읽어야 한다는 화면과 영구 기억이 아니라는 대본이 보완됨. Obsidian의 표시 역할도 명료. 컬러 카드의 동등한 크기는 역할 병렬로 자연스럽게 읽힘.
- 6장: raw와 wiki 두 영역, 아래 schema 가로선이 전체 규칙이라는 구조가 잘 맞음. raw에 "읽었던 판과 원본 위치"가 있어 나중 추적 가능성의 전제가 보임. schema를 세 번째 변환물로 읽을 이유가 적음.
- 7장: 새 자료 대조 후 자료요약/개념/비교/잠정종합을 갱신. "고정된 통과 순서는 없습니다"가 목록을 파이프라인으로 오해하지 않게 함. 대본에서 목차/이력도 덧붙여 운영성이 있으나 한 자료가 무조건 모든 페이지를 바꾼다는 약속으로는 읽히지 않음.
- 8장: index·검색 → 현재 문맥의 본문 → 근거 있는 답의 흐름, 답 저장 후 재읽기 루프가 명확. 화면과 대본 모두 파일 갱신/가중치 학습을 구별. 저장만 하면 자동 기억된다는 오해를 막음.
- 9장: 낡음/조건 차이/빠진 연결의 점검 질문이 실제 작업으로 해석됨. 화면은 후보 질문이고 대본은 후보≠확정 오류라고 제한. 아직 코드 검사와 의미 점검의 관계는 미공개이므로 후속에서 확인할 질문.
- 구간 현재 판단: 정의와 작동 구조는 2–8장만으로 재구성 가능. 단순 요약보다 관계·잠정 종합을 저장한다는 제품 의도가 선명하며 검증 범위나 자동성의 과장 문구는 현재 범위에서 보이지 않음. 다음 구간에서 실제 자료가 페이지 변화로 이어지는 장면이 필요한 상태.

## 구간 2: 10–18장

- 읽은 범위: input/phase-2.md, slide-10.png~slide-18.png 순차 직접 열람. 중간에 parent의 지시로 중립 WORK_LOG 1~6줄만 확인함. 아래 변경설명/이번 QA 판정은 열지 않음.
- 10장: 행동과 도윤의 감정 발언을 별개로 두고 인물의 동기는 미확인으로 표시. 신뢰 주제와 1장 근거가 연결돼 단순 요약과 다른 페이지 구조가 드러남. 가상 적용 예와 실행 결과 아님을 대본이 명시.
- 11장: 1장까지/3장까지의 한 페이지 문장이 나란히 있어 갱신 단위가 읽힘. "설명한다"와 "미확인"을 유지해 새 발언을 사실 확정으로 바꾸지 않음. 대본의 추적 장치 정보가 화면에는 없어도 해석 변화의 원인을 말로 보충함.
- 12장: 질문을 인물·신뢰와 연결해 저장하고 다음 장에서 확인할 의문을 남김. 답 본문 전체 대신 질문/작업 설명을 제시하는 구성이며 어떤 페이지를 읽는지는 대본이 명시. 근거와 해석을 구별하는 예가 완결됨.
- 13장: A/B 두 상담 카드가 같은 CSV라는 표면 공통점과 월말 수동/매일 자동의 차이를 바로 비교하도록 함. 5초 생각은 계획이지 실제 반응 측정이 아님. 카드 여백은 5초 읽기를 방해하지 않음.
- 14장: 요구 보존과 상태 갱신을 구별. 수동 CSV 범위 검토/예약 전송 보류/출시일 미확정이 한 화면에 있음. 보류 이유는 화면 하단의 FAQ 설명과 15장으로 이어짐. 상태가 곧 고객의 원래 요구를 덮어쓰는 구조가 아님.
- 15장: 큰 답 문장에 보류 이유와 미확정 일정을 함께 둬 근거를 넘는 약속을 막음. 개념·비교·회의를 읽는다는 줄과 대본 일치. 후속 질문은 수동 다운로드의 효용 확인으로 실제 상담에 연결됨.
- 16장: 2·7주차 → 공유 개념 제곱오차 연결이 간명. 같은 모델이 아니라 같은 기준임을 대본으로 구별. "이 예"라는 범위가 있기 때문에 회귀/트리의 모든 기준을 일반화하지 않음.
- 17장: 기존 두 행은 남고 분류트리/Gini 행만 파란색으로 추가. 과거가 오류였다는 서사가 화면에도 없음. 비교·질문 갱신이라는 행동을 목록 밖 한 줄에 표시해 표 자체가 위키의 전부라는 오해가 적음.
- 18장: 세 메모에서 얻은 종합을 크게 보이고 저장 경로를 제시. 구조/기준/과제 세 축이 비교의 가치로 이어짐. 다음 기준을 바꿀 때의 질문은 답을 닫지 않고 남은 탐색을 연결함.
- 구간 현재 판단: 소설/상담/강의 모두 새 입력→관계 갱신→질문의 재사용이라는 동일한 구조를 보이되, 미확인 동기/일정 약속/기준 일반화의 서로 다른 위험을 다룸. 실제 실행 증명이 아니라 구성 예라는 범위는 대본에서 분명함. 세 사례에 대한 기술 사실·파일 목적지는 FIRST 후 확인할 대상.

- 22장: 반복 비교/추가 자료라는 조건과 갱신·근거·검색 유지 부담을 나란히 둠. 무조건 도입하라는 결론이 아니며, 비용을 질문 시점에서 갱신 시점으로 옮긴다는 대본이 선택의 성격을 설명.
- 23장: 4장 도해를 회수해 같은 위키로 돌아오는 반복을 강화. ingest/query/lint의 용어는 대본에서만 명명하지만 화면 하단 동사로 이해 가능.
- 24장: 자기 노트 20초·공유 선택/자료 제목은 기억나는 만큼/근거는 다음 확인으로 시작 부담이 낮음. 직접 질문 한 줄 작성 완료. 실제 시간·관객 반응은 측정하지 않음.
- 25장: 파일 에이전트에 보내는 시작 요청이 복사 가능한 문장으로 있음. 근거/조건/충돌/미확인/주요변경/답저장을 함께 요청하고 위치·권한·규칙을 요구하므로 단순 채팅 프롬프트로 자동 파일 접근된다는 위험이 적음. 기본2~4+starter로 가는 링크가 있는 것은 관찰했지만 목적지는 아직 열지 않음.
- 26장: 자료 몇 개·질문 하나·확인할 사람으로 초기 범위를 제한. 사진 세 장은 1장 책상 이미지를 회수해 실제 독서 흐름에 돌아오게 함. 근거 재발견과 교정 부담이라는 확인 기준은 실행 성공률이 아닌 채택 기준.
- 27장: 개념 이해/내 자료로 작성/파일 교정 재현의 세 카드가 같은 크기. 가운데는 기본2~4→starter→읽은파일확인, 오른쪽은 ZIP의 고정 교정이라는 레이블과 대본이 있어 서로 다른 경로임을 알 수 있음. 다만 동등한 시각 크기로 LLM 작성과 고정 교정의 효력까지 같다고 읽는지 확인이 남음. 실제 목적지를 FIRST 이후 읽어 판단할 것.
- 28장: 핵심 문장·LLM 작성/갱신·개념/비교/종합·다시 찾아 읽기가 모두 회수됨. 큰 문장과 녹색 문장이 결론 위계를 분명히 함.
- 구간 현재 판단: 20·21·22장 한계가 앞의 예를 직접 재사용하고 24~27장이 작게 시작하는 실제 경로를 가리킴. 현재 화면/대본만으로는 제품 결함을 식별하지 못함. 링크 목적지와 읽음 확인의 실제 수준, ZIP과 실제 에이전트 경로의 구분이 다음 확인 대상.

- 38장: 8쪽·25링크·10보존파일의 서로 다른 단위를 따로 적음. 카드크기와 큰 수치가 검증 인상을 주지만 정확도/검색누락/시간절감 측정 아님이라는 문장이 화면과 대본에 명확. 발표 품질 자체의 근거로 사용하지 않음.
- 39장: 설계/코드/논문/구성예에 각기 다른 질문을 붙여 근거 종류를 정리. 앞 장들의 경계 설명을 한 표로 회수함.
