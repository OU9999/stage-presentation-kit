# A 순차 화면·대본 관찰

담당: 공개 Karpathy 설계 대조 역할의 신규 검토자 A. 실제 본인 참여·승인·말투 재현 아님. 화면과 명시된 발언·전환을 반복 검토하며 실제 음성, 20분 낭독, 사람 이해도는 측정하지 않는다. 제품 읽기 전용. core FIRST 전에는 변경 설명·기존 평가·연결 자료를 열지 않는다.

## 구간 1 — 1~9장

각 PNG를 1→9 순서로 tools.view_image로 개별 직접 열었다. input/phase-1.md의 발언과 전환을 대조했다.

- 1: 책상 사진과 “관계” 질문으로 진입. 하단 개념·비교가 다음 2장 정의를 예고한다. 효능 입증처럼 보이지 않는다.
- 2: “LLM이 원자료 사이의 개념·비교·연결을 Markdown 위키로 작성하고 계속 갱신”이 큰 문장으로 먼저 나온다. 읽는 사람이 쓰는 위키와 구별된다. Karpathy 아이디어를 발표팀이 풀어 쓴 정의임이 화면과 발언에 있다. 큰 본문은 밀도가 높지만 핵심이 단일하다.
- 3: 이번/다음 질문의 대비가 관계 재구성 비용에 집중한다. “이전 비교가 정리되어 있지 않으면”이라는 조건부 화면과 모든 검색 시스템을 배제하지 않는 발언이 잘 맞는다. CSV의 실제 조건은 뒤 사례를 기다려야 한다.
- 4: 원자료→위키→다음 질문과 답 저장 루프가 동시에 보인다. 연결된 위키에 개념·개체/비교·잠정 종합이 들어가므로 요약 저장소로만 읽히기 어렵다. 초록은 LLM 작성, 주황은 유용한 답의 환류로 기능한다.
- 5: 에이전트/사람/읽는 도구의 동일 카드 크기는 역할 구분용으로 읽힌다. 파일의 현재 문맥 읽기와 Markdown 작성이 명시되어 “파일 생성=영구 기억” 오해를 발언이 막는다.
- 6: raw/wiki 두 영역과 아래 가로 규칙띠가 구별된다. schema가 파이프라인 세 번째 출력이라는 인상을 주지 않는다. “원자료 보존”이 읽은 판·원본 위치를 포함하지만 실제 보존 절차는 아직 없다.
- 7: 새 입력을 기존 위키와 대조한 뒤 여러 페이지 갱신. 오른쪽 목록은 동일 단계 통과가 아니며, “고정된 통과 순서는 없습니다”와 발언이 이를 명시한다. 실제 갱신 예를 기대하게 한다.
- 8: 현재 답변의 문맥이라는 라벨과 본문 재읽기·답 저장 루프가 구체적이다. “파일 갱신과 가중치 학습은 별개”가 하단에도 있다. 모델 기억이라는 비유에 의존하지 않는다.
- 9: 점검 세 카드가 낡은 상태·조건 차이·연결을 다룬다. lint를 확정 오류 판정으로 단정하지 않는 발언이 필요하고 포함되어 있다. 정적 체크와 의미적 점검을 어떻게 나눌지는 아직 미해결 질문이다.

현재까지 전달: 관계를 지속 파일로 만들고 다음 문맥에서 읽는 설계. 아직 성능·정확도·운영 안정성은 주장되지 않았다. 다음 세 자료 사례가 원리에서 구현으로 넘어가는 연결이 된다.

## 구간 2 — 10~18장

각 PNG를 10→18 순서로 개별 직접 열고 phase-2의 발언·전환과 대조했다. 이 구간 13장 직전 parent가 마련한 중립 WORK_LOG 1~6줄만 읽어 인계 상태를 확인했다. 아래 변경 설명·팀 판정은 열지 않았다.

- 10: 실제 책/모델 결과가 아닌 가상 적용 예가 하단과 발언에 있다. 1장 행동과 도윤의 말, 인물 페이지의 “동기는 아직 미확인”이 선명하게 분리된다. 현재 근거 범위가 1장임을 화면 상단이 잡아준다.
- 11: 이제야 3장 새 정보가 발언에 등장한다. 화면의 “서하는 … 설명한다”는 자기 설명이고 미확인 행도 유지된다. 발언의 추적 장치 정보는 화면 본문에는 없지만 새 근거로 말해 주는 정보이며 앞 장 선공개는 없다. 큰 빈 공간은 단순 전후 상태 대비에 집중하게 한다.
- 12: 큰 질문을 먼저 보여 주고 저장/다음 질문으로 넘어간다. “도윤의 판단과 서하의 자기 설명을 구별”하므로 동기를 확정 사실로 바꾸지 않는다. 연결해 저장하는 무엇인지는 발언에서 인물·주제·장 근거를 함께 제시한다.
- 13: 3장에서 예고한 월말 수동/일별 자동의 구체 조건을 두 카드로 읽는다. 용도가 다른 동일 CSV라는 질문에 생각할 재료가 충분하다. 5초는 계획이며 실제 이해도 결과는 없다.
- 14: 왼쪽 접수 요구와 오른쪽 새 회의 이후 상태를 나누고, 요구 보존/상태 갱신을 하단에 명시한다. “수동 CSV 범위 검토”, “예약 전송 보류”, “출시일 미확정”은 약속으로 확장되지 않는다.
- 15: 큰 답은 상태와 운영 비용 검토 이유를 포함한다. 질문·읽는 개념/비교/회의·다음 확인의 층이 이어져 이전에 모은 관계의 재사용을 보여 준다. 가상 응대 초안이 실제 고객 메시지로 오인될 근거는 없다.
- 16: 서로 떨어진 두 메모가 제곱오차 개념에 합류하는 그림. 모든 회귀/트리 모델의 절대 분류가 아니라 “이 예”의 사용 위치라고 발언이 제한한다.
- 17: 기존 두 행을 유지하며 8주차 분류트리/Gini를 추가한다. 기존 오류를 만들어 고친다고 말하지 않아 증분 확장의 의미가 맞는다. 표의 “이 예의 기준”이 일반화 범위를 제한한다.
- 18: 요약을 넘은 비교·종합 문장이 큰 본문으로 남는다. 근거 셋을 연결해 저장하고 다음 확인 질문을 남긴다. 앞의 공통 구조를 잘 회수한다.

현재 반응: 세 사례가 같은 ingest/query 루프의 반복이라 예측 가능하지만, 인물 자기 설명·고객 약속·강의 일반화라는 서로 다른 오판을 제어한다. 성능 입증을 보여 준 것이 아니라 보존할 지식 구조를 설계한 예로 이해했다.

### 24장 직후 실제 적은 역할 질문

공개 LLM Wiki 원형과 우리 적용 예를 함께 읽으면, 어떤 문장은 저자 설계 설명이고 어떤 문장은 우리가 아직 입증하지 않은 운영 가정인가?

이 질문을 직접 쓴 뒤 25장으로 진행한다. 20초 경과나 사람 관객 입력은 측정하지 않았다.

## 구간 3 — 19~28장

PNG 19→28을 개별 직접 열고 phase-3의 발언·전환을 대조했다. 24장 질문은 위 시점에 실제 기록했다.

- 19: 세 입력·유지할 위키·다음 질문의 표가 같은 구조를 회수한다. 관리 이력보다 주제 지식의 재사용이라는 발언은 앞 사례를 정확히 요약한다.
- 20: index 진입, 본문 읽기, 원자료 복귀가 문장으로 구별된다. “이번 답이 읽었다는 것”이 별개라고 화면에도 명시한다. 도구 기록 검증 방법 자체는 아직 말하지 않았다.
- 21: 세 사례 각각의 위험을 한 카드씩 회수한다. 동일 카드 위계는 서로 다른 오판 범주를 병렬로 읽게 하며, 근거 효력의 동등성을 주장하지 않는다.
- 22: 반복 질문/추가 자료의 가치와 갱신·근거·경로 점검의 부담이 대응한다. 질문 시점 작업 일부의 선행 이동이지 전체 비용 절감 보장으로 말하지 않는다.
- 23: 첫 구조 그림 재사용이 학습한 ingest/query/lint를 통합한다. lint도 원자료 재읽기와 수정의 시작이라는 발언이 의미적 검토임을 보충한다.
- 24: 한 줄 질문, 기억나는 자료 제목, 나중에 확인할 근거 위치로 진입 장벽이 낮다. 예시가 고객 조건을 다시 보여 주어 앞 예고와 연결된다. 공개 공유가 선택이다.
- 25: 바로 복사할 요청이 “기존 개념·비교·종합”, “근거/조건/충돌/미확인”, “이유”, “유용한 답 저장”을 묶는다. 아래 권한·규칙 조건이 실제 파일 에이전트 실행의 전제를 명시한다. 아직 어떤 에이전트의 실행 성공을 보인 것은 아니다.
- 26: 사진 세 칸은 자료→질문→갱신된 쪽의 인간 작업 순서를 느슨하게 시각화한다. 하단 질문이 실제 재읽기와 교정 부담 확인으로 끝나 적합성 판단이 구체적이다.
- 27: 내 자료로 작성과 파일 교정 재현이 서로 다른 카드에 나뉜다. 기본2~4+starter와 다음 질문의 읽은 파일 확인이 실제 적용 경로이고, ZIP은 보조 교정 실습이라는 발언으로 경계를 밝힌다. 동일 카드 크기는 진입 경로의 병렬성으로 읽었고 효과나 LLM 실행 증거가 같다고 느끼지 않았다.
- 28: “LLM이 작성하고 갱신하는 위키”와 개념·비교·종합·재읽기의 한 문장 회수. 화면은 크고 미니멀하며 앞의 반복 구조를 잘 닫는다.

현재 남은 질문: 실제 파일 읽음은 자기 보고 외에 어떤 도구 흔적으로 확인하는가? 원형 설명과 세 응용의 출처 경계는 연결 자료에서 어떻게 표시하는가? 파일 교정 재현은 어떤 범위만 보증하는가?

## 구간 4 — 40장

40 PNG를 개별 직접 열고 phase-4 발언·전환을 대조했다. “내 자료·반복하는 질문·유지할 설명”을 큰 적용 질문으로 회수한다. 심화는 공개 구현/실험, 기존 파일 교정 예제로 링크되어 있고 발언도 조건부로 연다. 아직 심화 내용 자체는 읽지 않았다. 1~28,40의 core 29 PNG 개별 실독 완료.

## 구간 5 — 29~39장

PNG 29→39를 각각 직접 열고 phase-5 발언·전환과 대조했다. 이 시점까지 총40 PNG 모두 순차 지정 경로로 직접 실독했다.

- 29: 같은 공개 구현 내 기계 등록과 LLM 내용을 쓰는 경로의 분리. 자료+index가 모델 입력이고 기존 본문 전체 검토가 아니라는 발언은 원형과 이 구현 차이를 설명한다. 설치·실행 결과가 아니라는 제한도 화면에 있다.
- 30: 상위8쪽 각 앞3000자와 save handler의 수동 안내를 명시한다. README 기능 이름과 실제 구현 효력의 차이를 구체 문장으로 보인다.
- 31: 살아 있는 코드는 보존 raw와 다르며 판/해시는 변경 신호라는 발언. “의미 오류 판정이나 자동 수정은 아닙니다”가 화면에도 있어 추적과 복구 효력을 과장하지 않는다.
- 32: wiki 고정 section/목표 자료 포함/선택 실패 없음 대 RAG21중5 검색. 같은 크기 좌우 영역이지만 조건 차이를 직접 크게 말해 표현만의 공정 비교라는 인상을 줄이지 않는다.
- 33: 한 corpus·각arm 답변1회·한 judge, 미측정 학습성과/운영 비용. 32장의 차이와 결합해 위키 보편 우위로 확장하지 않는 제한이 분명하다.
- 34: 입력을 만든 사람, Node 반영, 실제 검사와 미실행 LLM/검색/생성을 구별한다. “실제 파일 읽기” 링크는 보조 실행 산출물을 읽는 뜻이지 모델 읽음 증명으로 느껴지지 않았다.
- 35: 모든 외부파일 시스템→이 데모의 파일수정으로 범위를 좁힌 전후 문장이 보인다. 일반 명제를 반대 일반 명제로 뒤집지 않아 설명이 정확하다.
- 36: 세 기록은 판단 입력의 다른 역할이며 같은 크기 텍스트 줄들이 근거 신뢰도 같음을 주장하지 않는다. 하단이 고정 승인 입력이며 자동 생성 기록이 아님을 고정한다.
- 37: 선택의 교체에 맥락·검토 부담을 남긴다. ADR은 이 예제 응용이며 Wiki 필수 형식이 아니라는 발언/하단이 효력 범위를 제한한다.
- 38: 8쪽/25링크/10파일을 같은 크기 숫자 카드로 보여도 각 단위와 의미가 다르고 정확도·검색·시간 수치가 아니라고 화면/발언이 명시한다. 숫자 수가 성공 지표처럼 크게 보일 여지는 있지만 주변 설명이 이를 직접 제어하므로 수정 필수로 보지 않는다.
- 39: 원저자 제안/공개 구현 관찰/특정 조건 실험/가상 구성의 네 종류를 구별한다. 같은 도입 성과로 합치지 않는다는 발언이 제목을 실제로 해석해 준다.

심화 이후: FIRST의 ZIP/원형/구현 효력 질문은 발표 자체의 심화에서 상당 부분 답해졌다. 실제 파일 재읽기 확인은 연결 실습 문서의 구체 지침을 대조해야 한다. 공개 코드·논문 주장은 아직 이번에 원문 검증한 것이 아니므로 다음 자료 단계에서 전검증 범위를 확인한다.
