# A 초기 반응 — AI 스터디 학습자 관점

이 기록은 현재 수정본의 화면과 정확 발언을 순서대로 읽는 반복 모의 검토다. 실제 초보자 대표, 새 블라인드 실험, 음성 청취, 실시간 낭독 또는 사람의 학습 효과를 뜻하지 않는다. 이전 발표를 개인적으로 들었던 기억은 없다. 원고 revision `e1df2cd2c288c3996ec58c661598587897dba88bbf6463d23afd7b0adfd51651` 고정 입력이며, 각 구간 메모는 뒤 구간을 보기 전에 저장한다.

## 구간 1 동결 — 1~9장

- 직접 확인: phase-1 발언·전환, PNG 01→09 각각 순차 열람.
- 현재 이해: LLM Wiki는 제품명이 아니라 원자료의 개념·비교·잠정 종합을 Markdown 페이지로 남기고 다음 질문에서 다시 찾아 읽게 하는 방식이다. 사람은 자료·질문과 범위를 정하고, 파일 도구가 있는 LLM이 작성·갱신한다. raw는 보존, wiki는 갱신, schema는 두 영역에 적용하는 규칙이다.
- 자기말 회상: 새 자료를 읽으면 관련된 기존 설명도 고치고(Ingest), 질문할 때 저장한 페이지를 현재 문맥에 읽고(Query), 낡은 상태·다른 조건·빠진 연결을 의심 목록으로 확인한다(Lint). 모델 자체가 그 내용을 영구 기억하는 것은 아니다.
- 남은 질문: 어떤 페이지에 어떤 근거를 달았는지 실제 한 번의 전후 사례를 보고 싶다. 에이전트가 관련 페이지를 놓치거나 잘못 고치면 사람이 어디서 확인하는가? 시작할 때 필요한 최소 파일과 실행 도구는 아직 모른다.
- 주의 변화: 1장의 책상 사진은 읽기 경험을 떠올릴 입구가 된다. 2장은 정의 문장이 길어 핵심을 두 번 읽게 되지만 3장의 월말 수동/일별 자동 CSV가 비교의 뜻을 구체화한다. 4장의 답→페이지 저장 귀환 화살표, 6장의 raw/wiki와 아래 schema 분리가 이해에 도움이 됐다. 7~8장은 갱신과 재읽기가 별개 동작임을 화면과 말이 같은 방향으로 보여 준다. 9장 카드의 낡은 상태/조건/연결은 구별되지만 실제 의심 목록이 어떻게 생기는지는 아직 추상적이다.
- 화면 사실/인지: 01~09에서 직접 본 주요 글자와 도형은 읽을 수 있었다. 일부 작은 하단 출처·캡션은 발표 핵심보다 주의를 덜 받았다. 글자가 없거나 잘렸다고 판정한 부분은 없다.

## 구간 2 동결 — 10~18장

- 직접 확인: 구간 1 저장 후 phase-2 발언·전환과 PNG 10→18 각각 순차 열람.
- 현재 이해/자기말 회상: 소설은 행동·남의 판단·자기 설명을 분리하고 새 장으로 해석을 갱신한다. 상담은 CSV라는 형식 아래 목적·주기·자동화 요구를 나누며, 회의에서 바뀐 팀 상태와 원래 고객 요구를 함께 보존한다. 강의는 제곱오차를 공유하는 두 모델을 연결한 뒤 분류트리와 Gini라는 비교 행을 더한다. 세 경우 모두 새 사실이 들어올 때 관련 페이지를 고치고 유용한 답·다음 질문도 남긴다.
- 13장 참여 질문에 대한 실제 현재 답: “CSV라는 출력 형식으로는 묶을 수 있지만, 월말 수동 전달과 매일 자동 수신은 목적·주기·자동화가 달라 같은 구현 요구로 합치면 안 된다.” 실제 5초 타이머나 집단 투표는 하지 않았다.
- 남은 질문: 구성 파일 예라는 경계는 알겠지만 실제 LLM 실행에서 이 페이지들이 생기는 장면은 아직 보지 않았다. 새 근거와 변경 전 설명을 어떤 형식으로 함께 남기는가? 원래 고객 요구와 팀 상태를 동시에 보존할 파일 위치는 어떻게 정하는가?
- 앞 질문의 현재 상태: 10~18장의 전후 사례로 ‘어떤 근거가 무엇을 고치는가’는 구체화됐다. 근거 링크가 어디에 어떻게 보이는지, 사람의 확인 절차와 시작 파일은 아직 궁금하다. 구간 1 원메모는 수정하지 않았다.
- 주의 변화/핵심 근거: 10~12장은 동기를 확정하지 않는다는 점이 이야기 해석과 맞아 따라가기 쉽다. 13장 질문은 3장의 CSV 예고가 있어도 목적·주기·자동화 차이를 스스로 한 줄로 말하게 한다. 14~15장의 ‘보류/출시일 미확정’은 요구를 약속으로 바꾸지 않는 이유를 선명하게 한다. 16~18장에서는 제곱오차/Gini 용어를 몰라도 ‘같은 기준을 쓰는 다른 구조, 다른 기준을 쓰는 같은 계열’의 비교는 읽을 수 있다. 다만 낯선 학습자에게 세 번째 사례가 새 ML 개념 학습으로 보일 수 있어 발언의 ‘이 예’라는 범위가 필요하다.
- 화면 사실/인지: 11장 비교, 14장 요구/상태, 17장 표의 주요 글자를 읽었다. 18장은 큰 종합 문장이 주의를 잡고 아래 구성 파일 경로가 보조 근거로 보인다. 글자 부재나 잘림으로 판정한 곳은 없다.

### 24장에서 실제 작성한 질문 — 25장 PNG 열람 전

“지난 AI 스터디의 모델 평가 메모와 이번 주 오류 사례를 함께 보면, 우리가 다음 실험에서 먼저 확인할 가정은 무엇일까?” 자료 제목은 지난 모델 평가 메모/이번 오류 사례, 근거 위치는 다음 확인으로 두었다. 실제 20초 측정이나 관객 입력을 대체하는 기록은 아니다. 화면의 큰 질문 칸과 선택 공유 안내 덕분에 당장 근거 위치까지 완성해야 한다는 부담은 없다.

## 구간 3 동결 — 19~28장

- 직접 확인: 구간 2 저장 후 phase-3 발언·전환과 PNG 19→28 각각 순차 열람. 24장 질문은 25장 PNG 전 작성했다.
- 현재 이해/자기말 회상: 위키는 찾는 경로와 읽은 근거를 확인해야 쓸 수 있다. 파일의 존재만으로 현재 답이 읽었다고 믿을 수 없고, 저장된 해석도 검토해야 한다. 반복 비교할 주제라면 갱신 부담을 감수할 수 있는지 작게 확인한다.
- 가능한 첫 행동: 내 스터디 메모 몇 개와 위 질문 하나를 고르고 확인할 사람을 정한다. 읽고 쓰는 파일 에이전트에 자료 위치·권한·규칙과 ‘관련 개념·비교·종합 함께 갱신, 변경 이유와 미확인 구분, 답 저장’을 요청한다. 다음 질문에서 어떤 파일을 읽었는지 확인한다. 25·27장 안내상 실습 기본 2~4와 starter 규칙을 함께 주면 된다.
- 남은 질문: 어디까지가 복사할 최소 규칙이며 에이전트 없는 학습자는 어느 환경을 준비해야 하는가? 27장의 ‘실제 실행 범위’와 ‘고정 데모 ZIP’은 파일 교정 재현이라는 다른 경로임은 읽히지만 목적지는 아직 열지 않았으므로 실제 실행을 이어 갈 수 있는지는 보류한다.
- 주의 변화/근거: 19장 표가 세 사례를 같은 구조로 회수한다. 20~22장은 검색·오해·유지 부담을 각기 말해 과장된 영구 기억 기대를 낮춘다. 23장 도식은 4장과 같아 현재는 귀환이 잘 읽히나 lint 동작 자체가 크게 그려지지는 않는다. 24장은 ‘질문 한 줄/근거 다음 확인’이 참여 진입을 낮춘다. 25장은 요청문이 구체적이고, 26장 사진 세 장은 긴 개념 구간 뒤 시선을 환기한다. 27장은 학습서/내 자료 작성/교정 재현 목적이 구별되지만 링크가 많아 초행자의 즉시 클릭 선택은 잠시 망설일 수 있다. 28장 핵심 문장으로 다시 묶여 종료 방향은 분명하다.
- 화면 사실/인지: 19~28 주요 문장과 링크 이름을 읽었다. 검정 바탕·밝은 본문, 파랑/초록/주황 강조와 사진이 유지되어 화면 리듬이 있다. 잘림/글자 부재로 판단한 곳은 없다.

## FIRST 최종 동결 — 40장까지의 핵심 회상

- 직접 확인한 입력 범위: phase-1→메모, phase-2→메모, phase-3→메모, phase-4 순서. PNG 01~28과 40을 각각 직접 열었다. 29~39 심화, 이전 보고, 상대 판정, 제품 소스와 실습 목적지는 아직 보지 않았다.
- 기억에 남는 중심: ‘LLM이 자료 사이 개념·비교·종합을 파일로 작성·갱신하고, 다음 질문이 실제로 그 페이지를 다시 찾아 읽는다.’ 인물의 자기 설명≠확정 동기, 고객 요구≠출시 약속, 한 강의 예≠모든 모델이라는 조건 구별이 필요하다.
- 흐름 판단: 왜 남기는가→무엇/누가/어떻게→세 적용 예→찾기와 오류·유지 부담→자기 질문→실제 요청과 다음 재읽기→질문 시간으로 이어진다. 3장에서 구체 CSV 조건을 먼저 알았지만 13장에서 구분 이유를 말하고 24장에서 자기 질문으로 옮기는 행동은 남았다. 낯선 사람의 자발적 발견 효과를 입증하지는 않는다.
- 40장 반응: ‘자료·반복 질문·유지할 설명’으로 이야기 범위가 명료하다. 심화 링크를 누르지 않고도 핵심 결론과 자기 질문으로 마칠 수 있다.
- 아직 해결되지 않은 핵심: 최소 실행 환경을 내가 골라 준비할 수 있는가, 목적지에서 진짜 파일 에이전트 요청과 읽은 파일 확인을 끝낼 수 있는가. 화면·발언만으로는 실제 실행 성공을 주장할 수 없다. 점검 후보가 오류 확정이 아님은 알지만 실제 후보 목록을 어떻게 해석하는지 더 보고 싶다.
- 현재 잠정 의견: 개념을 자기말로 회상하고 시작 요청을 설명할 수 있다. 남은 실행 환경·목적지 문제는 심화 및 목적지 확인 후 판단한다. 수정되었다는 이유로 통과를 전제하지 않는다.
