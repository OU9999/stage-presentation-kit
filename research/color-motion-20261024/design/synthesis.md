# 적용할 컬러·모션 디자인

2026-10-24 · 취합 `/root/design_manager/motion_designer`

**선명한 색을 중요한 대상에 집중하고, 짧은 움직임으로 읽을 순서를 연결한다.** 원본 DevDay의 주황 선언·보라 이름·파랑 비교 막대를 참고하되, 실제 제작 HEX·원본 모션 수치를 복제했다고 설명하지 않는다. 이번 사양은 [리서치 결과](../research/synthesis.md)와 [개발 검토](../engineering/synthesis.md)를 반영한 STAGE의 독자 디자인이다.

| 실무 | 독립 작성과 편집 소유권 | 직접 협의한 연결점 |

회사명은 디자인 검토 관점이며 실제 출신 경력을 뜻하지 않는다. 두 실무자는 같은 파일을 동시에 수정하지 않고 DOM selector·class·컨트롤·시간을 직접 합의했다.

## 확정한 시각 사양

Stage와 Midnight의 의미색은 주황 `#ff7a3d`, 보라 `#a080ff`, 파랑 `#24a8ff`, 초록 `#69cf82`, 노랑 `#edcf66`을 사용한다. Paper는 기존 어두운 대안을 유지한다. 중립 캔버스·기본 글자색·사진과 작업물 표면색을 보존한다. 자세한 대비와 대상별 적용은 [컬러 사양](color-spec.md)을 따른다.

| 대상 | 적용 | 주변 요소 |
| --- | --- | --- |
| 핵심 선언 | 강조하는 한 의미 단위만 주황 | 나머지 제목은 기본 글자색 |
| 발표자 소개 | 이름 전체를 보라 | eyebrow·보조 문구·번호는 중립, 자동 장식선은 줄임 |
| 범주 | 원형·대상과 라벨의 같은 의미색 | 제목·출처·구조선은 중립 |
| 비교 차트 | 선택된 한 막대만 파랑 | 다른 막대는 회색, 수치·축·라벨은 기본 밝기 |
| 주 수치 | 실제 메시지인 숫자에 선택한 의미색 | eyebrow·설명·구조선은 중립. `.metric-unit`과 metric-pair 단위는 총괄 확정에 따라 `--slide-muted`, 기존 크기·배치·수치는 유지 |

한 장의 `tone` 선택이 eyebrow·출처·장식선·경계 전체를 같은 색으로 물들이지 않도록 구조와 강조의 토큰을 분리한다. 색이 없는 장에 새 색을 자동 추가하지 않는다.

## 확정한 모션 사양

새 데이터는 `slide.motion: none | fade | rise | stagger | chart`다. 미지정은 200ms fade. `rise`는 제목 280ms·16px 이동과 보조 60ms 지연, `stagger`는 항목 300ms·60ms 간격·최대 지연 240ms, `chart`는 막대 440ms·40ms 간격·최대 지연 80ms다. 마지막 완료는 각각 340ms·540ms·520ms로 짧게 유지한다. ease-out 또는 `cubic-bezier(.22, 1, .36, 1)`은 [모션 사양](motion-spec.md)의 선택을 따른다.

루트 6·8·12장은 `rise`, 7·19장은 `stagger`, 9장은 `chart`를 지정한다. 기존 양식과 다른 장은 유지한다. `stagger`는 최소 `steps/categories/results`의 의미 항목을 지원하고, 차트는 정적 최종 수치와 라벨을 바꾸지 않은 채 막대만 나타낸다. 일치하는 효과 대상이 없을 때도 완성 화면을 표시한다.

읽기·모바일 읽기·편집·전체 보기·발표자 프리뷰·인쇄/PDF·시스템 모션 줄이기는 모든 내용을 즉시 정적으로 표시한다. 관객의 발표 모드·비편집·screen·no-preference에서만 일회성 효과를 얹는다. 장 넘김을 기다리게 하거나 숫자 count-up·수동 단계 상태를 추가하지 않는다.

| 예제·문서 | 루트 6·7·8·9·12·19장 옵션, 적절한 Markdown 예시·작성 안내와 공통 cache hash 갱신 |

새 프레임워크·외부 폰트·CDN·사용자 작성 selector·추가 build tool은 필요하지 않다. 기존 19개 양식·편집·저장·내보내기·발표자 동기화·`file://` 재생을 유지한다.

## 확인할 결과

[독립 프리뷰](preview.html)의 선언·범주·이름·차트·단계에서 실제 사양을 볼 수 있다. 화면 선택·다시 보기·키보드·모션 토글은 프리뷰 검토용이다. 제품에 재생 UI를 추가하라는 요구는 아니다.

매니저는 데스크톱·390px, 모션 중단·키보드·OS reduce·인쇄 정적 상태를 확인하고 [검수 결과](manager-review.md)에 기록한다. 이는 디자인 프리뷰 검수이며 실제 제품 구현과 회귀 검증은 후속 엔지니어링 단계에서 수행한다.

팀 목표·담당자·미완료 작업·결정의 단일 운영 기록은 루트 `WORK_LOG.md`다.
