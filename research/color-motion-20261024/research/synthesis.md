# 컬러·모션 리서치 통합안

작성: 2026-10-24 · 취합: `/root/research_manager/motion_researcher`

## 개선할 핵심

**더 선명한 강조색과 더 좁은 적용 범위**, 그리고 **의미가 있는 대상에만 짧게 적용하는 모션**을 함께 준비한다. 현재의 차이는 팔레트 수치만으로 설명하기 어렵다. 실제 자료에서 색이 맡는 역할과 현재 CSS의 accent 전파 범위를 함께 바꾸는 것이 우선이다.

팀의 두 실무자는 `/root/research_manager/color_researcher`와 `/root/research_manager/motion_researcher`이며, 전자는 공식 영상의 실제 색 사용과 현행 비교를, 후자는 Web API·접근성 및 현재 런타임 경로 검토와 이 취합을 맡았다. 두 사람은 관찰과 구현 제안의 경계를 직접 협의했다.

## 원본 관찰과 적용 판단

컬러 담당자가 이번에 공식 영상에서 새로 확인한 대표 장면은 [키노트 23:00](https://www.youtube.com/watch?v=Fls_onRviPM&t=1380s)의 다색 범주 아이콘·라벨과 흰 제목, [24:30](https://www.youtube.com/watch?v=Fls_onRviPM&t=1470s)의 큰 보라 이름, [25:50](https://www.youtube.com/watch?v=Fls_onRviPM&t=1550s)의 중립 막대 두 개와 파랑 강조 막대 한 개다. 이는 **같은 장식색을 모든 요소에 반복하는 규칙**보다, 장마다 설명하는 주역에 색을 집중하는 접근을 지지한다. 상세 재생·캡처 근거와 색상 제안은 [컬러 조사](color.md)에 있다.

현재 `styles.css`는 `slide.tone`을 장 전체 `--slide-accent`에 연결한다. 그러면 의도한 강조 문장뿐 아니라 eyebrow·테두리 등도 함께 바뀔 수 있다. 반면 현재 차트 강조 막대는 `--slide-text`로 흰색이어서 명시적인 색이 빠진다. 팔레트 선명도, 토큰 적용 범위, 차트의 의미색 연결을 함께 수정한다. 원본의 촬영·방송·압축 이미지를 공식 HEX 규격으로 간주하지 않는다.

컬러 담당의 Stage 제안은 주황 `#ff7a3d`, 보라 `#a080ff`, 파랑 `#24a8ff`, 초록 `#69cf82`, 노랑 `#edcf66`이다. 이는 OpenAI 공식 토큰이 아닌 STAGE 디자인 제안이며 최종 결정은 디자인 팀이 한다. Paper는 현재 어두운 tone 대안을 유지하거나 같은 방식으로 대비를 다시 계산한다. 계산 조건·대비값은 [컬러 조사](color.md)에 있다.

원본 DevDay의 duration·easing·모션 제작 도구는 이번 조사로 확정하지 않는다. [모션 조사](motion.md)는 실제 코드와 W3C·MDN 본문을 바탕으로 한 STAGE 독자 사양이다. 기본 전환, 제목·설명 진입, 짧은 항목 순차 등장, 차트 reveal을 의미별로 선택한다. 모션 없이도 최종 화면과 정보가 완성되어야 한다.

## 디자인·개발팀에 넘길 적용표

| 영역 | 디자인이 준비할 것 | 개발이 검토·구현할 것 | 완료 기준 |
| --- | --- | --- | --- |
| 선언·발표자 소개 | 선명한 단일 색상의 의미 단위와 충분한 빈 공간 | `tone`과 중립 chrome 역할 분리, 선택형 `rise`/`fade` | 강조 문구 외에 무관한 eyebrow·장식선까지 같은 색이 번지지 않음. |
| 범주·역할 | 여러 색이 구분해야 하는 실제 범주와 라벨 | 항목별 tone 유지, 제한된 `stagger` 후보 | 색 없이도 라벨로 구분되며 4–5개 의미 묶음 안에서 짧게 완결. |
| 메시지+차트 | 기준값과 강조값의 명확한 대비 | 최종 수치는 정적, 장식 막대만 `scaleX` 진입 | 수치 왜곡·count-up 없이 비교가 즉시 읽힘. |
| 사진·결과 타일 | 원래 미디어 색 유지, 중립 거터와 경계 | 기존 미디어·artifact 계약 보존 | 모든 타일을 같은 색으로 물들이거나 각각 튀게 하지 않음. |
| read·print·overview·presenter·edit | 움직임 없는 최종 화면 사양 | 모션 차단과 정적 완성 상태, JS smooth-scroll 분기 | 숨은 텍스트·누락 막대·복제된 애니메이션 없음. |
| 작성·재사용 | 작성자가 고를 수 있는 작은 모션 선택지 | 문자열 enum·검증·Markdown params·export 보존 | 미지정 입력과 기존 덱이 계속 작동하고, 잘못된 입력은 진단. |

추천 모션 후보는 `none`, `fade`, `rise`, `stagger`, `chart`다. 구체 수치·easing과 대상 selector는 [모션 사양표](motion.md)에 있으며 디자인·개발 합의에서 최종 확정한다. 이 선택지들이 React를 요구하지는 않는다. CSS keyframes 또는 native Web Animations API로 구현할 수 있으며 프레임워크 필요성은 개발 팀이 제품 범위와 유지 비용까지 검토한다.

## 우선순위와 검증

1. 기존 대표 장면의 강조색 선명도·전파 범위를 조정하고 전/후 화면으로 비교한다.
2. 선언·단계·차트 등 실제 덱에서 서로 다른 의미의 모션 3종 이상을 보여주되, 기존 덱의 기본 진입은 짧게 유지한다.
3. reduced-motion에서 CSS 효과와 JS 읽기 이동을 함께 끈다. 빠른 장 이동·편집·발표자 동기화·인쇄 중에도 최종 내용이 남아야 한다.
4. 테스트는 데이터 계약·기존 덱 호환성과 새 동작의 경계에 집중하고, 색상·모션·모바일·인쇄는 실제 브라우저에서 확인한다.

팀 조사 결과는 디자인·구현 입력이다. 매니저가 새 프레임·재생 기록·소스와 코드 경로를 독립 확인한 [검수 기록](manager-review.md)을 함께 전달한다. 전체 영상의 컬러 빈도, 공식 원본 HEX, 원본 전환 수치, 물리 프로젝터의 측색·발표 거리 가독성은 검증하지 않았다. 이번 단계에서는 제품 코드와 WORK_LOG를 수정하지 않았다.
