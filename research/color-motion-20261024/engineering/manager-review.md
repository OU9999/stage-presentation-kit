# 엔지니어링 매니저 검토

2026-10-24 · `/root/engineering_manager`

이 문서는 1차 기술 검토 기록이며 해당 단계에서는 제품 코드를 수정하지 않았다. 이후 확정 디자인을 적용한 실제 결과와 매니저 독립 검수는 [제품 적용 보고](implementation.md)에 있다. 목표·배치·현재 결정의 단일 기록은 루트 `WORK_LOG.md`다.

## 적용 경계

현행 HTML/CSS/JavaScript 렌더러를 유지하고, 의미 강조색과 구조색의 분리 및 `none`·`fade`·`rise`·`stagger`·`chart` 다섯 모션을 작은 데이터 옵션으로 확장한다. React나 라이브러리의 일반적인 우열이 아니라 현재의 작성·오프라인·배포 계약과 이번 개선 범위를 기준으로 결정한다.

React는 정적 호스팅을 지원하고 reveal.js도 기본 설치에는 빌드가 필요하지 않다. 현재 시스템에는 이미 19개 레이아웃·내용 편집·내보내기·발표자 동기화·Markdown 변환이 있어, 새 진행 엔진에 이를 연결하는 비용과 회귀 범위가 생긴다. 이번 개선에는 그 비용을 정당화할 새 제품 요구가 없다. 상세 공식 근거와 도입 조건은 [구조 검토](architecture.md)에 있다.

## 매니저의 독립 코드 검수

- `app.js`의 `renderSlide()`는 콘텐츠를 DOM으로 만든다. `slide.motion`을 검증된 문자열의 `data-motion`으로 내보내는 작은 확장이 가능하다.
- `updateActive()`는 주 무대의 현재 장을 제어하고 `renderPresenter()`는 별도 복제본에도 `.is-active`를 부여한다. 범용 `.slide.is-active` 선택자로 새 효과를 확장하면 미리보기도 움직일 수 있으므로 실제 관객 무대만 대상으로 한다.
- `toggleEdit()`는 `body[data-editing]`를 바꾼다. 모션 선택자에서 편집 상태를 제외하면 실행 중 효과를 제거하고 정적 최종 내용을 편집할 수 있다.
- `scripts/markdown-deck.cjs`는 `COMMON`과 레이아웃 필드의 허용 목록을 검사한다. 모델만 확장하면 Markdown의 새 옵션이 거절되므로 두 경로를 함께 바꿔야 한다.
- `updateActive()`의 읽기 모드 `scrollIntoView({behavior: "smooth"})`는 CSS reduced-motion 차단과 별개다. JS에서 `matchMedia()` 결과에 따라 `auto`로 분기한다.
- 기존 print 규칙은 슬라이드 자체의 animation을 끈다. 새 하위 요소 효과까지 정적으로 보장하려면 효과 전체를 `@media screen and (prefers-reduced-motion: no-preference)` 안에 두고 관객·발표·비편집 상태로 한정한다.

## 디자인팀에 전달하는 모션 계약

1. 미지정은 짧은 기본 fade이며 잘못된 문자열은 기존 입력 진단 경로로 안내한다.
2. 최종 화면을 기본 스타일로 만들고 모션은 일회성 추가 표현으로 둔다. 제목·라벨·최종 수치는 움직임 없이도 읽힌다.
3. 관객의 `#slideStage`·발표 모드·비편집 상태·모션 허용 환경에서만 실행한다. 읽기·인쇄·전체 보기·발표자 프리뷰·편집·reduced-motion에서는 정적 최종 화면을 표시한다.
4. `rise`는 제목과 설명 같은 작은 묶음, `stagger`는 최대 다섯 의미 항목, `chart`는 장식 막대의 `scaleX`만 움직인다. 수치를 0부터 세거나 도표 값을 바꾸지 않는다.
5. 장 이동은 효과 종료를 기다리지 않는다. 모드 전환이나 빠른 이동 뒤 숨은 내용·작아진 막대가 남지 않아야 한다.

CSS의 `animation-fill-mode`는 실행 전·후 스타일 유지 범위를 정한다는 [MDN 본문](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/animation-fill-mode)을 매니저 전용 브라우저 탭에서 직접 확인했다. 지연 구간을 포함한 표현을 쓸 때도 기본 스타일은 완성 상태로 유지하고, 효과 선택자가 사라지면 즉시 그 상태로 돌아가도록 설계한다. 실제 적용 시간·이동량은 디자인팀이 사양을 확정한다.

## 후속 구현과 검증

동일한 실무자를 재개해 런타임/CSS와 모델/작성 흐름을 나눈다. 데이터 enum·Markdown round trip·잘못된 입력·기존 덱 호환성은 자동 검사하고, 다섯 효과·빠른 이동·편집·발표자·모바일 읽기·시스템 설정 변경·인쇄·`file://`는 실제 브라우저로 확인한다. 공유 파일 해시와 다섯 예제 생성 결과도 함께 갱신한다.

이번 검토는 구현·성능 프로파일·모든 브라우저 검증을 완료했다는 뜻이 아니다. 실무자의 공식 문서 확인과 구조 검토는 [통합 권고](synthesis.md), [모션 계획](motion-plan.md)에 연결한다.

## 최종 산출물 확인

두 실무자의 문서를 매니저가 직접 읽고 코드 경계·상호 협의 결과를 대조했다. 실무자 둘 모두 작성과 편집 종료를 직접 보고했다. 최종 문서 네 개의 링크 23개 중 로컬 링크 9개의 대상 누락은 없었으며 EOF·후행 공백과 `git diff --check`를 확인했다. 구조 담당의 제한된 `file://` 검증과 매니저의 공식 문서 확인은 위에 분리해 기록했다. 제품 수정은 디자인 사양을 받은 뒤 같은 두 실무자를 재개해 진행한다.
