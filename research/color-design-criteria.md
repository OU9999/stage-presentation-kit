# 사진과 색의 운영 기준

2026-10-23 · 두 탐색 보고서와 대표 프레임의 직접 검수를 반영한 최종 설계 판단.

**공통 캔버스는 차분하게, 사진·작품은 원래 컬러로, 색 타이포와 발표자 소개용 색면은 목적에 맞게 사용합니다.** 초록 장식의 과도한 반복을 줄인다는 판단은 컬러 사진이나 유색 장면을 금지한다는 뜻이 아닙니다. 색 면적·등장 빈도·팔레트 수를 일률적으로 정하지 않습니다.

이 문서는 관찰과 재사용 기준을 기록하고, 후속 구현이 반영된 현재 상태를 구분합니다. 현재 예제는 16개 레이아웃을 사용하는 20장입니다. 제품 CSS·JS·콘텐츠는 이번 문서 갱신에서 수정하지 않았으며, 구현 상태와 실제 화면·모바일·PDF 검증 상태는 별도로 판단합니다.

## 최종 색 운영 판단

| 적용 대상 | 채택한 기준 | 제한적으로 해석할 부분 |
| --- | --- | --- |
| 공통 캔버스·본문·조작 UI | 반복되는 틀은 차분하게 유지하고 내용이 중심이 되게 함 | 모든 장이 검정이어야 한다는 뜻이 아님 |
| 사진·영상·작품·실제 UI | 파일이 가진 원래 컬러와 표현을 유지. 콘텐츠가 필요하면 화면 대부분을 차지할 수 있음 | 테마에 맞추기 위한 자동 탈색·단색 틴트를 기본값으로 삼지 않음 |
| 범주·비교 조건·도해·상태 | 연결된 대상·아이콘·라벨에 같은 의미색을 사용하고 이름·위치·단위 같은 비색상 단서도 유지 | 원본의 색 조합과 색 개수를 공통 팔레트로 규정하지 않음 |
| 주장과 수치의 강조 | 핵심 의미 단위나 중요한 변화량을 색으로 강조할 수 있음 | 색의 용도를 데이터·오류·상태에만 제한하지 않음 |
| 발표자 소개 전환 | 사람의 등장에 큰 유색 타이포 또는 색면을 선택할 수 있음. 다음 설명 화면과의 관계를 함께 설계 | Figma의 사례를 모든 챕터가 색면이어야 한다는 규칙으로 확대하지 않음 |
| 제품·작품의 정체성 | 제품색·작품색을 보존하고 바깥 프레임·간격으로 정돈 | 모든 결과물의 색을 한 테마색으로 통일하지 않음 |
| 장식선·배지·작은 라벨 | 콘텐츠와 독립적인 장식색의 상시 반복을 줄임 | 이 절제가 사진의 컬러나 목적 있는 색 타이포를 금지하지 않음 |

사진의 컬러와 장식색은 다른 대상입니다. 중립적인 틀 위에 풍부한 컬러 사진이 놓여도 일관성은 프레임·정렬·간격·캡션에서 생길 수 있습니다. 반대로 모든 장의 라벨·구분선·버튼에 같은 색을 반복하면 내용과 관계없는 색의 존재감이 커집니다. 문제는 색 자체가 아니라 적용 대상과 역할입니다.

## 사진·이미지 양식의 요구사항과 구현 상태

| 유형 | 재사용 기준 | 현재 상태 |
| --- | --- | --- |
| 한 장의 사진을 크게 | 피사체·초점 위치·필요한 크롭을 보존. 캡션은 사진 밖이나 중요한 대상을 피한 자리에 배치 | `image`·`media`에서 단일 이미지와 `fit`·`focalPoint`·`zoom` 지원. 전체 화면 컬러 풍경 예제 포함 |
| 사진을 조건별로 한 장씩 보여주기 | 바깥 프레임·조건 라벨 위치를 유지하고 비교 축과 순서를 분명히 함 | 단일 이미지 양식을 복제해 구성 가능. `zoom`은 숫자 1~3의 디지털 표시 확대이며 광학 줌이 아님 |
| 동등한 인물·사례 모음 | 같은 프레임 비율·일정한 간격·이미지별 설명·대체 텍스트·초점 위치 | `gallery`의 `variant: "portraits"` 구현. 현재 예제에는 풀컬러 스톡 사진 6장 배치 |
| 조건이 있는 사진 스트립 | 이미지 순서·이미지별 조건 라벨·공통 크레딧을 함께 유지 | `gallery`의 `variant: "strip"` 구현. 같은 사진의 디지털 확대 조건을 비교하는 예제 포함 |
| 비대칭 작품·제품 콜라주 | 큰 대표 이미지와 작은 보조 이미지, 공통 경계·간격, 이미지별 `fit`·출처 | `mosaic` 구현. `span: 1` 또는 `2`로 폭을 선택하며 현재 예제는 합계 8의 두 행. 사진과 자체 제작 SVG를 혼합 |
| 주장 옆의 여러 결과물 | 문서·분석 UI·3D 등 매체별 가독성과 중요한 내용을 보존 | `results` 구현. 왼쪽 메시지와 오른쪽 2×2 결과물. 기존 단일 화면 `demo`도 유지 |
| 범주와 같은 색의 아이콘·라벨 | 아이콘·이름·설명을 함께 제공하고 범주별 색을 연결 | `categories` 구현. 항목별 `tone`과 편집 가능한 심벌·이름·설명을 지원 |
| 사진과 인용·짧은 서사 | 인물·장소·작품과 발화를 연결 | 검토 후보. 이번 직접 사진 근거에서 확인된 양식이라고 주장하지 않음 |
| 발표자 소개용 유색 타이포·색면 | 이름과 전환의 역할을 분명히 하고 다음 내용 화면과 연결 | 슬라이드의 `tone`·`highlight`와 `surface: "butter"` 구현. 유색 이름과 밝은 소개 색면 뒤 중립 메시지로 돌아오는 예제 포함 |

현재 제품은 16개 레이아웃과 중앙 메시지 변형을 제공합니다. [사진 7장](../assets/photos/)과 [자체 제작 컬러 SVG 5개](../assets/examples/)을 로컬에 포함하며, [assets/CREDITS.md](../assets/CREDITS.md)에 작가·원본·자산 설명을 기록했습니다. 스톡 사진 속 인물을 실제 행사 참여자나 발표 사례로 소개하지 않습니다. 이미지·영상에 회색조 필터를 적용하지 않습니다. 소스가 원래 색을 보존한다는 사실과 20장 예제의 화면·모바일·PDF 결과를 실제 검증했다는 주장은 구분합니다.

화면의 내용 편집은 제목·라벨·캡션·설명 같은 문자 수정용입니다. 사진 경로·색·크롭 초점·확대·항목 수·레이아웃 선택은 `content.js`에서 수정합니다. 사진과 인용을 결합하는 전용 레이아웃은 아직 없습니다.

## 짧은 재사용 예

문장의 한 줄 전체를 강조할 때는 색의 목적과 범위를 따로 지정합니다.

```js
{
  layout: "statement", align: "center", tone: "orange",
  title: ["보여주는 방식이,", "이해를 바꿉니다."],
  highlight: "이해를 바꿉니다."
}
```

발표자 소개 장면은 `layout: "section"`, `align: "center"`, `surface: "butter"`로 밝은 면과 어두운 글자를 사용할 수 있습니다. 이는 소개 전환의 선택지이며 모든 장의 기본 배경이 아닙니다. 사진 모음의 편집 예와 지원 필드 값은 [디자인 가이드](../DESIGN.md#사진과-색을-바꿔-재사용하기)에 정리했습니다.

## 현재 예제와 후속 양식의 검수 기준

- 동일 조건의 비교는 프레임·순서·라벨 위치를 안정시킵니다. 서로 다른 작품은 원래의 가로·세로 구도를 살릴 수 있어야 합니다.
- 사진과 문서·UI에 같은 `cover` 크롭을 강제하지 않습니다. 정확한 원본 크롭 방식이 확인됐다고 주장하지 않습니다.
- 사진마다 큰 어두운 덮개나 그라데이션을 자동 적용하기보다 캡션 자리와 대비를 먼저 정합니다. 텍스트가 없는 사진도 허용합니다.
- 여러 이미지의 모바일 읽기에서도 순서·조건·설명·크레딧이 유지되어야 합니다. 인쇄에서는 이미지와 필요한 캡션이 의도한 한 장의 구도로 출력되는지 확인합니다.
- 색면은 그 장의 목적과 앞뒤 흐름으로 판단합니다. 고정 색 비율, 주기적 등장 빈도, 원본에서 추정한 정확한 색상 값을 규칙으로 만들지 않습니다.
- 발표 화면, 방송 합성, 제품 UI 안의 사례, 브랜드 필름을 구분합니다. 무대 조명·객석·의상·방송 외곽의 색을 발표 캔버스의 규칙으로 포함하지 않습니다.

이 문서 갱신 시점에 매니저가 현재 예제의 검증을 진행 중입니다. 렌더러와 스타일의 존재만으로 화면·모바일·PDF를 모두 통과했다고 단정하지 않으며, 최종 확인 결과는 프로젝트 README와 전달 기록을 기준으로 판단합니다.
