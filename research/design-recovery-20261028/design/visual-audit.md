# DevDay 디자인 의도와 새 Markdown 발표의 시각 감사

담당: `/root/design_manager/visual_auditor`. 기준 HEAD `cdb88b421d5a2fc018fe0269713e1ba16d4d8b20`, 2026-10-28. 회의용 독립 초안이며 제품 구현·기존 원고 편집·새 원본 영상 시청을 수행하지 않았다. 상태는 루트 [WORK_LOG.md](../../../WORK_LOG.md)에서 관리한다. 이 문서는 STAGE의 디자인 판단이며 OpenAI 공식 규격이 아니다.

## 판단

새 발표는 검정 캔버스와 공통 UI를 유지했지만, 기존 디자인의 중심이던 **내용 역할에 따른 화면의 변화**를 일반 Markdown 작성 경로에 연결하지 못했다. 단순한 색상 손실로 설명하기 어렵다. 같은 `layout:blocks`에 제목·본문을 세로로 쌓는 경로가 유일하므로, 짧은 주장도 이미지가 주인공인 장도 표와 설명이 있는 장도 비슷한 문서 구도로 나온다.

이는 본문을 잘못 파싱했다는 주장과 다르다. 기존 원고의 의미·순서·링크·표·코드를 보존하는 새 기능은 유지할 가치가 있다. 복원 과제는 그 원고를 버리거나 모든 장을 옛 구조형 YAML로 되돌리는 것이 아니라, 평범한 원고에서 얻는 기본 화면을 개선하고 역할 선택이 필요한 경계에서만 작성자에게 작은 결정을 요구하는 것이다.

## 보존할 원리와 확인한 차이

`확인`은 코드·문서 또는 직접 연 이미지에서 관찰한 사실, `추정`은 그 사실이 사용자 경험에 주는 영향에 관한 판단이다. 실제 캡처가 없는 모든 장의 최종 모양까지 확인했다고 확대하지 않는다.

| 차이 | 보존할 기존 원리 | 새 일반 Markdown 경로의 확인 근거 | 결과와 우선순위 |
| --- | --- | --- | --- |
| 1. 역할이 같은 구도로 합쳐짐 | 메시지→근거→시연의 역할 변화. 기존20양식을 수만큼 의무 사용하라는 뜻은 아님 | parser는 일반 장마다 `layout:'blocks'`를 반환한다. 두 새 덱은 각각6장 모두 일반 Markdown이다 | **확인:** 역할별 renderer로 연결되지 않는다. **추정/P0:** 덱의 박자와 정보량 대비가 약해진다 |
| 2. 큰 선언의 위계 | 큰 문장 하나를 중심에 놓고 부차 정보를 덜어냄 | blocks 제목은70px/1.18, body는30px/1.55. 기존 중앙 statement는126px이며 메시지 화면은 footer를 숨긴다 | **확인:** 짧은 선언도 동일 제목 크기다. **추정/P0:** 검정 바탕만 같고 시선의 중심은 문서 제목처럼 느껴진다 |
| 3. 주역 미디어의 면적 | UI·데모에서 읽어야 하는 화면에 큰 면적 제공. fit은 매체 목적에 따라 선택 | `.markdown-body img`는 모두 `max-height:230px;object-fit:contain`. 기존 media는 무대 전체 사용 | **확인:** 이미지가 용도와 관계없이 같은 상한을 받는다. **추정/P0:** 제품 원고#2의 대시보드는 근거보다 삽화로 읽힐 수 있다. 단순 상한 해제는 목록 넘침 반례가 있어 해결이 아님 |
| 4. 주장·근거의 관계 | wide/split에서 주장, 큰 값, plot을 가까이 묶고 시작선을 맞춤 | blocks는 제목 뒤에 하나의 `.markdown-body`만 둔다. 표는 원래 표이고 숫자도 본문 텍스트다 | **확인:** 일반 입력에는 wide/split 관계 표현이 없다. **추정/P0:** 표를 자동차트로 바꾸기보다 사용자가 단일 근거와 배치를 선택할 작은 계약이 필요 |
| 5. 부차 메타의 위계 | 큰 메시지·전체 미디어·quiet 요약에서 내부 footer/eyebrow를 숨김 | blocks 분기는 quiet/message 역할을 부여하지 않고 공통 footer를 추가한다 | **확인:** 일반 장에는 footer가 유지된다. **추정/P1:** 선언의 몰입과 빈 공간을 방해할 수 있다. 제목·화자·출처 같은 원문 정보 자체를 삭제해서는 안 됨 |
| 6. 강조의 의미 범위 | 한 의미 단위를 선명한 색으로 강조하고 단위·출처·경계는 중립으로 구분 | blocks의 `strong,em`은 모두 공통 accent로 처리된다. 두 새 덱에는 장별 의미색 선택이 없다 | **확인:** Markdown 강조와 장별 의미색 역할의 선택이 분리되지 않았다. **추정/P1:** palette 복구만으로는 역할 변화가 생기지 않으며 임의 의미색 자동추론은 피해야 함 |
| 7. 한국어 글폭과 줄바꿈 | 주장과 긴 본문은 읽기 폭·크기·행간을 달리한다. 의미와 작성자 줄바꿈 보존 | blocks 본문은 기본30px/1.55이며 전용 max-width가 없다. 기존 긴 본문 권고는30px/1.65·34em 이내 | **확인:** 본문 전용 글폭 규칙이 없다. **추정/P1:** 같은70px 제목에서도 긴 설명은 화면 너비에 끌려가고 읽기 리듬이 단조로울 수 있음 |
| 8. 요약의 편집 구조 | C안은 관련 결과물의 자체 표면·크기 위계·주역1~2개를 유지 | blocks allowlist는 의미 HTML이고 artifact·불균등 타일·주역 슬롯 계약은 없다. 기존#4는 `bento/seoul/editorial`과 artifact 종류를 명시한다 | **확인:** 평문·표·이미지 나열만으로 C안 요약을 자동 생성할 수 없다. **추정/P1:** 고급 요약에는 선택형 구성이 필요하며 매 장을 타일로 바꾸면 원래 문제를 반복. Markdown 그룹+주역 선택 후보를 검토해야 하며, 매번 JSON을 쓰는 기존 경로만 남으면 간단 작성 목표와의 간극은 미해결 |
| 9. 검증의 정의 | 기능 보존과 디자인 충실도를 둘 다 확인 | 이전210개 기능검사는 의미보존·독립 생성·오류·넘침 중심이다. 역할별 화면 비교는 해당 통과의 자동 귀결이 아님 | **확인:** 기능 통과와 시각 충실도는 다른 주장이다. **P0:** 같은 원고·동일 viewport로 역할·위계·미디어 가독성까지 검수해야 함 |

기존20양식과 palette가 삭제된 것은 아니다. renderer와 stylesheet에 여전히 남아 있다. 따라서 현재 증거가 지지하는 원인은 공통 테마 파일의 소실보다 **일반 작성 경로와 기존 시각 역할 사이의 연결 부재**다. 구체적인 parser·모델 확장 방식과 비용은 엔지니어링팀의 재현·검토로 확인해야 한다.

## 기존 원고를 보존하는 복원 경계

1. 두 `talks/*/slides.md`와 기존 예제 원고를 감사의 불변 기준으로 둔다. 제안 원고는 이번 연구 폴더에만 두며 기존 덱을 강제로 새 서사로 고치지 않는다.
2. 첫 H1 한 번 소비, 이후 제목·목록·표·코드·인용·링크·alt·줄바꿈의 의미 보존을 유지한다. 숫자를 제목으로 승격하거나 표를 차트로 해석하는 것은 자동 기본값으로 삼지 않는다.
3. 일반 기본값의 공간·글폭·이미지 표시를 개선하되 모든 장을 중앙 큰 문장·full bleed·타일로 추론하지 않는다. 자동 제안은 재현 가능한 구조 조건과 결과 미리보기를 갖추고 작성자의 명시 선택이 우선해야 한다.
4. 선택 배치는 의미 노드의 참조와 presentation metadata로 표현하는 방향을 검토한다. 별도 JSON/SVG에서 문장·수치를 다시 써야 한다면 원고 단일 권위를 약화한다. 정확한 문법·확장 범위는 이번 감사가 확정하지 않는다.
5. 발표에서 column으로 보여도 읽기 화면은 원고 순서·전체 본문·원래 링크를 유지한다. 정보가 다 들어가지 않으면 자동 삭제·전체 축소 대신 진단과 작성자의 분할을 사용한다. 긴 설명을 읽기로만 옮기는 별도 저작 정책은 사용자 동의 없이 도입하지 않는다.
6. 개념도·가상 수치·스톡 사진의 성격과 실제 출처를 유지한다. C안의24/6/3은 다른 작업 단위이며 퍼널 전환율로 변환하지 않는다.

메시지·근거·주역 미디어의 세 역할을 작은 힌트로 복구하는 방향만으로 두 수치와 C안까지 간단한 Markdown으로 재사용할 수 있다고 주장하지 않는다. 후속 후보는 원고 안의 관련 그룹을 지정하고 주역 그룹 하나를 고르는 방식이다. 같은 문장·수치를 별도 JSON에 복사하지 않고도 기존 미디어의 자체 면과 크기 위계를 만들 수 있는지 검토해야 한다. 그룹 문법·고정 슬롯과의 대응·빈 자료의 처리·작성 부담은 현재 미확인이다. 기존 정밀 양식 호환은 보존하되 이를 이 간극의 해결로 보고하지 않는다.

## 미확인과 다음 행동

- 새 동일 viewport 7장과 관찰 JSON은 root가 제공했고 이번 감사에서 실제 확인했다. 같은 내용의 기본/제안 A/B는 아직 없으며 새 배치의 가독성·기존 덱 회귀를 통과했다고 주장하지 않는다.
- 사용자의 최종 미감·원본과의 픽셀 동일성·공식 서체/토큰·전편의 전환 동작은 미확인이다. 보존된 정지 프레임은 이 항목의 증거가 아니다.
- 다음 회의에서는 B의 작성 계약에 `이미지+목록`의 순서 보존, `표→차트` 자동 변환 금지, `명시 역할이 본문을 숨기지 않음` 반례를 대조한다. 적용 문법·자동성의 정도·최소 구현 범위는 양팀 합의 후 결정한다.

## B 초안과 직접 교차 검토

B의 [작성 계약·7장 서사 초안](story-proposal.md)을 독립 초안 작성 뒤 직접 읽었다. A가 먼저 제시한 이미지+목록 자동 split의 순서 충돌 반례에 대해 B는 자동 split을 기본에서 제외하고 DOM·읽기 순서를 유지하는 방향으로 응답했다.

B가 제기한 **가상 삽화를 확대해도 근거 타당성이 생기지 않는다**는 반례를 수용한다. 위#2의 작은 대시보드 관찰은 현재 크기에서 세부를 읽기 어렵다는 뜻이며, 그 이미지의 목적이 삽화라면 무조건 근거 장으로 승격할 이유가 없다. 표 역시 관계 자체가 이미 적절한 근거일 수 있다. 복원에 앞서 읽어야 할 대상인지 보여 줄 분위기인지 작성자가 결정해야 한다.

A는 B의5장 `message` 가안에 추가 반례를 전달했다. H1과 인용문이 함께 있는 장에서 `message` 하나만으로는 무엇을 크게 해야 하는지 모호하다. 제목을 무조건 크게 하면 의도한 인용이 보조로 밀릴 수 있다. 기본 focal을 첫 H1로 명시하고 인용 주역은 별도 선택으로 남기거나 이 장은 기본 배치를 유지하는 것이 안전하다. 이 반례의 수신·최종 반영은 B가 자기 문서에 기록한다.
