# 재사용성 검토에 따른 수정과 검증

2026-10-23. 기존 예제의 디자인을 유지하며 params 입력과 분량의 실패를 보강했습니다.

| 재현한 문제 | 수정한 동작 |
| --- | --- |
| null 슬라이드, points 객체, steps 문자열, 잘못된 layout이 전체 초기화를 중단 | 해당 장에 필드 경로와 수정 방법을 표시하고 나머지 장의 탐색 유지 |
| mosaic의 span 합이 8이어도 배치 순서에 따라 이미지가 사라짐 | 4열×2행의 위치를 계산해 모든 항목 표시. 원본/DOM 순서와 모바일 읽기 순서는 유지하고 데스크톱 빈 칸 채우기는 허용 |
| 단계 7개·결과 5개가 경고 없이 잘리거나 다른 배치로 변함 | 양식별 수량을 검사해 해당 장에 분리 안내. 내보내기에는 모든 원본 항목 보존 |
| 긴 문장이 화면에서 잘림 | 활성 장의 실제 텍스트·미디어 크기를 확인해 작성자 점검에 표시. 읽기 모드로 전체 내용 확인, 짧게 수정하면 경고 해제 |
| 큰 숫자의 좁은 line-height를 잘림으로 오판 | 글리프가 보이는 overflow와 실제 제한된 clipping을 구분. 특정 양식을 검사에서 제외하지 않음 |

[입력 계약과 수량](../CONFIG.md), [다른 주제 params 예제](../examples/project-review.js)를 추가했습니다. 런타임은 설치·빌드·외부 의존성 없이 로컬 파일로 실행합니다. 임의의 긴 내용을 자동 축소하거나 항목을 조용히 삭제하는 방식은 사용하지 않습니다.

## 검증

- `node --test tests/*.test.cjs`: **43/43 통과**. 두 주제의 16종 입력, 오류 경로, 하한·상한·초과 수량, 배치 비중첩·용량, 데이터 불변성, classic/Node 인터페이스, 숫자 문자열 호환, metric 타입, 차트 0·음수 경계를 확인했습니다.
- 구현자와 별도의 검토 엔지니어가 Chromium에서 다른 주제 20장씩과 추가 예제 6장을 순회했습니다. 이미지 누락·본문 넘침·작성자 경고가 없었습니다.
- 정상 장 사이에 잘못된 입력을 넣어 해당 장만 오류 카드가 되는지 확인했습니다. 실제 다운로드한 content.js를 다시 파싱해 null·잘못된 배열 타입·단계 7개·결과 5개가 보존되는 것도 확인했습니다.
- 긴 문장의 경고 발생 → 실제 편집 → 경고 해제를 확인했습니다. 숫자 화면의 경고 오탐도 제거됐습니다.
- 매니저가 원본 20장 전체의 경고 없음, 전체 보기 20장, 발표자 창과 이동을 확인했습니다. 390px 읽기에서는 콜라주가 입력 순서의 한 열로 표시되고 가로 넘침이 없었습니다.
- 오류 발표의 390px 읽기·진단 창도 가로 넘침이 없었습니다. 작성자 점검 UI는 인쇄하지 않습니다.
- 발표·읽기 모드 각각 20페이지 PDF를 만들고 콜라주 페이지를 렌더링해 배치를 확인했습니다. `git diff --check`와 JavaScript 문법 검사도 통과했습니다.

Node 검증은 실제 브라우저의 geometry를 흉내 내지 않습니다. 같은 TC 식별자에 대응하는 장문·내보내기·모바일·PDF 동작은 별도의 실제 화면 확인으로 기록했습니다. 모든 운영체제·임의의 콘텐츠 분량을 보장한다는 뜻은 아닙니다.
