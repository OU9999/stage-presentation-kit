# 발표 제작 인수 계약

발표는 Zoom의 가벼운 한국어 AI 스터디를 위한 20분 자료다. 18분 발표와 2분 질문을 기준으로 한다. 한 가지 합성 스터디 준비 예제로 원자료, 연결된 위키, 출처 대조, 선택 이유, 새 자료에 따른 재검토를 설명한다.

## 변경 경계

- 원고: `talks/llm-wiki/slides.md`
- 발표팀 자산: 같은 폴더의 `assets/*.svg`, `assets/speaker-guide.txt`
- 엔지니어링팀 인수 자산: `assets/sources.txt`, `assets/decision-example.txt`, `assets/starter-template.txt`
- 기존 원고·runtime·CSS·기존 공개 주소는 보존한다. 생성·브라우저·Git·공통 WORK_LOG는 root가 소유한다.
- 원본에 연결된 자산만 builder가 복사하므로 각 첨부는 원고에서 실제로 링크한다. 임의 Markdown 첨부를 추가하지 않는다.

## 첨부 내용 계약

`sources.txt`는 실제 외부 조사 S1/S10/S11/S12와 C01~C10의 구분, 원문 URL·확인 범위·확인일·한계를 담는다. S1의 별도 수정일과 revision SHA는 미확인 상태를 유지한다. S11은 비규범 Note이며 S12 실험을 현재 제품 성능으로 확대하지 않는다. 조사 원본은 `../research/{sources,claim-ledger,synthesis}.md`다.

`decision-example.txt`는 E1/E2/E3/E4, EC1/EC2, ED1/ED2 전체가 합성 예제임을 첫머리에 밝힌다. ED1은 배경·선택과 이유·대안·결과·담당·결정일·상태·재검토 조건을 담고, ED2가 승인된 뒤 `superseded by ED2`로 보존한다. 변경은 11월 5일 한 날짜의 20시→20시 30분이다. 실제 초대장을 수정했다는 결과를 쓰지 않는다.

`starter-template.txt`는 원자료/위키/작업 규칙, 자료/주장/결정 카드, index(찾기)/log(변경 이력)를 작게 시작하는 공개 예시다. LLM Wiki·PROV·ADR 표준 양식으로 표시하지 않는다. 프롬프트는 사람 검토를 돕는 작업 요청이며 오류를 막는 보장으로 쓰지 않는다.

`speaker-guide.txt`는 비공개 notes를 대체하는 공개 첨부다. 장별 시간표, 말할 내용과 전환, 청중 질문, 주요 source/claim 대응을 담는다.

## 핵심 인수 기준

1. Karpathy의 LLM Wiki를 공개 설계 패턴으로 소개하며 원자료/wiki/schema 세 층에서 규칙을 옆에 놓는다.
2. E1/E3/E4가 운영/개념/질문 페이지에 연결되고, 검토한 유용한 질문 답이 위키에 남는 축적을 보여준다.
3. E1은 11월 5일 20시를 지원하며 '매주 20시'를 지원하지 않음을 청중과 대조한다.
4. 출처 링크와 문장 지원 여부를 구분한다. 자료에서 확인한 사실과 사람이 선택한 결정을 구분한다.
5. E2의 명시적 변경·대상 날짜를 확인한 뒤 관련 주장/결정을 다시 보고 과거 기록을 보존한다.
6. 파일 저장과 모델 가중치 학습을 구분하고 wiki와 RAG의 병행 가능성을 남긴다.
7. 합성 표시는 사례 화면에도 남긴다. 효과 수치·무오류·자동 최신성·유지비 0 주장은 넣지 않는다.
8. SVG 핵심 의미가 alt와 같은 장 본문에서도 확인 가능해야 한다. 390px 읽기에서 전문·alt·첨부 접근을 검수한다.

## 발표팀 검토 결과

실제 원고는 12장이다. 1~11장이 18분, 12장은 2분 질문이며 중간 상호작용 45초는 각 장 시간 안에 포함된다. 이 시간은 진행 계약이며 실제 낭독 리허설 실측치는 아니다. 원고 SHA-256은 `37fb4bd8eb5610d8545457337842d7f7ab1f475deeb417c4dd1ba694a4f7e6db`다.

A는 이야기·원고·공개 가이드를 독립 작성하고 B의 자체 SVG3개를 통합했다. 두 실무자가 원고/가이드와 SVG의 실제 텍스트·연결을 서로 읽고 직접 검토했다. B의 위치 표현 교정(오른쪽 wiki), 관리자의 모바일 본문/원본 링크 보완과 closing 목록 교정을 A가 반영했다. 자세한 구성 의도는 `story-plan.md`와 `visual-plan.md`에 있다.

관리자는 sources/claim-ledger/synthesis와 원고·가이드·SVG3개를 직접 대조했다. 합성 표시, 연결된 개념/질문과 검토한 답 축적, schema 옆 규칙, 근거 범위, 사실/선택 구분, ED1 대체 이력과 11월 5일만의 변경 범위가 일치한다. C* 상세 대응은 공개 가이드에 두어 화면의 내용이 먼저 보이게 했다.

관리자와 B가 생성물을 변경하지 않는 `parseDocument`→`planSlide`를 각각 실행했다. 12장 모두 요청한 구도(message2/media3/bento6/closing1)와 일치하며 경고는 0이다. `collectReferences`로 실제 원문4개, SVG3개 이미지/원본 링크, 가이드와 후속 txt3개의 원고 연결을 확인했다. 후속 txt3개는 아직 제작 대상이므로 지금 전체 빌드가 완료되었다는 뜻은 아니다.

실제 Stage·읽기·발표자·390px의 가독성/잘림·링크와 첨부 열기, 전체 생성·회귀·기존 파일 보존·공개 배포는 root의 후속 검수다. SVG의 축소된 작은 글자만으로 모바일 가독성 합격을 주장하지 않는다. 같은 장의 본문/alt/도식 원본 링크를 접근 경로로 제공했다.

발표 A/B 모두 편집 종료·completed 후 `/root/llm_engineering_manager`가 위 계약과 실물 문서를 읽고 직접 수용했다. 원고·가이드·SVG의 후속 단독 소유자는 engineering B, txt3개의 작성자는 engineering A다. 발표팀은 이 인계 문서를 포함해 편집을 종료한다.
