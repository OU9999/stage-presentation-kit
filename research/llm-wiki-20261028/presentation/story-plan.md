## 주장과 화면 경계

C01~C03은 S1 직접 지원, C04는 이 설계에서 파일 저장과 학습을 구분한 해석, C05는 S12 정의 직접 지원과 병행 가능 해석을 나눴다. C06은 S11 직접 지원으로 출처를 평가 단서로 설명하고 C07은 S10 직접 지원과 스터디 적용 제안을 구분했다. C08 통합 카드와 C10 영향 검토·승인은 우리 제안, C09 확인 필요성은 해석·제안이다. 화면은 자료 제목·역할·실제 문장을 우선하며 실제 primary4개의 짧은 S* ID와 원문 링크, 해석·제안 경계를 남긴다. 상세 C01~C10대응은 공개 guide와 sources.txt로 옮겼다.

E*가 나오는 4·6·7·8·9·10장은 본문/그림 caption에 합성 예제·합성 주장·합성 결정을 표시한다. ED1의 상세 배경·선택·이유·대안·결과·상태·담당·재검토는 decision-example.txt가 보충하며, 화면에는 이유·대안·재검토를 남겼다. ED1 당시 accepted와 이후 superseded by ED2를 나눠 보여 준다. 다른 날짜의 시작 시각으로 확대하지 않는다.

핵심 한계는 3장 규칙준수 불보장, 5장 점검 누락 가능, 6장 출처 링크≠정답/신뢰 보장, 9장 최신날짜만으로 자동교체 금지, 10장 실제 초대장 수정 아님, 11장 파일저장≠모델학습·RAG병행 가능·미측정 효과로 화면에 남겼다.

## B와 직접 합의

- B canonical: `/root/presentation_manager/visual_designer`.
- 2026-10-28 직접 메시지로 SVG3개 경로와 장 매핑 합의: `wiki-layers.svg`(3장), `knowledge-map.svg`(4장), `change-trace.svg`(10장).
- B는 raw→wiki와 옆 schema, E1/E3/E4→운영/개념/질문 및 검토한 답 축적, E2→EC2→ED2와 ED1대체보존을 그리는 데 동의했다.
- A가 SVG3개 XML의 실제 라벨·title·desc·연결을 직접 대조했다. raw 보존/wiki축적/옆규칙, 운영·개념·질문과 검토한답저장, E2→EC2→ED2 및 ED1대체보존이 계약과 일치한다. B에 확인 결과를 직접 보냈다.
- 관리자와 B의 모바일 보완 요청을 반영해 3·4·10장에 그림과 동일 핵심의 일반 본문, 상세 alt, 도식 원본 일반 링크를 추가했다. 1280px SVG의 축소 텍스트만으로 모바일 가독성을 주장하지 않는다.
- B가 완성 원고12장·guide·story-plan을 실제 실독하고 C01~10/S1·10·11·12, 시간, 합성 경계, 날짜, 보존, 축적, 옆규칙, RAG구분이 일치한다고 직접 회신했다. B의 교정 ‘가운데 wiki→오른쪽 wiki’를 guide에 반영했다.
- 관리자 최신 톤 지침을 반영해 C* 상세매핑을 guide로 옮기고 화면 링크는 ‘출처 정보 개요/결정 기록 원문’처럼 자료의 역할을 먼저 보이게 했다. E*는 역할 뒤의 보조 식별자로 유지한다.
- A가 B의 정적 PNG3개를 직접 열어 구조·한글·흐름을 확인했다. 1/2는 전체 도식이 보이며 3은 임시 렌더의 상단 크롭이 있어 원본 XML에 합성 badge가 있음을 별도 대조했다. 정적 PNG를 실제 앱·모바일 가독성 합격으로 확대하지 않는다.
- B가 최종 원고12장을 다시 실독해 3/4/10장의 동일핵심본문·alt·원본링크, guide의 ‘오른쪽 wiki’, 역할 우선/ID보조화, closing문단을 확인했다. B의 순수 parseDocument+planSlide 결과는12장, message2/media3/bento6/closing1, 경고0이었다. manager도 독립 실행으로 같은 결과와 실제4원출처URL·SVG3개·공개guide·예정txt3개 참조를 확인했다.

## 첨부·후속 인수 계약

원고가 참조하는 sources.txt, decision-example.txt, starter-template.txt는 후속 engineering 소유다. 고정 경로는 모두 `./assets/`이며 speaker-guide.txt만 A가 작성한다. SVG는 B소유이므로 A는 alt·caption·본문의 의미를 맞추고 SVG를 직접 수정하지 않는다. 생성물은 root가 첨부 완료 후 빌드하며 작성자 진단·브라우저의 잘림/대비/모바일 읽기를 확인한다.

## 편집 종료·인계

A 소유3파일의 편집을 종료한다. `slides.md`와 `speaker-guide.txt`의 다음 writer는 관리자 지시에 따른 engineering 담당이다. 브라우저에서 장별 밀도·출처/핵심한계 잘림·발표/읽기 일치·390px읽기·첨부 접근을 검수하고 필요시 그 담당자가 단독 수정한다. 시간표는18분+2분의 진행 설계이며 실제 발표자 리허설을 수행했다고 표시하지 않는다. WORK_LOG갱신은 root에게 직접 전달한다.
