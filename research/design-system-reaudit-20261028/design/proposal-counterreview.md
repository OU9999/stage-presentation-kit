## 이전 보고가 부족했던 이유

앞선 보고는 blocks의 획일성을 정확히 지적했지만 해결을 작은 view API의 안전성 문제로 너무 빨리 좁혔다. 최종 표현을 보지 않은 상태에서 원표의 모든 header를 발표에1회 표시, source1문단, H2별 그룹, 모든 보이는 순서 보존, 엄격한 hint 오류 같은 구현 선호를 디자인 계약으로 올렸다. 한두 장을 바꾸면 덱의 미감이 돌아온다는 증거도 없었다. **원문 권위는 내용 결정의 기준이며, 모든 문자열·위치를 발표에 기계적으로 같게 하는 규칙과 구분해야 한다.** 사실을 바꾸지 않으면서 의미 관계와 주역을 다시 조판할 수 있어야 한다.

직접 읽은 새 [inventory](../evidence/inventory.json)는11덱90장·21종 layout(legacy20+blocks)·native8종을 전수 집계한다. 새2덱12장은 모두 blocks이고, 장별 구성도 표지→이미지+목록→표→코드→인용→링크로 같다. 두 주제의 독립 생성은 파일/재사용 기능의 근거지만 서로 다른 서사·정보량·이미지 역할을 검증한 근거가 아니다. 나머지78장이 남아 있다는 사실도 새 기본 경로가 기존 미감을 전달한다는 증거가 아니다.

[README](../../../README.md)와 [Markdown 안내](../../../MARKDOWN-FIRST.md)의 첫 설명은 slides.md만으로 같은 기존 STAGE 스타일을 얻는다고 약속한다. 실제 기본 출력으로 약속을 검증해야 한다. 고급 JSON으로 돌아가거나 여러 새 규칙을 숙지한 뒤 얻는 결과로 기본 경험을 통과시켜서는 안 된다. 새 profile의 추가 opt-in을 의무화해 기본값 문제를 작성자에게 넘기는 방안도 필수 계약에서 뺀다.

## 원문 권위와 발표 표현을 나누는 조건

**유지:** 숫자·단위·대상·기간·조건·가상/실측 성격·인용 귀속·링크 목적·정량 관계·순서가 사실인 의미. 원고 전체와 read 전문은 남기고 발표 표현은 원고에 추적 가능해야 한다. 선택 없이 근거·조건을 삭제/요약하거나 새 수치를 계산해서는 안 된다.

**검토 가능:** 구조 header의 통합, 반복 제목의 위계 완화, 공통 범위/출처의 묶음 조판, 비선형 결과 모음의 주역 위치, 같은 원본에서 hero와 근거의 반복, 저자가 명시한 발표용 짧은 표현과 read 전문의 분리. 모두 작성자 통제·변경 가시성·사실 동등성의 조건을 검증한다. 발표에서 중요한 조건이 사라졌는데 read/aria에 있으니 보존됐다고 우회할 수는 없다.

**자동성 분리:** 같은 AST의 길이·블록 수·이미지 비율에 맞춘 글폭·크기·배치 조정은 사실/관계를 새로 만들지 않는 기본 조판 후보다. 반면 표를 성과 chart로 만들거나 숫자를 개선율로 읽고 목록을 범주로 해석하는 것은 사실 추론이다. 앞선 자동 역할 경계가 안전한 조판까지 금지하는 식으로 확대되면 기본 품질을 회복하기 어렵다. 어느 자동 조판이 충분히 안전한지는 실제 시안으로 판단한다.

발표/읽기 구분을 새 노트·부록·편집기 전체 프로젝트로 확대하지 않는다. 우선 동일 원고 조판과 필요한 명시 선택의 효과를 비교한다. 전문이 많아 명시 투영 없이는 발표가 성립하지 않을 때만 작은 선택의 비용/위험을 검토한다. 정확 문법은 이번 감사의 확정 산출물이 아니다.

## 작성 부담·대표 서사·후속 종료 조건

1. **무선택 기본을 먼저 인수한다.** 짧은 선언·제목+설명·이미지+목록·표·코드·인용·마무리가 일괄 문서 밀도로 고정되지 않아야 한다. H1과 quote가 함께 있으면 기본 균형과 저자 선택을 비교하며 의도를 무단 단정하지 않는다. 추가 profile을 배워야 기본 미감을 얻는 구조는 요구를 충족했다고 보지 않는다.
2. **실제 내용 수정으로 부담을 잰다.** 샘플 복사·제목/이미지 교체·목록1항목/표1행/출처1문단 추가·대표 그룹 교체에서 새 문법·중복 입력·막힌 build·수동 레이아웃 조정의 수를 기록한다. 시간·클릭 수는 아직 측정하지 않아 수치로 주장하지 않는다.
3. **서로 다른 실제 서사를 대표 예제로 삼는다.** 제품 결정(문제→장면→근거→결정), 사진/시연(큰 자료→설명→상세), 내부 학습(질문→코드/관찰→해석→다음 질문) 중 서로 다른 둘을 선택한다. 모든 예제에 표·코드·인용을 각1회 넣는 기능 카탈로그는 충분하지 않다.
4. **장수·유형 수 대신 전환을 평가한다.** 쉬는 장·읽는 장·회수하는 장의 주역/면적/밀도가 내용에 맞게 바뀌는지 연속으로 본다. C/두 수치/사진은 원고에 적합할 때 쓴다. 빈칸 채우기나 동일 profile 반복을 장간 리듬으로 세지 않는다.
5. **동일 내용 시안이 필요하다.** 현행·개선 기본·필요한 저자 선택을 같은 내용/자산/viewport로 비교한다. 원고를 편집한 서사안은 별도 arm이다. legacy의 글·수치·자산을 일반 MD로 옮긴 통제 사례도 최소 포함한다.
6. **인수는 기능·미감·작성·읽기로 나눈다.** 사실/링크/접근성, 주역/가독성/한글/색/면적, 연속 서사, 초보 재사용,390px read를 각각 통과시킨다. 기존210검사·geometry 후보0·자산 로드 성공은 시각 인수의 대체물이 아니다.

## 직접 교차 검토

A가 보낸 mosaic/C의 비선형 주역 반례를 직접 수신해 B-05에 반영했다. B는 A에게 두 새 덱의 같은6장 구조와 기존90장도 CSS 보존만으로 합격이 아니라는 반례를 보냈고, A는 수용했다. A의 독립 [시각 감사](visual-system-audit.md)를 읽었다. A가 추가한 H1+quote의 주역 모호 반례를 받아 무선택 기본의 균형 조판과 저자 선택을 분리했다. manager의 native hero+plot 반복 반례도 새 PNG로 직접 확인해 B-10에 반영했다.

실제 작성 사용자 실험, 새 기본/선택 시안, 같은 원고 통제 렌더, 모바일/출력 실기, 제품 구현·회귀는 미확인이다. 추가 외부 조사·브라우저/서버 조작·원고 변경은 하지 않았다. 후속 방향 판정을 위한 이 감사와 새 기능의 완료를 구분한다.
