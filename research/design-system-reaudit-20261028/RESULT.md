# 전면 재감사 결과 — 기본 미감과 컬러의 후속조치가 필요하다

2026-10-28 · 디자인팀·엔지니어링팀 재감사, 총괄 통합

**후속조치가 필요하다. 새 Markdown 기본 출력과 대표 예제가 기존 STAGE의 미감·색 사용법을 전달하지 못했다.** 이전에 제안한 ‘profile을 한 번 고르고 몇 장에 역할 힌트를 더한다’는 방식의 충분성도 철회했다. 좋은 기본 결과를 먼저 만들고 꼭 필요한 저자 선택만 남겨야 한다.

## 실제로 넓힌 확인 범위

- 11덱90장의 source를 전수 집계했다. 기존20양식+blocks, native 시각자료8종을 포함한다.
- 90장을 동일1440×1000 데스크톱으로 캡처했다. 초기51장은 디자인 실무자가 원본을 개별 검토했고 나머지39장은 다른 주제/변형의 보드 검토로 보강했다. 90장 모두에서 ready·이미지·실행 오류/요소박스 geometry 후보는0이었으나 미감 합격으로 해석하지 않았다.
- 같은 authored body·실제 렌더본문·자산을 가진 선언/이미지2쌍을 현재 명시 layout 경로와 일반 Markdown으로 비교했다. 선언126px/70px, 이미지 요소 약1187×505/257×193의 차이가 있다. contain 요소박스는 실제 그림 paint 면적과 다르다. 이 비교는 미래 복원 시안의 성공 증거가 아니다.
- 컬러는11덱 source·새3개 parser probe·실제14개 Stage/Paper 관찰로 확인했다. 부모 색과 실제 강조 자식의 색도 구분했다.
- 의심됐던 team-learning05 제목 잘림은 Range 실측에서 불재현으로 확인해 결함 목록에서 제외했다. 후보와 확인된 결함을 구분했다.

| 문제 | 영향과 판정 |

| 문서의 작성 약속과 기본 결과 불일치 | slides.md만으로 기존 스타일을 얻는다는 대표 안내를 실제 복사/수정/발표 결과로 인수하지 못했다. 문구만 완화해 종료할 수 없다. **필수 후속** |
| 기능/자료보존과 미감 합격을 혼동 | 210개 기능 검사·파일 보존·로드/geometry 성공은 색·독해·서사·작성 편의를 보장하지 않는다. 인수 기준을 분리해야 한다. **필수 후속** |

## 컬러도 복원 필수 항목이다

아래는 과거 참조 조사를 바탕으로 STAGE에 구현한 값이다. OpenAI 공식 HEX 명세라고 주장하지 않는다. 색마다 고정된 감정/성과 의미를 자동 부여하는 규칙도 아니다.

| 색 | Stage 구현값 | 실제 남은 기존 사용 예 |
| --- | --- | --- |
| 파랑 | `#24A8FF` | 선택 근거·수치·범주, 두 값 중 하나 |
| 주황 | `#FF7A3D` | 선언의 의미 단위, 선택 수치·범주 |
| 보라 | `#A080FF` | 큰 이름/전환·범주 |
| 초록 | `#69CF82` | 핵심 수치와 범주, 중립 단위와 구분 |
| 노랑 | `#EDCF66` | 사진 비교의 선택 라벨·범주 |

실제 강조 자식·수치/중립 단위·범주 이름/아이콘·노랑 라벨·두 값의 blue/orange와 각 Paper 대응색이 확인된다. 새 예제의 이미지 자체 색은 보존되지만 선언·수치·범주 등의 저자 의미색 사용법은 빠졌다. **tone 키 하나·강조 한 색을 추가한 것만으로 컬러 복원 완료라 하지 않는다.** 새 일반 원고의 실제 작성 경로에서 선택 의미 단위·중립 정보·범주 이름/위치·사진/UI 고유색·중립으로 돌아오는 리듬을 확인해야 한다. 매 발표에 모든 색을 넣거나 매 장 색을 순환시키지 않는다.

## 이전 복원안에서 수정한 것

| 이전 가정 | 이번 재판정 |
| --- | --- |
| profile 선택+1~2개 힌트면 충분 | **충분성/의무성 폐기.** 무선택 기본 미감과 실제 작성 비용을 먼저 인수 |
| 모든 header/문구를 발표에 가시1회 | 사실·조건·관계·추적성을 보존하면서 표현 형태는 시안 검토. 기계적 동일 문구 노출 강요는 철회 |
| 표시 중복0 | 입력 권위의 중복/불일치와 구분. 한 원본의 hero+plot 같은 유익한 반복은 유지 |
| 모든 보이는 순서=원고 순서 | steps/시간/인과의 순서는 보존. C/비선형 자료의 공간 위계와 의미/DOM/read 흐름은 별도 평가 |
| source1문단·3열2행·H2 그룹을 먼저 확정 | 미확인 기술 가안으로 환원. 자연스러운 추가 설명·출처·매체 교체를 막지 않는지 비교 |
| 표현 부적합도 모두 hard error | unsafe/모호 구조와 공간/표현 한계를 구분. 보이는 경고+온전한 기본 표현 후보를 검토하되 fallback 성공은 미감 합격이 아님 |
| 자동 역할을 피하면 자동 조판도 피함 | 구조·길이·비율에 맞춘 안전한 배치와 사실/정량관계의 자동 발명을 분리 |

기존 kit mosaic의 특정 샘플이 실제 순서를 역전했다고 단정하지 않았다. 일반 packMosaic의 빈칸 메움 지원과 C의 네 번째 자료가 주역인 사례를 각각 대조했다. 기존 명시 n/d 계산은 유지하며 무단 숫자/성과/인과 추론과 구분한다.

## 후속조치 우선순위

| 분류·순서 | 담당 제안 | 종료 조건 |
| --- | --- | --- |
| **필수 1 — 기본 품질/색 역할** | 디자인+표현 구현 | 선언·설명·자료·인용·마무리의 기본 위계/면적과 의미색이 같은 원고 시안에서 동작. 추가 CSS/JSON을 매번 작성해야 기본 품질이 나오면 실패 |
| **필수 2 — 서로 다른2서사** | 작성 경험+디자인 | 복사/제목·매체·표 행·출처·대표·맺음 수정의 부담을 실제 기록. 각 유형을1회 넣은 카탈로그나 장수로 서사를 대신하지 않음 |
| **필수 3 — 독립 인수/전달** | QA+디자인+root | 기능/사실/미감독해/서사/작성/read 각각 판정. 문서→명령→대표 결과와 컬러 사용법이 일치 |
| **시안 후 결정** | 디자인+엔지니어링 | H1+quote의 주역, header 통합, 비선형 배치, 복수 출처·그룹, 긴 값/작은 축·UI의 독해, 저자 선택과 severity/fallback을 실제 비교 |
| **유지·영향 회귀** | runtime+QA | 좋은 legacy20양식/native8종, 의미색·중립 정보·자료 자체 표면, 원고/read 권위·명시 계산·주소·복제를 유지 |

시안은 현행/개선 기본/필요한 저자 선택을 **같은 내용·자산·viewport**로 비교한다. 내용을 편집한 서사는 별도 arm이다. 실제 밝은 테마 대비·관객 독해·390px 읽기·키보드/논리 흐름·원고 위치 진단과 복구도 인수한다. 아직 새 시안/작성 실험/모바일 복원 QA나 구현 성공을 보고하는 단계가 아니다.
