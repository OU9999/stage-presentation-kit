# 전면 재감사 — 후속조치 판정 회의

2026-10-28 · 기준 HEAD cdb88b4 · 총괄 기록

사용자는 이전 복원 방향도 크게 재점검해 후속조치 필요성을 확인하도록 했고, 진행 중 기존 DevDay 참고 컬러의 예제 누락을 추가로 지적했다. 이번에는 직전 합의를 방어하지 않고 그 합의 자체를 반대 검토했다. 디자인 실무자 둘·엔지니어링 실무자 둘이 별도 초안을 작성하고 직접 반례를 교환한 뒤, 두 매니저가 아래 R1/R2를 실제 메시지로 제안·수정·상호 수신 확인했다.

## R1 — 무엇을 고치고 무엇을 유지할까

**디자인 제안.** 필수 후속은 새 일반 원고의 무선택 기본 조판, 자료 면적, quote/closing의 위계, 대표 예제의 실제 서사, 미감과 작성 경험의 독립 인수다. 기존20양식/native8종은 좋은 재사용 자원이며 전체 폐기 근거가 없다. 이전의 profile 의무·모든 header 가시1회·source1문단/H2 고정·모든 보이는 순서 동일·모든 표시 중복0·표현 부적합의 일률 build 실패는 사용자 요구가 아닌 미검증 가안으로 환원한다.

**엔지니어링 반례와 수정.** 같은 원고/자산 통제2쌍에서도 현재 경로 묶음에 따른 위계·면적 차이가 확인된다. 무주석 기본을 먼저 개선하고 명시 선택은 실제로 필요한 만큼만 남긴다. AST 길이·형태에 맞춘 안전한 조판과 숫자/표/인과의 사실 추론은 다른 자동성이다. 마지막 위치를 조판 입력으로 참고하는 것까지 금지하면 기본값 개선을 막지만, 마지막 장의 의미를 자동으로 새로 써서는 안 된다.

기존 native hero+plot은 한 원본을 유익하게 반복하며, C의 네 번째 자료는 큰 주역이다. mosaic 일반 API는 빈칸 메움을 지원하나 현재 kit의 특정 span 배열이 순서를 역전했다는 주장은 제외한다. steps·시간·인과의 순서는 사실로 유지하고 비선형 자료 모음의 공간 위계는 별도 검수한다. 원문 fallback이 안전하게 build됐다고 독해·미감까지 합격한 것은 아니다.

**사용자 컬러 지침 추가.** 새 두 덱12장은 authored tone0이며 strong도 중립색이다. 일반 frontmatter tone은 거절되고 legacy tone은 지원된다. 기존 선언/이름/수치/범주/라벨과 native·사진/UI의 색은 남아 있으므로 새 작성 경로와 대표 예제의 전달 누락으로 판정한다. tone 키 하나나 기본 accent 한 색만 추가해 컬러 복원 완료라고 보고하지 않는다.

**상호 합의.** 두 매니저가 필수/시안/유지와 위 수정에 동의하고 수신 확인했다. 임의의 감정·성과색 추론과 매 장 색 순환은 제외한다. 수사적 의미 단위의 선택색, 수치와 중립 단위·출처, 범주 색+이름/위치, 자료 고유색과 중립 회귀의 리듬을 새 작성 예제에서 인수한다.

## R2 — 담당·순서·종료 조건

엔지니어링의6단계 제안에 디자인이 컬러/작성 조건을 보강했고 엔지니어링이 모두 수용해 회신했다. 디자인이 최종 수신을 확인했다.

| 순서 | 담당 제안 | 필수 산출물·종료 조건 |
| --- | --- | --- |
| 1. 기본 약속과 보존 경계 | 디자인·엔지니어링 매니저 | 무선택 기본의 주역/면적·quote/closing·색 역할을 정의한다. 사실·원고/read 권위와 기계적인 문구/배치 표시 규칙을 분리한다. |
| 2. 같은 내용의 시안 | 디자인·표현 구현 담당 | 같은 원고·자산·viewport로 현행/개선 기본/필요 저자 선택을 비교한다. 원고를 편집한 서사는 별도 비교한다. 단순 font/tone 키 추가만으로 종료하지 않는다. |
| 3. 서로 다른 실제2서사·작성 | 작성 경험·디자인 담당 | 복사→제목/한글·매체 교체→표 행/출처 추가→대표 변경→맺음 수정에서 JSON/HTML/CSS 반복이나 과도한 조판 수정을 요구하지 않는지 기록한다. 기능 유형을 각1회 채운 카탈로그나 장수로 서사를 대신하지 않는다. |
| 4. 독립 인수 | QA·디자인 담당 | 기능/사실·추적성/미감·독해/서사/작성/read를 각각 판정한다. 390px native 읽기, 원고 위치 진단과 복구도 확인한다. |
| 5. 기존 유지 회귀 | runtime·QA 담당 | 좋은 legacy/native·명시적 n/d 계산·유익한 반복·색/중립 정보·media 자체 표면·기존 주소와 복제를 유지한다. |
| 6. 대표 전달 | root·문서 담당 | 문서→명령→대표 결과가 일치하고 같은 Markdown에서 색 사용법과 미감을 실제로 재사용할 수 있어야 한다. 문구 완화만으로 기본 품질 실패를 닫지 않는다. |

색 인수에는 저자가 고른 의미 단위, 중립 단위/메타, 범주 이름/위치 병행, Paper 대응색과 실제 대비, 사진/UI 고유색을 포함한다. 필요한 역할과 리듬을 두 서사에서 확인하며 모든 색을 매 덱에 할당하거나 색 개수로 합격시키지 않는다. 현재14관찰은 색이 실제 적용됨을 확인한 것이며 WCAG·관객 독해 합격은 아니다.

## 결정의 경계

후속조치는 필요하다. 기존 palette/native/20양식·Markdown 원본·사실/읽기 권위는 유지한다. 기존 명시 계산을 무단 수치 추론으로 혼동하지 않는다. 표 header의 통합, 비선형 자료의 주역 위치, 긴 본문의 저자 통제 투영, severity/fallback과 추가 선택의 실제 문법은 시안에서 판단한다. 무단 요약·조건 은폐·새 수치/인과 발명은 도입하지 않는다.

이번 회의는 구현·새 기본 시안·작성 시간/클릭 수 실험·모바일/미감 복원 성공이 아니다. 구문/schema를 먼저 확정한 이전 순서를 수정해 기본 품질과 실제 작성·서사·컬러를 먼저 인수한다. 제품과 배포는 유지했다.
