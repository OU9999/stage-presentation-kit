## 판정

**필수 후속조치가 필요하다.** 새 기본 Markdown의 조판·인용/마무리·자료 면적과 대표 서사, 이를 인수하는 품질 전달 체계를 함께 보완해야 한다. 스타일 파일·기능210검사·자산 로드·넘침0이 기존 미감을 보존했다는 판단을 대신했다. 앞선 `profile 한 번+1~2hint`는 검증되지 않은 해결 가설이지 사용자 확정 요구나 완료 조건이 아니다. 이번에는 시안을 보기 전에 parser 이름/schema부터 확정하지 않는다.

안내 문구만 약하게 고쳐 문제를 끝내거나, profile/hint를 더 배워야 기존 약속을 얻는 구조는 권고하지 않는다. 기본 출력과 실제 대표 예제를 먼저 인수하고 그 결과에 맞춰 문서를 정확하게 갱신한다. 모든 원고가 가장 좋은 기존 한 장과 같은 구도가 되어야 한다는 뜻은 아니다.

직접 본 새12장 묶음에서는 내용 종류가 바뀌어도 제목 위치/위계·세로 본문·메타의 박자가 반복된다. 새05 원본의 인용은 제목과 이어지는 설명보다 낮은 대비/작은 위계인 반면 kit18은 인용이 주역이다. 다만 서로 다른 내용이므로 새 H1+인용을 자동 quote로 바꾸라는 결론은 아니다. 무선택 균형 조판과 저자 선택 시안을 비교해야 한다. 새06 링크목록 끝 장도 같은 흐름이며 연속 묶음에서 마무리의 쉼/행동 중심이 약하다. 이 문제는 링크 삭제나 마지막 장 자동 closing으로 해결했다고 보지 않는다. 마지막이라는 위치를 조판 입력으로 쓰는 후보는 비교할 수 있지만, 새 맺음 문구 생성·저자 의도 단정·링크/조건 숨김과 구분한다.

명시 계산도 유지 대상이다. [visualSeries](../../../deck-model.js#L136)는 저자가 선언한 분자/분모에서 `n/d*100`을 계산하고 [visual.render](../../../visual.js#L365)는 원분자/분모를 표에 남긴다. 같은 선언 자료의 focus/hero/plot 반복도 원고 재입력과 다르다. 무단 성과·관계 추론 금지가 기존 명시 계산까지 금지한다는 뜻은 아니다.

## 미감·작성 비용을 확인할 후속 작업

아래는 **아직 실행하지 않은** 인수 작업이다. 문법/클릭 수·소요 시간·작성 편의 개선율은 측정하지 않았다.

| 실제 작성 작업 | 비교할 결과·기록 | 종료 조건 |
| --- | --- | --- |
| 샘플 복사→제목/긴 한글 교체 | 무힌트 기본, 필요시 작은 저자 선택, 수동 CSS/JSON 요구·선택 수 | 제목/설명/주장의 위계와 읽기 폭을 얻고 기존 글을 자동 삭제/과도축소하지 않음 |
| 이미지 교체: 사진→UI·종횡비 변경 | 읽어야 할 세부를 먼저 지정하고 contain/crop/전폭·설명 배치 비교 | 실제 대상이 식별되고 제목/설명이 밀리지 않음. 요소박스 면적이나 로드 성공만으로 통과하지 않음 |
| 목록1항목·표1행 추가, 값/단위 변경 | 실패/경고·fallback 위치와 원문/값·출처 대응 | 새 내용이 사라지지 않고 fact/조건 연결 유지. 두값 선택이3행을 임의로 자르거나 계산하지 않음 |
| 출처1문단 추가·범위/표본 보강 | 한 문단 제한·자연 원고·명시 묶음 후보의 재입력/복구 비교 | 복수 출처를 숨기거나 한 문자열로 다시 쓰게 만들지 않음. 필요한 조건이 발표에서 실제 이해됨 |
| 인용+H1·귀속·긴 설명 수정 | 균형 기본과 저자 focal 선택, quote-only 반례 | 어느 문장이 주역인지 실제 시안으로 판단하고 귀속/가상성격을 오인하지 않음 |
| 대표 자료를 첫/중간/뒤로 교체 | 시각 위계·키보드/DOM/read 흐름·group 표식 비용 | 절차는 보존, 비선형 관계는 오해 없이 표현. 순번만으로 대표가 조용히 바뀌지 않음 |
| 끝 장의 링크/행동 추가 | 링크목록과 맺음/다음 행동의 균형 | 링크 전문과 목적지를 유지하며 장이 끝나는 시각적 감각을 실제 연속 보기에서 확인 |

대표 원고는 실제 이야기가 다른 최소2개를 선택한다. 예를 들어 제품의 문제→근거→실제 작업→결정과, 사진/시연의 큰 자료→대조→세부→여운을 비교한다. 내부 학습도 질문→코드/관찰→해석→다음 질문처럼 실제 관계를 갖게 한다. 예제마다 표/코드/인용을1회씩 넣거나6장으로 맞추는 과제를 주지 않는다. 가상 수치/스톡 자료라면 성격을 명시하고 실제 성과로 읽히게 하지 않는다.

단장 게이트는 주역/자료 가독성·정보 조건·한글 줄바꿈·색/표면·겹침을, 연속 덱은 밀도/주역/면적 전환과 이야기 연결을 본다. read는 전문·논리 순서·링크/alt·국소 표/코드 스크롤·390px 본문 가로넘침을 본다. 의미 추적은 값/단위/대상/기간/조건/인용 귀속·가상 성격과 원고/원표 연결을 검사하며 ‘문자열 정확1회’와 구분한다. 기능 회귀와 미감 평가가 모두 필요하지만 전자가 후자를 대신하지 않는다.

경고+원문 fallback은 내용 손실 방지 후보일 뿐 발표 합격이 아니다. 긴 표/코드가 온전히 남아도 실제 발표에서 읽히지 않을 수 있다. build 성공·이전 성공본 보존과 release의 독해/미감 인수를 분리하고, 안전 fallback 상태의 원고가 미감 인수를 통과하지 못하면 수정 대상으로 남긴다.

이번 감사의 완료는 위 영향 범위·수정/폐기·필수/시안/유지·책임과 종료 조건 전달이다. 실제 새 기본 미감·작성 실험·독립 QA·제품 복원은 완료하지 않았다. 새 라이브러리/전면 재작성·schema 확대를 이 작업의 선행 해결로 제안하지 않는다.

## 실무 협의·소유권

A에게 두 대표 원고의 동형 서사와 기본 작성 약속/인수 부족, 기계적 header·중복·순서·실패 가정의 재검토, 실제 표/출처/이미지/대표 수정 작업을 직접 전달했다. 서로 전체 실질 초안을 읽고 root controlled generator/원고4개·body/content SHA·관찰 JSON을 대조했다. A의 mosaic 특정 샘플/일반 계약 구분을 반영했다. B는 마지막 위치를 조판에 쓰는 것까지 금지하면 자동성/사실을 다시 혼동한다는 반론을 보냈고 A가 수용했다. A는 온전한 fallback도 긴 표/코드의 발표 가독성 합격이 아니라는 반례를 보내 B가 build 손실 방지와 release 인수를 분리했다. 양쪽은 root가 전달한 기존 명시 분자/분모 계산·원분자/분모 표 보존도 유지함에 동의했다. 세부 문법보다 시안·기본 결과·작성 작업으로 판단한다는 방향에 합의했다.

이 담당의 편집은 quality-delivery-audit.md와 engineering/synthesis.md뿐이다. 이전 복원 보고·제품/원고/생성물·WORK_LOG·공통 evidence를 수정하지 않았다. 새 probe/default build/설치·서버/브라우저·210검사·Git 작업은 하지 않았다. 두 매니저 후속 판정 회의는 실무 인계 이후이며 이 담당이 수행했다고 주장하지 않는다.

소유 두 문서의 링크·공백 검수를 마쳤고 **편집을 종료한다.** 이후 회의 반영은 매니저 인수 범위다.
