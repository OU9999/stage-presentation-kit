# 40장 대본 · 본질과 세 사례의 20분 진행

기본 진행은 **1~28장 연속: 설명·참여1,080초(18분) → 40장 Q&A120초(2분)**입니다. 29~39장은 선택 심화이며 모두 열면555초가 별도로 추가됩니다. 시간은 준비한 배분안이며 실제 낭독·사람 반응을 측정하지 않았습니다.

정의→반복 재종합 문제→저장되는 개념·비교·종합→LLM의 작성·유지와 사람의 탐색→구조·ingest/query/lint→독서·고객 요구·강의 메모 순서로 진행합니다. 세 사례의 입력·파일·응답은 **가상 자료로 만든 적용 예**입니다. 공개 구현 관찰·논문 실험·기존 고정 교정 데모는 심화에서 범위를 구별합니다.

## 발표 이동과 읽기 링크

핵심은1→2→…→28→40입니다.28장 안의 **‘질문과 적용 이야기’**를 눌러40장으로 이동합니다.40장에는29장 ‘공개 구현과 실험 더 보기’와34장 ‘기존 파일 교정 예제’로 들어가는 실제 전환 링크가 있습니다.34/39장의 ‘질문으로 돌아가기’는40장으로 갑니다. 자료의 `../slides.md#N` 링크는 별도 읽기 화면을 여는 참고 경로입니다. O 개요는 예비 이동 수단입니다.

13장은 동등한 두 상담을 읽고5초 생각하며, 구분 이유는14/15장에서 회수합니다.24장은 자기 노트 작성20초와 선택 공유를 포함합니다. 웹 투표·자동 집계·입력 저장 기능은 없습니다.

**말하기**

“자료 다섯 개를 함께 읽고 좋은 답을 얻었다고 해봅시다. 다음 질문에서 이전에 어떤 조건을 비교했고 어떻게 해석했는지 정리되어 있지 않으면 자료의 관계를 다시 찾습니다. 이 종합 작업의 일부를 지속하는 페이지로 남겨 갱신하자는 생각입니다. 모든 검색 시스템이 축적할 수 없다는 뜻은 아닙니다.”

## 4장 · 답만 남기는 대신 개념과 비교를 남긴다

[읽기 4장](../slides.md#4) · 핵심 · 01:35~02:10 · 35초

**말하기**

“한 자료의 요약은 그 자료를 다시 읽을 입구입니다. 위키에는 여러 자료에서 반복해 만나는 개념, 같은 기준의 비교, 현재까지의 잠정 종합도 남깁니다. 다음 자료가 오면 그 설명을 고치고, 새 질문에서 유용한 답을 얻으면 다시 저장합니다.”

**진행:** 원자료→여러 페이지→질문→답 저장의 귀환을 짚는다. 도식을 모든 폴더를 거치는 필수 순서로 설명하지 않는다.

**전환:** “이 파일을 누가 읽고 쓰는지 나눠 보죠.”

**다음 핵심:** 5장. 다음 장으로 진행합니다.


## 5장 · LLM은 위키를 쓰고 사람은 탐색을 이끈다

[읽기 5장](../slides.md#5) · 핵심 · 02:10~02:45 · 35초

**말하기**

“파일 도구를 쓸 수 있는 LLM 에이전트가 관련 원자료와 위키를 읽어 현재 답변의 문맥에 넣고 Markdown을 작성·갱신합니다. 사람은 자료와 질문, 범위와 강조점을 정하고 결과를 확인합니다. 읽는 도구는 페이지와 연결을 살펴보는 창입니다. 파일이 생겼다고 모든 모델이 자동으로 접근하거나 영구 기억하는 것은 아닙니다.”

**진행:** LLM의 실제 읽기·쓰기와 사람의 탐색 역할을 구별한다. Obsidian은 저자의 예이며 필수 앱으로 소개하지 않는다.

**전환:** “저장하는 층과 작업 규칙을 보겠습니다.”

**다음 핵심:** 6장. 다음 장으로 진행합니다.


## 6장 · 원자료와 위키 그리고 작업 규칙

[읽기 6장](../slides.md#6) · 핵심 · 02:45~03:25 · 40초

**말하기**

“보존할 원자료와 고쳐 나갈 위키를 나눕니다. 원자료는 돌아가 확인할 입력이고, 위키는 LLM이 정리한 설명과 연결입니다. 작업 규칙은 페이지 형식과 자료 반영, 질문, 점검을 안내합니다. 규칙이 세 번째로 변환되어 나오는 결과물은 아닙니다. 목차는 읽을 입구, 로그는 작업 이력으로 둘 수 있습니다.”

**진행:** raw 보존과 wiki 갱신을 짚고 규칙이 전체 작업에 적용됨을 설명한다.

**전환:** “새 자료 하나를 넣었을 때부터 따라가죠.”

**다음 핵심:** 7장. 다음 장으로 진행합니다.


## 7장 · 새 자료 한 개가 여러 설명을 바꾼다

[읽기 7장](../slides.md#7) · 핵심 · 03:25~04:10 · 45초

**말하기**

“Ingest는 새 요약 파일 하나를 만드는 데서 끝나지 않습니다. 새 자료를 읽고 기존 개념의 조건, 비교표의 근거, 잠정 종합에서 달라지는 부분을 함께 갱신합니다. 자료에 따라 기존 페이지부터 고칠 수도 있습니다. 새로운 지지와 충돌, 아직 모르는 부분을 남기고 목차와 작업 이력도 맞춥니다.”

**진행:** 새 입력과 여러 갱신 대상을 짚는다. 모든 관련 페이지의 자동 발견을 보장하지 않는다.

**전환:** “질문할 때 이 저장 결과를 다시 읽습니다.”

**다음 핵심:** 8장. 다음 장으로 진행합니다.


## 8장 · 다음 질문은 저장된 위키를 찾아 읽는다

[읽기 8장](../slides.md#8) · 핵심 · 04:10~04:50 · 40초

**말하기**

“Query에서는 목차나 검색으로 필요한 페이지를 찾아 현재 답변의 문맥으로 읽습니다. 범위가 달라지면 원자료도 확인합니다. 새롭게 얻은 비교나 분석, 유용한 답은 실제 페이지로 저장해 관련 위키에 연결할 수 있습니다. 다음 질문도 저장된 쪽을 다시 읽어야 합니다. 이 파일 갱신은 모델 가중치를 학습시키는 작업과 구별됩니다.”

**진행:** 찾기→현재 문맥에 읽기→답→페이지 저장의 귀환을 짚는다. 파일과 가중치 구별은 여기서 짧게 마친다.

**전환:** “설명이 계속 쌓이면 무엇을 점검할까요?”

## 10장 · 소설을 읽으며 인물과 주제를 쌓는다

[읽기 10장](../slides.md#10) · 핵심 · 05:25~06:00 · 35초

**말하기**

“첫 사례는 가상 소설을 읽는 적용 예입니다. 실제 책이나 모델 실행 결과는 아닙니다. 1장에는 서하가 지도를 숨기고 북문을 떠났다는 행동과 도윤이 버림받았다고 느꼈다는 말이 있습니다. LLM이 이를 인물, 장소, 신뢰 주제에 연결하되 서하의 동기는 아직 모른다고 남기는 구성입니다.”

## 질문이 나올 때 참고할 답

- **기존 노트와 무엇이 다른가요?** LLM이 원자료를 읽고 연결된 페이지를 실제 작성·갱신하며 다음 질문과 점검에서도 유지하는 흐름을 말합니다. 기존 노트 환경에 도입할 수도 있습니다.
- **저장하면 모델이 기억하나요?** 다음 답에서 파일을 다시 읽어 현재 문맥에 넣는 경로가 필요합니다. 파일 갱신과 모델 가중치 학습은 구별합니다.
- **검색이 필요 없나요?** 목차로 시작하거나 위키와 원자료의 검색을 병행할 수 있습니다. 저장된 페이지가 질문에 필요한 근거를 담는지와 실제 읽었는지를 확인합니다.
- **모든 답을 저장하나요?** 다시 쓸 가치가 있는 답을 관련 페이지에 연결할 수 있습니다. 검토·저장 기준은 자신의 운영 선택입니다.
- **자동으로 정확해지나요?** 오류·낡은 설명·빠진 근거가 남을 수 있습니다. 실제 읽기와 의미 검토가 필요합니다.
- **지금 무엇부터 하나요?** 다시 묻고 싶은 질문 하나와 자료 몇 개를 정하고, 기존 개념·비교·종합을 갱신하게 한 뒤 다음 질문에서 실제로 다시 읽는지 봅니다.
