AI 스터디 준비: 자료·주장·결정 연결 예제
공개 합성 자료 / 2026-10-28

이 파일의 E1~E4·EC1~EC2·ED1~ED2, 날짜·이름·운영 상황은 모두 설명을 위한 합성 예제다. 실제 모임 운영 기록, 실제 초대장 수정, 실제 도입 성과가 아니다. S1·S10·S11·S12라는 실제 조사 출처와 구분한다.
자료→주장→결정의 통합 카드와 아래 검토 절차는 우리 제안이다. 공식 LLM Wiki·PROV·ADR 표준 양식이 아니다. 결정의 배경·선택·상태·결과 및 대체 이력은 S10에서 착안했고 스터디 운영에 응용했다.

원자료 카드
아래 문구는 발표자가 작성한 합성 자료의 전체 문장이다. 원자료를 덮어쓰지 않고 새 판 E2를 추가한다. 각 자료의 별도 수정일은 이 예제에서 설정하지 않았다. 확인일·검토자는 아래 예제 내 확인 시점을 뜻한다.

E1 / 운영 공지 1판
작성일: 2026-10-20 / 별도 수정일: 미설정
원본 위치: 합성 자료 E1의 본문 1문장
정확한 문구: “11월 5일 AI 스터디는 오후 8시에 시작한다.”
확인일·검토자: 2026-10-21 / 가상 운영자 민지
연결: 운영 페이지 → EC1 → ED1
지원 범위: 2026년 11월 5일의 시작 시각 20:00. 반복 주기나 다른 날짜의 시각은 지원하지 않는다.

E3 / 읽기 메모
작성일: 2026-10-22 / 별도 수정일: 미설정
원본 위치: 합성 자료 E3의 본문 1문장
정확한 문구: “이번 스터디에서는 답의 출처와 주장 범위를 나눠 적어 보자.”
확인일·검토자: 2026-10-23 / 가상 운영자 민지
연결: 개념 페이지 “출처와 주장 구별하기” → 질문 페이지
범위: 스터디에서 해 보자는 합성 제안이다. 기술 논문이나 효과의 근거가 아니다.

E4 / 질문 메모
작성일: 2026-10-23 / 별도 수정일: 미설정
원본 위치: 합성 자료 E4의 본문 1문장
정확한 문구: “답에 링크가 있으면 문장 전체를 믿어도 될까요?”
확인일·검토자: 2026-10-23 / 가상 운영자 민지
연결: 질문 페이지 “출처가 있어도 확인할 것은?” → 개념 페이지
범위: 질문 자체다. 답의 사실성이나 링크의 신뢰성을 입증하는 자료가 아니다.
검토 후 남기는 합성 답안: “링크된 자료가 이 문장과 적용 범위를 실제로 지원하는지 확인합니다.”
축적 방식: 이 답안을 사람이 근거·범위와 대조한 뒤 질문 페이지에 남기고 개념 페이지에 연결한다. 다음 질문에서 다시 사용할 수 있도록 파일에 남기는 운영 제안이며, 모든 답을 자동 저장하지 않는다.

E2 / 운영 변경 공지 2판
작성일: 2026-10-27 / 별도 수정일: 미설정
원본 위치: 합성 자료 E2의 본문 1문장
정확한 문구: “이번 11월 5일 모임은 오후 8시 30분으로 변경한다.”
확인일·검토자: 2026-10-28 / 가상 운영자 민지
연결: 운영 페이지 → EC2 → ED2 → ED1의 대체 이력
지원 범위: 이번 2026년 11월 5일 시작 시각을 20:30으로 명시적으로 변경한다. 다른 날짜까지 바꾸는 근거가 아니다. 채택 이유는 문서 날짜가 더 늦다는 사실만이 아니라 명시된 변경 내용과 대상 날짜를 확인했기 때문이다.

주장 카드

EC1 / 1판 기준으로 확인한 주장
한 문장: “11월 5일 시작은 오후 8시.”
근거 ID·위치: E1, 본문 1문장의 “11월 5일”과 “오후 8시에 시작한다”.
종류: 합성 예제 안에서 직접 지원.
적용 범위: 2026년 11월 5일, E1 공지 1판 기준의 20:00.
확인일·검토자: 2026-10-21 / 가상 운영자 민지
확인 상태: 1판 기준 확인. 2026-10-28에는 E2/EC2에 따른 변경을 확인했으므로 과거 판의 주장으로 보존하며 현행 안내에는 사용하지 않는다.
지원하지 않는 문장: “매주 오후 8시.” 반복 주기는 미확인이다. 미지원이라는 판단을 “실제로 매주가 아니다”라는 새 사실로 바꾸지 않는다.
연결: E1 → EC1 → ED1. 후속 주장은 EC2다.

EC2 / 변경 공지를 확인한 주장
한 문장: “11월 5일 시작은 오후 8시 30분.”
근거 ID·위치: E2, 본문 1문장의 “이번 11월 5일 모임”과 “오후 8시 30분으로 변경한다”.
종류: 합성 예제 안에서 직접 지원.
적용 범위: 이번 2026년 11월 5일, 변경 공지 2판 기준의 20:30.
확인일·검토자: 2026-10-28 / 가상 운영자 민지
확인 상태: 2판의 명시적 변경과 날짜 범위를 확인한 현행 주장.
지원하지 않는 확장: 매주 또는 다른 날짜도 모두 20:30이라는 문장.
연결: E2 → EC2 → ED2. 이전 주장 EC1은 삭제하지 않는다.

결정 카드
아래 결과는 가상 결정에 따라 예상되는 영향·남은 부담이다. 외부 안내물 수정 완료를 뜻하지 않는다.

ED1 / 1판 기준 오후 8시 안내 사용
배경: 11월 5일 모임 안내를 준비해야 하며 당시 확인한 자료는 E1 공지 1판이다.
근거: E1 / EC1. 근거가 지원하는 것은 해당 날짜의 시작 시각이다.
선택: 1판 기준 오후 8시 안내를 사용하기로 한다.
선택 이유: 확인한 공지와 안내를 맞춰 혼선을 줄이려는 가상 운영자의 판단이다.
대안: 추가 확인이 끝날 때까지 안내를 보류한다.
결과·부담: 안내를 준비할 기준이 생긴다. 공지가 바뀌면 관련 안내와 연결된 주장을 다시 점검할 부담이 생긴다. 실제 초대장 발송·수정 성과를 기록한 것은 아니다.
당시 상태: accepted (2026-10-21).
현재 상태: superseded by ED2 (ED2 승인일 2026-10-28).
담당·결정자: 가상 운영자 민지.
결정일: 2026-10-21.
재검토 조건: 11월 5일 공지의 변경, 시각에 관한 충돌, 또는 근거 범위 오류가 확인되면 재검토한다.
이전 결정: 없음. 이 합성 예제의 첫 안내 결정이다.
후속 결정: ED2. ED1을 삭제하지 않고 당시 근거·선택 이유와 대체 관계를 보존한다.

ED2 / 이번 11월 5일 안내를 오후 8시 30분으로 교체
배경: E2가 이번 11월 5일 모임의 시작을 명시적으로 20:30으로 변경했다. 이전 운영 페이지의 EC1과 안내 결정 ED1을 함께 검토해야 한다.
근거: E2 / EC2. 변경 문구와 해당 날짜 범위를 사람이 확인했다.
선택: 이번 11월 5일 안내를 오후 8시 30분으로 교체하기로 승인한다. 현행 운영 페이지에는 EC2·ED2를 연결하고 ED1은 대체된 결정으로 보존한다.
선택 이유: 명시적인 변경 공지에 안내 기준을 맞추고, 어느 날짜가 바뀌었는지와 과거 판단의 이유를 함께 추적하기 위해서다. 단순히 나중 날짜의 문서라서 채택하는 것은 아니다.
대안: 기존 20:00 안내를 유지하거나, 추가 확인까지 안내 교체를 보류한다.
결과·부담: 현행 안내의 기준은 이번 11월 5일 20:30이 된다. ED1과 EC1은 과거 판의 근거·판단으로 남는다. 초대장 등 관련 안내의 점검·필요한 수정은 남은 할 일이다. 실제 초대장이나 외부 시스템을 수정했다는 뜻은 아니다.
상태: accepted (2026-10-28).
담당·결정자: 가상 운영자 민지.
결정일: 2026-10-28.
재검토 조건: 해당 날짜의 추가 변경 공지, 서로 다른 시각의 충돌, 또는 E2 해석·적용 범위 오류가 확인되면 재검토한다.
이전 결정: ED1. ED1의 현재 상태를 superseded by ED2로 연결한다.
후속 결정: 없음. 이후 변경이 생기면 새 결정을 만들고 대체 이력을 잇는다.

검토와 이력을 보여 주는 흐름
1. E1·E3·E4를 읽고 운영·개념·질문 페이지를 연결한다.
2. E4의 유용한 답을 근거·범위와 대조하고 사람이 검토한 뒤 파일에 남긴다.
3. E1의 한 날짜와 시각에서 EC1을 확인한다. “매주”는 미확인으로 남긴다.
4. 가상 운영자가 ED1을 선택하고 이유·대안·재검토 조건을 적는다.
5. E2의 명시적 변경과 날짜를 확인해 EC2를 만든다. 관련 운영 페이지·EC1·ED1을 함께 본다.
6. 사람이 ED2를 승인한다. ED1은 superseded by ED2로 연결하고 EC1도 과거 1판 기준으로 보존한다.
7. index에서는 현행 운영·개념·질문 페이지를 찾고, log에는 무엇을 언제 왜 바꿨는지 남긴다. 관련 초대장 점검은 할 일로 남긴다.

이 연결은 검토할 자리를 만드는 제안이다. 누락된 연결을 모두 찾거나, AI가 오류 없이 범위를 해석하거나, 모든 파일이 자동으로 최신 상태가 된다고 보장하지 않는다. 파일 저장 자체는 모델 가중치 학습이 아니다. 파일 wiki도 필요하면 검색(RAG)과 함께 사용할 수 있다.
